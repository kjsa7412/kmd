# kmd-migrate: 기록으로 항목 다시 그리기

kmd 의 지식은 문서(항목 = `##` 머리)와 기록(`work/` · `log/`)이다. 저장이 조각조각 쌓인 항목은 경위가 섞이고 글이 길어진다. 이 스킬은 **그 항목을 건드린 기록 전부를 오래된 순으로 읽어 「지금」 으로 다시 쓰고**, 서비스와 같은 검사를 지나 넣는다.

화면 기능이 아니다. 지식 폴더를 직접 다루는 사람(그 지식의 지식관리자 · 총괄 관리자)이 세션에서 돌린다. 쓰는 길은 `scripts/kmd-migrate.mjs` 하나다. 이 스크립트가 core 의 저장(`core/save.js`)과 검사(`core/gate.js` `checkSection`)를 지식 폴더에 바로 건다. **지식 파일을 손(Edit · Write)으로 고치지 않는다.**

```
① 자리 잡기   지식 사본 받기 · 최신으로 · 진단(scan) · 다시 그릴 항목 · 빠진 사건 고르기(사람 승인)
② 항목마다    trail(지금 글 + 이어진 기록) → 다시 쓰기 → check → 승인 표 → put
              빠진 사건은 rec(재료 기록) → 새 항목 쓰기(new · sources) → check → 승인 → put
③ 올리기      git push → 팀 화면 「백업에서 받기」
④ 끝 보고     진단 전 → 후 · 넣은 것 · 걸러 둔 것
```

도구(kmd 저장소에서 · `<K>` = 지식 폴더):

| 명령 | 하는 일 |
|---|---|
| `node scripts/kmd-migrate.mjs scan <K> [--doc docs/x.md] [--json]` | 진단: 문서마다 항목 · 기록 없는 항목 · 다시 그릴 만한 항목(이어진 기록 5↑) · 큰 항목 · 같은 글 · 틀 문장 · 닿지 않은 기록 |
| `node scripts/kmd-migrate.mjs trail <K> <docs/x.md> "<머리>" [--json] [--full]` | 항목 하나: 지금 글 · `base` · 장부 항목 · 이어진 기록(오래된 순 · 표시) |
| `node scripts/kmd-migrate.mjs rec <K> <기록 id> [--json]` | 기록 하나: 상태 · 건드린 항목 · 넣은 곳 · 본문 |
| `node scripts/kmd-migrate.mjs check <K> <input.json>` | 마른 검사(쓰지 않음): 꼴 · 지문 · 값 대조 · 사라지는 표 행 · 문장 |
| `node scripts/kmd-migrate.mjs put <K> <input.json> --user <사람> [--allow-drop]` | 저장 줄 안에서 다시 검사 → 기록 + 항목 + git 커밋 한 묶음. 걸리면 아무것도 쓰지 않는다 |
| `node scripts/kmd-migrate.mjs put <K> <input.json> --user <사람> --format` | 서식 맞춤: 값 장부가 같을 때만 · 기록이 아니라 이력(`log/` · 태그 `format`) · 참고 줄 없음 |
| `node scripts/kmd-migrate.mjs check · put <K> <ledger.json> --user <사람> [--format]` | 장부만 고치기(항목 글 없음): 뜻 한 줄 · 폐기 · 합치기 · 별칭 빼기 · 종류 뜻 줄 · 장부 줄 걷기 · 새 항목 줄 · 갈래 · 문서 성격. 서버 화면의 장부 고침과 같은 저장 문 · 이력(`log/` · 태그 `ledger`) · 값 대조 없음 |
| `node scripts/kmd-migrate.mjs relog <K> --user <사람> (--title <제목 앞> \| <기록 id>…) [--dry]` | 기록으로 남긴 서식 맞춤을 이력으로 옮긴다(참고 줄 걷음 · 커밋 하나) |
| `node scripts/kmd-migrate.mjs residue <K> [--personal] [--json]` | 옛 꼴 셈 표(쓰지 않음): 기계 규칙마다 바꿀 셈 · 사람 · 세션이 볼 것 |
| `node scripts/kmd-migrate.mjs oldform <K> --user <사람> [--dry] [--drop <기록 id,… \| 파일>] [--personal]` | 옛 꼴 → 지금 꼴(기계 규칙만) · 다시 읽은 상태가 앞과 같을 때만 · 이력 하나(태그 `format`) · 커밋 하나 |


## ① 자리 잡기

1. **어디서 쓰나: 사본이 기본이다.** 지식의 백업 자리(GitLab)를 내 PC 에 받는다. 백업 주소는 팀 화면 설정 › 백업, 또는 서버에서 `kmd backup`. 이미 받은 사본이면 `git -C <K> pull --ff-only`.
   - 팀 서버가 도는 폴더(`/srv/kmd/<지식>`)에 바로 쓰지 않는다. 서버는 지식을 캐시로 들고 있어 낡은 글로 판정하고, 서버의 저장과 줄이 섞인다.
   - 어쩔 수 없이 서버에서 쓰면: 도는 일감(`/srv/kmd/.kmd/jobs.json`)이 없을 때, `sudo -u kmd node /opt/kmd/scripts/kmd-migrate.mjs …` 로 쓰고, 끝나면 `systemctl restart kmd`. 사람에게 먼저 묻는다.
2. **사람(`--user`)**: 그 지식의 지식관리자인 사람 id(예: `kjsa`). `kmd` · `kmd-auto` 같은 예약 이름은 거절된다. 스크립트는 자리를 보지 않으니 사람에게 확인한다.
3. **진단**: `scan <K>`. 결과 표를 그대로 보이고 이렇게 읽는다.
   - **다시 그릴 만한 항목**(이어진 기록이 많다)이 대상이다. 이슈 대장 · 화면 설계처럼 작은 저장이 쌓인 곳이다.
   - **기록 없는 항목**은 다시 그리지 않는다. 재료가 지금 글뿐이라 다시 써도 얻을 것이 없고 잃을 것만 있다. 「다듬기」(팀 화면)의 일이다.
   - **틀 문장**(여러 항목에 같은 안내 글)은 다시 그리기 대상이 아니다. 한 항목에 두고 링크로 바꿀지는 사람이 따로 정한다.
   - **갈래 문서에 빠진 사건 기록**: 갈래 장부(`_forms.md`)의 사건 갈래(회의록 · 주간보고서 · 장애 대응 …)마다, 이름 · 태그로 그 갈래에 드는 기록인데 그 문서에 항목이 없는 것. 회의 기록이 이슈 대장 같은 주제 문서에만 들어가고 회의록에는 빠진 경우다. **후보**다: 제목에 「통화」 가 든 이슈 대장 기록처럼 회의가 아닌 것도 섞인다. 기록마다 `rec` 로 읽고 가른다. 채우는 법은 ②-6.
4. **고르기**: 문서 하나 · 항목 열 개 안팎씩. 고른 목록(문서 › 머리 · 기록 수 · 줄 수)을 보이고 **사람 승인을 받는다**. 지식 통째로 하지 않는다.

## ② 항목마다

### 1. 읽기

`trail <K> <문서> "<머리>"` 로 지금 글과 이어진 기록을 읽는다. 기록 본문이 2천 자에서 접히면 `--full`. `--json` 으로 받아 두면 `base` 를 옮겨 적기 쉽다.

이어진 기록의 표시:

| 표시 | 뜻 | 다루는 법 |
|---|---|---|
| (없음) | 사람 · 세션이 남긴 기록 | **재료**. 오래된 것부터 읽고 늦은 것이 이긴다 |
| `derived` | 앞서 Claude 가 지은 글(다듬기 · 들이기 · 다시 그림) | 값의 근거로만. 문장을 옮겨 오지 않는다(합성 위에 합성을 쌓지 않는다) |
| `[문서 단위]` | 문서 전체에 걸린 기록 | 이 항목에 닿는 부분만 |

### 2. 다시 쓰기

먼저 [작성가이드](../../../agent/skills/kmd-build/작성가이드.md)와 [문서 작성기준](../../../docs/kmd_문서_작성기준.md) 3 ~ 5절을 읽는다(세션에 한 번). 지키는 것:

- **지금 글이 바탕이다.** 기록이 바꾼 것만 바꾼다. 지금 글의 사실을 지우려면 기록이 그렇게 말해야 한다.
- **대상 하나의 지금**으로 쓴다. 「…했다는 기록이 있다」 · 날짜별로 덧붙인 줄 · 회의 경위 · 질문 목록은 걷는다(기록에 남아 있다). 대장(이슈)의 진행상태 · 결론은 지금으로 고쳐 쓴다.
- **값은 글자 그대로**(수 · 날짜 · 이름 · `코드`). 기록에 없는 값을 지어내지 않는다.
- **머리 이름은 바꾸지 않는다.** 글에 `#` · `##` 줄 · `<!-- -->` · `**경과**` · `work/` · `log/` 링크를 넣지 않는다. 참고 블록 · 표지는 kmd 가 단다.
- 링크는 문서(`x.md`) · 항목(`x.md#머리`) · 바깥(`https://…`) 셋만. 줄표 「—」 를 쓰지 않는다.
- 문단 다섯 줄까지 · 나란한 것 셋 이상은 목록 · 견주는 속성 둘 이상은 표 · 「…한다」 체 · 항목 300줄 안.
- **수준 표시(작성기준 5-1절)**: 항목 안 짜임은 들여쓰지 않고 줄 머리 표시로 쓴다. 덩이 `1.` · `1.1.`, 순서 있는 낱낱 `1)` · `1.1)`, 순서 없는 나열 `-`, 그 아래 덧말 `*`. 새로 쓰는 글에 `###` 소제목 · 들여쓴 목록을 두지 않는다. 회의록 항목의 「정한 것」 아래 낱낱도 들여쓰지 않고 `*` 로 쓴다.

좋은 예와 나쁜 예(이슈 대장):

```md
나쁜 예
**결론**: 2026-10-01 매뉴얼을 조사했다. 2026-10-14 통화에서 회신을 받았다. 그 뒤 PLC 로 바꾸기로 했다는 기록이 있다.

좋은 예
**결론(지금)**: CIMON 사용자 프로토콜로는 외부에서 제어 명령을 낼 수 없다. SCADA 를 연계 경로에서 빼고, 게이트웨이가 펌프장 PLC 에 Modbus TCP 로 직접 붙는다(`DPMS-ISS-02`).
```

### 3. 기록 · 입력 짓기

새 글은 파일로 둔다(예: 세션 스크래치의 `iss01.md`). 입력 `input.json`:

```json
{
  "record": {
    "title": "다시 그림: 위험및이슈관리대장 › DPMS-ISS-01",
    "body": "이어진 기록 11건으로 DPMS-ISS-01 을 지금 상태로 다시 썼다.\n\n## 바뀐 것\n- 진행상태: 확인 중 → 해결 (2026-10-14)\n- 남은 확인 목록: `Q1 ~ Q18` → (뺌)\n\n## 까닭\n- 작은 저장 11건이 쌓여 결론 · 경위가 섞였다\n\n## 근거\n- 이어진 기록: 2026-0930-… · 2026-1014-… (11)"
  },
  "sections": [
    { "doc": "docs/1.2_사업관리/위험및이슈관리대장.md", "heading": "DPMS-ISS-01: SCADA(CIMON) 외부 인터페이스 확인", "base": "<trail 의 base>", "contentFile": "iss01.md" }
  ]
}
```

- **항목 하나 = 입력 하나 = 기록 하나**가 기본이다. 여러 항목을 한 기록에 담으면 「바뀐 것」 의 허용이 다른 항목으로 샌다.
- 기록 본문은 [기록 서식](../../../docs/템플릿/기록.md)이다. 첫 문단은 한두 문장 요약(300자 안).
- **`## 바뀐 것`** 에 이 다시 쓰기로 바뀐 값만 적는다.
  - 바꾼 값: `- 무엇: 옛 값 → 새 값`.
  - 지운 값: `- 무엇: 옛 값 → (뺌)`. 값이 빠지면 저장 검사가 「옛 글의 값이 빠졌다」 로 거절한다. 그래서 지운 값을 여기에 적어야 넘는다. 사람이 승인한 것만 적는다.
  - 오른쪽 새 값은 글에 꼭 있어야 한다(「기록의 값이 글에 없다」).
  - 여러 기록에서 값이 8080 → 9090 → 9191 로 갔으면 한 줄로 접는다: 「8080 → 9191」. 중간 값을 적으면 그것이 요구 값이 된다.
- `## 까닭` · `## 근거` 에는 화살표(→)를 쓰지 않는다. 화살표 왼쪽 값은 어디에 있든 「빼도 되는 값」 으로 읽힌다. 진단 수 · 날짜 · 기록 id 도 이 두 칸에 둔다(요구 값이 되지 않는다).
- `touches` 는 비워 둔다. `put` 이 그 항목(장부의 `종류:값`)을 단다. 태그 `rebuild` 도 `put` 이 단다.

### 4. 마른 검사

`check <K> input.json`. 걸린 까닭마다 고친다.

| 까닭 | 고치는 법 |
|---|---|
| 그사이 항목이 바뀌었다(conflict) | `trail` 로 다시 읽고 새 `base` 위에서 다시 쓴다 |
| 옛 글의 값이 빠졌다 | 그 값을 글에 살리거나, 지운 것이 맞으면(사람 확인) `## 바뀐 것` 에 「옛 → (뺌)」 |
| 기록의 값이 글에 없다 | `## 바뀐 것` 의 새 값을 글에 쓴다 |
| 기록 › 본문 반영(unreflected) | 바뀐 것의 새 값을 그 값을 지닌 항목 글에 넣는다(넣는 항목들을 합쳐 본다). 「옛 → 새」 의 새 값은 옛 글에 다른 뜻으로 있던 것으로 대신하지 않는다. 바꾸지 않은 값은 바뀐 것이 아니라 요약 · 까닭에 |
| 근거에 없는 값이 있다 | 지어낸 값이다. 지우거나, 원천에 있으면 새 값은 `## 바뀐 것` 「옛 → 새」 로 · `## 근거` 에는 원천 파일 · 줄(근거 기록)을 적는다. 값만 늘어놓아 넘기지 않는다 |
| 글에 머리 · 표지가 들었다 | `#` 줄 · 주석 · 기록 링크 · 경과 꼬리를 뺀다 |

「사라지는 표 행」 · 「사라지는 문장」 은 걸림이 아니라 **사람이 볼 것**이다. 표 행은 첫 열 열쇠가 새 글에 없는 행이고, 문장은 새 글 어디와도 닮지 않은 옛 문장이다(어림 · 말만 바꾼 줄도 나온다).

### 5. 승인 · 넣기

검사가 「걸림 0」 이면 사람에게 이 표를 보인다. **사람이 승인한 항목만 넣는다.**

```
【다시 그리기】 위험및이슈관리대장 › DPMS-ISS-01 · 이어진 기록 11(파생 1)
  줄           30 → 18
  바뀐 값       진행상태: 확인 중 → 해결 (2026-10-14) · 남은 확인 목록 → (뺌)
  사라지는 문장  2   「해결방안: SCADA 매뉴얼에서 …」 · 「남은 확인 1 ~ 18 …」
  사라지는 표 행 0
  지금 글 ↔ 새 글: (diff 요지 몇 줄)
승인하시면 넣습니다(기록 1 · 커밋 1).
```

- 사라지는 것이 없으면 `put <K> input.json --user <사람>`.
- 사라지는 문장 · 표 행이 있고 사람이 「빼도 된다」 고 하면 `--allow-drop` 을 붙인다. 하나라도 살려야 하면 글에 되살려 다시 `check`.
- `put` 은 저장 줄 안에서 새로 읽은 지식으로 다시 검사한다. 걸리면 **아무것도 쓰지 않는다**(넣지 못함을 남기지 않는다).
- 넣으면 기록 id 와 커밋이 나온다. 항목 표지(`applied`) · 참고 블록 줄 · 기록의 `## 넣은 것` 은 저장이 단다. 그래서 팀 화면 이력에서 그 항목을 [되돌리기] 할 수 있다.

### 6. 갈래 문서에 빠진 항목 채우기

회의록처럼 사건이 쌓이는 갈래 문서에 그 사건의 항목이 없을 때다. 재료 기록은 이미 다른 문서(이슈 대장 · 설계)에 들어가 있어도 된다. 회의록 항목은 「그날 무엇을 나누고 무엇을 정했나」 이고, 주제 문서는 「지금」 이라 둘 다 있어야 한다.

1. `scan` 의 「갈래 문서에 빠진 사건 기록」 에서 후보를 고르고, 기록마다 `rec <K> <id>` 로 읽는다. **열린 회의 · 통화의 기록만** 항목이 된다. 회의를 준비하는 글(안건 · 질의서 · 스크립트) · 문서 고친 기록 · 이슈 대장 갱신은 항목이 아니다(후보에서 뺀다고 표에 적는다).
2. 머리는 「YYYY-MM-DD 무엇」(회의 · 통화가 열린 날 · 기록 제목의 상대 · 주제). 이미 있는 머리와 겹치지 않게.
3. 글은 갈래의 서식([작업기록](../../../docs/템플릿/작업기록.md))대로: **누가 · 무엇을 · 정한 것 · 남은 것**. 정한 것 · 할 일만 옮기고, 원문 붙여 넣기 · 인사말 · 진행 멘트 · 시간 배분 · 묻는 말 목록은 옮기지 않는다. 지금도 이어지는 주제는 그 이슈 · 항목 이름(`DPMS-ISS-01`)으로 가리킨다. 값은 재료 기록에 있는 것만.
4. 입력은 ②-3 과 같고, 항목에 `base` 대신 `"new": true` · `"sources": ["<재료 기록 id>"]` · `"kind"` · `"gist"` 를 둔다(「새 항목의 장부 줄」 절). 기록은 「회의록 채우기: <머리>」, `## 바뀐 것` 에 「- 회의록 항목: <머리> 새로 둠」, `## 근거` 에 재료 기록 id.
5. `check` 는 재료 기록을 근거로 값을 대조한다(재료에 없는 값은 「근거에 없는 값」). 사건 갈래의 머리 꼴 · 이미 있는 머리도 거절한다.
6. 승인 표(②-5)에 새 항목 글 전체를 보이고 승인받아 `put`. 회의 하나 = 입력 하나 = 기록 하나.
7. **날짜 자리에 끼운다.** 사건 갈래 문서면 `check` 가 새 머리의 날짜보다 늦은 첫 항목을 찾아 「자리: 「…」 앞」 으로 보이고, `put` 이 그 앞에 넣는다(같은 날은 뒤 · 날짜 없는 머리는 건너뜀 · 다른 항목의 글은 한 줄도 바뀌지 않는다). 사건 갈래가 아닌 문서는 끝에 붙고, 자리를 정하려면 항목에 `"before": "<있는 머리>"`. 이미 있는 항목의 차례는 바꾸지 않는다: `scan` 이 「날짜 차례 어긋난 항목 n」 으로 알리면 끝 보고에 적는다.
   - 갈래 문서가 아직 없으면(`scan` 의 「문서 없음」) 그 갈래 장부의 폴더 · 이름 그대로(`docs/<폴더>/<갈래>.md`) 항목의 `doc` 에 적는다. `check` 가 「자리: 새 문서」 로 보이고 `put` 이 문서(`# 갈래`)를 세워 첫 항목을 넣는다. 장부에 없는 문서 · 다른 폴더는 거절한다.
8. 넣은 뒤 `scan` 을 다시 돌려 그 기록이 「빠진」 목록에서 사라졌는지 본다.

## ③ 올리기

1. 묶음(문서 하나) 끝마다 올린다. 오래 쥐고 있을수록 서버와 갈라진다.
2. `git -C <K> pull --rebase` 로 그사이 서버가 올린 것 위에 얹는다. 같은 문서가 겹쳐 충돌하면 `git rebase --abort` → `git reset --hard @{u}` → 그 항목들을 ② 부터 다시 한다(옛 base 로 넣은 글이라 맞추지 않는다).
3. `git -C <K> push`.
4. **곧바로** 팀 화면(총괄 관리자) 알림의 「백업이 앞섰다」 줄에서 [백업에서 받기]. 서버에서는 `sudo -u kmd node /opt/kmd/server/bin/kmd.mjs backup pull <지식> --root /srv/kmd --team` 뒤 `systemctl restart kmd`(서버가 지식을 캐시로 들고 있다). 앞으로만 받고, 받은 글에 새 오류가 있으면 되돌린다.
   - push 와 받기 사이에 서버에서 저장이 있으면 「갈라졌다」 가 된다. 이때는 받지 말고 사람에게 알린다(어느 쪽이 맞는지 사람이 정한다).
5. 받은 뒤 팀 화면에서 그 항목을 열어 글 · 이력(「다시 그림」 기록)을 확인한다.

## 서식 맞춤은 기록이 아니라 이력이다

기록도 지식이다. 기록(`work/`)에는 그 일 · 대상에서 무엇이 정해지고 바뀌었나만 남긴다. 값은 그대로 두고 문서를 새 서식(작성기준 6-3)으로 옮기는 일(첫 문장 더하기 · 라벨 줄 · 속성 표 · 날짜 표기 · 문서 요약)은 지식이 바뀐 것이 아니라서 **이력**이다.

- 넣기는 `put <K> input.json --user <사람> --format`. 저장 문이 옛 글과 새 글의 값 장부를 견주어(날짜 표기만 YYYY-MM-DD 로 맞춰) 같을 때만 넣고, 이력(`log/` · 태그 `format` · 이력 갈래 「서식」)으로 남긴다. 항목의 참고 블록(출처)에 줄을 달지 않는다. `rebuild` 태그도 달지 않는다.
- 값이 하나라도 바뀌면 서식 맞춤이 아니다(「서식 맞춤은 값을 바꾸지 않는다」 로 아무것도 쓰지 않는다). 그 값은 다시 그리기(기록)로 따로 넣는다.
- 기록 본문은 짧게: 무엇을 맞췄나 한 문장과 `## 까닭`(서식 계약). `## 바뀐 것` 에 「옛 → 새」 를 적지 않는다(값이 바뀌지 않는다).
- 앞서 서식 맞춤을 기록으로 넣었으면 `relog <K> --user <사람> --title "서식 맞춤:" [--dry]`(또는 기록 id 들)로 이력으로 옮긴다: 기록 파일을 `log/` 로(태그 `format` 더함 · `rebuild` 뺌) · 문서 참고 블록의 그 기록 줄을 걷는다 · 커밋 하나. 다른 기록이 근거로 가리키는 기록은 옮기지 않는다.
- 갈래 장부만 바꾼 저장 · 문서 짜임(머리 이름 · 옮기기)은 저장 문 · 짜임 엔진이 이미 이력으로 남긴다.

## 장부만 고치기(ledger)

항목 글을 바꾸지 않고 장부만 고칠 때(옛 장부 줄의 뜻 한 줄 채우기 · 섹션 없는 장부 줄 걷기 · 종류 뜻 줄 · 갈래 · 문서 성격 표) core 를 직접 부르지 않고 `put` 에 싣는다. `sections` 를 비우고(또는 빼고) 아래 칸을 싣는다. 서버 화면의 장부 고침(`hub.ledgerEdit`)과 같은 저장 문(`core/save.js` system 걸음)을 지나 이력(`log/` · 태그 `ledger`) 하나 · 커밋 하나로 남는다. 걸음 하나라도 걸리면 아무것도 쓰지 않는다. 먼저 `check <K> ledger.json` 으로 걸음 목록과 걸림을 본다.

```json
{
  "why": "옛 장부 줄의 뜻 한 줄 채우기",
  "ledger": [
    { "op": "gist", "coord": "이슈:ISS-001", "gist": "로그인 시 세션이 끊기는 문제" },
    { "op": "kind", "kind": "이슈", "gist": "사업 중 생긴 문제 하나" },
    { "op": "retire", "coord": "시험:통합시험", "to": "시험:통합시험_계획", "why": "섹션 없는 장부 줄(O-2)" },
    { "op": "merge", "coord": "term:버퍼", "into": "term:버퍼링" },
    { "op": "unalias", "coord": "term:버퍼링", "alias": "buf" },
    { "op": "unplace", "coord": "시험:통합시험" }
  ],
  "names": [{ "coord": "이슈:ISS-002", "gist": "있는 항목이면 뜻 한 줄 고치기가 된다" }],
  "natures": [{ "doc": "설계/게이트웨이", "nature": "대상", "summary": "게이트웨이의 구성과 설정" }]
}
```

- 걸음: `gist`(있는 항목의 뜻 한 줄 · 있으면 갈음) · `retire`(폐기 · `to` 로 이을 항목) · `merge`(합치기 · 라벨 · 별칭을 `into` 의 별칭으로) · `unalias`(별칭 하나 빼기) · `kind`(「## 종류」 아래 「뜻:」 줄 · 있으면 갈음) · `unplace`(문서 장부 줄 걷기: 섹션 없는 옛 줄 포함) · `unform`(갈래 줄 걷기) · `unnature`(문서 성격 줄 걷기).
- `names` 에 이미 장부에 있는 항목을 `gist` 와 함께 적으면 `gist` 걸음이 된다. 없는 항목은 새 항목 줄(자리 `doc` · `heading` 이 있으면 문서 장부 줄도)로 선다.
- `record` 는 없어도 된다(걸음 목록과 `why` 로 짓는다). `--format` 을 달면 태그 `format` 도 단다(서식 맞춤 이력과 같이 모아 볼 때).
- `ledger` 는 `sections` 와 같이 싣지 않는다. 항목 글은 따로 `put` 한다.

## 옛 꼴 옮기기(residue · oldform)

옛 꼴(정리 시절 장부 머리 · 저장 문 밖에서 들어간 기록 · 옛 표지 · 정리 시절 이력 · 이관 흔적)을 아는 곳은 `core/oldform.js` 하나다([KMD_옛잔재_정리](../../../docs/품질개선/KMD_옛잔재_정리.md) O-9). 팀 지식은 이 명령으로, 개인 지식은 개인 프로그램이 지식을 열 때 한 번(`runOnce`) 옮긴다. 다른 코드는 지금 꼴만 읽는다.

차례(사본에서 · ①-1 과 같다):

1. `residue <K>` 로 셈 표와 「사람 · 세션이 볼 것」 을 보인다. 기계 규칙은 옛 읽기(이행기 안에 둔 사본)로 본 결과를 지금 꼴로 굳힌다(갈래 장부 새 문서 줄 · 장부 머리 · 사람 장부 옛 줄 · 저장 문 밖에서 들어간 기록의 `put` + 「넣은 것」 · 머리말 `source` · `attachments` · work/ 에 쓴 이력(log/ 로) · 참고 블록의 옛 기록 줄(링크 뒤 「 · 」 없는 한 마디 · 같은 기록 줄은 한 줄로) · 옛 표식 메모 · 정리 시절 이력(태그 `curate` · `curate-llm` · `curate-auto` · `docfmt` · `levels` · `tidy`) · `_seed.json` · 기록 없는 첨부). 되돌림 · 바로잡기(`touches-fix` 포함)를 지닌 정리 시절 이력은 지우지 않고 볼 것으로 돌린다.
2. 볼 것을 세션에서 가른다. 옛 표지 기록(held · memo · migrate-held)과 「지금 글에 다 들지 않은 기록(old)」 은 `rec` 로 읽어 값이 지금 글에 있는지 대 본다. 없는 값은 ② 의 다시 그리기로 새 기록과 함께 넣고, 다 들어간 기록 id 를 파일(한 줄에 하나 · `#` 줄은 설명)에 적는다. 사람 승인을 받는다.
3. `oldform <K> --user <사람> --dry [--drop <파일>]` 로 바꿀 파일과 「대 보기」 를 보인다. 대 보기는 계획대로 쓴 사본을 지금 코드로 다시 읽어 기록 상태 · 항목 장부 · 문서 장부 자리 · 갈래 장부 · 사람 장부 · 문서 본문이 앞과 같은지 본다(지운 기록이 바로잡았던 기록이 바로잡힘이 풀려 「들어감」 이 되는 것만 다르다 · 다른 상태로 바뀌면 막는다). 다르면 쓰지 않는다.
4. 사람 승인 뒤 `--dry` 없이. 고친 · 지운 파일과 이력 하나(`log/<날짜>-옛-꼴-옮김` · 태그 `format`)가 커밋 하나로 남는다. 지운 기록을 가리키는 참고 줄 · `applied` 표지(다른 기록으로 옮기지 않고 걷기만 한다 · 굳힌 기록은 `put` 으로 읽혀 표지에 기대지 않는다) · 다른 기록의 `supersedes` · `reflects` 도 같이 걷는다. 되돌릴 때는 그 커밋을 revert 한다.
5. `residue <K>` 를 다시 돌려 기계 규칙 셈이 모두 0 인지 본다(두 번 돌려도 바뀌지 않는다). 그 뒤 ③ 올리기.

`--personal` 은 개인 지식 꼴(옛 표지 기록을 「## 남은 것」 사람 말로 바꿔 항목 없는 기록으로 · 저절로 채우는 표 블록 표식 · 사본 문서 표지도 기계로)이다. 팀 지식에는 쓰지 않는다.

## ④ 끝 보고

한글로, 원인 → 고친 것 → 남은 것.

- 진단 합계 전 → 후(`scan` 다시).
- 넣은 항목 · 기록 id · 커밋 · 줄 수 전 → 후 · 승인받아 뺀 값 · 문장 수.
- 건너뛴 항목과 까닭(기록 없음 · 사람이 보류).
- 올리기 결과(push · 백업에서 받기).

## 하지 않는 것

| | 어디로 |
|---|---|
| 지식 파일을 손(Edit · Write)으로 고치기 | 없다. 늘 `put` |
| 기록 없는 항목 다시 쓰기 · 문체만 고르기 | 팀 화면 [다듬기] |
| 머리 이름 바꾸기 · 항목 나누기 · 합치기 · 지우기 | 팀 화면 문서 고치기(지식관리자) · 항목 장부 |
| 원 기록 고치기 · 지우기 | 옛 꼴을 굳히거나 버릴 기록을 지우는 것만 `oldform`(이력 한 커밋 · O-8). 그 밖은 기록을 고치지 않는다(정정은 팀 화면 기록 고치기) |
| 옛 표지(넣지 못함 · 메모) 기록을 재료로 넣기 | 하지 않는다(값이 확정이 아니다 · 이행 도구는 P12 에서 걷었다) |
| 사람 승인 없이 넣기 · 지식 통째로 한 번에 | 하지 않는다 |

## 새 항목의 장부 줄(엮기)

빠진 항목 채우기로 새 항목을 세울 때(`sections[].new`) 그 줄에 `kind`(종류 한 낱말) · `gist`(뜻 한 줄 · 「이것은 무엇인가」 에 답하는 80자 안)를 꼭 적고, 필요하면 `id`(식별자) · `aliases` · `nature`(성격)를 같이 적는다. `put` 이 화면 · 세션의 저장과 같은 엮기로 항목 장부 줄(뜻 한 줄) · 문서 장부 줄을 같이 짓는다. 새 문서를 세우면 `docs[{ path, nature, summary }]` 에 성격과 요약을 적는다. `kind` · `gist` 가 없으면 `check` 가 거절한다(장부 밖 항목을 세우지 않는다).

## 생성 룰

무엇이 항목이고 어느 문서에 두는지 · 성격과 종류 · 새 문서를 세울지는 고정 생성 룰(R1 ~ R9)로 정한다. 일을 시작할 때 `node scripts/kmd-migrate.mjs rules` 로 조문을 읽고, 이 스킬 글의 다른 줄과 다르면 생성 룰을 따른다. 판단의 근거는 조문 번호로 적는다.
