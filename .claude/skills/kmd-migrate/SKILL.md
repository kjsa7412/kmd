# kmd-migrate: 기록으로 항목 다시 그리기

kmd 의 지식은 문서(항목 = `##` 머리)와 기록(`work/` · `log/`)이다. 저장이 조각조각 쌓인 항목은 경위가 섞이고 글이 길어진다. 이 스킬은 **그 항목을 건드린 기록 전부를 오래된 순으로 읽어 「지금」 으로 다시 쓰고**, 서비스와 같은 검사를 지나 넣는다.

화면 기능이 아니다. 지식 폴더를 직접 다루는 사람(그 지식의 지식관리자 · 총괄 관리자)이 세션에서 돌린다. 쓰는 길은 `scripts/kmd-migrate.mjs` 하나다. 이 스크립트가 core 의 저장(`core/save.js`)과 검사(`core/gate.js` `checkSection`)를 지식 폴더에 바로 건다. **지식 파일을 손(Edit · Write)으로 고치지 않는다.**

```
① 자리 잡기   지식 사본 받기 · 최신으로 · 진단(scan) · 다시 그릴 항목 · 빠진 사건 고르기(사람 승인)
② 항목마다    trail(지금 글 + 이어진 기록) → 다시 쓰기 → check → 승인 표 → put
              빠진 사건은 rec(재료 기록) → 새 항목 쓰기(new · sources) → check → 승인 → put
③ 올리기      git push → 팀 화면 「백업에서 받기」
④ 끝 보고     진단 전 → 후 · 넣은 것 · 걸러 둔 것
```

도구(kmd 저장소에서 · `<K>` = 지식 폴더):

| 명령 | 하는 일 |
|---|---|
| `node scripts/kmd-migrate.mjs scan <K> [--doc docs/x.md] [--json]` | 진단: 문서마다 항목 · 기록 없는 항목 · 다시 그릴 만한 항목(이어진 기록 5↑) · 큰 항목 · 같은 글 · 틀 문장 · 닿지 않은 기록 |
| `node scripts/kmd-migrate.mjs trail <K> <docs/x.md> "<머리>" [--json] [--full]` | 항목 하나: 지금 글 · `base` · 이름 · 이어진 기록(오래된 순 · 표시) |
| `node scripts/kmd-migrate.mjs rec <K> <기록 id> [--json]` | 기록 하나: 상태 · 이름 · 넣은 곳 · 본문 |
| `node scripts/kmd-migrate.mjs check <K> <input.json>` | 마른 검사(쓰지 않음): 꼴 · 지문 · 값 대조 · 사라지는 표 행 · 문장 |
| `node scripts/kmd-migrate.mjs put <K> <input.json> --user <사람> [--allow-drop]` | 저장 줄 안에서 다시 검사 → 기록 + 항목 + git 커밋 한 묶음. 걸리면 아무것도 쓰지 않는다 |

공통 옵션 `--cutover "YYYY-MM-DD HH:MM"`: 팀의 개편 때(`/srv/kmd/.kmd/cutover.json` 의 값). 사본에는 이 파일이 없으니 넘긴다(188 은 `2026-11-05 10:41`). 없으면 개편 전 기록 판정이 달라진다.

## ① 자리 잡기

1. **어디서 쓰나: 사본이 기본이다.** 지식의 백업 자리(GitLab)를 내 PC 에 받는다. 백업 주소는 팀 화면 설정 › 백업, 또는 서버에서 `kmd backup`. 이미 받은 사본이면 `git -C <K> pull --ff-only`.
   - 팀 서버가 도는 폴더(`/srv/kmd/<지식>`)에 바로 쓰지 않는다. 서버는 지식을 캐시로 들고 있어 낡은 글로 판정하고, 서버의 저장과 줄이 섞인다.
   - 어쩔 수 없이 서버에서 쓰면: 도는 일감(`/srv/kmd/.kmd/jobs.json`)이 없을 때, `sudo -u kmd node /opt/kmd/scripts/kmd-migrate.mjs …` 로 쓰고, 끝나면 `systemctl restart kmd`. 사람에게 먼저 묻는다.
2. **사람(`--user`)**: 그 지식의 지식관리자인 사람 id(예: `kjsa`). `kmd` · `kmd-auto` 같은 예약 이름은 거절된다. 스크립트는 자리를 보지 않으니 사람에게 확인한다.
3. **진단**: `scan <K>`. 결과 표를 그대로 보이고 이렇게 읽는다.
   - **다시 그릴 만한 항목**(이어진 기록이 많다)이 대상이다. 이슈 대장 · 화면 설계처럼 조각 저장이 쌓인 곳이다.
   - **기록 없는 항목**은 다시 그리지 않는다. 재료가 지금 글뿐이라 다시 써도 얻을 것이 없고 잃을 것만 있다. 「다듬기」(팀 화면)의 일이다.
   - **틀 문장**(여러 항목에 같은 안내 글)은 다시 그리기 대상이 아니다. 한 항목에 두고 링크로 바꿀지는 사람이 따로 정한다.
   - 「아직 안 넣은 옛 기록」 이 있는 항목은 넣을 수 없다(`legacy-mix`). 팀 화면의 [옛 기록 다시 들이기] 를 먼저 한다.
   - **갈래 문서에 빠진 사건 기록**: 갈래 장부(`_forms.md`)의 사건 갈래(회의록 · 주간보고서 · 장애 대응 …)마다, 이름 · 태그로 그 갈래에 드는 기록인데 그 문서에 항목이 없는 것. 회의 기록이 이슈 대장 같은 주제 문서에만 들어가고 회의록에는 빠진 경우다. **후보**다: 제목에 「통화」 가 든 이슈 대장 기록처럼 회의가 아닌 것도 섞인다. 기록마다 `rec` 로 읽고 가른다. 채우는 법은 ②-6.
4. **고르기**: 문서 하나 · 항목 열 개 안팎씩. 고른 목록(문서 › 머리 · 기록 수 · 줄 수)을 보이고 **사람 승인을 받는다**. 지식 통째로 하지 않는다.

## ② 항목마다

### 1. 읽기

`trail <K> <문서> "<머리>"` 로 지금 글과 이어진 기록을 읽는다. 기록 본문이 2천 자에서 접히면 `--full`. `--json` 으로 받아 두면 `base` 를 옮겨 적기 쉽다.

이어진 기록의 표시:

| 표시 | 뜻 | 다루는 법 |
|---|---|---|
| (없음) | 사람 · 세션이 남긴 기록 | **재료**. 오래된 것부터 읽고 늦은 것이 이긴다 |
| `derived` | 앞서 Claude 가 지은 글(다듬기 · 정리 · 들이기 · 다시 그림) | 값의 근거로만. 문장을 옮겨 오지 않는다(합성 위에 합성을 쌓지 않는다) |
| `held` · `memo` | 넣지 못함 · 메모 | 재료가 아니다. 확정이 아니다 |
| `pend` | 아직 안 넣은 개편 전 기록 | 있으면 이 항목은 건너뛴다(①-3) |
| `[문서 단위]` | 문서 전체에 걸린 기록 | 이 항목에 닿는 부분만 |

### 2. 다시 쓰기

먼저 [작성가이드](../../../agent/skills/kmd-build/작성가이드.md)와 [문서 작성기준](../../../docs/kmd_문서_작성기준.md) 3 ~ 5절을 읽는다(세션에 한 번). 지키는 것:

- **지금 글이 바탕이다.** 기록이 바꾼 것만 바꾼다. 지금 글의 사실을 지우려면 기록이 그렇게 말해야 한다.
- **대상 하나의 지금**으로 쓴다. 「…했다는 기록이 있다」 · 날짜별로 덧붙인 줄 · 회의 경위 · 질문 목록은 걷는다(기록에 남아 있다). 대장(이슈)의 진행상태 · 결론은 지금으로 고쳐 쓴다.
- **값은 글자 그대로**(수 · 날짜 · 이름 · `코드`). 기록에 없는 값을 지어내지 않는다.
- **머리 이름은 바꾸지 않는다.** 글에 `#` · `##` 줄 · `<!-- -->` · `**경과**` · `work/` · `log/` 링크를 넣지 않는다. 참고 블록 · 표지는 kmd 가 단다.
- 링크는 문서(`x.md`) · 항목(`x.md#머리`) · 바깥(`https://…`) 셋만. 줄표 「—」 를 쓰지 않는다.
- 문단 다섯 줄까지 · 나란한 것 셋 이상은 목록 · 견주는 속성 둘 이상은 표 · 「…한다」 체 · 항목 300줄 안.

좋은 예와 나쁜 예(이슈 대장):

```md
나쁜 예
**결론**: 2026-10-01 매뉴얼을 조사했다. 2026-10-14 통화에서 회신을 받았다. 그 뒤 PLC 로 바꾸기로 했다는 기록이 있다.

좋은 예
**결론(지금)**: CIMON 사용자 프로토콜로는 외부에서 제어 명령을 낼 수 없다. SCADA 를 연계 경로에서 빼고, 게이트웨이가 펌프장 PLC 에 Modbus TCP 로 직접 붙는다(`DPMS-ISS-02`).
```

### 3. 기록 · 입력 짓기

새 글은 파일로 둔다(예: 세션 스크래치의 `iss01.md`). 입력 `input.json`:

```json
{
  "record": {
    "title": "다시 그림: 위험및이슈관리대장 › DPMS-ISS-01",
    "body": "이어진 기록 11건으로 DPMS-ISS-01 을 지금 상태로 다시 썼다.\n\n## 바뀐 것\n- 진행상태: 확인 중 → 해결 (2026-10-14)\n- 남은 확인 목록: `Q1 ~ Q18` → (뺌)\n\n## 까닭\n- 조각 저장 11건이 쌓여 결론 · 경위가 섞였다\n\n## 근거\n- 이어진 기록: 2026-0930-… · 2026-1014-… (11)"
  },
  "sections": [
    { "doc": "docs/1.2_사업관리/위험및이슈관리대장.md", "heading": "DPMS-ISS-01: SCADA(CIMON) 외부 인터페이스 확인", "base": "<trail 의 base>", "contentFile": "iss01.md" }
  ]
}
```

- **항목 하나 = 입력 하나 = 기록 하나**가 기본이다. 여러 항목을 한 기록에 담으면 「바뀐 것」 의 허용이 다른 항목으로 샌다.
- 기록 본문은 [기록 서식](../../../docs/템플릿/기록.md)이다. 첫 문단은 한두 문장 요약(300자 안).
- **`## 바뀐 것`** 에 이 다시 쓰기로 바뀐 값만 적는다.
  - 바꾼 값: `- 무엇: 옛 값 → 새 값`.
  - 지운 값: `- 무엇: 옛 값 → (뺌)`. 값이 빠지면 저장 검사가 「옛 글의 값이 빠졌다」 로 거절한다. 그래서 지운 값을 여기에 적어야 넘는다. 사람이 승인한 것만 적는다.
  - 오른쪽 새 값은 글에 꼭 있어야 한다(「기록의 값이 글에 없다」).
  - 여러 기록에서 값이 8080 → 9090 → 9191 로 갔으면 한 줄로 접는다: 「8080 → 9191」. 중간 값을 적으면 그것이 요구 값이 된다.
- `## 까닭` · `## 근거` 에는 화살표(→)를 쓰지 않는다. 화살표 왼쪽 값은 어디에 있든 「빼도 되는 값」 으로 읽힌다. 진단 수 · 날짜 · 기록 id 도 이 두 칸에 둔다(요구 값이 되지 않는다).
- `touches` 는 비워 둔다. `put` 이 그 항목의 이름을 단다. 태그 `rebuild` 도 `put` 이 단다.

### 4. 마른 검사

`check <K> input.json`. 걸린 까닭마다 고친다.

| 까닭 | 고치는 법 |
|---|---|
| 그사이 항목이 바뀌었다(conflict) | `trail` 로 다시 읽고 새 `base` 위에서 다시 쓴다 |
| 옛 글의 값이 빠졌다 | 그 값을 글에 살리거나, 지운 것이 맞으면(사람 확인) `## 바뀐 것` 에 「옛 → (뺌)」 |
| 기록의 값이 글에 없다 | `## 바뀐 것` 의 새 값을 글에 쓴다 |
| 근거에 없는 값이 있다 | 지어낸 값이다. 지우거나 근거 기록을 찾아 `## 근거` 에 그 값을 적는다 |
| 글에 머리 · 표지가 들었다 | `#` 줄 · 주석 · 기록 링크 · 경과 꼬리를 뺀다 |
| 개편 전 기록이 아직 안 들어갔다(legacy-mix) | 이 항목은 건너뛴다(①-3) |

「사라지는 표 행」 · 「사라지는 문장」 은 걸림이 아니라 **사람이 볼 것**이다. 표 행은 첫 열 열쇠가 새 글에 없는 행이고, 문장은 새 글 어디와도 닮지 않은 옛 문장이다(어림 · 말만 바꾼 줄도 나온다).

### 5. 승인 · 넣기

검사가 「걸림 0」 이면 사람에게 이 표를 보인다. **사람이 승인한 항목만 넣는다.**

```
【다시 그리기】 위험및이슈관리대장 › DPMS-ISS-01 · 이어진 기록 11(파생 1)
  줄           30 → 18
  바뀐 값       진행상태: 확인 중 → 해결 (2026-10-14) · 남은 확인 목록 → (뺌)
  사라지는 문장  2   「해결방안: SCADA 매뉴얼에서 …」 · 「남은 확인 1 ~ 18 …」
  사라지는 표 행 0
  지금 글 ↔ 새 글: (diff 요지 몇 줄)
승인하시면 넣습니다(기록 1 · 커밋 1).
```

- 사라지는 것이 없으면 `put <K> input.json --user <사람>`.
- 사라지는 문장 · 표 행이 있고 사람이 「빼도 된다」 고 하면 `--allow-drop` 을 붙인다. 하나라도 살려야 하면 글에 되살려 다시 `check`.
- `put` 은 저장 줄 안에서 새로 읽은 지식으로 다시 검사한다. 걸리면 **아무것도 쓰지 않는다**(넣지 못함을 남기지 않는다).
- 넣으면 기록 id 와 커밋이 나온다. 항목 표지(`applied`) · 참고 블록 줄 · 기록의 `## 넣은 것` 은 저장이 단다. 그래서 팀 화면 이력에서 그 항목을 [되돌리기] 할 수 있다.

### 6. 갈래 문서에 빠진 항목 채우기

회의록처럼 사건이 쌓이는 갈래 문서에 그 사건의 항목이 없을 때다. 재료 기록은 이미 다른 문서(이슈 대장 · 설계)에 들어가 있어도 된다. 회의록 항목은 「그날 무엇을 나누고 무엇을 정했나」 이고, 주제 문서는 「지금」 이라 둘 다 있어야 한다.

1. `scan` 의 「갈래 문서에 빠진 사건 기록」 에서 후보를 고르고, 기록마다 `rec <K> <id>` 로 읽는다. **열린 회의 · 통화의 기록만** 항목이 된다. 회의를 준비하는 글(안건 · 질의서 · 스크립트) · 문서 고친 기록 · 이슈 대장 갱신은 항목이 아니다(후보에서 뺀다고 표에 적는다).
2. 머리는 「YYYY-MM-DD 무엇」(회의 · 통화가 열린 날 · 기록 제목의 상대 · 주제). 이미 있는 머리와 겹치지 않게.
3. 글은 갈래의 서식([작업기록](../../../docs/템플릿/작업기록.md))대로: **누가 · 무엇을 · 정한 것 · 남은 것**. 정한 것 · 할 일만 옮기고, 원문 붙여 넣기 · 인사말 · 진행 멘트 · 시간 배분 · 묻는 말 목록은 옮기지 않는다. 지금도 이어지는 주제는 그 이슈 · 항목 이름(`DPMS-ISS-01`)으로 가리킨다. 값은 재료 기록에 있는 것만.
4. 입력은 ②-3 과 같고, 조각에 `base` 대신 `"new": true` 와 `"sources": ["<재료 기록 id>"]` 를 둔다. 기록은 「회의록 채우기: <머리>」, `## 바뀐 것` 에 「- 회의록 항목: <머리> 새로 둠」, `## 근거` 에 재료 기록 id.
5. `check` 는 재료 기록을 근거로 값을 대조한다(재료에 없는 값은 「근거에 없는 값」). 사건 갈래의 머리 꼴 · 이미 있는 머리 · 넣지 못함 · 메모 재료도 거절한다.
6. 승인 표(②-5)에 새 항목 글 전체를 보이고 승인받아 `put`. 회의 하나 = 입력 하나 = 기록 하나.
7. **날짜 자리에 끼운다.** 사건 갈래 문서면 `check` 가 새 머리의 날짜보다 늦은 첫 항목을 찾아 「자리: 「…」 앞」 으로 보이고, `put` 이 그 앞에 넣는다(같은 날은 뒤 · 날짜 없는 머리는 건너뜀 · 다른 항목의 글은 한 줄도 바뀌지 않는다). 사건 갈래가 아닌 문서는 끝에 붙고, 자리를 정하려면 조각에 `"before": "<있는 머리>"`. 이미 있는 항목의 차례는 바꾸지 않는다: `scan` 이 「날짜 차례 어긋난 항목 n」 으로 알리면 끝 보고에 적는다.
8. 넣은 뒤 `scan` 을 다시 돌려 그 기록이 「빠진」 목록에서 사라졌는지 본다.

## ③ 올리기

1. 묶음(문서 하나) 끝마다 올린다. 오래 쥐고 있을수록 서버와 갈라진다.
2. `git -C <K> pull --rebase` 로 그사이 서버가 올린 것 위에 얹는다. 같은 문서가 겹쳐 충돌하면 `git rebase --abort` → `git reset --hard @{u}` → 그 항목들을 ② 부터 다시 한다(옛 base 로 넣은 글이라 맞추지 않는다).
3. `git -C <K> push`.
4. **곧바로** 팀 화면(총괄 관리자) 알림의 「백업이 앞섰다」 줄에서 [백업에서 받기]. 서버에서는 `kmd backup pull <지식>`. 앞으로만 받고, 받은 글에 새 오류가 있으면 되돌린다.
   - push 와 받기 사이에 서버에서 저장이 있으면 「갈라졌다」 가 된다. 이때는 받지 말고 사람에게 알린다(어느 쪽이 맞는지 사람이 정한다).
5. 받은 뒤 팀 화면에서 그 항목을 열어 글 · 이력(「다시 그림」 기록)을 확인한다.

## ④ 끝 보고

한글로, 원인 → 고친 것 → 남은 것.

- 진단 합계 전 → 후(`scan` 다시).
- 넣은 항목 · 기록 id · 커밋 · 줄 수 전 → 후 · 승인받아 뺀 값 · 문장 수.
- 건너뛴 항목과 까닭(기록 없음 · 개편 전 기록 · 사람이 보류).
- 올리기 결과(push · 백업에서 받기).

## 하지 않는 것

| | 어디로 |
|---|---|
| 지식 파일을 손(Edit · Write)으로 고치기 | 없다. 늘 `put` |
| 기록 없는 항목 다시 쓰기 · 문체만 고르기 | 팀 화면 [다듬기] |
| 머리 이름 바꾸기 · 항목 나누기 · 합치기 · 지우기 | 팀 화면 문서 고치기(지식관리자) · 이름 장부 |
| 원 기록 고치기 · 지우기 | 없다. 기록은 고치지 않는다(정정은 팀 화면 기록 고치기) |
| 넣지 못함 · 메모를 재료로 넣기 | 팀 화면 넣지 못함 › [다시 들이기] |
| 사람 승인 없이 넣기 · 지식 통째로 한 번에 | 하지 않는다 |
