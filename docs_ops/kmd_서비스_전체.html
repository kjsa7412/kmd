2말

지식

폴더 하나 · git 저장소 하나. 팀 지식(팀 서버) · 개인 지식(내 PC).

문서 · 항목

문서는 docs/**.md 한 파일, 항목은 그 안의 ## 머리 한 덩이. 정리 · 링크 · 출처의 단위.

이름

종류:값(예 table:tb_user). 이름 장부 · 자리 장부가 이름 → 항목을 잇는다.

기록

work/<id>.md. 사람 · 세션 · 파일 · 코드 묶음이 남긴 글. 바뀐 것 · 까닭 · 영향 · 근거 · touches.

정리

기록을 문서의 항목에 넣는 일. 승인 없이 검사 뒤 넣고, 줄마다 되돌린다.

자리

사람이 지식 하나에 갖는 권한. 받지 않은 지식은 「없음」 이 기본.

일 줄

가져오기 · 정리 일감이 차례로 선다. 수집 › 검토 › 기록 생성 › 문서 생성.

기기 열쇠

PC 마다 사람 이름으로 만든 열쇠. Claude Code 연결과 지식 보내기가 쓴다. 내 기기에서 끊는다.

화면 말은 디자인 컨벤션 9절의 용어집을 따른다: 「개인 프로그램」 · 「팀 프로그램」 · 「반영 대기 n」 · 「출처」 · 「총괄 관리자」 · 「취소」(창 닫기) / 「잠깐 멈춤」(이어 할 수 있음) / 「그만두기」(도는 일을 끝냄).

본문에는 확정된 지식만

쓰는 길은 하나

core/save.js: 기록은 늘 남고 · 같은 지식의 저장은 한 줄로 서고 · 실패하면 되돌린다. 문서를 쓰는 모든 길이 저장 검사(E_FORMAT)를 거친다.

링크는 셋

문서 x.md · 항목 x.md#머리 · 바깥 https://…. 기록 링크(work/)와 시스템 주소는 본문에 두지 않는다.

6원천 → 기록 → 문서: kmd 의 핵심 로직

kmd 의 일은 한 줄이다. 어디서 왔든(세션 · 화면 · 파일 · 코드 · DB · 개인 지식) 먼저 기록으로 남기고, 그 기록을 검사를 거쳐 문서의 항목에 넣는다. 문서를 쓰는 길은 core/save.js 하나뿐이고, 기록과 문서와 장부가 늘 같은 git 한 묶음으로 바뀐다. 아래 그림이 그 전체이고, 그 아래 단계마다 입력 · 처리 · 출력 · 실패와 출처(코드 파일:줄 · 기준 문서 절)를 적는다. 기준일 2026-11-03 · 코드 9e7eb94.

색: 파랑 팀 · 초록 개인 · 넣음 / 보라 기록 · Claude / 노랑 사람 확인 · 저장소 · 둠. 점선은 사람이 고르거나 다시 하는 길이다.

들어오는 길: 원천 → 기록

A-1사람 · 세션 저장

입력
MCP save(이미 있는 항목은 base 지문이 있어야 한다) · 화면 고치기 POST /api/k/:id/edit · HTTP POST /api/k/:id/save
처리
  1. MCP 는 기록 서식 recordBody로 엮는다: 「바뀐 것」 이 꼭 있다 · 요약 300자 · 칸마다 40줄 · ## 바뀐 것 / 까닭 / 버린 안 / 영향 / 근거.
  2. 항목 글을 기록으로 넘기는 조건: 지식관리자가 아니거나(!canDirect) 팀 MCP 저장이면, 고친 항목 글을 문서에 바로 쓰지 않고 기록 본문의 ## 머리 칸으로 넘긴다(반영 대기). 이름 장부에 없는 항목에는 at/<지문> 태그를 단다.
  3. 항목에 edits(찾아 바꾸기 조각)이 있으면 제안으로 검사해 기록의 ## 고친 조각 칸(json)에 싣는다(B-10).
  4. 지식관리자의 화면 고치기는 system 저장으로 문서에 바로 들어간다(지우기 · 이름 바꾸기도). 같은 글을 1분 안에 다시 보내면 앞의 결과를 돌려준다.
  5. core/save.js 의 열 단계(그림 2)를 거친다. 중간에 넘어지면 저널로 모두 되돌린다.
출력
기록 work/<id>.md(id = YYYY-MMDD-<제목 조각 40자> · 겹치면 -2) · 바로 쓰는 경우 항목 글 + applied 표지 + 참고 줄 · git 한 묶음 · 이력 한 줄 · 1분 뒤 결정 규칙 · 실시간 방식이면 5분 뒤 정리.
실패
꼴 E_INPUT · 문서 꼴 E_FORMAT(몇째 줄 · 까닭) · 지문이 다르면 E_CONFLICT · 장부 밖 이름(strict) · 원본이 주인인 문서 E_FORBIDDEN · 백업이 닫혔으면 E_BEHIND.

A-2파일 넣기

입력
화면 파일 넣기 · 폴더 들이기 · 문서 폴더 가져오기(A-3) 모두 hub.importFiles. 한 번에 300 파일 · 200MB.
처리
  1. 글로 바꾸기 planImport: md 그대로 · txt/csv/html/json → md · docx/pptx/xlsx/hwpx ooxml(풀린 항목 32MB · 합 64MB · 압축비 200배) · hwp 64MB · pdf 2000쪽(쪽당 20자 미만이면 스캔) · 그림은 첨부 · 목차는 걷는다.
  2. 파일마다 기록 하나: 제목 <파일>: 넣은 파일 · 태그 ingest/<경로> · md/<지문>(같은 지문이면 다시 쓰지 않는다) · 원본은 docs/assets/ 첨부. 가드는 붙잡아 두기(hold).
  3. 개인 프로그램: 처음 20 파일은 Claude 로 기록 정리(무엇인가 · 핵심 · 정한 것 · 남은 것 · 본문 · $2 · 600초 · 15만 자 넘으면 앞 70% 와 끝) 뒤, 에이전트 넣기(Claude Code 가 kmd MCP 로 세션처럼 문서에 넣는다 · 단기 열쇠 kmda_ 40분 · $3 · 20분). 안 되면 규칙으로.
  4. 팀: 기록만 남기고 바로 tidyNow(손으로만 방식은 빼고). 일꾼이 같은 에이전트 길(agentIngest)을 먼저 해 보고, 문서를 못 남기면 초안 길로 간다.
출력
ingest/ 태그 기록(이름 없음 · 반영 대기) · 일 줄 네 단계(수집 › 검토 › 기록 생성 › 문서 생성).
실패
글로 못 바꾸면 「글로 바꾸지 못한 파일」 기록 · 줄마다 fail · skip 이 남는다.

A-3가져올 곳

입력
_sources.json 선언 { name, kind: git | docs | db, at, every, rules } · 시계가 분마다 본다(change 5분 · hourly · daily HH:MM · weekly · manual 은 사람만). 실패가 이어지면 간격을 두 배씩 여덟 배까지.
처리
  • git(규칙 없음): 처음은 기준 커밋만 적는다. 그 뒤 합침을 뺀 커밋마다 코드 파일이 바뀌었으면 기록 하나(한 번에 20 커밋 · 커밋마다 20 파일 · 차이 4천 자 · 첫 줄 「바뀐 값: 옛 → 새」 · 태그 code-change · 이름은 파일에서 다섯까지).
  • git · 폴더(규칙 있음): 스캔(1MB · 3000 파일) → 규칙(deps · tables · files) → 표 블록(baseline)을 200개씩 넣는다.
  • 문서 폴더: 바뀐 파일만 파일 넣기 길(A-2)로. 지운 파일은 지식을 바꾸지 않는다.
  • DB: PostgreSQL 읽기 전용 세션 · 카탈로그만 · 테이블마다 지문 · table:<이름> 이 장부에 있으면 그 항목에 정의 표를 채운다.
브레이크
처음이 아닌데 새 항목이 10 을 넘거나 사라진 것이 10% 를 넘으면 쓰지 않고 멈춘다(일 줄 「크게 바뀜」 · [그대로 맞추기] 로 넘는다).
출력
kmd 저장(system · 가드 hold) · 기록이 생기면 팀은 tidyNow, 개인 프로그램은 곧바로 정리.

  1. planSave 가 정리 기록을 짓는다: 제목 정리: <항목> · 태그 curate-llm(그래서 log/) · reflects(넣은 기록) · curates(넣지 않고 둔 기록) · 본문 「- 넣음 id: 제목」 줄.
