한 장으로

칸을 누르면 그 절로 간다. 흐린 칸의 예는 저장소의 시험 지식(test/fixture/kmd/dpms)의 문서 「배포절차 › 카나리」 로 든 것이다: 세션이 「카나리 첫 30분 비율: 10% → 20%」 를 조각과 함께 저장하면 기록 · 항목 · 참고 줄 · git 이 한 번에 바뀐다.

파란 선이 예가 지난 길. 채널이 어느 것이든 저장 문 하나를 지난다. 넘은 조각은 그 순간 문서에 들어가고, 못 넘은 조각은 기록에 「넣지 못함」 으로 남고, 조각 없이 온 사람 기록은 메모가 된다. 개인 프로그램은 저장 뒤 바로 넣기(core/pcplace.js)가 곧바로 문서에 넣는다.

1짜임

두 화면은 서로를 부르지 않는다. 팀 화면은 팀 서버에만, 개인 화면은 개인 프로그램에만 붙는다. 둘 사이의 길은 Claude Code 연결 둘과 지식 보내기(개인 → 팀 · 기기 열쇠) 뿐이다.

요청 하나가 지나는 길: 세션의 save

위에서 아래로 시간 순. 세션이 항목 조각을 실어 save 를 부르면 검사 · 쓰기 · git 이 한 줄(같은 지식의 저장은 차례로 선다) 안에서 끝나고, 조각마다 결과(proposals)가 돌아온다.

스킬 판 kit 이 옛것이거나 없으면 저장은 그대로 하고 답에 reinstall 을 싣는다(지금 판 TEAM_KIT_REV 4 · core/teamkit.js). 커밋 뒤의 일(측정 줄 <data>/savelog/<지식>.jsonl · 알림 · 백업)은 실패해도 저장을 되돌리지 않고 log 만 남긴다.

팀 일꾼이 들이기 일감을 받는 길

팀 일꾼은 서버 밖 클라이언트라 지식을 직접 쓰지 않는다. 원천 하나를 claude -p 한 번(도구 0)으로 기록 + 조각 초안으로 짓고, 서버가 같은 저장 문으로 넣는다. 걸리면 까닭을 받아 고쳐 쓴다(KMD_INGEST_FIX · 기본 2번까지).

시도는 서버가 센다(일꾼이 보낸 수를 믿지 않는다). 쓰는 동안은 …/progress 로 소식을 올리고, 실패는 …/fail. 팀 일꾼이 쉬면(로그인 끝 · 한도) 들이기는 기다리고, 24시간 넘게 기다린 일감은 기록만 + 넣지 못함으로 닫힌다. 옛 정리 일감 · 팀 쪽 에이전트 길은 개편으로 걷었다(core/worker.js).

5흐름 한눈에

길마다 한 장씩 그리고, 오른쪽에 그 길의 차례를 둔다. 모든 길은 기록 + 조각을 한 번에 저장하고, 저장 문이 그 자리에서 넣거나 「넣지 못함」 으로 남긴다(DB 테이블 정의 표는 저절로 채우는 표 그대로). 검사 칸마다의 로직은 6 핵심 로직에서 다룬다.

① 세션 저장② 화면 고치기 · 정정③ 파일 넣기 · 대량 넣기④ 가져올 곳⑤ 지식 보내기⑥ 백업 · 되살리기

① 세션 저장 → 그 순간 문서

팀 세션은 쓰기 자리 이상이면 검사를 넘은 조각이 그 순간 들어간다(지식관리자도 같은 저장 문). 조각 없이 확정 기록만 보내도 팀에서는 메모가 된다(저절로 메모). 개인 지식의 세션 저장은 바로 넣기가 곧바로 넣는다.

예시험 지식 · 카나리 비율 10% → 20%
  1. section읽기section { knowledge: "dpms", coord: "proc:카나리" } → 지금 글 · base(16자 지문)
  2. save저장record: 제목 「카나리 비율: 10% → 20%」 · changes 「카나리 첫 30분 비율: 10% → 20%」 · touches proc:카나리 / sections: { coord: "proc:카나리", base, edits: [{ find: "요청의 10% 만", replace: "요청의 20% 만" }] }
  3. 검사넘음find 가 지금 글에 꼭 한 번 · 지문이 같다 · 새 값 20% 는 기록에 있다 · 빠진 옛 값 10% 는 기록이 「옛 → 새」 로 말했다 · changed [{ from: "10%", to: "20%" }]
  4. 쓰기한 묶음work/2026-1104-카나리-비율.md(끝에 「## 넣은 것」) · docs/배포절차.md(## 카나리 글 · 표지 · 참고 줄) · git 커밋 하나 → 백업
  5. 답proposals{ saved, docs: ["배포절차"], put, proposals: [{ coord, ok: true, changed }] }

같은 저장에서 find 가 지금 글에 없으면 그 조각만 넣지 못함(why · 가까운 줄 near), 그사이 남이 고쳐 지문이 다르면 E_CONFLICT 로 아무것도 쓰지 않는다. 값 바꿈도 바로 들어가고 따로 알리지 않는다(이력에 「옛 값 → 새 값」 · 항목마다 되돌리기).

② 화면 고치기 · 기록 정정

같은 기록의 정정이 도는 중이면 두 번째는 E_CONFLICT 다(받은 척하지 않는다). 정정 일감은 규칙이 본 항목만 맡고, 간접 항목은 건드리지 않는다.

⑤ 지식 보내기: 개인 → 팀

받는 팀 지식이 「Claude 에 보내지 않음」 이면 내 PC 도 Claude 를 부르지 않고 기록만 보낸다(팀은 넣지 못함 noclaude). 내 개인 지식이 「Claude 에 보내지 않음」 이거나 Claude 로그인이 없을 때도 기록만 간다.

차례글 하나를 보낼 때
  1. 고르기보낼 것개인 지식의 기록 · 문서 · 받는 팀 지식은 쓰기 자리 이상인 것만 고를 수 있다
  2. 읽기팀 지식이 PC 의 기기 열쇠로 MCP brief · match · section(이름 · 후보 문서의 항목 글 · 지문)
  3. 짓기내 Claude들이기와 같은 프롬프트로 기록 + 조각 · 넣을 곳을 고르지 못한 조각은 left(넣지 못함 notfound)
  4. 저장팀 저장 문channel: send · 조각마다 검사 · 넘은 것은 그 순간 문서, 못 넘은 것은 기록에 넣지 못함
  5. 다시바로잡기[지금 다시] 는 다시 지어 보내고 앞의 넣지 못함 기록을 fixes 로 바로잡는다 · 받는 지식의 지식관리자는 팀 화면 › 넣지 못함에서 같은 기록을 고친다

⑥ 백업 · 되살리기

백업 자리는 따로 이름 지은 원격 kmd-backup(clone 으로 받은 origin 은 백업이 아니다). 판정 여섯 가운데 갈라진 둘(behind · moved)만 저장을 닫는다. 운영 쪽 손일은 10 운영.

차례저장 하나가 백업에 닿기까지
  1. 커밋 뒤밀기저장 · 들이기 · 가져오기가 남긴 묶음마다 그 지식을 백업 줄에 세운다(backup.enqueue · 커밋 뒤의 일이라 실패해도 저장은 그대로)
  2. 닿지 않으면다시1 · 5 · 15 · 60분, 그 뒤 시간마다 · 켤 때 · 매일 · 자격 실패는 되풀이하지 않는다
  3. 6시간 · 24시간나이 경보「○○ 백업이 멈췄다 · 백업 자리에 닿으면 이어서 보낸다 · 저장은 그대로 된다」 노랑 → 빨강
  4. 갈라지면닫음저장이 E_BEHIND · 화면 「이 지식은 지금 읽기만 된다」 · 사람이 받기 · 이어 쓰기 · 덮기 가운데 고른다

6들어오는 길 → 기록 → 문서: kmd 의 핵심 로직

kmd 의 일은 한 줄이다. 어느 채널로 왔든 기록과 항목 조각을 한 번에 저장하고, 저장 문이 그 자리에서 넣거나 「넣지 못함」 으로 남긴다. 문서를 쓰는 길은 hub.save → core/save.js 하나, 기록 · 문서 · 참고 블록 · 장부는 늘 git 한 묶음. 칸을 누르면 오른쪽에 자세히가 뜬다(무엇을 보나 · 규칙 · 통과하는 예 · 걸리는 예 · 코드).

그림의 칸을 누르면 그 칸이 무엇을 보나 · 규칙 · 통과하는 예 · 걸리는 예 · 코드가 여기에 뜬다. Tab 으로 칸을 옮기고 Enter 로 연다.

한 번의 저장 · 예
  1. section읽기시험 지식 proc:카나리 의 지금 글과 지문(base)
  2. save보냄기록(바뀐 것 「카나리 첫 30분 비율: 10% → 20%」) + 조각(요청의 10% 만 → 요청의 20% 만) + base
  3. 저장 문검사1 ~ 9 칸을 넘음 · changed [{ from: "10%", to: "20%" }]
  4. 쓰기한 묶음기록 · 항목 · 표지 · 참고 줄 · 「## 넣은 것」 · git 커밋 하나 → 백업
  5. 답proposals조각마다 { ok, why, code, stale, changed }

예의 지식은 저장소의 test/fixture/kmd/dpms 다. 실제 응답 꼴은 8 Claude Code 의 save 칸에 있다.

저장 한 번의 단계

  1. 원천을 지은 쪽(세션 스킬 · 들이기 · 사람 글)이 기록 + 조각 + 지문(base) 을 한 번에 보낸다(세션은 스킬 판 kit 도: 옛 판이거나 없으면 저장은 하고 답에 「다시 설치」 reinstall).
  2. 서버 저장 검사 한 곳: 자리(쓰기 이상) · 저장 속도(E_RATE) · 같은 저장(same) · 조각마다 꼴(E_FORMAT) · 값 대조 · 지문 · 원본이 주인 · 저절로 채우는 표 · 섞인 자리(같은 항목에 아직 안 들어간 개편 전 기록). 조각 검사는 팀만 한다(개인 프로그램은 바로 넣기가 넣는다).
  3. 넘으면 문서 · 참고 블록 · 기록 · git 한 묶음(하나가 실패하면 모두 되돌린다) · 기록 본문 끝에 ## 넣은 것(값이 바뀌면 「옛 값 → 새 값」) · 이력에 항목마다 「옛 값 → 새 값」 · [되돌리기](그 기록을 쓴 사람 · 지식관리자). 값 바꿈도 바로 들어가고 따로 알리지 않는다.
  4. 지문이 어긋나면 사람 · 세션 · 보내기는 E_CONFLICT 로 아무것도 쓰지 않는다(다시 읽고 다시 댄다). 들이기는 서버가 새 글에 조각을 한 번 다시 대고, 그래도 안 되면 그 조각만 넣지 못함(content 조각은 다시 대지 않고 넣지 못함).
  5. 못 넘은 조각은 기록만 남고 「넣지 못함」 표지(held · 까닭)가 붙는다. 응답의 proposals[] 가 조각마다 { ok, why, code, stale, changed } 를 돌려주고, 세션은 그 자리에서 고쳐 다시 저장한다.
  6. 확정(머지 · 배포 · 결정)이 아니면 메모: 기록만 남고 문서는 바꾸지 않는다.
  7. 7일 안에 두 번 되돌린 문서는 값을 바꾸는 조각만 넣지 못함.

개편 앞에 들어와 아직 문서에 안 넣은 기록은 「개편 전 기록」 으로 이 화면에 보이고, 지식관리자가 [옛 기록 다시 들이기] 로 팀 일꾼에게 한 번에 넘긴다. 개편을 켠 때는 팀 서버가 처음 켤 때 <data>/cutover.json 에 적는다(serve.json 의 cutoverAt 이 있으면 그것이 먼저).

메모

메모는 확정이 아니라 문서를 바꾸지 않고 기록만 남긴 것이다(태그 memo · 조각을 같이 받지 않는다). 세션 스킬은 저장 전에 「확정인가(머지 · 배포 · 결정)」 를 사람에게 묻고, 아니면 record.memo: true 로 보낸다. 팀에서 조각 없이 온 사람 기록도 저절로 메모가 된다(예외는 서버가 정한 채널로 가른다: 들이기 · 다듬기는 일감이 정하고, 대량 넣기는 조각이 없으면 넣지 못함, 보내기는 넣지 못함). 메모는 그 사람의 brief 에 「안 넣은 메모 n」 으로 실리고, 확정되면 조각을 실어 다시 저장하면서 fixes 로 메모를 바로잡는다.

MCP 도구 다섯

brief

지금 무엇이 있나 · 일을 시작할 때 한 번

넣는 것
{ knowledge? }
받는 것
없으면 지식 목록 · stops · notices / 있으면 docs · recent · notYetInDocs · you(role · direct · ledgers · mine) · kinds · forms · rules · put · kit · parser

match

이름 → 항목 · 정확히 같으면 확정(found)

넣는 것
{ q*, knowledge? }
받는 것
found[{ coord, name, doc, heading, exact, inDocs, pending }] · weak(확정 말 것) · ladder

search

말 → 항목 후보 · 자리 없는 글의 토막

넣는 것
{ q | words[≤10], knowledge? }
받는 것
results[{ knowledge, exact, coords, passages, more, exhaustive, label? }]
예

section

항목 하나의 지금 글 · 지문 · 그 항목의 기록

넣는 것

받는 것
doc · heading · coords · content · base · records · notYetInDocs
예
section { knowledge: "dpms", coord: "proc:카나리" }

save

기록 + 조각 한 번 · 기록은 서식 칸으로만(줄글 하나는 E_INPUT)

넣는 것
{ knowledge*, kit, record*{ title*, changes, body, why, dropped, impact, refs, touches | touchesEmpty, fixes, memo }, sections[{ coord | doc · heading, base, edits | content }], names, forms, attach }
받는 것

9깔기 · 올리기

올리는 길은 하나다: 커밋된 HEAD 를 깨끗한 폴더에 꺼내 꾸러미 셋을 만들고, 팀 꾸러미를 팀 서버에 풀어 설치를 다시 돌린다. PC 는 팀 화면의 설치 한 줄이 받기 자리(/dl)에서 받아 간다.

노랑은 사람이 보고 넘어가는 자리, 초록 선은 확인으로 모이는 길이다. 배포 때 옛 정리 일감 줄이 남아 있으면 「개편으로 걷은 정리 일감」 으로 닫힌다. 서버 밖에서 지식 파일을 고쳤으면 systemctl restart kmd(팀 서버는 지식을 캐시한다).
