6원천 → 기록 → 문서: kmd 의 핵심 로직

kmd 의 일은 한 줄이다. 어디서 왔든(세션 · 화면 · 파일 · 코드 · DB · 개인 지식) 먼저 기록으로 남기고, 그 기록을 검사를 거쳐 문서의 항목에 넣는다. 문서를 쓰는 길은 core/save.js 하나뿐이고, 기록과 문서와 장부가 늘 같은 git 한 묶음으로 바뀐다. 아래 그림이 그 전체이고, 그 아래 단계마다 입력 · 처리 · 출력 · 실패와 출처(코드 파일:줄 · 기준 문서 절)를 적는다. 오른쪽 칸은 그 단계의 실제 예(188 DPMS 의 기록 · 커밋 · 일감 줄 · 정리 장부, 188 에 아직 없는 것은 시험 지식에 실제 함수를 돌린 출력)와 그 단계에서 쓰는 스킬 · MCP 도구 · HTTP 길이다. 기준일 2026-11-03 · 코드 9e7eb94.

색: 파랑 팀 · 초록 개인 · 넣음 / 보라 기록 · Claude / 노랑 사람 확인 · 저장소 · 둠. 점선은 사람이 고르거나 다시 하는 길이다.

괄호 속 번호

코드 · 기준 문서가 검사에 붙인 이름이다. 번호 갈래가 둘이라 같은 「G2」 가 뜻이 다르다.

  • 저장 가드 G1 ~ G4(작성기준 9절 · core/guard.js): G1 새 이름 모양 · G2 이름 장부에 있는 이름만 · G3 이름도 자리도 없으면 까닭 · G4 새 문서는 갈래 장부대로.
  • 정리 검사 G1 ~ G6(core/tidy.js check): G1 초안 모양 · G2 읽은 뒤 바뀜 · G4 값 대조(빠진 값 · 지어낸 값) · G5 크기 · G6 문서 꼴.
  • F1 · F4(core/save.js): F1 쓰고 다시 읽어 대조 · F4 읽은 뒤 바뀌었나(지문 base). E_FORMAT 은 문서 꼴에 걸렸을 때의 오류 이름(작성기준 8절).

그림의 칸을 누르면 그 칸이 무엇을 보나 · 이렇게 본다 · 통과하는 예 · 걸리는 예(실제 오류 글) · 출처가 여기에 뜬다. 키보드는 Tab 으로 칸을 고르고 Enter.

처리
  1. MCP 는 기록 서식 recordBody로 엮는다: 「바뀐 것」 이 꼭 있다 · 요약 300자 · 칸마다 40줄 · ## 바뀐 것 / 까닭 / 버린 안 / 영향 / 근거.
  2. 항목 글을 기록으로 넘기는 조건: 지식관리자가 아니거나(!canDirect) 팀 MCP 저장이면, 고친 항목 글을 문서에 바로 쓰지 않고 기록 본문의 ## 머리 칸으로 넘긴다(반영 대기). 이름 장부에 없는 항목에는 at/<지문> 태그를 단다.
  3. 항목에 edits(찾아 바꾸기 조각)이 있으면 제안으로 검사해 기록의 ## 고친 조각 칸(json)에 싣는다(B-10).
  4. 지식관리자의 화면 고치기는 system 저장으로 문서에 바로 들어간다(지우기 · 이름 바꾸기도). 같은 글을 1분 안에 다시 보내면 앞의 결과를 돌려준다.
  5. core/save.js 의 열 단계(그림 2)를 거친다. 중간에 넘어지면 저널로 모두 되돌린다.
