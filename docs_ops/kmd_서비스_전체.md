# kmd 서비스 전체

kmd 를 처음부터 끝까지 한 장에 담는다. 무엇을 하는 서비스인지, 무엇으로 이루어졌는지, 지식이 어떤 모양으로 어디에 놓이는지, 누가 무엇을 할 수 있는지, 일이 어떤 흐름으로 도는지, 어떻게 깔고 올리고 지키는지. 그림으로 보는 판은 [kmd_서비스_전체.html](kmd_서비스_전체.html), 화면별 쓰는 법은 [설명서](manual/)(서버에서는 `<서버 주소>/manual`)다.

기준일 2026-11-03 · HEAD 2275f24 · 188 빌드 0.1.0-20261103-1437 · 판 0.1.0(꾸러미 이름 `<판>-<날짜>-<시각>`). 그림 판은 절마다 흐름 그림과 188 DPMS 실제 예(기록 하나가 들어와 항목이 되기까지)로 같은 내용을 보인다. 그림 판은 개편 전(HEAD 2275f24 · 정리 흐름) 그림이다.

**「저장이 곧 반영」 개편 중**(2026-11-03 ~ · [KMD_개편_설계.md](../docs/품질개선/KMD_개편_설계.md) 단계 S1 ~ S13): 1 · 3 · 6절의 「(Sx 부터)」 는 그 단계 커밋부터 코드가 따른다는 표시이고, 표시가 없는 줄은 지금 도는 대로다. 「(Sx 에 걷음)」 은 그 단계에서 없어진다.

## 1. 한 줄로

**팀과 내 PC 의 지식(md 문서 · 기록)을 사람은 화면으로, Claude Code 세션은 MCP 로 같이 읽고 쓴다.** 어느 길로 들어오든 기록과 문서(항목 조각)가 한 번의 저장으로 같이 바뀐다(세션 · HTTP 저장 · 가져올 곳 들이기 · 파일 넣기 · 고치기 · 대량 넣기 · 보내기). 저장 검사를 넘지 못한 것은 기록만 남고 「넣지 못함」 으로 보인다(화면 S10 부터). 그 전까지는(조각 없는 사람 기록은 S13 까지) 고친 것이 기록으로 남고 kmd 가 정해진 때에 기록을 문서의 항목에 넣는다(정리 · S13 에 걷음). 지식 하나는 폴더 하나 · git 저장소 하나이고, 저장마다 git 한 묶음이 되어 백업 자리로 밀린다.

| 무엇을 푸나 | kmd 의 답 |
|---|---|
| 팀 문서가 흩어지고 낡는다 | 지식마다 한 폴더 · 항목(`## 머리`) 단위로 나누고 이름(테이블 · 화면 · 절차 · 용어)을 장부에 세운다 |
| 누가 무엇을 바꿨는지 모른다 | 쓰기는 늘 기록을 남기고, 저장마다 이력 · 되돌리기를 남긴다(값이 바뀐 곳은 「옛 값 → 새 값」 · 항목마다 되돌리기 · 정리는 S13 까지 단계마다 이력 · 되돌리기) |
| Claude Code 가 팀 사정을 모른다 | 작업 폴더에 팀 지식을 붙이면 세션이 일 전에 사실을 찾아 읽고(brief · match · search · section), 일 뒤에 배운 것을 남긴다(save) |
| 옛 자료(오피스 · pdf · hwp · 코드 · DB)가 지식이 되지 않는다 | 파일 넣기 · 가져올 곳이 글로 바꾸고, 들어온 그때 하나씩 기록과 항목 글을 같이 짓는다(들이기 · 가져올 곳 · 팀 화면 파일 넣기는 지금 · 많은 파일은 Claude Code 대량 넣기 · S11 부터). 그 전까지는 기록으로 남겨 정리가 항목에 넣는다 |
| 개인 메모가 팀에 섞인다 | 개인 프로그램은 내 PC 에만 · 팀으로는 고른 기록 · 문서만 「지식 보내기」 |

## 2. 짜임

| 부분 | 어디서 도나 | 하는 것 |
|---|---|---|
| **팀 프로그램**(팀 서버) | Linux · `kmd serve` · systemd `kmd.service` · 기본 포트 8090(테스트 서버) | 팀 지식 · 팀 화면 · 사람 · 권한 · 정리 일감 · 가져올 곳 · 백업 · MCP(`kmd-team`) · 설명서 `/manual` · PC 꾸러미 받기 `/dl` |
| **정리 일꾼** | 팀 서버 · `kmd-worker.service` · 정리 전용 Claude 로그인 | 일 줄에서 정리 · 들이기 일감을 받아 Claude Code 로 항목 초안을 쓴다. 쉬면 서버가 규칙으로 넣는다 |
| **개인 프로그램** | Windows PC · `kmd up` · `127.0.0.1:7373` · 작업 스케줄러로 늘 켜기 | 개인 지식(`D:\kmd`) · 개인 화면 · 파일 넣기 · 편집기 직접 고침 감시 · 지식 보내기 · MCP(`kmd`) |
| **Claude Code** | 사람의 PC · 작업 폴더 | 연결 `kmd-team`(팀) · `kmd`(개인) 과 스킬(`kmd-team-work` · `kmd-team-save` · `kmd-work` · `kmd-save` · `kmd-build`)로 지식을 읽고 남긴다 |
| **백업 자리** | GitLab(봇 · 만들기 권한만) · 폴더 · https · ssh | 지식마다 git 저장소. 저장 뒤 바로 밀고, 안 되면 다시 |

두 화면은 서로를 부르지 않는다. 팀 화면은 팀 서버에만, 개인 화면은 개인 프로그램에만 붙는다. 둘 사이의 길은 Claude Code 연결 둘과 **지식 보내기**(개인 → 팀 · 기기 열쇠) 뿐이다.

## 3. 말(용어집)

| 말 | 뜻 |
|---|---|
| 지식 | 폴더 하나 · git 저장소 하나. 팀 지식(팀 서버) · 개인 지식(내 PC) |
| 문서 | 지식의 `docs/**.md` 한 파일 |
| 항목 | 문서 안의 `## 머리` 한 덩이. 저장 · 링크 · 출처의 단위 |
| 이름 | 항목을 가리키는 `종류:값`(예 `table:tb_user` · `proc:배포승인`). 이름 장부 `_vocab.md` · 자리 장부 `_managed.md` |
| 갈래 | 새 문서가 설 수 있는 문서 묶음(예 회의록). 갈래 장부 `_forms.md` |
| 기록 | `work/<id>.md`. 사람 · 세션 · 파일 · 코드 묶음이 남긴 글 하나. 그 자체로 지식이 될 글만 |
| 저장 | 기록 + 항목 조각 + 지문(base) 한 덩이. 서버 저장 검사 한 곳이 들어갈지 정한다 · 넘으면 그 순간 문서에 · git 한 묶음(팀 · 개인 프로그램은 옛 길 그대로) |
| 조각 | 항목 글을 바꾸는 단위: 지금 글에 꼭 한 번 나오는 글 → 바꿀 글. 새 항목은 글 전체 |
| 들이기 | 쓴 사람이 없는 것(파일 · 가져올 곳 · 보내기 · 규칙 밖 정정)을 Claude 가 기록 + 조각으로 지어 한 번에 저장하는 일(보내기는 개인 프로그램이 내 Claude 로 짓는다) |
| 문서 다듬기 | 지식관리자가 문서 하나를 골라 거는 문체 · 짜임 정돈. 값은 바꾸지 않는다 · 늘 도는 단계가 아니다(S13 부터) |
| 정리 | 기록을 문서의 항목에 넣는 일. 모으기 › 자리 찾기 › 글 쓰기 › 검사 › 넣기(S13 에 걷음) |
| 넣지 못함 n | 저장 검사를 넘지 못해 기록만 남은 수(까닭 · 들어온 길 · [고치기] · [다시 들이기] · [이름 세우기] · [버리기] · 설정 › 넣지 못함 · 지식 카드 · 항목 머리 칩). 팀은 「개편 전 기록」(아직 문서에 안 넣은 옛 기록)도 여기 보이고 지식관리자가 [옛 기록 다시 들이기] 로 한 번에 팀 일꾼에게 넘긴다 |
| 반영 대기 n | 옛 말. 정리 화면 안에만 S13 까지 남는다(그 밖은 S10 에서 「넣지 못함 n」 으로) |
| 메모 | 확정이 아니라 문서를 바꾸지 않고 기록만 남긴 것(세션은 brief 의 「안 넣은 메모 n」 으로 본다) |
| 정정 기록 | 기록을 고칠 때 원래 기록은 두고 새로 남기는 기록(옛 값 → 새 값) |
| 팀 일꾼 | 팀 서버의 Claude(팀 구독 · `kmd-worker.service`). 들이기 일감과 (S13 까지) 정리 일감을 받는다. 화면 이름은 S13 까지 「정리 일꾼」 |
| 대량 넣기 | 폴더째 팀 지식에 넣기: Claude Code 스킬 `kmd-team-import` + 파서 `kmd-parse`(내 PC · 내 구독 · S11 부터) |
| 참고 · 출처 | 문서 끝 `<!-- kmd:참고 -->` 블록. 항목마다 어느 기록에서 들어왔나 |
| 일 줄 | 가져오기 · 정리 일감이 차례로 서는 줄(가져오기가 넘긴 들이기 일감은 그 가져오기 일의 줄에 하나마다 결과 한 줄). 수집 › 검토 › 짓기 › 넣기 · 팀 화면 파일 넣기는 파일마다 일 줄 하나(들이기 일감) |
| 가져올 곳 | 정한 때마다 다시 보는 문서 폴더 · 소스 코드(git) · DB |
| 자리 | 사람이 지식 하나에 갖는 권한: 없음 · 읽기 · 쓰기 · 지식관리자 |
| 총괄 관리자 | 사람에 붙는 자격. 모든 지식의 지식관리자 + 서버 일 |
| 기기 열쇠 | PC 마다 사람 이름으로 만든 열쇠(`kmdk_`). Claude Code 연결과 지식 보내기가 쓴다 |
| 살림 자리 | 지식 폴더의 `.kmd`: 명부 · 상태 · 비밀 · 색인 · 일 줄 |
| 취소 · 잠깐 멈춤 · 그만두기 | 창 닫기 · 이어 할 수 있게 세우기 · 도는 일을 끝내기 |

## 4. 지식의 모양

```
<지식>/
  README.md            지식 이름(# 제목)
  docs/**.md           문서(항목 = ## 머리) · 문서 끝 <!-- kmd:참고 --> 블록
  docs/assets/         첨부(넣은 원본 · 그림)
  work/<id>.md         기록(frontmatter: id · title · date · author · touches · tags …)
  _vocab.md            이름 장부(종류:값 · 보이는 이름 · 다른 이름)
  _managed.md          자리 장부(이름 → 문서 · 머리)
  _forms.md            갈래 장부(새 문서가 설 수 있는 곳)
  _members.md          주인 · 지식마다 자리 · 정리 설정(백업과 같이 간다)
  _sources.json        가져올 곳
  .git/                저장마다 한 묶음 · 백업 자리로 밀기
<지식 폴더>/.kmd/      살림 자리: auth.json · auth.log · owners.json · secrets.json · jobs.json · 색인
```

- 본문에는 **확정된 지식만**. 경위 · 초안 · 아직 넣지 않은 기록은 본문에 두지 않는다. 시스템 참고 정보는 문서 끝 참고 블록과 표지 셋(`applied` · `watched` · `baseline`)에만.
- 링크는 문서(`x.md`) · 항목(`x.md#머리`) · 바깥(`https://…`) 셋만.
- 쓰는 길은 `core/save.js` 하나(기록은 늘 남는다 · 같은 지식의 저장은 한 줄로 선다 · 실패하면 되돌린다). 문서를 쓰는 길은 모두 저장 검사(`E_FORMAT`)를 거친다.
- 기준: [docs/kmd_문서_작성기준.md](../docs/kmd_문서_작성기준.md) · 서식 [docs/템플릿/](../docs/템플릿/).

## 5. 사람과 자리

| 일 | 총괄 관리자 | 지식관리자 | 쓰기 | 읽기 | 없음 |
|---|---|---|---|---|---|
| 그 지식이 보인다 · 찾기 · Claude 로 읽기 | ✓ | ✓ | ✓ | ✓ | |
| 기록 남기기 · 파일 넣기 · 가져오기 부탁 · 자기 기록 되돌리기 | ✓ | ✓ | ✓ | | |
| 바로 고치기 · 정리(남의 기록) · 되돌리기 · 지식 설정 · 권한 주기 · 가져올 곳(허락된 호스트) | ✓ | ✓ | | | |
| 사람 · 묶음 · 지식 세우기/지우기/되살리기 · 주인 넘기기 · 백업 · Claude 연결 · 일 줄 멈춤 · 동시에 도는 수 · 서버 폴더 · ssh | ✓ | | | | |

- 받지 않은 지식은 **없음**이 기본이다. 실제 자리는 사람 줄과 묶음 가운데 높은 것.
- 서버는 지식 단위 판정을 `hub.levelOf(ctx, kn)` 하나로 한다. 읽기 길은 `hub.meta(id, ctx)`(읽기 미만은 404), 쓰기 · 관리 길은 `hub.need(ctx, kn, 'write'|'admin')`(403). 지식 id 를 싣는 응답(목록 · 찾기 · 지금 하는 일 · 일 줄 · 이력 · 알림 · MCP)은 모두 자리로 거른다.
- 개인 프로그램은 그 PC 사람 하나만 쓰므로 이 모델 밖이다(늘 관리).
- 기준: [docs/kmd_권한_모델.md](../docs/kmd_권한_모델.md).

## 6. 흐름

### 6-1. 채널마다 기록 + 문서 한 번에

팀 반영 채널은 다섯(세션 · 고치기 · 파일 넣기 · 가져올 곳 · 보내기)이다. 어느 채널이든 기록과 항목 조각을 **한 번의 저장**으로 만들고, 들어갈지는 서버의 저장 검사 한 곳(`hub.save` → `core/save.js`)이 정한다. 자리 판정은 [권한 모델 7절](../docs/kmd_권한_모델.md). 개편 전 상세 로직(단계마다 입력 · 처리 · 출력 · 실패 · 검사 표 · 숫자 · 코드 출처 파일:줄)은 그림 판 [「6 들어오는 길 → 기록 → 문서」](kmd_서비스_전체.html#core) · 길마다 한 장 [「5 흐름 한눈에」](kmd_서비스_전체.html#flows)(둘 다 개편 전 그림)에 있다.

| 채널 | 시작 자리 | 원천 | 도는 곳 · Claude | 기록 + 문서(한 번의 저장) | 단계 |
|---|---|---|---|---|---|
| 세션 | Claude Code | 세션 작업 | 내 PC · 내 구독 | 세션 스킬 `kmd-team-save`(확정인지 묻고 조각 + 지문 + 스킬 판 `kit` · 확정이 아니면 메모 · 걸리면 그 자리에서 고쳐 `fixes` 로 다시) · 일 전 `kmd-team-work` 가 brief 의 「안 넣은 메모 n · 넣지 못함 n」 을 전한다 | 지금 |
| 고치기(문서) | 팀 화면 | 사람이 고친 글(쓰기 이상 · 항목 지우기 · 이름 바꾸기는 지식관리자) | 팀 서버 · Claude 없음 | 글 그대로 + 이력 「고침」(옛 값 → 새 값) · 읽은 뒤 누가 고쳤으면 새 글을 다시 읽는다 | 지금 |
| 고치기(기록) | 팀 화면 기록 [고치기] | 고친 기록 → 정정 기록(옛 값 → 새 값) | 팀 서버 · 규칙(옛 값이 한 곳), 안 되면 팀 일꾼(팀 구독) | 정정 기록 + 조각 · 들어간 항목이 없으면 정정 기록만 + 넣지 못함 | 지금 |
| 파일 넣기(20개까지) | 팀 화면 | 여러 꼴 파일 | 팀 서버 파서 · 팀 일꾼(팀 구독) | 들이기 일감(파일마다) | S8 |
| 대량 넣기 | Claude Code | 여러 꼴 파일 | 내 PC 파서 `kmd-parse` · 내 구독 | 스킬 `kmd-team-import` → 팀 저장(파일마다 git 한 묶음) | S11 |
| 가져올 곳 | 시계(팀 서버) | 문서 폴더 · git · DB | 팀 서버 · 팀 일꾼 | 들이기 일감(파일 · 커밋 하나씩 · DB 표는 저절로 채우는 표 그대로) | 지금 |
| 보내기 | 개인 프로그램 | 개인 md | 내 PC · 내 구독 | `claude -p` 가 팀 `section` · 지문을 읽고 조각으로 → 팀 저장(`channel: send` · 글마다 한 번) · 못 넘으면 넣지 못함 · 보내기 화면에 「넣음 n · 넣지 못함 n」 | 지금 |

새 흐름(줄마다 들어가는 단계):

1. 원천을 지은 쪽(세션 스킬 · 들이기 · 사람 글)이 **기록 + 조각 + 지문(base)** 을 한 번에 보낸다(세션은 스킬 판 `kit` 도: 옛 판이거나 없으면 저장은 하고 답에 「다시 설치」 `reinstall`).
2. 서버 저장 검사 한 곳: 자리(쓰기 이상) · 저장 속도(`E_RATE`) · 같은 저장(`same`) · 조각마다 꼴(`E_FORMAT`) · 값 대조 · 지문 · 원본이 주인 · 저절로 채우는 표 · 섞인 자리(같은 항목에 아직 안 들어간 개편 전 기록)(팀만, 개인 프로그램은 지금 그대로).
3. 넘으면 문서 · 참고 블록 · 기록 · git **한 묶음**(하나가 실패하면 모두 되돌린다) · 기록 본문 끝에 `## 넣은 것`(값이 바뀌면 「옛 값 → 새 값」) · 이력에 항목마다 「옛 값 → 새 값」 · [되돌리기](그 기록을 쓴 사람 · 지식관리자). 값 바꿈도 바로 들어가고 따로 알리지 않는다(K-D13).
4. 지문이 어긋나면 사람 · 세션 · 보내기는 `E_CONFLICT` 로 아무것도 쓰지 않는다(다시 읽고 다시 댄다). 들이기는 서버가 새 글에 조각을 한 번 다시 대고, 그래도 안 되면 그 조각만 넣지 못함(`content` 조각은 다시 대지 않고 넣지 못함).
5. 못 넘은 조각은 기록만 남고 「넣지 못함」 표지(`held` · 까닭)가 붙는다. 응답의 `proposals[]` 가 조각마다 `{ ok, why, code, stale, changed }` 를 돌려주고, 세션은 그 자리에서 고쳐 다시 저장한다(`fixes` 로 내 앞 기록을 바로잡음 · 남의 기록은 지식관리자만). 넣지 못함은 그 사람의 brief(`mine` · `you.recent`) · 지식관리자 화면(S10 부터)에 보인다.
6. 확정(머지 · 배포 · 결정)이 아니면 메모: 기록만 남고 문서는 바꾸지 않는다.
7. 7일 안에 두 번 되돌린 문서는 값을 바꾸는 조각만 넣지 못함.

개편 전 흐름(조각 없는 사람 기록에 S13 까지 남는다 · S13 에 걷음):

1. 쓰기 자리 사람(또는 세션)이 항목을 고치면 **기록**이 남는다(`work/<id>.md` · `touches` 에 그 항목의 이름).
2. 정리 방식대로 일감이 선다: 정해진 시각(기본 매일 02:30) · 실시간(기록 뒤 5분 조용하면) · 손으로만([지금 정리]).
3. 정리 일꾼이 자리(문서 › 항목)마다 묶어 Claude Code 로 초안을 쓴다(같은 문서의 항목은 한 번에 · 세 자리까지 같이 · 큰 자리부터 · Claude 한 번의 예산은 `KMD_INGEST_BUDGET`(달러 · 기본 1.0) · 생각 정도는 `KMD_INGEST_EFFORT` · 옛 이름 `KMD_TIDY_BUDGET` · `KMD_TIDY_EFFORT` 도 읽는다). 묶음 답에 빠진 자리는 까닭을 줄에 남기고 빈 칸이 따로 다시 쓴다. 자리마다 걸린 시간 · 보낸 글 · 받은 토큰이 줄과 일꾼 기록에 남는다.
4. **검사**: 숫자 · 이름이 기록과 맞나(「옛 값 → 새 값」 줄은 새 값만 · 날짜는 값 하나 · 띄어 쓴 단위는 뒤에 한글이 없을 때만 붙는다) · 지어낸 값이 없나 · 작성기준. 넘지 못하면 「그대로 둔 것」.
5. **넣기**: 문서 · 참고 블록 · git 한 묶음 · 이력 한 줄. 값이 바뀌면 쓴 사람의 이력 맨 위 노란 「값 바뀜」(정리 넣기의 이 알림은 S13 에 걷음).
6. 줄마다 비교 · 되돌리기. 같은 문서를 7일 안에 두 번 되돌리면 그 문서의 값 바뀜은 7일 넣지 않는다.

쓰기 이상이 화면에서 고치면 이력을 남기고 바로 문서에 들어간다. 개인 프로그램에는 정리가 따로 없다(기록이 남는 즉시 넣는다 · 이번 개편에서 바꾸지 않는다).

### 6-2. 파일 넣기(일 줄 네 단계)

개인 프로그램: 수집(받기 · 글로 바꾸기: md · txt · csv · html · json · docx · pptx · xlsx · hwpx · hwp · pdf) › 검토(같은 파일 · 크기) › 짓기(파일마다 기록 하나 · 원본은 첨부) › 넣기(Claude Code 가 세션처럼: 읽기 › 둘러보기 › 이름 맞추기 › 갈래 · 주제 문서의 항목에 넣기 › 이력). 한 번에 300 파일 · 200MB. 개인 프로그램은 20 파일까지 Claude, 나머지는 규칙. 손잡이: 멈춤 · 이어서 · 그만두기 · 다시 · 맨 앞으로 · 빼기.

팀 화면(쓰기 자리부터 · 설정 › 가져오기의 일 줄 탭 · 가져올 곳 탭은 지식관리자): 수집 · 검토는 서버가 받자마자 닫고(글로 바꾸기 `fileToMd` · 같은 파일이면 「그대로」) 파일마다 들이기 일감 하나 + 일 줄 하나 › **짓기**(팀 일꾼이 집어 기록 + 조각을 짓는다 · 검사에 걸리면 두 번까지 고쳐 쓴다) › 넣기(저장 문 한 번 · 파일 하나 = 저장 하나 = git 한 묶음 · 못 넣은 곳은 기록만 + 넣지 못함). 정리 일감을 세우지 않는다. 한 번에 20 파일(21개부터는 보내지 않고 「많으면 Claude Code 에서 대량 넣기」 안내 · 서버도 막는다) · 파일 하나 32MB · 요청 하나 64MB(화면이 묶음으로 나눠 보낸다 · 넘으면 413) · 원본 첨부는 「원본 파일도 첨부로 둔다」 를 고를 때만(기본 해제 · 하루 합 200MB). 글이 없는 pdf(스캔)는 「못 넣음」: 대량 넣기(Claude Code)가 원본을 읽는다. 손잡이는 그만두기 · 빼기뿐(아직 쓰지 않은 것은 기록 없이 닫는다 · 팀 일꾼이 짓는 중이면 초안을 넣지 않고 닫는다).

S11 부터(대량 넣기): Claude Code 에 「이 폴더 팀 지식에 넣어 줘」 → 스킬 `kmd-team-import` 가 처음 한 번 파서 `kmd-parse` 를 팀 서버 `/dl` 에서 받고 → 파일마다 brief · match · section → 기록 + 조각 → 팀 저장(`same` 이면 이미 넣음 · 끊겨도 이어서) · 내 PC · 내 구독.

### 6-3. 가져올 곳

| 유형 | 들어오는 것 | 브레이크 |
|---|---|---|
| 문서 폴더 | 바뀐 파일만 · 팀은 파일마다 들이기 일감 하나(팀 일꾼이 기록 + 조각을 한 번에 · 정리 일감은 세우지 않는다) · 개인 프로그램은 파일 넣기 길 | 한꺼번에 많이 사라지면(10% 넘게) 멈추고 「크게 바뀜」(일 줄 탭 「살펴볼 일 n」) · 새 파일 수 브레이크는 없다(일감이 그만큼 선다 · 지식마다 하루 300 · K7-2) |
| 소스 코드(git) | 더한 때의 묶음이 기준 · 새 묶음마다 들이기 일감 하나(팀 일꾼이 「바뀐 값」 · 차이를 읽고 기록 + 항목 조각 · 넣을 항목이 없으면 기록만 + 넣지 못함) · 개인 프로그램은 묶음마다 기록(분석을 켰으면 Claude 요약) | 없음(한 번에 20 묶음까지) |

### 6-4. 지식 보내기(개인 → 팀)

개인 지식마다 받는 팀 지식 하나를 묶어 둔다(쓰기 자리 이상인 것만). 기록 · 문서를 골라 보내면 고른 것마다 개인 프로그램이 이 PC 의 기기 열쇠로 팀 지식을 읽고(MCP `brief` · `match` · `section`: 이름 · 후보 문서의 항목 글 · 지문), 내 PC 의 Claude(내 구독 · 들이기와 같은 프롬프트)가 팀 작성기준에 맞춘 기록 + 조각을 지어 팀 저장 문(`POST /api/k/<지식>/save` · 채널 `send`)으로 한 번에 보낸다. 팀이 조각마다 검사해 넘은 것은 그 순간 문서에 들어가고, 못 넘은 것은 기록에 「넣지 못함」 으로 남는다(정리를 기다리지 않는다).

- 보내기 화면: 「넣음 n · 넣지 못함 n · 이미 넣음 n」. 넣지 못함이 남은 글은 위에 「넣지 못함」 줄이 서고 [지금 다시](다시 지어 보내고 앞의 넣지 못함 기록을 `fixes` 로 바로잡는다) · [버리기]. 받는 지식의 지식관리자는 팀 화면 › 넣지 못함에서 같은 기록을 고칠 수 있다.
- 같은 글을 다시 보내면 「이미 넣음」(받는 쪽 `sent/<지문>` · 쓰지 않는다). 넣지 못함으로 끝난 글은 다시 보낼 수 있다.
- 새 문서는 받는 지식의 지식관리자 자리일 때만 선다. 쓰기 자리면 그 조각만 넣지 못함이다.
- 받는 팀 지식이 「Claude 에 보내지 않음」 이면 내 PC 도 Claude 를 부르지 않고 기록만 보낸다(팀은 넣지 못함 `noclaude`). 내 개인 지식이 「Claude 에 보내지 않음」 이거나 Claude 로그인이 없을 때도 기록만 간다(넣지 못함).
- 닿지 않으면(연결 · 5xx) 「닿지 않았다」 줄에 두고 분마다 저절로 다시 보낸다. 저장 속도 한도(429)는 `Retry-After` 만큼 쉬고 다시 보낸다(실패 줄이 아니다).
- 옛 판 개인 프로그램이 쓰던 `POST /api/k/<지식>/receive` 는 남아 있다. 팀 지식에는 기록만 서고 넣지 못함(`legacy-send` 「개편 전 보내기」)이다.

### 6-5. Claude Code 세션

| MCP 도구 | 하는 것 |
|---|---|
| `brief` | 지식 목록 · 지식 하나의 문서 · 최근 기록 · 반영 대기 · 알릴 것 · 갈래 서식 · 팀이면 그 사람의 「안 넣은 메모 n · 넣지 못함 n」(지식마다 `mine` · 지식 하나는 `you.recent` 에 제목 · 까닭) · 팀 서버의 스킬 판 `kit` |
| `match` | 이름으로 항목 찾기(정한 이름 · 다른 이름 · 머리가 같으면 확정) |
| `search` | 말 → 항목 후보와 자리 없는 글 토막 |
| `section` | 항목 하나의 지금 글 · 지문(base) · 그 항목을 건드린 기록 |
| `save` | 기록(바뀐 것 · 까닭 · 버린 안 · 영향 · 근거 · touches) · 항목 글 · 새 이름 · 새 갈래 · 항목 조각 + 지문 · 메모 · 스킬 판 `kit`(답의 `proposals[]` 로 조각마다 결과 · 판이 옛것이면 `reinstall`) |

스킬 순서: 일 전 `kmd(-team)-work`(brief → match → search → section, 지식에 없는 것은 지어내지 않는다) · 일 뒤 `kmd(-team)-save`(어느 지식에 남길지 묻고 save). 팀 세션은 조각을 같이 보내고 쓰기 자리 이상이면 검사를 넘은 조각이 그 순간 들어간다(지식관리자도 같은 저장 문). 걸리면 까닭을 읽고 그 자리에서 고쳐 다시 저장한다(`fixes` 로 내 앞 기록). 확정인지 사람에게 묻고, 아니면 메모로.

### 6-6. 백업 · 되살리기

저장 뒤 바로 백업 자리로 밀고, 안 되면 1 · 5 · 15 · 60분 · 매일 다시(6시간 노랑 · 24시간 빨강). 갈라지면 사람이 정한다([이 백업 이어 쓰기] · [서버 것으로 백업 덮기]). 살림 자리는 밤 묶음 + auth.log 따로. 되살리기는 `kmd restore`(`--practice` 는 읽기만 사본) · `kmd auth reapply`.

## 9. 깔기 · 올리기

### 9-1. 꾸러미

`node scripts/pack.mjs` → `dist/`

- `kmd-<판>-pc.zip`: node.exe · app · core · server · agent · 설명서(`docs_ops/manual`) · 쓰는 node_modules · `kmd.cmd` · `kmd-key.cmd`.
- `kmd-parse-<pver>.zip`: 대량 넣기 파서(node.exe · `core/{importer,ooxml,pdf,hwp,text,errors}.js` · `server/bin/kmd-parse.mjs` · `kmd-parse.cmd` · pdf.js 쓰는 부분). `pver` 는 묶는 파일 글 + node 판 + pdf.js 판의 sha256 앞 12(내용이 같으면 판이 같다). 묶는 파일이 묶음 밖을 import 하면 pack 이 멈춘다.
- `kmd-<판>-team.tgz`: 같은 것(node 빼고) + `kmd-install.sh` + PC zip + 파서 zip.

### 9-2. 팀 서버

`sudo sh kmd-install.sh --team --url <팀 주소> --root /srv/kmd --port 8090` → `/opt/kmd` · kmd 사용자 · `kmd.service` · `kmd-worker.service` · `/usr/local/bin/kmd` · PC zip · 파서 zip 을 `/srv/kmd/.kmd/dl` 에(옛 파서 zip 은 그대로 둔다 · 팀 서버는 가장 새 것만 `GET /api/agent/parser` · MCP `brief` 의 `parser` 로 알린다). 첫 설정 주소로 총괄 관리자를 만든다. 다시 돌리면 새 판(코드만 바꾸고 지식 · 살림 자리는 그대로 · `/etc/kmd/worker.env` 가 있으면 덮지 않는다).

팀 일꾼 환경 변수(`/etc/kmd/worker.env` 에 더한다 · 옛 이름 `KMD_TIDY_PAR` · `_JOBS` · `_TICK_MS` · `_BUDGET` · `_EFFORT` 도 읽는다): `KMD_WORKER_PAR`(Claude 동시 호출 1 ~ 8 · 기본 3) · `KMD_WORKER_JOBS`(일감을 나란히 1 ~ 4 · 기본 2) · `KMD_WORKER_TICK_MS`(쓰는 중 소식 · 15000) · `KMD_INGEST_BUDGET`(들이기 한 번의 예산 달러 · 기본 1.0) · `KMD_INGEST_EFFORT`(생각 정도) · `KMD_INGEST_FIX`(고쳐 쓰기 1 ~ 2 · 기본 2 · 서버는 `serve.json` 의 `ingestFix`). 들이기 한도는 `serve.json` 의 `intakeQueue`(사람 × 지식마다 기다리는 일감 · 20) · `intakeDaily`(지식마다 하루 · 300) · `intakeStaleMs`(기다림 24시간이면 기록만 + 넣지 못함). 들이기 일감의 원천은 `<data>/queue/<일감>.md` · `.bin`, 넣지 못함으로 끝난 것은 `<data>/held/<지식>/<기록>.*` 에 남는다(바로잡히거나 버리면 팀 시계가 걷는다).

### 9-3. 내 PC

팀 지식만 쓰면 개인 프로그램은 필요 없다. 작업 폴더에 팀 지식을 붙이는 한 줄(팀 화면 › 설정 › 에이전트 설치 · `irm '<팀>/a/<표>?kn=<지식>' | iex`)이 PC 에 두는 것은 넷이다(K11-3):

| 무엇 | 어디 |
|---|---|
| 팀 스킬 셋 | `<폴더>/.claude/skills/kmd-team-work` · `kmd-team-save` · `kmd-team-import`(저장 · 대량 넣기에 `작성가이드.md` 사본) |
| 연결 | `<폴더>/.mcp.json` 의 `kmd-team`(열쇠는 넣지 않고 헤더 도우미 `%USERPROFILE%\.kmd\bin\kmd-key-<판>.exe`) |
| 기기 열쇠 | `%USERPROFILE%\.kmd\keys\<지문>.dpapi`(이 PC 에 없을 때만 표로 하나 받는다) |
| 대량 넣기 파서 | 처음 대량 넣기 때 스킬이 받는다: `%USERPROFILE%\.kmd\parse\<pver>`(`/a/` 한 줄은 받지 않는다 · K-D9) |

한 줄은 끝에 Claude Code 가 이 PC 에 있나 · 로그인했나를 한 줄로 알린다(없으면 깔라고 · 로그인하지 않았으면 `claude auth login` · 멈추지 않는다 · `KMD_SKIP_CLAUDE_CHECK` 가 있으면 건너뛴다). 폴더째 많은 파일은 그 폴더의 Claude Code 에서 대량 넣기(`kmd-team-import`: 파서 → 파일마다 기록 + 조각 저장 하나 · 다시 돌리면 넣은 것은 `same`).

개인 지식을 쓰려면 팀 화면 › 개인 지식 쓰기의 한 줄(`irm <팀>/i/<표> | iex`): 없으면 받아 `~/.kmd-app/versions/<판>` 에 깔고 · 옛 판이면 올리고 · 팀에 잇고(기기 열쇠) · Claude Code 에 잇고 · 늘 켜기.

### 9-4. 테스트 서버 10.10.20.188 배포

1. 커밋된 HEAD 를 깨끗한 폴더로: `git archive HEAD | tar -x -C <폴더>`(Git Bash · Windows tar.exe 금지) · node_modules 는 junction.
2. 그 폴더에서 `node scripts/pack.mjs` → `scp dist/kmd-<판>-team.tgz root@10.10.20.188:/tmp/`.
3. 배포 전 `/srv/kmd/.kmd/jobs.json` 의 도는 일을 본다(배포는 kmd · kmd-worker 를 다시 켜 도는 정리 · 들이기가 기다림으로 돌아간다 · 들이기는 같은 일감의 기록(`job/<id>`)이 이미 있으면 다시 넣지 않고 닫는다).
4. 서버에서 풀고 `kmd-<판>-team/` 에서 `sh kmd-install.sh --team --url http://10.10.20.188:8090 --root /srv/kmd --port 8090`.
5. 확인: `curl :8090/healthz` 의 build · 바뀐 코드가 `/opt/kmd` 에 있는지 grep · 보고에 커밋 해시.
6. 서버 밖에서 지식 파일을 고쳤으면 `systemctl restart kmd`(팀 서버는 지식을 캐시한다). root 로 git 을 칠 때는 `sudo -u kmd git …`.

## 11. 지키는 것(보안)

- 비밀(GitLab 열쇠 · 원천 자격 · claude-token)은 셸 숨김 입력 · `secrets.json` 에만. 화면 · 로그 · 응답에 0.
- 비밀번호는 브라우저가 미리 해시해 보낸다(`app/prehash.js`) · 서버는 scrypt. 여러 번 틀린 자리는 잠시 막힌다. 위험한 일은 비밀번호 한 번 더(15분).
- 기기 열쇠는 Windows 자격 저장소(`%USERPROFILE%\.kmd\keys` · DPAPI). Claude Code 는 헤더 도우미(`kmd-key-*.exe`)로 꺼내 쓴다(설정 파일에 열쇠 없음).
- 다른 곳의 화면에서 온 쓰기 요청은 받지 않는다(Origin · Sec-Fetch-Site). 서버가 그리는 페이지(설명서 · 받기)는 CSP `default-src 'none'`.
- 장부 · 설정 파일은 임시 파일 뒤 이름 바꾸기(원자 쓰기). 깨진 파일을 빈 것으로 읽어 덮지 않는다.
- DB 가져오기는 늘 읽기 전용 세션 · 카탈로그만. GitLab 봇 열쇠는 만들기 권한만.
