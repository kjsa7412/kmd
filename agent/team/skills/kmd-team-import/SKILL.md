# kmd 팀 지식에 대량 넣기

**어디에**: CLAUDE.md 「이 폴더의 팀 지식」 표의 팀 지식 가운데 하나. 연결은 `kmd-team`, knowledge 에 그 id 를 준다. 이 일은 내 PC · 내 Claude 구독으로 한다(팀 일꾼을 쓰지 않는다).

**스킬 판**: `save` 마다 `kit: "{{KIT_REV}}"` 를 같이 보낸다.

**승인은 규칙 표 한 번이다.** 파일마다 `propose` 로 저장 제안을 받아 규칙 표 하나로 묶어 보이고, 대화로 고친 뒤 한 번 승인받으면 파일마다 그 파일의 `proposal` 을 실어 모두 넣는다. 표의 경고는 승인에 포함된다.

0. **어느 팀 지식에 넣을지 묻는다**(`kmd-team-save` 와 같은 규칙): 넣을 폴더 · 파일 수와 표의 팀 지식(이름 · 보는 사람)을 보여 주고 「어느 팀 지식에 넣을까요?」. 표의 지식이 하나면 「여기에 넣을까요?」. `brief { knowledge }` 의 `you.direct` 가 거짓(읽기 자리)이면 넣지 못한다고 말하고 멈춘다. `brief` 에 `noClaude` 가 있으면(「Claude 에 보내지 않음」 지식) 이 지식은 글을 Claude 에 보내지 않는다고 말하고 멈춘다: 대량 넣기는 파일마다 팀 항목 글을 이 대화로 읽는다. 사람이 그래도 하라고 하면 `match` · `section` 은 꼭 필요한 항목만 읽는다. 그 지식이 빈 지식(`brief` 의 문서가 없거나 「처음」 하나뿐)이면 대량 넣기보다 기초 세우기가 먼저라고 말한다: 지식관리자가 팀 화면 지식관리 › 기초 세우기에서 짜임(갈래 · 문서 · 항목)을 먼저 세운다(한 묶음 300 파일 · 200MB · 넘으면 kmd 저장소의 세션 스킬 kmd-seed 로 꾸러미를 만들고 기초 세우기에서 묶음을 이어 올린다). 바탕이 선 뒤의 대량은 이 스킬로 넣는다. 사람이 그래도 넣으라고 하면 이어 간다.
1. **파서**: 파일을 글로 바꾸는 kmd 파서(`kmd-parse`)를 쓴다. 팀 화면 · 개인 프로그램과 같은 바꾸기다.
   - `brief` 의 `parser`(`{ ver, url, sha256, bytes }`)를 본다. `null` 이면 「팀 서버에 대량 넣기 파서가 없다: 총괄 관리자에게 부탁한다」 고 말하고 멈춘다.
   - `%USERPROFILE%\.kmd\parse\<ver>\kmd-parse.cmd` 가 있으면 그것을 쓴다(판이 같으면 다시 받지 않는다).
   - 없으면 「파서(<bytes 를 MB 로> MB)를 팀 서버에서 받습니다」 를 사람에게 묻고, 좋다고 하면 PowerShell 로 받는다. 팀 서버 주소는 `.mcp.json` 의 `kmd-team` url 에서 `/mcp` 를 뗀 것이다.
     ```powershell
     $v = '<ver>'; $d = Join-Path $env:USERPROFILE ".kmd\parse\$v"; $z = "$d.zip"
     New-Item -ItemType Directory -Force (Split-Path $d) | Out-Null
     Invoke-WebRequest '<팀 서버 주소><url>' -OutFile $z -UseBasicParsing
     if ((Get-FileHash $z -Algorithm SHA256).Hash.ToLower() -ne '<sha256>') { Remove-Item $z; throw 'sha256 이 다르다' }
     $t = "$d.tmp"; Remove-Item $t -Recurse -Force -ErrorAction SilentlyContinue; New-Item -ItemType Directory $t | Out-Null
     tar -xf $z -C $t; Move-Item (Join-Path $t "kmd-parse-$v") $d; Remove-Item $t, $z -Recurse -Force
     ```
     sha256 이 다르면 받은 파일을 지우고 멈춘다(사람에게 말한다).
2. **글로 바꾼다**: `& "$env:USERPROFILE\.kmd\parse\<ver>\kmd-parse.cmd" "<폴더>" --out "$env:TEMP\kmd-parse\<폴더 이름>" --attach`. 줄마다 파일 하나: `{ rel, mdFile, sha, tags, scan?, img?, why?, failed?, atts }` · 끝 줄 `{ done, n, fail }`. 같은 내용이 `index.json` 에도 있다.
   - `failed` 면 그 파일은 넣을 수 없다(까닭 `why` 를 끝에 같이 알린다).
   - `scan` 이면 글이 없는 pdf · 그림만 든 문서다. 원본 파일을 직접 읽어 글(md)을 짓는다. 지은 글이 그 파일의 글이다.
   - `img` 는 그림이다. 원본 첨부를 하지 않으면 건너뛴다.
   - 파일이 많으면 사람에게 수와 걸릴 일을 한 줄로 말하고 시작한다.
3. **파일마다 제안**(파일 하나 = 기록 하나 = 제안 하나 · 아직 저장하지 않는다): `mdFile` 을 읽고
   - 파일에 나오는 것을 `match` 로 맞추고(항목 맞추기), 들어갈 항목을 `section` 으로 읽는다(`base` 를 받는다). 넣을 곳을 고르는 규칙 · 항목 글 모양은 `kmd-team-save` 와 옆의 `작성가이드.md` 그대로다.
   - 기록: 제목 「<파일 이름>: 무엇」 · `tags` 는 파서가 준 `tags` 그대로(`ingest/<경로>` · `md/<sha>`: 같은 파일을 다시 넣으면 팀 서버가 `same` 으로 답한다 · 원본이 8MB 를 넘어 첨부할 수 없으면 표지를 떼고 짓는다: 제안과 저장의 입력은 같아야 한다) · `changes` 에 이 파일로 정해진 것 · `touches` 는 글이 바뀌는 항목만.
   - 고칠 항목(`sections`): 이미 있는 항목은 `{ coord, base, edits }`, 아직 없는 항목은 `{ doc, heading, content }`. 새 문서와 자리는 이 글 끝의 생성 룰 R3 · R4 로 정한다(문서 이름에 파일 이름 · 날짜 · 판을 쓰지 않는다).
   - 정해지지 않은 것(묻는 말 · 검토 중 · 초안)은 넣지 않는다. 문서에 들어갈 것이 없는 파일은 제안하지 않고 표에 「넣을 곳 없음」 으로 둔다.
   - `propose` 의 `errors` 가 있으면 입력을 고쳐 다시 propose 한다. 두 번 고쳐도 안 되면 표에 「제안 오류: 까닭」 으로 두고 넣지 않는다.
4. **규칙 표를 보이고 한 번 승인받는다**:
   ```
   【대량 넣기 제안】 지식: DPMS · 파일 42 · 넣을 것 39 · 넣을 곳 없음 2 · 제안 오류 1
   파일                       넣을 곳                          갈래   새 문서  경고
   회의/2026-10-21 통화.hwp   회의록 › 2026-10-21 HNC 통화      신설   0        0
   설계/연계 v0.3.docx        SCADA 연계 › 연계 구성            변경   0        1  w1 옛 값 「주기 5초」 빠짐
   ...
   승인하시면 표의 경고 n 을 받아들이고 39 파일을 넣습니다. 빼거나 넣을 곳을 바꿀 파일이 있으면 말씀해 주세요.
   ```
   - 경고가 있는 줄 · 새 문서 · 새 갈래가 서는 줄은 늘 보인다. 표가 길면 나머지는 「그 밖에 n 줄(경고 없음)」 로 줄이고, 사람이 「전체」 라고 하면 다 보인다.
   - 대화로 고친다: 파일 빼기(그 파일은 넣지 않음) · 넣을 곳 바꾸기 · 값 고치기(그 파일 입력을 고쳐 다시 propose 하고 바뀐 줄만 다시 보인다).
5. **파일마다 넣는다**(승인 뒤 묻지 않고 이어서): 그 파일의 입력에 승인한 `proposal` · `kit` · 원본 첨부를 실어 `save` 한다.
   - **원본 첨부**(늘 · 저장은 늘 승인이다): 그 파일 줄의 `atts`(`path` · `file` · `bytes`)를 `attach: [{ path, b64 }]` 로 같은 저장에 싣는다. `b64` 는 `[Convert]::ToBase64String([IO.File]::ReadAllBytes('<file>'))`. 팀 서버는 첨부 원본을 글로 바꿔 `md/<sha>` 와 맞을 때만 대량 넣기로 받는다. 한 저장에 8MB 까지: 더 큰 원본은 첨부하지 않고 글만 넣는다(`ingest/` · `md/` 표지도 떼고 · 끝에 알린다).
   - `same: true` 면 「이미 넣음」 이다(앞에서 넣은 파일: 이어 하기). 다음 파일로.
   - `E_APPROVE` · `E_CONFLICT`(앞 파일이 같은 항목을 고쳐 지문이 바뀜): 그 파일만 `section` 으로 다시 읽고 다시 propose 한다. 표의 그 줄과 같고(넣을 곳 · 갈래 같음) 새 경고가 없으면 새 `proposal` 로 넣는다. 다르면 넣지 않고 끝에 모아 그 줄들만 다시 보이고 승인받는다.
   - `E_RATE` 면 `details.retryAfter` 초 쉬고 같은 파일을 다시 보낸다.
   - 다른 오류는 그 파일만 건너뛰고 까닭을 적어 둔다.
6. **끝에 한 줄**: 「넣음 n · 이미 넣음 n · 건너뜀 n」(+ 못 바꾼 파일 · 넣을 곳이 없는 파일 · 제안 오류 · 첨부하지 않은 큰 원본의 이름 · 받아들인 경고 수). 응답 note · warnings 는 그대로 전한다.

중간에 멈췄으면 같은 폴더로 처음부터 다시 돌린다: 넣은 파일은 `same` 으로 건너뛴다. 비밀(비밀번호 · 열쇠 · 개인정보)이 든 파일은 넣지 않고 사람에게 묻는다. 줄표(—)는 쓰지 않는다(제목 · 글 모두): 풀이는 쌍점, 문장 끊기는 마침표.

## 생성 룰(자리 · 항목 · 종류 · 새 문서 · 과거 결정)

무엇이 항목이고 어느 문서에 두는지 · 성격과 종류 · 새 문서를 세울지 · `match` 가 준 과거 결정(`cards`)을 따를지는 아래 생성 룰로 정한다. 이 스킬 글의 다른 줄과 다르면 생성 룰이 앞선다. 사람에게 자리 · 종류를 설명할 때와 기록의 까닭에는 근거 조문 번호(R1 ~ R9)를 적는다. kmd 가 돌려준 오류 글의 조문 번호도 이 룰의 번호다.
