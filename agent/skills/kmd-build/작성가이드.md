# kmd 문서 작성 가이드: 항목 글의 모양

kmd 의 문서는 **항목(`## 머리`) 하나가 대상 하나의 지금**이다. 기록(`work/`)은 일어난 일 · 경위 · 근거를 그대로 남기고,
문서는 그 기록들을 녹여 **지금 어떤가**만 담는다. 문서를 읽는 사람이 「이 글이 어디서 왔고, 어디까지가 한 항목이고,
무엇이 지금 값인가」 를 글만 보고 알 수 있어야 한다.

이 가이드는 사람 · Claude Code 세션 · kmd 의 넣기 에이전트 · 정리 일꾼이 모두 따른다. 기준 문서는
`docs/kmd_문서_작성기준.md` 다(이 가이드는 그 줄임과 예시).

**항목 글은 본문만이다.** 문서 안 정보는 셋: 본문(확정된 지식) · 문서 간 연결(지식 문서 · 항목 · 바깥 링크) ·
시스템 참고 정보(출처 기록 · 표지). 시스템 참고 정보는 kmd 가 문서 끝 참고 블록과 표지에만 둔다. 사람 · Claude 는 본문만 쓴다.

## 항목 하나 = 대상 하나

- 항목 머리는 **대상의 이름**이다. 기능 · 화면 · 테이블 · API · 절차 · 용어 · 회의 한 번. 커밋 · 판 · 날짜 · 파일 이름으로 항목을 세우지 않는다(회의 · 보고 같은 사건 문서만 「YYYY-MM-DD 상대 · 무엇」).
- 이름 장부의 이름(`func:기록 분석`)이 있으면 그 이름이 항목 머리다. 같은 대상을 두 항목에 나눠 쓰지 않는다.
- 한 항목이 대략 **300줄**을 넘으면 대상이 둘 이상 섞인 것이다. 대상마다 항목을 나누고 이름을 세운다.

## 사실 하나에 정본 한 곳

- 한 사실(값 · 규칙 · 동작)은 그것을 **가장 오래 책임지는 대상**의 항목에만 쓴다. 컬럼이면 테이블, 규격이면 인터페이스, 뜻이면 용어, 동작이면 그 기능.
- 다른 항목은 한 줄로 그 이름을 부른다(「저장 방식은 기록 분석 항목을 따른다」). 같은 글을 두 항목에 옮기지 않는다. 한쪽만 고쳐지면 둘이 어긋난다.

## 지금으로 다시 쓴다. 덧붙이지 않는다

- 항목은 **대상의 지금**이다. 새 기록이 오면 날짜별로 끝에 붙이지 않고, 지금 글에 녹여 **다시 쓴다**.
- 「추가했다 · 고쳤다 · 바꿨다」(사건)가 아니라 「…한다 · …이다 · …까지」(상태)로 쓴다. 어디에 · 누구용 · 몇 개 · 예외.
- 뒤집힌 내용은 본문에서 지운다. 바뀐 경위는 기록에 있고, 문서 끝 참고 줄이 그 기록으로 잇는다.
- **확정된 내용만** 쓴다. 아직 넣지 않은 기록 · 검토 중인 초안 · 「~했다는 기록이 있다」 같은 경위는 쓰지 않는다.
- 기록 · 근거보다 크게 쓰지 않는다. 기록에 없는 값 · 설명을 지어내지 않는다.

## 항목에 옮기지 않는 것

| 무엇 | 어디에 남나 |
|---|---|
| 경위 · 논의 · 버린 안 · 「왜 이렇게 됐나」 의 이야기 | 기록(`work/`): 참고 줄이 잇는다 |
| 기록 · 이력 링크(`../work/…` · `../log/…`) · `/api/…` 같은 시스템 주소 · `<!-- -->` 주석 | kmd 가 참고 블록 · 표지에 둔다(본문에 쓰면 저장이 거절한다) |
| 코드 바뀜 기록의 「무엇이 바뀌었나 · 바뀐 것 · 영향 · 문서에서 맞춰 볼 것」 목록 | 기록: 항목에는 그 결과로 **지금 어떻게 동작하나**만 |
| 커밋 메시지 · 커밋 번호 · 코드 차이(diff) · 코드 줄 | 기록 · git |
| 회의의 발언 · 원문 그대로의 긴 글 | 기록(넣은 파일의 기록): 회의록 항목엔 정한 것 · 할 일 |
| 준비 글의 진행 틀: 인사말 · 말할 거리 · 시간 배분 · 묻는 말 · 확인할 것 · 빈 칸 양식 · 메모 칸 · 체크 상태(`- [ ]`) · 구분선 | 기록: 항목엔 그 글이 담은 확정 사실(구성 · 역할 · 범위 · 일정 · 규칙)만 |
| 비밀(비밀번호 · 열쇠 · 개인정보) | 어디에도: 「(가림)」 |

## 항목 안의 짜임

```
## <대상 이름>
<!-- applied: … -->            ← kmd 가 단다(쓰지 않는다)
<한두 줄: 이 대상이 무엇인가>

### <소제목>                    ← 항목 안의 짜임은 ### 아래로(# · ## 는 쓰지 않는다)
- 지금 동작 · 규칙 · 값 · 예외
| 표 | … |

관련: [다른 문서](다른문서.md) · [다른 항목](다른문서.md#항목)

## <다음 대상>
…

<!-- kmd:참고 · kmd 가 적고 고친다. 손으로 고치지 않는다 -->   ← 문서 끝 하나 · kmd 가 단다(쓰지 않는다)
**참고**

- <대상 이름>
  - 2026-10-26 [기록 제목](../work/<기록 id>.md)
<!-- /kmd:참고 -->
```

- **첫 줄**: 이 대상이 무엇인가 한두 줄. 항목만 읽어도 홀로 서야 한다.
- **소제목**은 `###` · `####` 또는 굵은 글. `#` · `##` 는 항목 머리라 글 안에 쓰지 않는다(쓰면 항목이 갈라진다. 정리 일꾼의 글이면 kmd 가 거절한다).
- **표 · 목록**은 값 · 규칙에. 줄글은 판단 · 까닭에.
- **표지**(`<!-- applied -->` · `<!-- watched -->` · 저절로 채우는 표 블록)는 kmd 의 자리다. 손대지 않는다.
- **줄표(—) 쓰지 않는다**. 제목 · 항목 머리 · 본문 · 표 · 기록 제목 어디에도. 풀이를 붙일 때는 쌍점(`이름: 풀이`), 문장을 끊을 때는 마침표, 덧말은 괄호로 쓴다. 원본 글에 줄표가 있으면 같은 뜻으로 바꿔 옮긴다.
- **머리 단계를 건너뛰지 않는다**. `##` 아래 소제목은 `###` 부터, 그 아래가 `####` 다. `##` 바로 아래 `####` 는 쓰지 않고, `#####` 는 쓰지 않는다(화면 개요와 위계가 어긋난다).

## 문서 머리: 제목 · 요약

```
# PLC 연계 규격서                 ← 제목 하나(파일 이름이 아니라 문서 속 실제 이름)

PLC 와 게이트웨이가 주고받는 전문의 틀 · 주기 · 오류 처리를 정한다. 주기는 5초, 끊기면 3번 다시 잇고 경보를 낸다.
                                  ← 요약 1~3문장: 무엇을 다루고 지금 결론이 무엇인지

| 작성 | 판 | 상태 |           ← 메타 표는 요약 아래에(요약이 아니다)
|---|---|---|
| 홍길동 | 1.2 | 확정 |

## 전문 틀                         ← 첫 ## 앞에 ### · #### 를 두지 않는다
```

- **메타 표는 요약이 아니다**. 제목 바로 아래가 작성자 · 판 · 상태 · 근거 문서 표나 인용 · 목록이면 「요약 없음」 이다. 표 위에 1~3문장을 쓴다.
- **머리글에 kmd 운영 규칙을 쓰지 않는다**. 「좌표는 `screen:{화면ID}`」 · 「작업 기록의 `touches` 에 넣는다」 · 「다음 동기화는 이 섹션을 덮지 않는다」 · 「`_vocab.md` alias 로 남겼다」 같은 글은 읽는 사람의 지식이 아니다. kmd 운영 메모는 `CLAUDE.md` · `_managed.md` 안내에 둔다.
- 나쁜 예: 제목 없이 `<!-- applied: … -->` 로 시작해 메타 표가 오는 문서 · 요약이 3문장(5줄)을 넘는 머리글 · 첫 `##` 앞의 `### 기준선` · `## ACA011` 바로 아래 `#### 1. 업무 흐름`.
- 저장 · `kmd docfmt` 는 이것을 「문서 짜임」 알림으로 보인다(거절하지 않는다). 고치는 일은 문서 주인 · 정리가 한다.

## 링크: 종류마다 하나

| 종류 | 쓰는 꼴 |
|---|---|
| 지식 문서 | `[배포 절차](배포절차.md)` · 다른 폴더면 `[백업](../운영/백업.md)`(이 문서에서 본 상대 경로 · `.md` 붙임) |
| 항목 | `[준비](배포절차.md#준비)` · 같은 문서면 `[준비](#준비)` |
| 바깥 | `[이름](https://…)` 또는 `<https://…>` |
| 기록 · 이력 | 본문에 쓰지 않는다. 참고 블록에 kmd 가 단다 |

## 참고: 어디서 왔나

- 문서 끝 참고 블록(`<!-- kmd:참고 … -->` ~ `<!-- /kmd:참고 -->`)에 항목마다 `- YYYY-MM-DD [기록 제목](../work/<id>.md)` 한 줄씩: 이 항목에 들어간 기록마다 하나. 화면은 이 블록을 본문에 그리지 않고 항목 옆 「출처」 로 보인다.
- **kmd 가 단다**. 저장할 때 이번에 넣은 기록의 줄을 더하고, 옛 줄은 보낸 글에 없어도 지킨다(지우지 않는다). 항목을 지우면 그 줄도, 이름을 바꾸면 줄 이름도 같이 바뀐다. 사람 · Claude 는 본문만 쓴다.
- Claude 로 다듬지 못해 규칙으로 기록 글을 붙인 항목은 그 기록의 참고 줄 끝에 `· 다듬지 못함` 이 붙는다. 다음 정리 · 사람이 지금 글로 녹인다. 코드 바뀜 기록은 붙이지 않고 참고 줄만 남는다.
- 옛 꼴(항목 끝 `**경과**` 목록 · `> 기록 그대로: …` 줄)은 kmd 가 읽을 때 받아 주고, 그 항목을 쓸 때 참고 블록으로 옮긴다. 한 번에 옮기려면 `kmd docfmt <지식>`.

## 예: 좋은 글 · 나쁜 글

좋은 예(대상의 지금 · 확정된 것만 · 문서 · 항목 링크):

```
배포 창은 화 · 목 14:00 ~ 17:00 이다. DB 커넥션 풀은 40 으로 둔다.
되돌릴 때는 [롤백](#롤백) 순서를 따른다.
```

나쁜 예(경위 · 기록 링크 · 출처 목록 · 주석을 본문에):

```
2026-10-21 배포 창을 화 · 목으로 바꿨다는 기록이 있다([기록](../work/2026-1021-배포-창.md)).
<!-- 나중에 다시 볼 것 -->

**경과**
- 2026-10-21 [배포 창](../work/2026-1021-배포-창.md)
```

## 문서 종류별 모양

| 종류 | 문서 예 | 항목은 | 새 기록이 오면 |
|---|---|---|---|
| **대상** | 기능 · 화면 · 테이블 · API · 설계 | 대상의 지금 사양: 동작 · 표 · 규칙 · 예외 | 본문을 고쳐 쓴다 |
| **정의** | 용어 | 뜻 · 쓰임 · 관련 이름. 판단 · 수치는 넣지 않는다 | 고쳐 쓴다 |
| **대장** | 이슈 · 장애 · 위험 | 표 + 결론 한 줄. 설계 서술은 그 대상 항목으로 | 표 · 결론을 고쳐 쓴다 |
| **사건** | 회의록 · 보고서 | 「YYYY-MM-DD 상대 · 무엇」 항목: 정한 것 · 할 일 | 새 항목을 더한다(지난 항목은 그대로) |
| **서술** | 가이드 · 절차 · 운영 | 절차 · 규칙: 문서 전체가 내용 | 그 절을 고쳐 쓴다 |

대상 문서의 항목에 날짜 소제목(`### 2026-10-26 …`)이 생기거나, 기록의 글이 통째로 쌓이면 사건 모양이 섞인 것이다. 지금 글로 다시 쓴다.

## 넣기 · 정리에서

- **넣은 파일**(회의록 · 설계서 · PDF): 파일의 글 · 값은 `from` 으로 가리키면 kmd 가 원문 그대로 옮긴다. 사건 문서(회의록)의 새 항목, 서술 문서의 절에 맞다. 대상 항목의 **값을 고칠 때**는 `section` 으로 읽고 지금 글을 고친 새 글 전체를 `content` + `base` 로.
- **코드 바뀜 기록**(커밋 분석): `from` · `append` 를 쓰지 않는다(kmd 가 거절한다). 바뀐 기능의 항목을 `section` 으로 읽고 **지금 동작으로 고쳐** `content` + `base` 로. 그 기능의 항목이 없으면 기능 이름으로 새 항목. 커밋마다 항목 · 문서를 세우지 않는다.
- **append** 는 사건 문서 항목에 정한 것 · 할 일을 보탤 때만: 대상 항목에 덧붙이면 일지가 된다.
