# kmd 에 남기기

**어디에**: CLAUDE.md 「이 폴더의 지식」 표의 기본 지식이 기본이다. 사람이 표의 다른 지식을 말했으면(이 세션에서 한 번이라도) 그 지식. 그 지식의 연결(팀이면 `kmd-team` · 개인이면 `kmd`)로 부르고 knowledge 에 그 id 를 준다. 표가 없거나 어디인지 애매하면 지식 목록을 보여 주고 묻는다. 기본이 아닌 팀 지식에는 사람이 말하지 않으면 남기지 않는다(팀 사람이 본다).

1. 무엇을 남길지 한 줄 제목으로: 「무엇: 어떻게」 (예: 「카나리: 첫 30분 20%」).
2. 건드린 이름을 `match` 로 맞춰 `touches` 에 넣는다. 맞는 이름이 없으면 비워 둔다(정리 때 kmd 가 찾는다).
   - 이 기록으로 글이 실제로 바뀌는 항목만 단다(값 · 정한 것이 바뀐 곳). 읽기만 한 항목 · 이름만 나온 항목은 달지 않는다. 이름 하나가 정리의 자리 하나다.
   - 문서 하나를 판 갈이하듯 크게 고쳤으면(항목 여럿이 다 바뀜) 항목마다 쪼개 남기지 말고 그 문서 고친 일을 기록 하나로: 이름은 크게 바뀐 항목 몇 개만.
3. `save` 하나로 보낸다. 글은 사실만, 짧게. 누가 · 왜 정했는지 알면 같이.
4. `brief { knowledge }` 의 `you.direct` 가 참(팀 관리자 · 이 PC)이면 `sections` 로 그 항목의 새 글을 같이 보낸다. 덧붙이지 말고 지금 글을 고친 새 글 전체(현재형 · 소제목 `###` · 끝 `**경과**` 는 kmd 가 단다 · 자세히는 `../kmd-build/작성가이드.md`). 아니면 기록만: 정리 때 문서에 들어간다(`names` 도 기록에 실려 정리 때 세워진다).
5. 어느 지식에 남겼는지(이름 · 팀 / 개인) 사람에게 한 줄로 말한다. 응답의 note · warnings(백업 멈춤 · 아직 세우지 않은 이름 등)는 사람에게 그대로 전한다. 「세웠다」 고 말하지 않는다. note 가 말한 만큼만.

비밀(비밀번호 · 열쇠 · 개인정보)은 남기지 않는다. 줄표(—)는 쓰지 않는다(제목 · 글 모두): 풀이는 쌍점, 문장 끊기는 마침표.
