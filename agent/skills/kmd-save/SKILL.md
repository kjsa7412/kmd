# kmd 개인 지식에 남기기

**어디에**: CLAUDE.md 「이 폴더의 개인 지식」 표의 개인 지식 가운데 하나. 연결은 `kmd`, knowledge 에 그 id 를 준다. 여기 남긴 것은 나만 본다.

- 표의 개인 지식이 하나면 그 지식에 남긴다. 여럿이면 남기기 전에 남길 제목 한 줄과 표를 보여 주고 「어느 지식에 남길까요?」 로 묻는다. 사람이 이 세션에서 이미 골라 주었으면 그 지식에.
- 이 폴더에 팀 지식(연결 `kmd-team` · 스킬 `kmd-team-save`)도 붙어 있고 사람이 팀인지 개인인지 말하지 않았으면, 팀 지식인지 개인 지식인지부터 묻는다.
- 표가 없으면 brief 가 준 지식 목록을 보여 주고 묻는다.

**스킬 판**: `save` 마다 `kit: "{{KIT_REV}}"` 를 같이 보낸다(이 스킬 글의 판).

**늘 제안하고 승인받는다.** kmd 가 정한 꼴의 【저장 제안】 글을 사람에게 보이고 승인받은 뒤에만 `save` 한다. 「한 번에 끝내 달라」 고 해도 한 번은 보이고 묻는다. 승인은 제안서의 경고를 받아들이는 것까지 포함한다. 흐름은 팀 지식(`kmd-team-save`)과 같고, 제안서 머리가 「보는 사람: 나만 · 이 PC」 인 것만 다르다.

## 순서

1. **brief**: `brief { knowledge }` 로 종류(`kinds`) · 갈래(`forms`: 이슈를 받는 갈래가 있나) · 문서 목록 · `saveMode` 를 본다.
2. **길을 정한다**: 이 세션의 작업 / 넣어 달라는 원문(성격을 한 줄로) / 문서를 고치라는 지시(지시 자체가 기록이다).
3. **정리 거리 고르기**(세션 작업이 길 때): 작업을 결정 · 변경 단위 묶음으로 나눠 한 줄씩 보이고 넣을 묶음을 고르게 한다.
   ```
   정리 거리
   1. 헬스체크 주기 30초 → 10초(11-07 장애 회고에서 정함)
   2. 배포 알림 대상에 운영팀 더함
   3. 롤백 기준: 정해지지 않음 · 넣지 않음(이슈로 제기할 수 있음)
   어느 묶음을 남길까요?
   ```
   - 묶음 하나 = 기록 하나 = 제안서 하나. 여럿을 고르면 제안서를 차례로 보이고 「모두 넣어」 로 한 번에 승인받을 수 있다(각자 자기 `proposal`).
   - 정해지지 않은 묶음은 「정해지지 않음 · 넣지 않음」. 이슈를 받는 갈래가 있으면 「이슈로 제기」 를 고를 수 있다(「무엇이 열려 있다」 는 그 자체로 확정된 지식이다). 없으면 넣지 않는다.
   - 짧은 작업이면 묶음 하나로 바로 4로 간다.
4. **읽기**: 건드린 항목을 `match` 로 맞추고, 고칠 항목을 `section` 으로 읽는다(지금 글 · `base` · `history`).
5. **제안 입력을 짓는다**(아래 「입력」).
6. **propose**: `propose { knowledge, record, sections, names, forms, kinds, distinct, excluded }`. `errors` 가 있으면(`proposal` 이 null) 사람에게 보이기 전에 입력을 고쳐 다시 propose 한다. 같은 이름이 정말 다른 것이면 `distinct` 에 그 이름을 넣는다.
7. **보이고 승인받는다**: 답의 `text` 를 **고치지 않고** 그대로 보인다. 경고가 있으면 끝 줄 「승인하시면 경고 w1 을 받아들이고 그대로 남깁니다」 가 보이게 둔다.
8. **대화 조절**: 사람이 고칠 것을 말하면 입력을 고쳐 6으로 돌아가 다시 propose 한다. 몇 번이든 되풀이한다.
   - 고치는 꼴: 항목 빼기(입력에서 빼고 `excluded` 에 `{ name, why: "사람이 뺌" }`) · 넣기 · 값 · 문장 고치기(`edits` 와 기록 「바뀐 것」 을 같이) · 기록 범위 줄이기(기록 칸과 고칠 항목을 그 범위의 작업만으로 다시 짓기) · 넣을 곳 바꾸기.
   - 다시 보일 때는 앞 `text` 와 새 `text` 의 **바뀐 줄만** 보이되, 경고 줄과 끝 줄(「승인하시면 …」)은 늘 보인다. 사람이 「전체」 라고 하면 전체를 보인다.
   ```
   사람: 이 값은 30 이 아니라 60
   세션: (그 edits 의 옛 값과 기록 「바뀐 것」 을 60 으로 고쳐 다시 propose)
         바뀐 줄
           【기록】 바뀐 것   헬스체크 주기: 30초 → 10초  →  헬스체크 주기: 60초 → 10초
           배포절차 › 헬스체크   - 주기는 60초이다.
         경고 w1 없어짐 · 오류 없음 · 승인하시면 남깁니다.
   사람: 좋아, 넣어
   세션: save { …, proposal: <마지막으로 보인 제안서의 proposal> } → 들어감
   ```
9. **save**: 승인되면 마지막으로 보인 제안서와 **같은 입력**에 `proposal` 과 `kit` 을 실어 `save` 한다. `proposal` 없이 부르지 않는다.
   - `E_APPROVE`: 승인한 제안과 지금 제안이 다르다. 아무것도 쓰지 않았다. `details.propose.text` 의 바뀐 줄을 보이고 7로 돌아가 다시 승인받는다.
   - `E_CONFLICT`: 읽은 뒤 바뀐 항목이 있다(편집기에서 고쳤을 수 있다). 아무것도 쓰지 않았다. `details.stale` 항목을 `section` 으로 다시 읽고 다시 propose 해서 바뀐 부분만 보이고, 다시 승인받아 꼭 다시 보낸다.
   - `E_INPUT` · `E_FORMAT`: 까닭대로 입력을 고쳐 다시 propose 한다(아무것도 쓰지 않았다).
10. **끝 보고 세 줄**: 들어간 곳(지식 › 문서 › 항목) · 세운 것(문서 · 갈래 · 항목) · 받아들인 경고 수와 남은 묶음(고르지 않은 것 · 넣지 않은 것). 응답의 note · warnings 는 그대로 전한다. note 가 말한 만큼만 말한다.

## 넣는다 · 뺀다

- **넣는다**: 신설 · 변경 · 폐기했다, 정의했다, 그렇게 정했다, 제기했다(이슈 갈래가 있을 때).
- **뺀다**(`excluded`): 참조 · 언급 · 예시, 그것을 쓰는 다른 것을 만들었다, 아직 정해지지 않았다.
- 물음은 하나다: 「6개월 뒤 이 대상을 다시 볼 때 이 기록을 찾아야 하나」. 억지 항목은 없는 것보다 나쁘다.
- 정한 것 · 바뀐 것 · 제기한 것이 없으면 기록을 만들지 않는다(남기지 않는다고 말한다). 기록을 만들었으면 반드시 항목에 잇는다.
- 이을 항목이 하나도 없으면 멈추고 사람에게 묻는다. 사람이 「이을 항목 없음」 을 고르면 `touchesEmpty` 에 까닭 한 줄을 적는다: 「기록 모음」 문서의 그 달 항목에 이어진다. 「기타 · 메모 · 임시」 같은 머리를 만들지 않는다.

## 입력

- **record**(기록 · 서식 칸으로만 · 줄글 하나는 거절된다 · 머리는 kmd 가 단다):
  - `title`: 「무엇: 어떻게」(예: 「카나리: 첫 30분 20%」).
  - `changes`(바뀐 것): 줄마다 「무엇: 옛 값 → 새 값」 · 새로 정한 것은 「무엇: 값」. 여기 적은 값은 고칠 항목 글에 꼭 들어가야 한다(안 들어가면 오류).
  - `why`(까닭: 왜 · 누가 정했나) · `dropped`(버린 안과 까닭) · `impact`(영향) · `refs`(근거: 커밋 · 문서 판 · 회의): 있는 것만.
  - `body`: 한두 문장 요약(300자 안 · 문단 하나).
  - `touches`: 글이 실제로 바뀌는(또는 경위를 잇는) 항목만. `match` 로 찾은 항목 장부의 항목(`종류:값`). 읽기만 한 항목 · 말만 나온 항목은 달지 않는다(`excluded` 로).
  - 바뀐 값 없이 결정 경위만 있는 기록은 항목 글 없이 `touches` 로 그 항목에 잇는다(글은 그대로).
  - 문서 하나를 판 갈이하듯 크게 고쳤으면 항목마다 쪼개지 말고 기록 하나로: `touches` 는 크게 바뀐 항목 몇 개만.
- **sections**(고칠 항목 · 새 항목):
  - 있는 항목: `{ coord | doc · heading, base, edits: [{ find, replace }] }`. `base` 는 `section` 이 준 지문 그대로. `find` 는 지금 글에 **꼭 한 번** 나오는 글을 그대로 복사하고, `replace` 에 고친 글을 둔다. 덧붙이지 말고 그 문장을 현재형 · 확정된 것만으로 고쳐 쓴다. 지금 글을 고친 새 글 전체를 `content` + `base` 로 보내도 된다.
  - 없는 항목(새 항목 · 이슈 제기): `{ doc, heading, content }`.
  - 새 문서는 `forms`(갈래 장부)의 갈래 이름 · 폴더로만 세운다. 파일 이름 · 날짜 · 판을 문서 이름에 쓰지 않는다. 통화 · 미팅 · 면담은 회의록 문서의 「YYYY-MM-DD 무엇」 항목이다.
- **names**: 장부에 올릴 새 항목(새 테이블 · 화면 · 절차 · 이슈 …). 종류는 `kinds` 가운데서(새 종류면 `kinds` 에). 값은 빈칸 없는 열쇠(`이슈:DPMS-ISS-20` · `proc:헬스체크` · 60자 안). 문장 · 설명은 `label` 에. `touches` 에도 단다.

## 항목 글 규칙(작성기준 3 ~ 5절 · 자세히는 `../kmd-build/작성가이드.md`)

- 확정된 지금만 쓴다: 대상 하나의 지금을 「…한다 · …이다」 로. 아직 반영되지 않은 기록 · 검토 중인 초안 · 「~했다는 기록이 있다」 같은 경위는 쓰지 않는다.
- 본문만: 기록 링크(`../work/…` · `../log/…`) · `/api/…` 같은 시스템 주소 · `**경과**` 목록 · `<!-- -->` 주석 · `#` · `##` 줄을 넣지 않는다(저장이 거절한다). 출처는 kmd 가 문서 끝 참고에 단다.
- 링크는 셋만: 지식 문서 `[배포 절차](배포절차.md)` · 항목 `[준비](배포절차.md#준비)` · 바깥 `https://…`.
- 짜임은 수준 표시(`1.` · `1.1.` · `1)` · `-` · `*`)로, 들여쓰지 않는다. `###` 소제목을 새로 쓰지 않는다. 나란한 것이 셋 이상이면 목록 · 견줄 속성이 둘 이상이면 표.
- 기록이 바꾼 값만 바꾼다. 옛 글의 다른 값(판 · 포트 · 이름 · 수)을 빼지 않는다.
- 서식(작성기준 6-3 · 서식 계약): 항목 머리 다음 첫 블록은 대상 · 결론 한 문장이다. 회의 · 사건 항목은 `- **누가**:` · `- **때 · 곳**:` · `- **정한 것**:` · `- **남은 것**:` 라벨 줄(아래 낱낱은 `*` · 할 일은 `* <할 일>: <맡은 이> · 기한 <YYYY-MM-DD 또는 ->`), 대장 항목은 머리 「ID: 이름」 + `| 속성 | 값 |` 표 + `- **내용**:` · `- **해결방안**:` · `- **결과**:`. 같은 수준 번호는 1 → 2 → 3 으로 이어 세고, 표 한 칸에 값을 몰지 않으며, 날짜는 YYYY-MM-DD. 결정 · 할 일 · 상태를 지어내지 않는다(없으면 「원본에 따로 없음」). 저장 응답 warnings 의 「서식(알림 · 저장은 했다)」 은 다음 저장에서 고친다.
- 좋은 예: 「배포 창은 화 · 목 14:00 ~ 17:00 이다.」
- 나쁜 예: 「배포 창을 바꿨다는 기록이 있다([기록](../work/2026-1021-배포-창.md))」

비밀(비밀번호 · 열쇠 · 개인정보)은 남기지 않는다. 줄표(—)는 쓰지 않는다(제목 · 글 모두): 풀이는 쌍점, 문장 끊기는 마침표.
