# KMD 홍보 페이지 원고

한 장짜리 제품 소개 페이지 `KMD.html` 의 구획 원고다. 구획마다 「## 머리」 를 단다. 페이지 자체가 항목으로 짜인 문서다.
글은 제목과 도식 안 낱말 위주다. 예시는 188 팀 서버 DPMS 지식의 항목 「개소 현황」 하나로 끝까지 간다.

| | |
|---|---|
| 파일 | `KMD.html` · 그림 `img/` (팀 화면 캡처 밝은 · 어두운 한 벌씩) |
| 자료 | DPMS 지식 2026-11-11 기준 사본 |
| 색 | 기록 주황 · 문서 파랑 · 항목 초록 · 장부 보라 (모든 구획에서 같은 뜻 · 항목의 값 · 라벨 · 머리는 모두 초록) |
| 틀 | 가운데 틀 양 끝의 세로 괘선 + 구획 사이 가로 괘선(장부) |
| 글자 | Pretendard · JetBrains Mono (연결이 없으면 Noto Sans KR) |

## 말

| 말 | 뜻 |
|---|---|
| 항목 | 지식의 단위 하나. 자리마다 달리 적힌다. 장부에서는 값 `사업현황:개소현황` 과 라벨 「개소 현황」, 문서에서는 `## 4. 개소 현황` 머리와 그 아래 글, 기록에서는 `touches` 의 값 |
| 항목 장부 | `_vocab.md` · 어떤 항목이 있나 |
| 문서 장부 | `_managed.md` · 그 항목이 어느 문서의 어느 `##` 인가 |
| 고칠 항목 | 저장에 실리는 항목 하나: 자리 + 지문 + 바꿀 글 |

「이름」 · 「조각」 은 쓰지 않고 항목이라 한다. 비교 구획의 「비슷한 조각」 만 남긴다(RAG 가 원문을 길이로 자른 토막이라 항목이 아니다).

## 첫 화면

- 알림 알약: DPMS 사업 5주 실사용 · kmd v0.1.0
- 제목: 지식은 「항목」 으로 구성되고, 「기록」 으로 남으며, 「문서」 로 관리됩니다 (세 낱말은 색 알약)
- 한 줄: KMD 는 팀과 AI 세션이 함께 쓰는 지식 장부입니다. 세션은 문서의 내용을 항목 단위로 맥락에 주입합니다.
- 단추: 원칙 보기 · 개소 현황으로 보기
- 배경: 지식 그래프 그림(`img/graph.png` · 위에서 아래로 흐려진다 · 어두운 테마에서는 뒤집는다)
- 그림: 팀 화면 「항목으로 보기 › 개소현황」 을 HTML 로 다시 그린 창. 항목(4. 개소 현황) → 기록(항목의 히스토리) → 문서(항목의 최신) 을 차례로 짚는다

## 문제

- 큰 글: 문서를 읽는 쪽이 사람에서 AI 세션으로 바뀌었습니다. 만드는 형식과 나누는 방식은 그대로입니다.
- PROBLEM 1 문서는 통째로 AI 세션에 들어간다 · 받은 것 300줄 · 필요한 곳 1칸
- PROBLEM 2 골라내는 주체가 사람에서 AI로 바뀌었다 · 형식은 사람용 그대로 · 구조 없는 300줄
- PROBLEM 3 알리고 · 열어보고 · 찾는 공유는 샌다 · 누락 지점 3

## 해결

- 큰 글: 기록과 공유가 자동입니다. 일을 마친 세션이 남기고, 일을 시작하는 세션이 받습니다.
- 도식: 일을 마친 세션(정한 것 · 바뀐 것을 남긴다 · 기록 + 고칠 항목 · 스킬 `kmd-team-save`) → 자동 기록(승인 한 번) → 팀 지식(기록 「질매 연내 테스트 계획」 · 문서 「사업 현황 및 이해관계자」 · 항목 `## 4. 개소 현황` · 질매 전기공사 11월 말 ~ 12월 초) → 자동 공유(알림 없이) → 일을 시작하는 세션(그 일의 항목만 받는다 · 맥락에 주입 · 스킬 `kmd-team-work`)
- 사람이 하던 일(지움 표시): 정리 문서 쓰기 · 알리기 · 열어 보기 · 골라 붙이기
- 근거: 작업 폴더에 한 줄로 깔리는 세션 스킬 둘. `kmd-team-work` 는 일 전에 팀 지식에서 그 일의 항목을 찾아 읽고, `kmd-team-save` 는 일 끝에 저장 제안을 보이고 승인받아 기록과 항목을 한 번에 넣는다. 파일 · 폴더 · git · DB 는 팀 일꾼이 승인 없이 들인다

## 원칙

- 큰 글: 지식의 원자는 항목입니다. 기록은 항목의 히스토리, 문서는 항목의 최신입니다.
- 그림 「항목 격자」(DPMS 실제 자료): 세로줄이 항목, 맨 위 줄이 문서(항목의 최신), 가로줄이 기록(항목의 히스토리 · 새것 위)
  - 항목 다섯: `이슈:DPMS-ISS-06` · `이슈:DPMS-ISS-16` · `이슈:DPMS-ISS-18` · `사업현황:주요일정` · `사업현황:개소현황`(고른 항목)
  - 문서 둘: 위험 및 이슈 관리대장(이슈 셋) · 사업 현황 및 이해관계자(주요 일정 · 개소 현황). 개소 현황의 지금 글은 질매 전기공사 11월 말 ~ 12월 초
  - 기록 다섯 줄: 11-06 ISS-16 현장 공사 지연(ISS-16) · 11-05 질매 PLC 연계 일정 조정(2건 · 다섯 모두) · 11-04 질매 연내 테스트 계획(다섯 모두) · 10-26 ISS-18 원격 제어 방식 변경(ISS-16 · ISS-18) · 10-14 패키지형 납품 결정(ISS-06 · ISS-16)

- 원칙 셋. 문제별 답을 여기에 같이 싣는다(해결 구획의 줄 셋을 옮김)

| 원칙 | 격자에서 | 지운 문제 | 답 |

## 기능

- MCP(흰 배경 · 주고받는 표): 세션(스킬 kmd-team-work · kmd-team-save) ⇄ kmd 팀 서버(Streamable HTTP · JSON-RPC · 무상태 · 자리로 거른다). 일 전 받는다: brief(지식 · 문서 36 · 알릴 것) · match(값 · 라벨 · 별칭 · 머리가 같으면 확정) · search(항목 후보 · 자리 없는 글의 토막) · section(지금 글 · 지문 base · 히스토리). 일 뒤 남긴다: propose(【저장 제안】 글 · proposal · 아무것도 쓰지 않는다) → 사람이 승인한다 → save(들어감 · 기록 1 · 항목 1 · git 한 묶음). 오류: E_CONFLICT(지문이 어긋남) · E_APPROVE(승인한 제안과 달라짐)은 아무것도 쓰지 않고 다시 읽어 다시 제안한다
- 채널(들어오는 길은 여럿, 지나는 절차는 하나): 들어오는 길 = 사람 줄기 셋(세션 · 공유 개인 → 팀 · 파일 넣기)과 무인 줄기 셋(git · 폴더 · DB) → 같은 절차 = LLM 세션(찾기 → 판단 + 글) · 코드(짝 짓기 → 검사 → 저장 → 측정) · 사람 승인(사람이 넣은 것만) → 지식(항목 · 기록 · 문서 · 항목 장부 · 문서 장부). 근거 그림은 docs/품질개선/지식생성_하네스_결정.html 의 [채널]
- 변환(서술 없이 핵심 낱말만): 재료 · 여러 유형(hwp · hwpx · docx · pptx · xlsx · pdf · csv · html · txt · json · 스캔) → 변환(변환기 · Claude 읽기) → MD · 원천(원본 첨부) → 들이기(Claude · 저장 문) → 지식(항목 원자 · 기록 히스토리 · 문서 최신). 아래 줄 기초 세우기: 왜 필요한가와 장점을 두 그림으로. 그대로 넣으면(착수보고_v2.pptx · 착수보고_최종.pptx · 회의록(3).hwp 가 저마다 문서 하나 · 파일 = 문서 · 이름 · 판이 굳음 · 같은 내용이 흩어짐) / 기초 세우기(같은 세 파일 → 구조안 → 문서 「착수 보고」 의 항목 · 문서 「회의록」 의 날짜 항목 · 여러 파일을 하나로 · 늦은 판이 이김 · 주제별 문서 · 항목 · 장부 · 차례까지). 일곱 단계(지식 › 재료 › 거르기 › 구조안 › 짓기 › 진단 › 넣기 · 구조안과 짓기는 사람 승인). 파일 이름은 설명용으로 지은 것이다
- 개인 지식: 내 PC(개인 지식 · 내 Claude · MCP kmd · 파일 300) → 공유 → 팀 서버(팀 지식 · 팀 일꾼 · MCP kmd-team · 파일 20)

## 비교

- 제목: RAG 는 쌓인 자료에서 찾고, KMD 는 바뀌는 사실을 맞춰 둡니다
- 뜻: 둘은 경쟁이 아니라 맞는 자리가 다르다. RAG 는 읽을 때마다 추정하고, KMD 는 쓸 때 한 번 확정한다
- 그림: 같은 질문 「질매 전기공사 언제야?」 를 두 쪽에 던진 장면
  - RAG(문서 검색 AI · 쌓여 있는 자료에서 찾기): 비슷한 대목 셋(PLC 설치 10월 말 ~ 11월 초 예상 · 전기공사 11월 말 ~ 12월 초 · 연내 완공 시 현장 테스트) → 추정 · 어느 것이 지금인지는 읽을 때마다 짐작한다 · 강한 곳 정리 안 된 자료 더미와 예상 못 한 질문 · 약한 곳 옛 판과 새 판을 가르지 못한다
  - KMD(팀 지식 장부 · 계속 바뀌는 사실을 맞춰 두기): 항목 `사업현황:개소현황` 의 지금 값 11월 말 ~ 12월 초 + 이력(10월 말 ~ 11월 초 → 11월 말 ~ 12월 초 · 질매 연내 테스트 계획) → 확정 · 쓸 때 한 번 맞춰 둔 것을 꺼낸다 · 강한 곳 계속 바뀌는 사실과 여럿이 함께 · 약한 곳 항목으로 세운 것만 꺼낸다, 저장마다 승인
- 맺는 줄: 프로젝트 지식의 물음은 「지금 값이 무엇이냐」 입니다
