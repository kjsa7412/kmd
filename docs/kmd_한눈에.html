kmd 한눈에

kmd 는 md 로 된 지식을 정리해 두고, 사람과 Claude 가 찾아 쓰게 하는 프로그램이다. 이 문서는 지식 한 조각이 들어와서 → 쌓이고 → 정리되고 → 찾아 쓰이고 → 보내지고 → 지켜지는 순서로 kmd 를 설명한다. 검토 문서 v0.3 ~ v0.6 의 내용을 그림으로 묶었다(운영자 확인 전인 v0.6 권장안 포함).

0전체 지도 — 같은 프로그램이 두 자리에

kmd 는 하나의 프로그램이다. 팀 서버에 깔면 여럿이 같이 쓰고(SaaS), 내 PC에 깔면 나만 쓴다(로컬 프로그램). 할 수 있는 일은 같다. 지식은 늘 어느 한 kmd 안에 살고, git 은 저절로 하는 백업이다.

내 PC나만 쓴다

망이 끊겨도 된다. 들어가기 화면이 없다. 다른 기기에서는 안 열린다.

팀 서버같이 쓴다

어디서든 열린다. 아이디 · 비밀번호로 들어간다. 관리자가 볼 수 있다는 점은 정직하게 알린다.

kmd할 일은 같다

보기 · 찾기 · 고치기 · 저장이 곧 반영 · 세션 저장 · 보내기 · 저절로 채우는 표 · 받은 것 정리.

1데이터의 일생 — 여섯 걸음

kmd 에서 지식 한 조각은 늘 같은 길을 간다. 아래 여섯 걸음이 이 문서의 차례다. 사람이 손댈 수 있는 곳은 굵은 테두리 뿐이고(정리는 누르지 않아도 저절로 돈다), 나머지는 kmd 가 한다.

2들어온다 — 네 개의 입구

지식이 kmd 로 들어오는 길은 넷이다. 어느 길로 오든 결국 기록 하나가 된다. 사람은 고르지 않는다 — 어디에 둘지는 지식 이름이 정한다.

입구어디서 하나목업 화면
Claude Code 세션세션이 한다(화면 없음)M7 세션 저장
편집기 · 화면에서 고침브라우저의 문서 화면 · 바깥 편집기M6 읽기 · 고치기
파일 넣기브라우저 — 자료 가져오기 화면에 끌어다 놓기M14 자료 가져오기

세션 말고 브라우저에서 하는 들이기는 중요도가 높아 따로 한 화면(자료 가져오기)으로 모았다 — 운영자 지시. 지식 자체를 목록에 더하는 일(새로 만들기 · 내 폴더를 지식으로 · 팀 지식 들어가기)은 지식 추가(M3)로 갈랐다.

3쌓인다 — 기록과 문서는 다르다

kmd 지식에는 두 층이 있다. 기록은 "그날 있었던 일"이고 한 번 쓰면 고치지 않는다. 문서는 "지금 상태"이고 정리할 때만 바뀐다. 기록은 자기가 건드린 문서의 항목을 적어 둔다. 그래서 kmd 는 어느 기록까지 문서에 넣었는지를 항목마다 안다.

4정리된다 — 밤에 미리 쓰고, 넣는 것은 정해진 사람이

"정리"는 기록을 문서의 항목에 녹이는 일이다. 개인 지식에서도 팀 지식에서도 같은 일이고, 승인 없이 바로 한다. 정해진 시간(기본 밤 02:30)에 저절로 돌거나, 바로 넣고 싶으면 누구든 [지금 정리] 를 한 번 누른다.

왜 승인이 없나(운영자 결정) — 대상이 많아 관리자가 모두 검토할 수 없고, 자기 업무가 아닌 사람이 보면 오히려 틀린 결정을 할 수 있다. 그래서 사람이 하는 일은 승인이 아니라 알림을 보고 필요하면 되돌리는 것이고, 알림은 그 기록을 쓴 사람(그 일을 아는 사람)에게 간다.

정리하는 길은 셋 — 기본은 ③, 사람이 직접 해도 된다

LLM 이 필요한 것 · 필요 없는 것

LLM 은 늘 kmd 바깥에서 돈다 — 사람의 Claude Code 세션이거나, 밤의 정리 일꾼(도구 · 열쇠 없이 초안만 내는 Claude). kmd 서버 자신은 LLM 을 부르지 않고, 받은 초안을 검사한 뒤 넣기만 한다.

kmd 가 바로 하는 길(③)의 모양

무엇이 바뀌는지에 따라 세 등급으로 나누지만, 셋 다 승인 없이 넣는다. 다른 것은 넣은 뒤 누구에게 무엇을 알리느냐다. 내 지식과 팀 지식이 같다.

글을 쓰는 Claude 는 도구도 열쇠도 없이 글만 낸다. 문서에 넣는 것은 kmd 가 검사(값 · 이름 대조 · 크기 · 표지)를 한 뒤에 한다. 팀 지식의 정리는 팀 서버에 정리 전용으로 로그인해 둔 Claude Code 가 한다(운영자 결정). 정해진 시간에도, 누가 [지금 정리] 를 눌러도 팀 서버에서 돈다. 그 로그인이 끝나면 「자동 정리가 쉬고 있다 — 관리자에게 알렸다」 한 줄이 뜬다.

5찾아 쓴다 — 이름이 안 맞으면 비슷한 글에서

Claude 가 "상태 점검은 어떻게 해?" 라고 물으면 kmd 는 사다리를 내려가며 찾는다. 이름이 딱 맞으면 그 항목을 준다. 안 맞으면 점점 넓게 찾되, 무엇을 어떻게 찾았는지를 늘 함께 말한다.

왜 이 순서인가

정리된 문서는 "지금" 이 맞다(낡은 답이 0). 비슷한 글은 넓게 찾지만 낡은 것이 섞인다. 그래서 정리된 쪽을 먼저, 넓은 쪽을 나중에, 표지를 달아서.

바로잡은 글은 같이

조각이 옛 기록이면 그 기록을 바로잡은 새 기록을 위에 함께 싣는다("10-20 에 바로잡혔다").

남의 지식은 섞이지 않는다

찾기는 볼 수 있는 지식 안에서만. 내 PC 지식의 말은 팀 서버에 남지 않는다.

6보낸다 — 내 PC 에서 팀으로, 한 방향

먼저 — 팀 지식의 기록은 보내기로만 오지 않는다

내 지식에서 팀이 알아야 할 것은 보낸다. kmd 가 바뀐 것을 골라 두고, 사람은 [N개 보내기] 한 번. 팀 서버에 닿지 않으면 닿을 때 저절로 간다. 팀 쪽에서는 기록으로 들어가 다음 정리(02:30 또는 누군가의 [지금 정리])에 바로 문서에 들어간다.

7지킨다 — git 은 저절로 하는 백업

저장할 때마다 kmd 가 백업 자리에 민다. 잘 될 때는 아무 줄도 없다. 밀지 못하거나 백업이 지워지거나 되감기면 조용히 넘어가지 않고 한 줄을 띄운다.

멈춤 한 줄은 늘 같은 틀이다 — 무엇이 · 얼마나 — 풀리는 길 / 누구에게 알렸나.

백업이 멈췄다 · 3시간 — E: 드라이브를 꽂으면 이어서 보낸다
gdi DB 표를 2일째 못 가져왔다 — 표는 10-20 것 · 관리자에게 알렸다
자동 정리가 쉬고 있다 · 2일 — Claude Code 에서 다시 로그인하면 이어서 한다

8자동으로 가져오는 곳 — 표는 원천에서 저절로

테이블 컬럼 · 꾸러미 판 · 파일 목록 같은 표는 사람이 옮겨 적으면 낡는다. 코드 폴더 · git 주소 · DB 를 자료 가져오기 화면에 한 번 더하면 kmd 가 때마다 다시 읽어 문서 안의 정해진 표만 고친다. 언제 읽을지는 정해진 시간(1시간마다 · 매일 06:00 · 매주 · 바뀔 때만)과 [지금 가져오기] 둘 다 된다 — 둘은 같은 길을 타서, 누른 실행도 바뀐 것만 쓰고 크게 바뀌면 멈춘다. 이 모든 것은 자료 가져오기 화면(M14) 한 곳에서 본다.

9들어가기 — 사람은 비밀번호, 기계는 열쇠(사람이 보지 않는다)

계정은 팀 서버에만 있다. 내 PC 프로그램은 들어가기가 없다. 사람은 아이디 · 비밀번호(브라우저가 채운다), Claude Code 가 팀에 붙을 때 쓰는 열쇠는 설치 한 줄이 받아 둔다.

10하루 — 세 사람과 kmd

2026-10-22 하루를 따라가면 위의 흐름이 한 번에 보인다. 사람이 누른 것은 김 「2개 보내기」 · 이 「링크 만들기」 뿐이다. 정리하는 사람 박은 누를 것이 없다 — 02:31 에 kmd 가 정리를 마쳤다.
