# kmd 권한 모델 v1.1 — 총괄 관리자 › 지식관리자 › 쓰기 › 읽기

팀 서버(팀 프로그램)의 권한은 「사람(또는 묶음)이 지식 하나에 갖는 자리」 로 정한다. 지식 하나는 폴더 하나 · git 레포 하나다. 개인 프로그램(개인 지식)은 그 PC 사람 하나만 쓰므로 이 모델의 대상이 아니다. 팀 화면에는 개인 지식이 아예 나오지 않는다([분리 검토](kmd_팀_개인_분리_검토.html)).

권한은 넷이다: **총괄 관리자 › 지식관리자 › 쓰기 › 읽기**. 바깥 자리는 안쪽 자리가 하는 일을 모두 한다. 총괄 관리자는 사람에 붙는 자격이고, 나머지 셋은 팀 지식마다 받는 자리다. **받지 않은 지식은 「없음」(보이지 않음)이 기본이다.**

## 1. 지식마다의 자리

| 자리 | 화면 이름 | 할 수 있는 것 |
|---|---|---|
| `none` | 없음 | 그 지식이 어디에도 보이지 않는다: 목록 · 찾기 · 이력 · 지금 하는 일 · 알림 · MCP · 설치 한 줄 |
| `read` | 읽기 | 문서 · 항목 · 기록 · 이력 · 그래프 보기, 찾기, MCP brief · match · search · section |
| `write` | 쓰기 | 읽기 + 기록 남기기(세션 save · 화면 「고치기」 는 기록으로), 파일 넣기, 지식 보내기로 받기, 가져오기 부탁, 자기 기록 되돌리기 · 정리 부탁 · 이름 고치기, 찾기 학습 |
| `admin` | 지식관리자 | 쓰기 + 문서에 바로 고치기, 이름 세우기(`names`) · 갈래 세우기(`forms`), 정리(남의 기록까지) · 정리 결정, 되돌리기, 가져오는 곳 더하기 · 고치기 · 돌리기, 원본 표지 걷기, 지식 설정(정리 때 · Claude 보내기) · 이 지식의 권한 주기, 지식 점검(이름 없는 기록 · 장부 밖 이름 · 이름 없는 항목 …) |

- 내부 값(`none` · `read` · `write` · `admin`)은 그대로다. 바뀐 것은 화면 · 오류 글 · 설명서의 이름뿐(옛 이름 「관리」 → 「지식관리자」).
- 주인(owner)은 늘 그 지식의 지식관리자다. 예전 「정리하는 사람」(curators)도 지식관리자로 들어가 있다(권한 표를 처음 저장할 때 사람 줄의 지식관리자로 옮기고 비운다).
- 지금 가져오기(가져오는 곳 돌리기)는 지식관리자다. 쓰기 자리는 「가져오기 부탁」 만.
- 쓰기 자리의 `names` · `forms` 는 장부를 바꾸지 않고 기록에 「세울 이름」 · 「세울 갈래」 로 실린다. 그 기록의 touches 에 세울 이름을 달 수 있다(「장부 밖 이름」 으로 보이다가 지식관리자가 세우면 풀린다 · 문서 작성기준 9절).
- 지식관리자(총괄 관리자가 아닌)가 더하거나 고치는 가져오는 곳은 `serve.json` 의 `sourceHosts`(허락된 호스트 목록) 안의 https git · DB 만이다. ssh · `git@` · 서버 폴더 · 목록 밖 호스트는 총괄 관리자만 다룬다(서버 자원 보호). `sourceHosts` 가 비어 있으면 지식관리자는 가져오는 곳을 더하지 못한다.

**총괄 관리자**(`auth.json` 의 `admin` · 예전 이름 「전역 관리자」)는 모든 지식이 보이고 모든 지식에서 `admin` 이다. 그 밖에 총괄 관리자만 하는 일:

- 사람 만들기(지식마다 자리 고르기 · 아래 6절) · 묶음 · 떠남 · 새 링크 · 총괄 관리자로 올리기/내리기
- 지식 세우기 · 지우기 · 되살리기 · 주인 넘기기
- 백업 · Claude 연결(정리 전용 로그인) · 일 줄 멈춤 · 동시에 도는 수 · 팀 서버 지식 폴더 다시 읽기([동기화])
- 서버 자원 가져올 곳(서버 폴더 · ssh · 허락 목록 밖 호스트)

**누구나**(들어온 사람이면 자리와 상관없이): 받은 지식 보기, 「개인 프로그램 설치」(설치 · 잇기 한 줄 · 작업 폴더에 받은 팀 지식 붙이기 · 내 기기 목록).

## 2. 정하는 법(실제 자리 = 아래 가운데 가장 높은 것)

1. 총괄 관리자 → `admin`
2. 그 지식의 주인(owner) → `admin`
3. `access.users[<아이디>]`
4. 그 사람이 든 묶음마다 `access.groups[<묶음>]`
5. `access.all`(그 밖의 모든 사람의 기본 · **기본값 `none`**)

판정 로직은 하나(`hub.levelOf`)이고 바뀌지 않는다. 바뀐 것은 `access` 가 없을 때의 기본(`write` → `none`)뿐이다(4절).

떠난 사람(`off`) · 기계 · 일꾼 열쇠는 이 표를 쓰지 않는다(일꾼 · 초안 · 에이전트 열쇠는 지금처럼 지식 하나에 묶인다).

## 3. 저장

`<data>/owners.json`(주인 장부)에 함께 둔다. 잠금 · 원자 쓰기 · 셸과 같이 고치기가 이미 있다.

```json
{
  "groups": { "개발": { "members": ["kim", "lee"] }, "운영": { "members": ["park"] } },
  "knowledge": {
    "dpms": { "owner": "kim", "curators": [], "access": { "all": "read", "users": { "choi": "write" }, "groups": { "개발": "write", "운영": "admin" } } }
  }
}
```

- 지식 안 `_members.md` 에도 같은 것을 적어 백업 · 되살림을 따라가게 한다:
  `- 모두: 읽기` · `- 쓰기: choi` · `- 지식관리자: ` · `- 묶음: 개발=쓰기, 운영=지식관리자`. 묶음의 사람 목록은 서버(owners.json)에만 둔다.
  옛 줄 이름 `- 관리:` · `=관리` 도 읽는다(같은 뜻). 쓸 때는 새 이름으로.
- 옛 지식 옮기기(4절)를 마친 장부는 맨 위에 `"accessV": 2` 를 단다. 이 표시가 있으면 다시 돌지 않는다.

## 4. 기본 자리 없음 · 옛 지식 한 번 옮기기

`access` 가 없는 지식(옛 줄 · 줄 없음)의 기본은 **`all = none`** 이다. 새로 세운 지식도 `all = none` 으로 선다(주인 · 총괄 관리자만 보이고, 지식관리자가 권한 창에서 사람 · 묶음에 자리를 준다).

예전에는 기본이 「모두: 쓰기」 였다. 옮기는 날 겉으로 바뀌는 것이 없게, 서버가 켤 때 **한 번만** 아래를 한다.

1. 장부에 `accessV: 2` 가 있으면 하지 않는다.
2. 그때 있는 사람(떠난 사람 · 기계 · 일꾼 열쇠 제외) 모두에게, 팀 지식마다(장부에 줄이 없는 지식도) 옛 규칙의 기본 자리(`owners.accessOf`)를 사람 줄로 적는다: `access` 가 없으면 `write`(단 `restored` · 주인 없음이면 `none` — 적지 않는다), 있으면 옛 `access.all`(`read` · `write` · `admin`). 그 사람의 사람 줄이 이미 그 이상이면 고치지 않는다 — 낮추지 않는다. 주인 · 묶음으로 받은 자리는 그대로 두고 사람 줄만 더한다.
   예전 정리하는 사람(`curators`)은 같은 때 그 지식의 사람 줄 `admin` 으로 옮기고 `curators` 를 비운다(지식관리자 자리를 잃지 않게 · `setAccess` 로 `users` 를 보낼 때 `curators` 가 비워지므로 먼저 합친다).
3. 그 지식의 `access.all` 을 `none` 으로 한다.
4. 바뀐 지식마다 `_members.md` 를 새 꼴로 다시 쓰고 git 한 묶음(「권한 옮김: 기본 없음」).
5. 장부에 `accessV: 2` 를 달아 원자 쓰기(임시 파일 뒤 이름 바꾸기). 장부가 깨져 있으면 옮기지 않고 멈춘다(빈 장부로 덮지 않는다).

| 옛 상태 | 옮긴 뒤 |
|---|---|
| 줄이 없거나 `access` 가 없는 지식 | 그때 있는 사람마다 `쓰기` + `all = none` |
| `access.all = read` · `write` · `admin` | 그때 있는 사람마다 그 자리(높은 자리는 그대로) + `all = none` |
| `access.all = none` | 그대로 |
| 총괄 관리자 | 모든 지식 `admin`(그대로) |
| 주인 | 그 지식 `admin`(그대로) |
| 예전 정리하는 사람(`curators`) | 사람 줄 `admin` 으로 옮김 · `curators` 비움(자리는 그대로 지식관리자) |
| `restored` · 주인 없음 | 사람 줄을 적지 않음 · `all = none`(총괄 관리자만 · 그대로) |

옮긴 뒤로는 총괄 관리자 · 지식관리자가 사람 카드 · 권한 창에서 자리를 줄여 나간다. 옮긴 뒤 새로 더한 사람은 자리를 받은 지식만 본다.

## 5. 검사하는 곳(서버)

- **한 곳에서 판정**: `hub.levelOf(ctx, kn)` → `none|read|write|admin`. `hub.visible(ctx)`(목록)과 `hub.meta(id, ctx)`(지식 하나)가 `read` 미만을 「없는 지식」 으로 돌린다(있는지조차 드러내지 않게 `E_NOTFOUND`).
- 쓰기 · 관리 길은 `hub.need(ctx, kn, 'write'|'admin')` 를 먼저 부른다. 모자라면 `E_FORBIDDEN`(403) 「이 지식에 쓰기 자리가 없다」 · 「이 지식의 지식관리자가 아니다」.
- 지식이 실린 모든 응답을 거른다: 목록 · 찾기 · 지금 하는 일(`/api/busy`) · 일 줄(`/api/queue`) · 정리 일감(`/api/job/:id`) · 오늘 · 이력 · 알림(feed) · 멈춤 줄 · 설정 · 관리 개요 · MCP brief(알림 포함) · 지식 보내기의 「받을 곳」 목록(`write` 이상만) · 개인 프로그램 설치의 「붙일 팀 지식」 목록(`read` 이상만).
- 기본 없음은 모든 길에서 같다: 자리를 받지 않은 사람에게 그 지식은 목록 · 찾기 · MCP 어디에도 없고, 지식 id 로 불러도 404 다.
- MCP 는 같은 판정을 쓴다. `brief` 의 `you.role` 은 자리의 화면 이름(읽기 · 쓰기 · 지식관리자 · 개인 프로그램은 주인)이다.

## 6. 화면

자리 이름: 없음 · 읽기 · 쓰기 · 지식관리자, 사람 자격: 총괄 관리자. 「관리(자리)」 · 「전역 관리자」 · 「정리하는 사람」 · 「일반」 은 쓰지 않는다.

- **팀 화면 › 설정 › 사람**(총괄 관리자): 사람 카드 · 묶음 카드(묶음 더하기 · 사람 넣기 · 빼기). 사람 줄에 「지식 n개에 자리 · 지식관리자 m」.
- **사람 더하기 창**(총괄 관리자): 아이디 · 총괄 관리자 여부 + **지식마다 자리 표**(팀 지식마다 없음 · 읽기 · 쓰기 · 지식관리자 · 처음은 모두 없음). 더하면 처음 들어오기 링크(24시간 · 한 번)가 나온다 · 비밀번호는 그 사람이 정한다.
- **사람 카드**(총괄 관리자): 같은 지식마다 자리 표로 뒤에도 바꾼다. 묶음으로 받은 자리는 「묶음 개발: 쓰기」 처럼 따로 보인다(사람 줄과 묶음 가운데 높은 것이 실제 자리).
- **지식 카드 ⋯ › 권한**(지식관리자 이상): 「모두」 기본 자리 고르기(처음은 없음) + 사람 · 묶음 줄마다 자리 고르기 + 더하기. 주인은 맨 위 고정 · 주인 넘기기는 총괄 관리자만(비밀번호 한 번 더).
- 지식 카드 · 머리 줄에 내 자리 칩: 읽기(회색) · 쓰기(파랑) · 지식관리자(보라).
- 읽기 자리 사람에게는 쓰기 단추(고치기 · 파일 넣기 등)를 감추지 않고 흐리게 + 「쓰기 자리가 없다」 안내를 둔다(왜 안 되는지 알게).
