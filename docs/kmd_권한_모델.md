# kmd 권한 모델 v1.0 — 지식(레포)마다 읽기 · 쓰기 · 관리

팀 서버의 권한은 「사람(또는 묶음)이 지식 하나에 갖는 자리」 로 정한다. 지식 하나는 폴더 하나 · git 레포 하나다. 이 PC 의 kmd(개인 지식)는 그 PC 사람 하나만 쓰므로 이 모델의 대상이 아니다.

## 1. 자리 넷

| 자리 | 화면 이름 | 할 수 있는 것 |
|---|---|---|
| `none` | 없음 | 그 지식이 어디에도 보이지 않는다: 목록 · 찾기 · 이력 · 지금 하는 일 · 알림 · MCP · 설치 한 줄 |
| `read` | 읽기 | 문서 · 항목 · 기록 · 이력 · 그래프 보기, 찾기, MCP brief · match · search · section |
| `write` | 쓰기 | 읽기 + 기록 남기기(세션 save · 화면 「고치기」 는 기록으로), 파일 넣기, 지식 보내기로 받기, 가져오기 부탁, 자기 기록 되돌리기 · 정리 부탁 · 이름 고치기, 찾기 학습 |
| `admin` | 관리 | 쓰기 + 문서에 바로 고치기, 정리(남의 기록까지) · 정리 결정, 되돌리기, 가져오는 곳 더하기 · 고치기 · 돌리기, 받은편지함, 원본 표지 걷기, 지식 설정(정리 때 · Claude 보내기) · 이 지식의 권한 주기 |

- 지금 가져오기(가져오는 곳 돌리기)는 관리 자리다. 쓰기 자리는 「가져오기 부탁」 만.
- 지식 관리자(전역 관리자가 아닌)가 더하거나 고치는 가져오는 곳은 `serve.json` 의 `sourceHosts`(허락된 호스트 목록) 안의 https git · DB 만이다. ssh · `git@` · 서버 폴더 · 목록 밖 호스트는 전역 관리자만 다룬다(서버 자원 보호). `sourceHosts` 가 비어 있으면 지식 관리자는 가져오는 곳을 더하지 못한다.

**전역 관리자**(`auth.json` 의 `admin`)는 모든 지식에서 `admin` 이고, 그 밖에 사람 · 묶음 관리, 지식 세우기 · 지우기 · 되살리기, 백업, Claude 연결, 일 줄 멈춤을 한다.

## 2. 정하는 법(실제 자리 = 아래 가운데 가장 높은 것)

1. 전역 관리자 → `admin`
2. 그 지식의 주인(owner) → `admin`
3. `access.users[<아이디>]`
4. 그 사람이 든 묶음마다 `access.groups[<묶음>]`
5. `access.all`(그 밖의 모든 사람의 기본)

떠난 사람(`off`) · 기계 · 일꾼 열쇠는 이 표를 쓰지 않는다(일꾼 · 초안 · 에이전트 열쇠는 지금처럼 지식 하나에 묶인다).

## 3. 저장

`<data>/owners.json`(주인 장부)에 함께 둔다. 잠금 · 원자 쓰기 · 셸과 같이 고치기가 이미 있다.

```json
{
  "groups": { "개발": { "members": ["kim", "lee"] }, "운영": { "members": ["park"] } },
  "knowledge": {
    "dpms": { "owner": "kim", "curators": [], "access": { "all": "read", "users": { "choi": "write" }, "groups": { "개발": "write", "운영": "admin" } } }
  }
}
```

- 지식 안 `_members.md` 에도 같은 것을 적어 백업 · 되살림을 따라가게 한다:
  `- 모두: 읽기` · `- 쓰기: choi` · `- 관리: ` · `- 묶음: 개발=쓰기, 운영=관리`. 묶음의 사람 목록은 서버(owners.json)에만 둔다.

## 4. 옛 권한에서 옮기기

새 칸(`access`)이 없는 지식은 읽을 때 지금 동작과 똑같이 본다. 파일은 처음 고칠 때 새 꼴로 쓴다.

| 옛 상태 | 새 자리 |
|---|---|
| 줄이 없거나 `access` 가 없는 지식 | `all = write`(들어온 사람 모두 읽고 기록 — 지금과 같다) |
| 전역 관리자 | 모든 지식 `admin`(지금과 같다) |
| 주인 | 그 지식 `admin`(지금은 설정만 고쳤다 — 넓어진다) |
| 정리하는 사람(curators) | 그 지식 `admin`(지금은 효과가 없었다 — 이름대로 정리를 하게 한다) |
| `restored` · 주인 없음 | `all = none`(관리자만 — 지금과 같다) |

## 5. 검사하는 곳(서버)

- **한 곳에서 판정**: `hub.levelOf(ctx, kn)` → `none|read|write|admin`. `hub.visible(ctx)`(목록)과 `hub.meta(id, ctx)`(지식 하나)가 `read` 미만을 「없는 지식」 으로 돌린다(있는지조차 드러내지 않게 `E_NOTFOUND`).
- 쓰기 · 관리 길은 `hub.need(ctx, kn, 'write'|'admin')` 를 먼저 부른다. 모자라면 `E_FORBIDDEN`(403) 「이 지식에 쓰기 자리가 없다」.
- 지식이 실린 모든 응답을 거른다: 목록 · 찾기 · 지금 하는 일(`/api/busy`) · 일 줄(`/api/queue`) · 정리 일감(`/api/job/:id`) · 오늘 · 이력 · 알림(feed) · 멈춤 줄 · 설정 · 관리 개요 · MCP brief(알림 포함) · 지식 보내기의 「받을 곳」 목록(`write` 이상만).
- MCP 는 같은 판정을 쓴다. `brief` 의 `you.role` 은 이 자리 이름이다.

## 6. 화면

- **관리 › 사람**: 묶음 카드(묶음 더하기 · 사람 넣기 · 빼기). 사람 줄에 「지식 n개에 자리」.
- **지식 카드 ⋯ › 권한**(관리 자리 이상): 「모두」 기본 자리 고르기 + 사람 · 묶음 줄마다 자리 고르기 + 더하기. 주인은 맨 위 고정.
- 지식 카드 · 머리 줄에 내 자리 칩: 읽기(회색) · 쓰기(파랑) · 관리(보라).
- 읽기 자리 사람에게는 쓰기 단추(고치기 · 파일 넣기 등)를 감추지 않고 흐리게 + 「쓰기 자리가 없다」 안내를 둔다(왜 안 되는지 알게).
