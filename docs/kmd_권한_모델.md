# kmd 권한 모델 v1.1 — 총괄 관리자 › 지식관리자 › 쓰기 › 읽기

팀 서버(팀 프로그램)의 권한은 「사람(또는 묶음)이 지식 하나에 갖는 자리」 로 정한다. 지식 하나는 폴더 하나 · git 레포 하나다. 개인 프로그램(개인 지식)은 그 PC 사람 하나만 쓰므로 이 모델의 대상이 아니다. 팀 화면에는 개인 지식이 아예 나오지 않는다.

권한은 넷이다: **총괄 관리자 › 지식관리자 › 쓰기 › 읽기**. 바깥 자리는 안쪽 자리가 하는 일을 모두 한다. 총괄 관리자는 사람에 붙는 자격이고, 나머지 셋은 팀 지식마다 받는 자리다. **받지 않은 지식은 「없음」(보이지 않음)이 기본이다.**

## 1. 지식마다의 자리

| 자리 | 화면 이름 | 할 수 있는 것 |
|---|---|---|
| `none` | 없음 | 그 지식이 어디에도 보이지 않는다: 목록 · 찾기 · 이력 · 지금 하는 일 · 알림 · MCP · 설치 한 줄 |
| `read` | 읽기 | 문서 · 항목 · 기록 · 이력 · 그래프 보기, 찾기, MCP brief · match · search · section |
| `write` | 쓰기 | 읽기 + 저장(기록 + 항목 조각 한 번에 · 검사를 넘으면 값 바꿈까지 그 순간 문서에 · 7절), 문서 고치기(화면 편집기 · 바로 문서에 · 이미 있는 항목은 지문 필수), 기록 고치기(자기 기록의 정정 기록), 파일 넣기(팀 화면 한 번에 20 · 파일마다 들이기 일감 · 많으면 Claude Code 대량 넣기 · S11 부터), 지식 보내기로 받기, 가져오기 부탁, 자기 기록 되돌리기(항목마다) · 이름 고치기, 자기 넣지 못함의 [고치기] · [다시 들이기], 정리 부탁(S13 에 걷음), 찾기 학습 |
| `admin` | 지식관리자 | 쓰기 + 화면 고치기의 항목 지우기 · 이름 바꾸기 · 저절로 채우는 표 고치기, 남의 기록 고치기(정정 기록), 이름 세우기(`names`) · 갈래 세우기(`forms`), 문서 짜임(폴더 · 이름 · 새 문서 · 차례 · 7-1절), 남의 넣지 못함 처리([다시 들이기] · [버리기] · [이름 세우기] · [옛 기록 다시 들이기]), 문서 다듬기(`POST /api/k/:id/polish` · 들이기 일감 type polish), 되돌리기(남의 저장까지), 가져오는 곳 더하기 · 고치기 · 돌리기, 원본 표지 걷기, 지식 설정(Claude 에 보내지 않음 · 설정 › 팀 지식) · 이 지식의 권한 주기, 지식 점검(이름 없는 기록 · 장부 밖 이름 · 이름 없는 항목 …) |

- 내부 값(`none` · `read` · `write` · `admin`)은 그대로다. 바뀐 것은 화면 · 오류 글 · 설명서의 이름뿐(옛 이름 「관리」 → 「지식관리자」).
- 주인(owner)은 늘 그 지식의 지식관리자다. 예전 「정리하는 사람」(curators)도 지식관리자로 들어가 있다(권한 표를 처음 저장할 때 사람 줄의 지식관리자로 옮기고 비운다).
- 지금 가져오기(가져오는 곳 돌리기)는 지식관리자다. 쓰기 자리는 「가져오기 부탁」 만.
- (P3 부터) **approve 모드 지식**(새 팀 지식은 처음부터 · 저장 승인 설계 P-D8 · P-D9 · 4절)에서는 쓰기 자리가 승인한 저장 제안 안에서 새 문서(갈래 장부 안 · G4 꼴 · `E_FORMAT`) · 새 이름 · 새 갈래 · 새 종류를 같은 저장으로 세운다(비슷한 이름은 제안 오류 · `distinct` 로 넘음 · 새로 선 것은 기록 끝 `## 새로 세움` · 14일 뒤 저절로 떨어지는 fresh 표지 · 지식관리자는 원하면 사후에 조정). 아래 「세울 이름」 줄은 held 모드 지식에만 걸린다.
- 쓰기 자리의 `names` · `forms` 는 장부를 바꾸지 않고 기록에 「세울 이름」 · 「세울 갈래」 로 실린다. 그 기록의 touches 에 세울 이름을 달 수 있다(「장부 밖 이름」 으로 보이다가 지식관리자가 세우면 풀린다 · 문서 작성기준 9절).
- 지식관리자(총괄 관리자가 아닌)가 더하거나 고치는 가져오는 곳은 `serve.json` 의 `sourceHosts`(허락된 호스트 목록) 안의 https git · DB 만이다. ssh · `git@` · 서버 폴더 · 목록 밖 호스트는 총괄 관리자만 다룬다(서버 자원 보호). `sourceHosts` 가 비어 있으면 지식관리자는 가져오는 곳을 더하지 못한다.

**총괄 관리자**(`auth.json` 의 `admin` · 예전 이름 「전역 관리자」)는 모든 지식이 보이고 모든 지식에서 `admin` 이다. 그 밖에 총괄 관리자만 하는 일:

- 사람 만들기(지식마다 자리 고르기 · 아래 6절) · 묶음 · 떠남 · 새 링크 · 총괄 관리자로 올리기/내리기
- 지식 세우기 · 지우기 · 되살리기 · 주인 넘기기
- (P3 부터) 지식의 저장 방식 바꾸기(`POST /api/k/:id/save-mode { save: 'approve' | 'held' }` · 비밀번호 한 번 더 · 감사 기록 · `hub.setSaveMode`). approve 로 켜려면 그 지식의 넣지 못함 · 메모 · 개편 전 기록이 0 이어야 한다(이행 먼저 · 아니면 `E_CONFLICT`). 새 팀 지식은 처음부터 approve(`_members.md` `- 저장 방식: 승인` · 기록 모음 문서를 같이 세운다)
- 저장소 붙이기 · 바꾸기 · 떼기 · GitLab 새로 · GitLab 그룹 목록(저장소 보기는 지식관리자부터 · 주소 가림 · 7-0) · Claude 연결(팀 일꾼 로그인) · 일 줄 멈춤 · 동시에 도는 수 · 팀 서버 지식 폴더 다시 읽기([동기화])
- 서버 자원 가져올 곳(서버 폴더 · ssh · 허락 목록 밖 호스트)

**누구나**(들어온 사람이면 자리와 상관없이): 받은 지식 보기, 설정 › 나(내 자리 · 내 설정 · 내 기기 · 나가기) · 설정 › 에이전트 설치(둘째 카드 「개인 지식 쓰기」: 개인 프로그램 설치 · 잇기 한 줄 · 작업 폴더에 받은 팀 지식 붙이기) · 대량 넣기 파서 받기(`GET /api/agent/parser` · 들어온 사람 · 넣기는 저장 문이 쓰기 자리를 본다).

## 2. 정하는 법(실제 자리 = 아래 가운데 가장 높은 것)

1. 총괄 관리자 → `admin`
2. 그 지식의 주인(owner) → `admin`
3. `access.users[<아이디>]`
4. 그 사람이 든 묶음마다 `access.groups[<묶음>]`
5. `access.all`(그 밖의 모든 사람의 기본 · **기본값 `none`**)

판정 로직은 하나(`hub.levelOf`)이고 바뀌지 않는다. 바뀐 것은 `access` 가 없을 때의 기본(`write` → `none`)뿐이다(4절).

떠난 사람(`off`) · 기계 · 일꾼 열쇠는 이 표를 쓰지 않는다(일꾼 · 초안 · 에이전트 열쇠는 지금처럼 지식 하나에 묶인다).

## 3. 저장

`<data>/owners.json`(주인 장부)에 함께 둔다. 잠금 · 원자 쓰기 · 셸과 같이 고치기가 이미 있다.

```json
{
  "groups": { "개발": { "members": ["kim", "lee"] }, "운영": { "members": ["park"] } },
  "knowledge": {
    "dpms": { "owner": "kim", "curators": [], "access": { "all": "read", "users": { "choi": "write" }, "groups": { "개발": "write", "운영": "admin" } } }
  }
}
```

- 지식 안 `_members.md` 에도 같은 것을 적어 백업 · 되살림을 따라가게 한다:
  `- 모두: 읽기` · `- 쓰기: choi` · `- 지식관리자: ` · `- 묶음: 개발=쓰기, 운영=지식관리자`. 묶음의 사람 목록은 서버(owners.json)에만 둔다.
  옛 줄 이름 `- 관리:` · `=관리` 도 읽는다(같은 뜻). 쓸 때는 새 이름으로.
  지식 설정 `- 이슈 주소: https://…/{값}`(있을 때만 · 지식관리자가 지식 카드 ⋯ 에서 · `/api/k/:id/owner` 의 `issueUrl`)도 같은 파일에 둔다.
- 옛 지식 옮기기(4절)를 마친 장부는 맨 위에 `"accessV": 2` 를 단다. 이 표시가 있으면 다시 돌지 않는다.

## 4. 기본 자리 없음 · 옛 지식 한 번 옮기기

`access` 가 없는 지식(옛 줄 · 줄 없음)의 기본은 **`all = none`** 이다. 새로 세운 지식도 `all = none` 으로 선다(주인 · 총괄 관리자만 보이고, 지식관리자가 권한 창에서 사람 · 묶음에 자리를 준다).

예전에는 기본이 「모두: 쓰기」 였다. 옮기는 날 겉으로 바뀌는 것이 없게, 서버가 켤 때 **한 번만** 아래를 한다.

1. 장부에 `accessV: 2` 가 있으면 하지 않는다.
2. 그때 있는 사람(떠난 사람 · 기계 · 일꾼 열쇠 제외) 모두에게, 팀 지식마다(장부에 줄이 없는 지식도) 옛 규칙의 기본 자리(`owners.accessOf`)를 사람 줄로 적는다: `access` 가 없으면 `write`(단 `restored` · 주인 없음이면 `none` — 적지 않는다), 있으면 옛 `access.all`(`read` · `write` · `admin`). 그 사람의 사람 줄이 이미 그 이상이면 고치지 않는다 — 낮추지 않는다. 주인 · 묶음으로 받은 자리는 그대로 두고 사람 줄만 더한다.
   예전 정리하는 사람(`curators`)은 같은 때 그 지식의 사람 줄 `admin` 으로 옮기고 `curators` 를 비운다(지식관리자 자리를 잃지 않게 · `setAccess` 로 `users` 를 보낼 때 `curators` 가 비워지므로 먼저 합친다).
3. 그 지식의 `access.all` 을 `none` 으로 한다.
4. 바뀐 지식마다 `_members.md` 를 새 꼴로 다시 쓰고 git 한 묶음(「권한 옮김: 기본 없음」).
5. 장부에 `accessV: 2` 를 달아 원자 쓰기(임시 파일 뒤 이름 바꾸기). 장부가 깨져 있으면 옮기지 않고 멈춘다(빈 장부로 덮지 않는다).

| 옛 상태 | 옮긴 뒤 |
|---|---|
| 줄이 없거나 `access` 가 없는 지식 | 그때 있는 사람마다 `쓰기` + `all = none` |
| `access.all = read` · `write` · `admin` | 그때 있는 사람마다 그 자리(높은 자리는 그대로) + `all = none` |
| `access.all = none` | 그대로 |
| 총괄 관리자 | 모든 지식 `admin`(그대로) |
| 주인 | 그 지식 `admin`(그대로) |
| 예전 정리하는 사람(`curators`) | 사람 줄 `admin` 으로 옮김 · `curators` 비움(자리는 그대로 지식관리자) |
| `restored` · 주인 없음 | 사람 줄을 적지 않음 · `all = none`(총괄 관리자만 · 그대로) |

옮긴 뒤로는 총괄 관리자 · 지식관리자가 사람 카드 · 권한 창에서 자리를 줄여 나간다. 옮긴 뒤 새로 더한 사람은 자리를 받은 지식만 본다.

## 5. 검사하는 곳(서버)

- **한 곳에서 판정**: `hub.levelOf(ctx, kn)` → `none|read|write|admin`. `hub.visible(ctx)`(목록)과 `hub.meta(id, ctx)`(지식 하나)가 `read` 미만을 「없는 지식」 으로 돌린다(있는지조차 드러내지 않게 `E_NOTFOUND`).
- 쓰기 · 관리 길은 `hub.need(ctx, kn, 'write'|'admin')` 를 먼저 부른다. 모자라면 `E_FORBIDDEN`(403) 「이 지식에 쓰기 자리가 없다」 · 「이 지식의 지식관리자가 아니다」.
- 지식이 실린 모든 응답을 거른다: 목록 · 찾기 · 지금 하는 일(`/api/busy`) · 일 줄(`/api/queue` · 들이기 일감 줄 `t:<일감>`) · 들이기 일감(`/api/job/:id` · 비용은 그 지식의 지식관리자 이상만) · 넣지 못함 목록(`/api/k/:id/held` · 7절) · 지식 목록 줄의 넣지 못함 수(`held` · `heldMine`) · 문서 항목의 넣지 못함(`held` · `heldN`: 지식관리자 · 쓴 사람 것만) · 오늘 · 이력 · 알림(feed) · 멈춤 줄 · 설정 · 관리 개요 · MCP brief(알림 포함) · 지식 보내기의 「받을 곳」 목록(`write` 이상만) · 개인 프로그램 설치의 「붙일 팀 지식」 목록(`read` 이상만).
- 기본 없음은 모든 길에서 같다: 자리를 받지 않은 사람에게 그 지식은 목록 · 찾기 · MCP 어디에도 없고, 지식 id 로 불러도 404 다.
- MCP 는 같은 판정을 쓴다. `brief` 의 `you.role` 은 자리의 화면 이름(읽기 · 쓰기 · 지식관리자 · 개인 프로그램은 주인)이다. 세션의 `save` 는 기록 + 조각(`sections[{ coord | doc+heading, base, edits | content }]`)을 한 덩이로 보내고, 쓰기 자리 이상이면 검사를 넘은 조각을 그 순간 넣는다(7절). `you.direct` 는 판정 `hub.canSave`(개인 프로그램 · 그 지식의 에이전트 · 쓰기 이상)를 따른다. 지식관리자의 장부 고침(`names` · `forms` 만 보낸 저장)은 곧바로 들어간다(`you.ledgers` = `hub.canDirect` · 뜻은 바뀌지 않는다).

## 6. 화면

자리 이름: 없음 · 읽기 · 쓰기 · 지식관리자, 사람 자격: 총괄 관리자. 「관리(자리)」 · 「전역 관리자」 · 「정리하는 사람」 · 「일반」 은 쓰지 않는다.

- **설정 메뉴 보이기**: 화면은 서버 판정과 같은 자리로만 메뉴를 보인다(`setMenu` 하나) · 팀 일꾼 · 운영은 총괄 관리자 · 서버 정보 · 에이전트 설치 · 개인 프로그램 설치는 누구나 · 숨기는 것으로 끝내지 않는다(서버가 403). (메뉴 개편 N6 · 2026-11-10)
- **지식관리 › 모든 지식**(누구나 · 자기 자리 지식만 · 메뉴 개편 6-4): 표의 저장소 · Claude 칸은 지식관리자인 지식이 하나라도 있을 때만 · 저장소 값은 총괄 관리자 실제 값(`/api/admin/overview`) · 지식관리자 붙음/없음(`/api/knowledge` 의 `repo` · 그 지식의 지식관리자에게만 싣는다 · 주소 없음). [+ 새 지식] · [불러오기] 는 총괄 관리자. 지식 상세 탭: 지식관리자 정보 · 권한 · 저장소(보기만) · 정책 / 총괄 관리자 + 삭제 · 저장소 바꾸기 / 쓰기 · 읽기 정보만. 순서 · 메뉴에서 빼기는 사람마다(`/api/knowledge/menu`).
- **지식관리 › 사람 · 묶음**(팀): 총괄 관리자만 바꾼다(사람 카드 · 묶음 카드 · 사람 줄에 「지식 n개에 자리 · 지식관리자 m」) · 그 밖은 보기만 판(`/api/people` 이름 목록 · 자리 (!)).
- **사람 더하기 창**(총괄 관리자): 아이디 · 총괄 관리자 여부 + **지식마다 자리 표**(팀 지식마다 없음 · 읽기 · 쓰기 · 지식관리자 · 처음은 모두 없음). 더하면 처음 들어오기 링크(24시간 · 한 번)가 나온다 · 비밀번호는 그 사람이 정한다.
- **사람 카드**(총괄 관리자): 같은 지식마다 자리 표로 뒤에도 바꾼다. 묶음으로 받은 자리는 「묶음 개발: 쓰기」 처럼 따로 보인다(사람 줄과 묶음 가운데 높은 것이 실제 자리).
- **지식 카드 ⋯ › 권한**(지식관리자 이상): 「모두」 기본 자리 고르기(처음은 없음) + 사람 · 묶음 줄마다 자리 고르기 + 더하기. 주인은 맨 위 고정 · 주인 넘기기는 총괄 관리자만(비밀번호 한 번 더).
- 지식 카드 · 머리 줄에 내 자리 칩: 읽기(회색) · 쓰기(파랑) · 지식관리자(보라).
- 읽기 자리 사람에게는 쓰기 단추(고치기 · 파일 넣기 등)를 감추지 않고 흐리게 + 「쓰기 자리가 없다」 안내를 둔다(왜 안 되는지 알게).


## 7. 저장(기록 + 조각 한 번에) · 모든 채널의 기본 · 2026-11-03 넓힘

모든 채널(세션 · 고치기 · 파일 넣기 · 가져올 곳 · 보내기)은 **기록과 항목 조각(찾을 글 → 바꿀 글) + 항목 지문(base)을 한 번의 저장**으로 보낸다. 들어갈지는 채널과 상관없이 서버의 저장 검사 한 곳(`hub.save` → `core/save.js`)이 정한다. 스킬 · Claude 는 글을 짓는 쪽일 뿐이다. 11-02 의 「제안」(세션이 기록과 조각을 같이 보냄)을 모든 채널의 기본으로 넓혔다. 구현 단계와 까닭은 [KMD_개편_설계.md](품질개선/KMD_개편_설계.md)(정한 것 S-D1 ~ S-D55).

줄 끝 「(Sx 부터)」 는 그 단계 커밋부터 코드가 따른다는 표시다. 표시가 붙은 줄은 그 단계 전까지 11-02 판 7절(제안 · git 이력 `d07dcde`)대로 돈다. 「(Sx 에 걷음)」 은 그 단계에서 없어지는 것이다.

### 7-0. 지식 카드 배지 · 운영 값(읽기만) · 2026-11-08

- `/api/knowledge` 의 `chk`(점검 경고 · 가져올 곳 부탁 · 가져오기 문제 수)는 그 지식의 지식관리자(`levelOf = admin`)에게만 싣는다(`hub.knChecks`). 그 밖의 자리는 키가 없다.

- 찾기 0건의 「다른 이름 더하기」 — 찾기 학습(`learn` · 쓰기 자리부터) + 저장 문의 `names`(지식관리자는 바로 장부에 · 쓰기 자리는 넣지 못함 「세울 이름」). 새 길은 없다.
- 떠난 사람의 기기 열쇠 — 떠날 때 열쇠 해시(50개까지)를 남겨 두고, 그 열쇠로 오면 E_AUTH 「팀을 떠났다」(열쇠를 가진 사람에게만 · 비밀번호 들어가기 답은 그대로).

- 「승인 받고 넣기」(지식 설정 · `_members.md` `- 승인 받고 넣기: 예` · `/api/k/:id/owner` 의 `review` · 지식관리자) — (P3 부터 approve 모드 지식에서는 「들어간 것 하루 요약」 알림으로 뜻이 바뀐다 · 7절) held 모드 지식에서 켜면 쓰기 자리의 조각(팀 검사 길 · 화면 고치기)은 문서에 넣지 않고 넣지 못함 `review`(넣으려던 글 · 지문 그대로)로 남긴다. 지식관리자 · 총괄 관리자 · 들이기 일감은 그대로 바로 넣는다. `POST /api/k/:id/held/:rec/approve`(지식관리자 · `heldOf(admin)`)가 같은 글로 저장 문을 지난다(지문이 어긋나면 E_CONFLICT) · fixes 로 원 기록은 바로잡힘.
- 경고 걷기 `POST /api/stops/ack {key}` — 들어온 사람 누구나 자기 것만(`<살림>/acks.json` · 30일 · 원자 쓰기) · 감사 기록에 남는다. 받는 `/api/stops` 줄마다 `key`.

### 7-1. 문서 짜임(폴더 · 이름 · 새 문서 · 차례 · 항목 옮기기 · 항목 이름 · 빈 문서 걷기) · 2026-11-06 · 2026-11-10 넓힘

| 무엇 | 정한 것 |
|---|---|
| 자리 | 지식관리자 · 개인 프로그램. 읽기 `GET /api/k/:id/structure`(읽기 미만 404 · 지식관리자 미만 403) · 바꾸기 `POST /api/k/:id/structure { ops, base, dry }`(`hub.need(ctx, kn, 'admin')`) |

| 항목(Z1) | `ops.items [{ from: { doc, h }, to: { doc, h, before } }]` — 항목 옮기기 · 항목 이름 · 같은 문서 차례. 글은 글자 그대로(applied 표지 · `###` 소제목까지 · 엔진이 떼어 낸 글과 넣은 글을 견준다) · 참고 줄은 `moveSection`(core/sections.js)으로 목표 문서 블록에 · 옮긴 글 속 상대 링크 · 들어오는 `x.md#머리` · `#머리` · 자리 장부는 `placeExact`(정확한 줄은 제자리 · 패턴 줄로 닿던 이름은 패턴 줄 **위에** 정확한 줄). `ops.drops ["문서"]` — 항목 0 · 요약 0 · 들어오는 링크 0 · 자리 장부 줄 0 인 문서만 걷는다(옛 글은 git 이력에). 대장 갈래 새 문서는 자리 장부 패턴 줄을 같이 세운다 |
| 지문 | 화면이 읽은 짜임의 지문(문서 목록 + 차례 장부 · `base`)이 지금과 다르면 `E_CONFLICT`(409) · 아무것도 쓰지 않는다. 걸음 지문 `stepFp`(그 걸음이 건드리는 문서들의 머리 목록 + 옮기는 항목 글 + 장부 셋 + 문서 id 목록)도 `base` 로 받는다 — 건드리지 않는 문서의 글이 바뀐 것으로는 서지 않는다. 걸음 표지 `step`(`shape/<work>/<n>` · 서버 안 함수만)이 이력에 있으면 다시 쓰지 않는다(멱등) |
| 마른 실행 | `dry: true` 는 쓰지 않고 요약(옮김 · 새 문서 · 고칠 링크 · 장부 줄)만 |
| 막는 것 | 이름 꼴(작성기준 6-1절) · 같은 경로(대소문자 무시) · 원본이 주인인 문서 · 갈래의 다른 이름에 걸리는 새 문서(G4). 항목은 더해: 목표 문서에 같은 머리 · 앞부분이 겹치는 머리(「배포」 와 「배포 절차」) · 출처 · 목표가 원본이 주인 · 사건 · 대장 갈래의 머리 꼴 · 저절로 채우는 표가 든 항목 · 옮긴 뒤 항목에 닿지 않는 이름 · **섞인 자리**(팀: 아직 안 들어간 개편 전 기록이 걸린 항목 · `details[].code` `legacy-mix`) · 쓴 뒤 기록 상태(`recordState`)가 하나라도 바뀜(저널 되돌림). 하나라도 걸리면 아무것도 쓰지 않는다(`E_INPUT` · `details` 에 줄마다 까닭) |
| 되돌리기 안전 | 표지를 처음 단 묶음이 짜임 커밋(태그 `structure` 이력이 든 커밋)이면 되돌리기가 그 항목을 지우지 않는다. 이력의 「항목 옮김 · 이름: 옛 문서 › 옛 머리 → 새 문서 › 새 머리」 · 「옮김 · 이름: 옛 문서 → 새 문서」 줄로 앞 자리를 찾아 그 앞 판의 글로 되돌리고, 못 찾으면 `E_CONFLICT`(문서 고치기로 고친다 · `core/revert.js`) |
| 저장 문 밖 | 항목 조각이 아니라 파일 짜임이라 `hub.save` 의 조각 검사를 지나지 않는다(옛 문서 옮기기 `docfmt` 와 같은 자리). 글은 경로 · `# 제목` 줄 · 항목 머리 줄 · 링크 · 참고 줄 · 장부만 바뀐다(항목 글은 글자 그대로 · 글을 다시 쓰는 나누기 · 합치기 · 문서 요약은 저장 문을 지난다 · 7-2). 백업 · 오늘 바뀐 것 줄은 커밋 뒤(던지지 않는다) |

### 7-2. 짜임 다시 잡기 · 바탕 세우기(구조안 · 걸음) · 2026-11-10

근거: [품질개선/KMD_바탕세우기_설계.md](품질개선/KMD_바탕세우기_설계.md) 3-3 · 4절 · 7-4 · 8-1. 구조안은 「새 짜임 전체」 이고 걸음 재료(ops · 걷을 출처 · 장부 줄 · 링크)는 서버가 지금 지식을 새로 읽어 만든다. 사람 · 화면 · PC 가 보낸 걸음 재료는 받지 않는다.

| 길 | 판정 |
|---|---|
| `GET /api/k/:id/shape` | `hub.meta(id, ctx)`(읽기 미만 404) + `hub.need(ctx, kn, 'admin')`(403). 지금 짜임(문서 · 항목 머리 · 줄 수 · 이름 수 · 갈래 · watched) · `shapeFp` · 열린 짜임 일 요약(연 사람 · 단계 · 초안 있음) |
| `POST /api/k/:id/shape/check { plan }` | 같음. 구조안 꼴(문서 500 · 항목 5천 · 이름 2천 · 머리 120자 · `__proto__` 같은 이름 막기) → `planCheck` · `diffPlan` · 짜임 걸음 마른 실행(7-1 엔진) → 걸림 · 경고 · 바뀔 것 · 걸음. 짜임 일을 열고(처음이면) 초안을 장부에 둔다. 단계를 잇는 것은 연 사람만(다른 사람이면 409) |
| 짜임 일 장부 | `<살림>/shape/<지식>.json` — 지식마다 열린 짜임 일 하나(초안 구조안 · 연 사람 · 단계 · 넣은 걸음 · 넣기 직전 짜임). 임시 파일 뒤 이름 바꾸기 · 깨진 파일은 빈 것으로 읽어 덮지 않는다(「잠깐 멈춤: 장부가 깨졌다」 · 409) |
| 구조안 걸림 | 덮임 빠짐(지금 항목이 어디에도 없음 · 지우기는 문서 고치기에서) · 구조안에 없는 지금 문서 · 새 이름의 G4(다른 갈래의 이름 · 다른 이름에 걸림) · 갈래 다른 이름 겹침 · 머리 겹침(같음 · 앞부분) · 갈래 머리 꼴 · 이름 자리 밖(`names` 가 구조안에 없는 항목) · 나누기 · 합치기 출처에 닿던 이름을 다시 놓지 않음 · 한 저장 50 조각 넘는 엮임 · **출처에 아직 안 넣은 기록(pend)이 걸린 나누기 · 합치기**(그 기록이 조용히 「넣음」 이 되지 않게) · 원본이 주인인 문서를 바꿈. 경고: 폴더 깊이 · 폴더당 문서 3~12 · 문서당 항목 5~40 · base 없음 · 지을 때 본 지문과 지금이 다름(`stale`) |
| 감사 줄 | `AUDIT_RE` 에 `k/<지식>/shape/*` · `shape/job/<일>/stop` |
| `POST /api/k/:id/shape/ask { plan?, note? }` · `POST shape/write { sources, targets }` · `GET shape/job/:job` · `POST shape/job/:job/stop`(Z6 부터) | 같은 자리(읽기 미만 404 · 지식관리자 미만 403 · 본문은 자리 판정 뒤). 「Claude 에 보내지 않음」 지식은 `E_FORBIDDEN`. 팀은 팀 일꾼 일감 `shape-plan` · `shape-write`(들이기 일감 줄 · 하루 들이기 수 `intakeDaily` 를 센다 · 사람마다 기다림 20 · 24시간 · 아는 type 을 알린 일꾼에게만 · 재료는 서버가 지금 지식에서 짓고 일꾼 열쇠는 그 일감 · 그 지식만 · 일꾼이 짓는 동안 건 사람이 지식관리자 자리를 잃으면 닫는다), 개인은 이 PC 의 claude -p(메모리 안 일 · 동시에 넷). 이 일은 **지식에 쓰지 않는다**: 구조안은 화면 나무에 덧씌우는 초안(`cleanPlan` · `planCheck` 로 다시 봄)이고, 글은 화면 구조안의 `items[].text` 가 되어 그 뒤 해 보기 · 넣기의 글 걸음을 지난다. 글 초안의 결정적 오류(`judgeShape` errors)만 두 번까지 고쳐 쓰고 그래도면 「걸음 실패」(규칙 길이 아니다 · P-D24), 값 대조는 재기만(P-D15). 일 id 는 그 지식의 것만 읽고 그만둔다(다른 지식의 id 는 404) |
| 글 걸음(나누기 · 합치기 · 엮임 · 문서 요약 · 바탕 새 항목) | 서버 안 함수 `hub.shapeWrite` 만 `hub.save(…, { channel: 'shape', shape })` 로 부른다(HTTP 로 열지 않는다 · 채널 · `opt.shape` 는 서버 코드만). 받는 것은 구조안 · 단위 번호 · 글 지문(`unitFp`) · 목표 글 · 요약 글뿐이고, 걷을 출처(remove) · 조각 · 자리 장부 줄(`placeExact`) · 참고 줄은 저장 줄 안에서 새로 읽은 지식으로 엔진이 만든다. 자리는 `hub.need(ctx, kn, 'admin')` · 속도 한도는 세지 않는다 |
| 값 대조(`checkShape` · core/gate.js) | **팀 · 개인 모두** 돈다(7절 「새 저장 검사는 팀에서만」 의 이 채널만의 예외). 근거는 출처 항목의 지금 글(바탕은 재료 글)뿐 — 기록 본문 · 제목은 근거가 아니다. 지어낸 값(목표 ⊂ 출처 ∪ 이름 · 머리) · 잃은 값(출처 ⊂ 목표 합) · 꼴(draftBad · 갈래 머리 꼴 · 빈 글) · 섞인 자리(팀: 개편 전 기록 · legacy-mix). 걸리면 기록(work/ · 태그 `shape`) + 「넣지 못함」 — 한 걸음은 한 덩이라 조각 하나라도 넣지 못함(값 · 꼴 · 원본이 주인 · 없는 문서)이면 모두 넣지 못함(기록만 · 출처 걷기 · 자리 장부 줄 · 요약도 쓰지 않는다) · 출처 글 지문이 어긋나면 `E_CONFLICT`(아무것도 쓰지 않는다) · 출처에 아직 안 넣은 기록이 걸려 있으면 `E_CONFLICT` |
| 기록 · 태그 | 글 걸음 기록은 **work/**(태그 `shape` + 걸음 표지 `shape/<work>/<n>` · 저장 문이 붙인다) — 기록 상태 · 넣지 못함 목록 · 처리 길이 그대로 걸린다. 마감은 log/(`shape-done`). 셋 다 예약 태그(사람이 보내면 `E_FORBIDDEN`). 건드린 이름은 출처 · 목표 항목에 닿는 이름 모두. 같은 걸음 표지 기록이 들어갔으면 건너뛰고(멱등), 넣지 못함이면 다시 넣되 새 기록에 `fixes`. 걷힌 출처로 들어오던 링크(`x.md#옛머리` · `#옛머리`)는 같은 묶음에서 그 출처를 쓴 첫 목표 항목으로 고친다(원본이 주인인 문서는 그대로 · 남은 끊긴 링크는 끝 진단 「고칠 링크」). 저절로 채우는 표가 든 항목은 걷히는 출처(나누기 · 합치기)가 되지 않는다(`planCheck` 걸림 `machine` · 항목째 옮기기 · 같은 머리 고쳐 쓰기만) |
| 되돌리기 | 태그 `shape` · `shape-done` 기록은 이력에 [되돌리기]를 싣지 않고 서버 `revert` 도 `E_FORBIDDEN`(「짜임으로 다시 쓴 항목은 문서 짜임의 되돌리기 구조안이나 문서 고치기로 되돌린다」) |
| `POST /api/k/:id/shape/try` · `/put` · `/stop` · `/undo` | 같은 자리(읽기 미만 404 · 지식관리자 미만 403). 해 보기 · 넣기 · 되돌리기 구조안은 **짜임 일을 연 사람만**(다른 사람이면 409) · 그만두기는 그 지식의 지식관리자 누구나(총괄 관리자 전용 일이 아니다). 자리는 본문을 읽기 전에 본다 · 몸은 check 의 plan 말고 받지 않는다. 해 보기 · 넣기 · 그만두기 · 되돌리기는 지식마다 한 줄(`shape-run`). 그만두기는 장부부터 바꿔 도는 해 보기 · 넣기가 다음 걸음 앞에서 서게 한다 — 넣기를 시작한 일은 넣기 직전 짜임을 남긴 「그만둠」(`stopped-final` · 되돌리기 구조안을 열 수 있다) · 아니면 장부를 지운다 · 깨진 장부면 그 지식의 연습 판을 모두 걷는다 — 걸음 내용(ops · remove · kind · structure)은 어느 길로도 받지 않는다 |
| 연습 판 · 해 보기 | `<살림>/shape/<지식>.<work>` 에 지식 폴더를 `git clone --local` 한 것(지식 목록 · 백업 자리 밖). hub 함수가 아니라 core 함수(applyRestructure · core save · checkShape)를 바로 부른다 — 「같은 core 검사를 지난다」 가 약속이다. 끝나면 지우고 결과(걸음 · 글 지문 · 끝 진단)는 장부에 둔다 · 꺼지며 남은 연습 판은 켤 때 걷는다 |
| 넣기 | 승인 3(끝 진단의 막는 것 0) 뒤. 걸음은 진짜에서 새로 읽은 지식과 같은 구조안으로 다시 만든다(장부 → 짜임 → 글 → 걷기 → 마감 · 번호 고정 forms 1 · frame 2 · write 10+n · tidy 9998 · seal 9999). 걸음마다 멱등(걸음 표지) · 지문(stepFp · unitFp). 짜임 걸음 뒤 구조안(`afterFrame`)으로 글 걸음을 만든다. 넣기 직전 짜임을 장부에 남긴다(되돌리기 구조안 재료 · 처음 한 번). 넣은 걸음은 장부의 done 과 이력의 걸음 표지 둘로 센다(커밋 뒤 장부 쓰기를 잃어도 다시 하지 않는다). 넣다 선 일(넣지 못함 `stopped` · `rebase`)은 지금 짜임에 맞춘 구조안으로 다시 검사할 수 있다 — 같은 일 · 넣은 걸음 · 넣기 직전 짜임 그대로 · 이미 넣은 갈래 장부 · 짜임 걸음이 다시 나오면 걸림 · 글 걸음 번호는 넣은 글 걸음 뒤로. 다른 사람의 저장은 막지 않는다 |
| 다시 맞추기 | 진짜 지문이 해 보기 때와 다르거나 넣는 중 `E_CONFLICT` 가 나면 연습 판을 지금 지식에서 다시 떠서 남은 걸음을 견준다. 걸음 목록 · 글 지문이 같고 막는 것이 0 이면 다시 묻지 않고 잇는다 · 바뀐 단위가 있으면 다시 승인(`again`) |
| 마감 · 되돌리기 구조안 | 마감 이력(log/ · `shape-done` · 서버가 붙임) · 장부는 「끝남」 으로 남는다. 끝남 · 그만둠 뒤 새 검사가 장부를 새 일로 바꿔도 넣기 직전 짜임은 `undoable` 로 넘어간다(검사가 걸려도 되돌리기를 잃지 않게). 되돌리기 구조안은 넣기 직전 짜임을 새 짜임으로 하는 역 구조안을 새 짜임 일로 연다(글이 그대로 간 항목은 그대로 돌아가고 · 나누기 · 합치기는 넣기 앞 글로 하는 글 걸음 · 같은 값 대조) |

### 7-3. 팀 기초 세우기 올리기 · 2026-11-10

근거: [품질개선/KMD_메뉴개편_설계.md](품질개선/KMD_메뉴개편_설계.md) 8-2 · 9절. 팀 화면이 빈 팀 지식에 원본 폴더 · 파일을 올리고, 팀 서버가 글로 바꿔 재료로 둔다(원본은 두지 않는다).

| 길 | 판정 |
|---|---|
| `POST /api/k/:id/seed/upload { group: { id, total, last }, files: [{ path, b64 }] }` | **본문을 읽기 전에** `hub.meta(id, ctx)`(읽기 미만 404) · `hub.need(ctx, kn, 'admin')`(403) · 빈 지식(문서 0 · 아니면 409 · 팀은 앞 묶음이 넣은 문서뿐이면 다음 묶음을 받는다 — 이어 올리기 장부 `series.json` · 통합 I2) — `/import` 처럼 자리부터. 열린 다른 짜임 일 · 남이 연 기초 세우기(24시간 안) · 넣는 중이면 새 묶음을 열지 않는다(409). 요청 하나 64MB(넘으면 413) · 묶음 누계 300 파일 · 200MB(`MAX_FILES` · `MAX_BYTES`)를 서버가 센다(다시 보낸 같은 파일 · 같은 원본은 다시 세지 않는다). 경로는 `cleanPath`(폴더 밖으로 못 나감 · 300자) · `b64` 꼴 · `group.id` 는 서버가 준 12자 16진만. 감사 줄(`AUDIT_RE`) |
| 재료 자리 | `<살림>/shape/<지식>.seed/<묶음>.json`(묶음 장부: 연 사람 · 누계 · 파일 줄 · 원자 쓰기) + `<묶음>/<sha16>.md`(`fileToMd` 글 · 지문은 들이기 `md/<sha16>` 와 같다 · 줄이 가리키지 않게 된 글은 그 자리에서 걷는다). 원본 · 그림은 두지 않는다. 지식마다 묶음 하나: 묶음을 이어 보내는 것 · 조사 · 짓는 것은 연 사람만 · 닫힌(`last`) 묶음에는 더하지 못한다 · 남의 묶음이 다 짓지 않은 채 24시간 안이면 새 묶음을 열지 못한다(409). 깨진 장부는 빈 것으로 덮지 않는다(24시간 안이면 409 · 그보다 오래면 log 를 남기고 걷는다). 새 묶음은 앞 묶음을 걷되 이어 올리기 장부는 둔다(깨졌으면 덮지 않고 409). 지식을 지우면 같이 지운다(올리기와 한 줄) |
| 기초 세우기(TODO 9 · 10 · Z7 · Z8) `POST /api/shape/survey { kn, dir }`(개인) · `{ kn, group }`(팀) · `GET /api/seed/open` · `GET /api/k/:id/seed(?doc=)` · `POST seed/pick { picks }` · `seed/plan { mode: claude · folder · hand, plan?, note? }` · `seed/write { doc? · all? · items? · approve? · stop? }` · `seed/try` · `seed/step { ui }` | 둘 다. 팀은 경로를 받지 않는다(팀 서버 폴더를 읽지 않는다 · `dir` 은 400) — 내가 연 닫힌 올리기 묶음(`group`)으로 일을 연다(조사 줄은 묶음 장부에 원자 쓰기). `hub.meta(id, ctx)`(읽기 미만 404) · `hub.need(ctx, kn, 'admin')`(403) · 조사는 빈 지식(아니면 409) · 단계를 잇는 것은 일을 연 사람만(짜임 일 장부 kind `seed` 하나 · 열린 다시 잡기 일과 겹치지 않는다 · 그만두기는 `shape/stop`). 재료 경로는 전체 경로 · 드라이브 통째 · 집 폴더 · 지식 폴더 · 살림 폴더는 받지 않는다 · 300 파일 · 200MB(넘으면 kmd-seed 꾸러미 경로 · 꾸러미는 읽기만 · 지문이 어긋난 재료 글은 쓰지 않는다). 비밀 의심 파일은 넣음 · 근거만으로 고를 수 없고 Claude 재료에서 빠진다. 지식에 쓰는 것은 넣기(`shape/put`) 하나 — 짜임 걸음(채널 `shape` · 서버가 정함 · 걸음 재료 · 이름은 서버가 장부의 구조안 · 글로 짓는다 · 입력 sections · names 를 받지 않는다). approve 지식은 걸린 걸음이 입력 오류 + 일 멈춤(P-D24 · 통합 I1) · 값 대조는 재기만. 글을 고치면 연습 판 결과를 걷는다(넣기는 다시 해 본 글만) · 다시 잡기 길의 `shape/try` 는 기초 세우기 일을 받지 않는다. `seed/upload` 는 팀만 · `GET /api/seed/open` 은 지식관리자인 지식만. 팀의 Claude 안 · 짓기는 팀 일꾼 일감 `shape-plan` · `shape-write`(`src.seed` · 재료는 서버가 장부의 일 · 묶음에서 짓는다 · 일감이 그 일의 것인지 끝에서 다시 본다 · 받은 초안은 `seedPlanOfDraft` · `seedCheckOf` · `writeOfDraft` · `seedJudge` 로 서버가 다시 본다 · 지식에 쓰지 않는다) · `shape-seed` 를 알린 일꾼에게만 · 옛 일꾼뿐이면 409 · 「Claude 에 보내지 않음」 지식은 `E_FORBIDDEN` · 일을 건 사람이 지식관리자 자리를 잃으면 Claude 에 보내지 않고 닫는다. 24시간 걸음이 없는 남의 일은 「멈춤」(다른 지식관리자가 새로 연다) · 넣다 선 일(걸음 실패)은 그 문서 글만 고쳐 이어 넣는다(연습 판 · 넣은 걸음은 그대로) |
