# kmd 운영 — 밤 묶음 · 데이터 묶음 · 되살리기 연습

관리자(팀 서버) · 이 PC 의 주인이 읽는다. 명령은 kmd 를 띄운 폴더에서.

## 1. 늘 하는 것 — 저절로

- **백업** — 지식마다 붙인 백업 자리로 저장 뒤 바로 · 안 되면 1 · 5 · 15 · 60분 · 매일 한 번 다시. 6시간 밀리면 노랑 · 24시간이면 빨강 한 줄.
- **GitLab 봇**(팀 서버 · 쓰면) — `serve.json` 에 `"gitlab": { "api": "https://gitlab.team.local", "group": "kmd-backup" }` · 열쇠는 `kmd serve secret set gitlab` 로만. 백업 자리가 없는 지식마다 그룹 안에 저장소를 찾거나 만들어 붙인다. 봇 열쇠에는 **만들기 권한만** 준다(지우기 · 보호 해제 없음). 밀기는 서버의 ssh 키가 한다.
- **DB 가져오기**(쓰면) — 계정은 가리지 않는다(슈퍼유저도 받는다). 어떤 계정이든 kmd 는 세션을 읽기 전용으로 열고 카탈로그만 읽는다 — 행은 읽지 않는다. 비밀번호는 비밀에만(`kmd secret set <자격 이름>`).
- **이 PC 늘 켜기** — `kmd pc task` 한 번. 로그온 때 `kmd up --no-open` · 멈추면 1분마다 다시 켠다(작업 이름 `kmd`).

## 2. 밤 묶음(팀 서버)

지식 폴더는 백업 자리가 지킨다. 살림 자리(`<폴더>/.kmd`)는 따로 묶는다 — 명부(auth.json · auth.log) · 주인 · 상태 · 비밀.

```bash
tar -czf /backup/kmd-data-$(date +%F).tgz -C /srv/kmd .kmd
```

- 묶음은 kmd 가 돌고 있어도 된다. **auth.log 는 따로 한 벌 더**(다른 디스크) — 되살릴 때 명부보다 늦은 일을 다시 적용한다.
- 비밀(`.kmd/secrets.json`)이 든다 — 묶음 자리는 관리자만 읽게.

## 3. 되살리기

| 무엇이 없어졌나 | 하는 것 |
|---|---|
| 지식 하나(폴더가 깨짐 · 지움) | `kmd restore <백업 주소> <지식> --root <폴더>` — 새 폴더로 받아 fsck · 검사 · `_members.md` 로 주인 · 개인 · 정리하는 사람 · 정리 설정을 다시 걸고(목록에 보이기 전에 · `_members.md` 가 없으면 팀 지식 · 정리 설정 줄이 없는 옛 백업이면 「손으로만 · Claude 에 보내지 않음」 으로 두고 주인에게 알린다) 같은 백업 자리로 이어 보낸다. 도는 팀 서버에는 관리자의 [동기화] 로 목록에 선다(개인 지식은 그 전에도 `_members.md` 로 가려진다) |
| 새 PC | kmd 를 깔고 지식마다 `kmd restore <백업 주소>` (이 PC 로 되살리기) |
| 백업과 갈라졌다 | 띠에 「갈라졌다」 — 어느 쪽이 맞는지 사람이 정한다. 백업이 맞으면 `POST /api/k/<지식>/backup/adopt`(관리 화면 [이 백업 이어 쓰기]) — 지금 머리는 가지 `kmd-before-<시각>` 로 남는다 |
| 백업이 앞섰다 | [백업에서 받기] — 앞으로만 · 받은 글에 새 오류면 되돌린다 |
| 살림 자리 전부 | 밤 묶음을 풀고 → `kmd auth reapply <따로 둔 auth.log>` — 끊은 기기 · 기계 열쇠는 다시 끊기고, 늦게 바꾼 비밀번호의 사람은 「다시 정하기」(관리자가 링크를 새로) · 늦게 이은 기기는 다시 잇는다. 서버는 켤 때 지식마다 주인 장부를 지식 안의 `_members.md` 와 맞춘다 — 묶음 뒤에 만든 개인 지식도 다시 가려진다(서버 기록 「주인 장부를 지식 안의 _members.md 와 맞췄다 — …」) |

## 4. 되살리기 연습 — 석 달에 한 번

1. 빈 폴더에서 `kmd restore <백업 주소> 연습 --root D:\연습` 
2. 화면으로 열어 문서 · 첨부 그림 · 항목 이름이 보이는지 본다.
3. 원래 지식의 `git rev-parse HEAD^{tree}` 와 되살린 것의 값이 같은지 본다.
4. 연습 폴더를 지운다.

## 5. 새 판

**이 PC** — `kmd pc update <새 판 폴더> <판>`. 새 판 폴더는 PC 꾸러미(`kmd-<판>-pc.zip`)를 푼 폴더다. 판 이름은 지금 판과 달라야 한다.

1. 새 판을 `~/.kmd-app/versions/<판>` 에 두고(옆 임시 폴더에 다 복사한 뒤 이름을 바꾼다) 그 판의 node 로 빈 폴더에서 한 번 켜 본다(healthz). 안 켜지면 앞 판을 그대로 쓴다(되돌릴 것이 없다).
2. 켜지면 지금 판(`current.json`)과 실행기(`~/.kmd-app/bin/kmd.cmd` · `kmd-key.cmd`)를 새 판으로 바꾼다. PATH · 늘 켜기 작업 · 시작 메뉴의 kmd · Claude Code 의 헤더 도우미는 모두 실행기를 부르므로 따라 바뀐다. 늘 켜기 작업 · 시작 메뉴 · 헤더 도우미는 이때 실행기로 다시 건다 — 지식 폴더는 늘 켜기 작업 · 도는 kmd 가 쓰는 그 폴더 그대로다(`--root` 로 정할 수도 있다).
3. 도는 kmd 를 이 PC 의 열쇠로 멈추고 같은 포트로 새 판을 켠다 — 「✓ 다시 켰다 — 판 …」. 새 판이 다시 켜지지 않으면 앞 판으로 되돌려 켠다. 꺼져 있었으면 다음에 켤 때부터 새 판이다.
4. 앞 판 폴더는 지우지 않는다 — 되돌리려면 `kmd pc update "%USERPROFILE%\.kmd-app\versions\<앞 판>" <앞 판>`(켜 보고 · 지금 판과 실행기를 앞 판으로 · 다시 켠다 · 같은 폴더라 복사하지 않는다). `kmd pc link <판>` 만 하면 도는 kmd 는 `kmd pc restart` 나 다음 로그온까지 그대로다.

**이 판(WP1) 전에 깐 PC 의 첫 올리기** — PATH 의 `kmd` 는 옛 판이고 도는 옛 kmd 는 멈추는 길이 없다.

1. 새 꾸러미를 푼 폴더의 `kmd.cmd pc update <그 폴더> <판>` 으로 부른다(옛 판의 `kmd pc update` 는 판을 바꾸지 않는다).
2. 「도는 kmd 를 멈추지 못했다」 가 나오면 늘 켜기 작업을 끝냈다 다시 켠다(로그아웃했다 들어오거나 `schtasks /End /TN kmd` 뒤 `schtasks /Run /TN kmd`). 작업이 이제 실행기를 부르므로 새 판으로 켜진다.
3. 사용자 PATH 에서 옛 꾸러미 폴더를 빼고 `%USERPROFILE%\.kmd-app\bin` 을 둔다.

새 판은 저절로 오지 않는다 — 팀 서버의 받기 자리에 새 zip 이 놓여도 이미 깐 PC 는 그대로다(제품화 단계에서 「새 판 있음」 알림 · 받아 오기).

**팀 서버** — 새 팀 꾸러미를 풀어 `sudo sh kmd-install.sh --team …`(처음과 같은 인자)를 다시 돌린다. `/opt/kmd` 의 코드 폴더를 새 것으로 바꾸고 kmd.service 를 다시 켠다(지식 · 살림 자리는 그대로). 꾸러미 안의 새 PC zip 이 받기 자리에 놓인다 — 설치 한 줄은 서버와 같은 판의 PC zip 을 먼저, 없으면 가장 높은 판을 준다.
