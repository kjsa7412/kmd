팀 프로그램과 개인 프로그램 나누기

개인 지식은 처음부터 개인 프로그램(이 PC 의 kmd)에 살고, 팀 서버에는 없다. 섞여 있는 것은 팀 화면이 개인 프로그램에 붙어 개인 지식을 같이 보여 주는 길이다. 이 길을 걷어 내고, 두 프로그램이 각자 자기 지식만 다루게 한다.

1나눈 뒤의 모습

두 프로그램 사이에 남는 길은 셋이다. Claude Code 세션의 MCP 연결 둘, 그리고 개인 → 팀 지식 보내기. 브라우저에서는 개인 화면과 팀 화면이 서로 다른 탭이다.

① 세션개인 프로그램팀 프로그램걷어 내는 길

2정한 것 넷

결정 1

팀 화면에 개인 지식은 아예 보이지 않는다

지식 목록 · 찾기 · 지금 하는 일 · 멈춤 줄 · 이력 · 설정 어디에도 개인 지식이 나오지 않는다. 팀 화면은 팀 서버에만, 개인 화면은 개인 프로그램에만 붙는다.

결정 2

지식 보내기는 개인 화면에서만

보내는 쪽은 개인 화면의 「지식 보내기」 하나다. 팀 화면에는 보내기 메뉴가 없다. 받은 것은 팀 지식의 기록이 되고 그 지식의 정리 때 문서에 들어간다.

결정 3

팀 가져오기: 세팅은 관리자, 사용자는 넣기만

관리자 = 총괄 관리자 · 지식관리자 (3절)

가져올 곳 더하기 · 고치기 · 지금 가져오기 · [그대로 반영]은 그 지식의 지식관리자와 총괄 관리자가 한다. 서버 폴더 · ssh · 목록 밖 호스트는 총괄만. 쓰기 자리는 일 줄에 파일 · 폴더를 넣어 기록을 만들고, 가져올 곳이 필요하면 [관리자에게 부탁]을 쓴다.

결정 4

개인 프로그램 설치는 팀 화면의 별도 자리에서

설치 · 잇기 한 줄은 그 사람의 기기 열쇠를 만들기 때문에 팀 화면이 내준다. 개인 칸 띠에 있던 것을 「개인 프로그램 설치」 한 자리로 모은다. 작업 폴더에 팀 지식을 붙이는 한 줄도 여기서. 지식 폴더 경로는 깐 뒤 개인 화면에서 정한다.

3권한 네 자리

총괄 관리자 › 지식관리자 › 쓰기 › 읽기. 바깥 자리는 안쪽 자리가 하는 일을 모두 한다. 총괄 관리자는 사람에 붙는 자격이고, 나머지 셋은 팀 지식마다 받는 자리다. 받지 않은 지식은 「없음」(보이지 않음)이 기본이다.

4총괄 관리자가 사용자를 만드는 길

총괄 관리자가 사용자를 만들 때 팀 지식마다 자리(지식관리자 · 쓰기 · 읽기)를 고르고, 접속 계정을 그 사람에게 전한다. 지식관리자는 자기 지식에서 있는 사람에게 자리를 더 줄 수 있다. 사용자는 받은 지식만 본다. 자리를 받지 않은 지식은 목록 · 찾기 · MCP 어디에도 나오지 않는다.

예: 관리자가 이렇게 주면, 각자 팀 화면과 Claude Code 세션에서 아래처럼 본다.

지금 코드와 다른 곳

  • 사람 더하기에서는 아이디 · 관리자 여부만 고른다. 지식 자리는 지식마다의 권한 창에서 따로 준다. 사람 더하기 창에 「지식마다 자리」 표를 더한다 · 사람 카드에서도 고친다
  • 지금 기본은 「모두: 쓰기」다. 자리를 받지 않은 사람도 모든 팀 지식을 읽고 기록한다. 정함: 「없음」 자리를 두고, 기본은 「없음」. 옛 지식 옮기기도 정함: 바꾸는 날 있는 사람 모두에게 옛 지식마다 쓰기 자리를 적어 준 뒤 기본을 없음으로 한다. 겉으로는 그대로이고, 관리자가 사람 카드에서 줄여 나간다. access.all 기본 none · 바꾸는 날 access.users 에 쓰기를 채운다
  • 화면 말: 「관리」 자리를 「지식관리자」로, 전역 관리자를 「총괄 관리자」로 부른다. 권한 판정은 그대로 · 이름만

그대로 쓰는 것

  • 접속 계정 전달은 지금처럼 아이디 + 처음 들어오기 링크(24시간 · 한 번)다. 비밀번호는 사용자가 정한다. 관리자가 비밀번호를 정해 보내지 않는다.
  • 자리 판정은 한 곳(hub.levelOf)이고, 읽기 미만이면 「없는 지식」(404)이다. docs/kmd_권한_모델.md
  • 묶음(개발 · 운영 …)에 자리를 주면 묶음 사람 모두가 받는다.

6진행 순서

  1. 기준 문서부터

    KM52 · v0.5 §5 · TODO L4(팀 화면에서 내 PC 지식)를 거두는 결정을 적는다. 설명서 · 디자인 컨벤션 용어도 같이.

  2. 개인 화면 대조

    팀 화면에서 하던 개인 일이 개인 화면에 다 있는지 하나씩 본다. 지식 보내기 · 받는 팀 지식 고르기 · 에이전트 설치.

  3. 팀 화면 걷기

    S.pc · pcSide() · /pc/api · ~ id 분기를 지운다. 빈 상태 · 오류 문구도 팀 지식만 말하게.

  4. 팀 서버 걷기

    pcUrl · pcpass · CSP 예외 · 설정 키.

  5. 개인 프로그램 짝짓기 걷기

    /pair · 짝 열쇠 ctx · 잊기. 개인 화면의 확인 창은 둔다.

  6. 권한 네 자리

    이름을 총괄 관리자 · 지식관리자 · 쓰기 · 읽기로. 사람 더하기 창에 지식마다 자리 표 · 기본 자리 없음 · 옛 지식은 바꾸는 날 모두에게 쓰기.

  7. 개인 프로그램 설치 자리

    팀 화면에 「개인 프로그램 설치」 한 곳: 설치 · 잇기 한 줄, 작업 폴더에 팀 지식 붙이기, 내 기기 목록. PC 일꾼 열쇠는 걷는다.

  8. 테스트 · 배포

    pair · pc-confirm · kit-area · open · settings · watch2 · screen-kmd 를 맞추고, 네 폭에서 화면 확인 뒤 188 에.

7그 밖에 정한 것

미팅에서 남았던 넷은 모두 정했다. 개발 전에 정할 것은 남지 않았다.

지식마다의 관리 자리 → 「지식관리자」로 그대로 둔다권한을 총괄 관리자 › 지식관리자 › 쓰기 › 읽기 넷으로 정했으므로, 지금 주인 · 권한 표에서 「관리」를 받은 사람 · 묶음은 바꾸는 날 그대로 지식관리자다. 옮길 사람이 없다(이름만 바뀐다).
정리하는 사람 칸 → 할 일 없음(이미 지식관리자로 들어가 있다)「이 지식의 사람」 화면은 이미 걷혔고, 정리를 맡길 사람은 권한 창의 사람 줄에서 「관리」로 준다. 예전 「정리하는 사람」 목록은 권한 표를 처음 저장할 때 「관리」 줄로 옮겨지고 비워진다(core/owners.js setAccess). 정리 · 가져오기 알림도 이미 「그 지식의 관리 자리 사람 + 총괄」에게 간다(hub.curatorsOf). 남은 것은 설명서 · 관리자 명령(kmd owner --curators)의 옛 낱말을 「지식관리자」로 고치는 일뿐이다.
개인 프로그램 설치 → 팀 화면에 별도 자리로 유지팀 화면에 「개인 프로그램 설치」 한 곳을 둔다: 설치 · 잇기 한 줄 복사, 작업 폴더에 팀 지식 붙이기 한 줄, 내 기기(이은 PC) 목록. 누구나 쓴다. 개인 지식 · 개인 폴더 내용은 보여 주지 않고, 연결 상태는 팀 서버가 아는 기기 목록으로만 보인다(PC 에 묻지 않는다).
사람 몫 PC 일꾼 열쇠 → 걷는다팀 서버가 사람 PC 에 일을 넘기던 옛 설계의 흔적이다. 지금 만드는 곳이 없어 늘 0 이다. 열쇠 코드 · 사람 카드의 「PC 일꾼 n」 · 떠남 · 새 링크 · 기기 끊기 문구 · 관리자 설명서에서 걷는다. 팀 정리 일꾼과 개인 프로그램의 일꾼은 그대로다.
검토안이다. 코드는 아직 바꾸지 않았다. 위치는 kmd main dc7cb43 기준이다.
