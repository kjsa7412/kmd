## 0. 운영자의 말 · 한 줄

> 개인 지식문서와 프로젝트 지식문서 2개가 있을 때 어디가 어디에 연결되어 있는지를 알아야 할 텐데, 개인 지식문서가 프로젝트 지식과 1:1 이 아닐 수도 있다. 양방향이면 경계가 나중에 모호해질 것 같다. 세션에서 작업 시 개인 문서 또는 공유 지식에서 선택해서 저장할 수 있어야 한다. 내부 지식은 폴더 및 경로만 연결하면 바로 볼 수 있도록 하면 로컬에 설치형 서비스가 필요 없을 것으로 보인다.

**네 지적 모두 맞다. 그리고 넷은 한 가지 바꿈으로 같이 풀린다.**

> **개인 지식은 「내 폴더 그대로」 다 — 서버도 사본도 없다. 프로젝트 지식은 팀 서버에만 있다. 둘 사이에는 「보내기」(내 것 → 팀) 한 방향 길만 있고, 팀 문서는 내 폴더에 들어오지 않고 옆에서 읽기만 한다.**

## 2. 권장 구조 — 둘로 나누고, 길은 하나

```
[내 PC]                                         [팀]
내 폴더(들) — 그냥 md 파일                       프로젝트 kmd = 지금 팀 서버
  D:\notes\배포   D:\notes\설계                     dpms_wiki · gdi_wiki …
  (원하면 그 폴더를 git 으로 — 내 일)              큐레이터 · 대기열 · 정본
        │                                              ▲
        │ 브라우저가 폴더를 직접 읽는다(설치 없음)      │ 보내기(고친 안 · 새 문서 제안 · 기록)
        ▼                                              │  — 한 방향 · 사람이 누를 때
  팀 서버의 화면 › 「내 폴더」 영역  ──────────────────┘
  팀 문서는 「프로젝트」 영역에서 읽기만 — 내 폴더에 쓰지 않는다
```

| | 개인 지식 | 프로젝트 지식 |
|---|---|---|
| 어디에 | 내 PC 의 폴더(여러 개 가능) — 원본 그대로 | 팀 서버의 지식 레포 |
| 누가 쓰나 | 나 — 편집기 · 화면 · 세션 | 큐레이터(정본) · writer(기록) — 지금 CDP 그대로 |
| 무엇이 지키나 | 아무 규칙 없음 — 그냥 md(자유) | CDP 의 save · 불변조건 전부 |
| 보는 곳 | 팀 서버 화면의 「내 폴더」 영역(브라우저가 직접 읽음) · 편집기 · 세션 | 「프로젝트」 영역 |
| 다른 쪽으로 | 보내기 → 프로젝트 대기열 | **없음.** 내 폴더에 쓰지 않는다 |

**사라지는 것** — PC 의 개인 서버 · 포트 · 개인 토큰 · 서비스 등록 · 가져오기(복사) · 원본 따라가기 · 편집기 자동 저장(거두기) · 프로젝트 소식 받기 · o · k 맞춤 기준 · 「양쪽이 다르게 고쳤다」. 원본이 곧 내 지식이라 복사본과 원본을 맞출 일이 없다.

## 3. 넷을 어떻게 푸나

### 3.1 A · 1:1 이 아님 — 레포가 아니라 **폴더 · 문서 단위의 「보낼 곳」**

- 연결은 「개인 레포 ↔ 프로젝트」 가 아니라 **보낼 곳 규칙**이다. 규칙은 폴더 · 문서마다 0..n 개.
  - 폴더 규칙(기본) — `D:\notes\배포` → dpms_wiki · `D:\notes\설계` → gdi_wiki · `D:\notes\개인` → (없음 = 보내지 않음).
  - 문서 규칙(덮어쓰기) — 한 문서만 다른 프로젝트로 · 또는 「보내지 않음(비공개)」.
  - 한 문서를 두 프로젝트로 보내는 것도 된다(규칙 둘). 프로젝트 쪽에서는 각자 다른 사람의 기록이다.
- 규칙은 **그 폴더 안의 작은 파일 하나**(`.kmd.json` — 보낼 곳 · 비공개 목록)에 둔다. 폴더를 옮기거나 git 으로 다른 PC 에 가져가도 따라간다. 처음 폴더를 이을 때 화면이 물어 한 번 정하고, 그 뒤로는 묻지 않는다(v0.2 P1).
- **「어디가 어디에 연결되어 있나」** 는 화면 한 장에서 본다 — 내 폴더 목록 옆에 보낼 곳 칩(「→ dpms_wiki」 · 「보내지 않음」). 프로젝트 쪽에서는 받은 것마다 「김의 D:\notes\배포 › 헬스체크」 출신이 붙는다(지금 정형 출처 그대로).
- 문서 안의 섹션이 프로젝트의 어느 자리로 가는지는 여전히 시스템이 정한다(같은 제목 · 별칭 → 그 섹션의 고친 안 · 없으면 새 문서 제안 · v0.2 KM34).

### 3.2 B · 경계 — **한 문서에 주인 하나 · 길은 한 방향**

| 규칙 | 뜻 |
|---|---|
| 내 폴더의 글은 내 것 | 시스템이 내 폴더에 쓰는 일이 **없다.** 팀 글이 내 문서로 흘러들지 않는다 |
| 팀 글은 팀 것 | 「프로젝트」 영역에서 읽는다. 내가 바꾸고 싶으면 **고친 안을 보낸다**(큐레이터가 반영) |
| 팀 글을 내 것으로 쓰고 싶으면 | 「내 폴더로 복사」 — 사람이 누르는 한 번의 복사. 복사본 맨 위에 「dpms_wiki › 배포절차 에서 10-21 복사」 한 줄. 그 뒤로는 내 글이고 자동으로 맞춰지지 않는다 |
| 내가 보낸 것이 반영되면 | 내 글은 그대로다. 「보낸 것」 목록에 「반영됨 — 팀 문서 보기」 가 뜬다. 둘을 맞추고 싶으면 그 팀 문서를 다시 복사할 뿐 |

v0.2 의 「프로젝트 소식 받기」 가 풀려던 문제(내 판이 팀 정본에서 멀어진다)는 **멀어져도 괜찮게** 만들어 푼다 — 팀 정본은 언제나 옆 영역에서 최신으로 읽히고, 보내는 고친 안은 **팀 문서의 지금 글 위에** 짓는다(보낼 때 프로젝트 섹션을 읽어 비교 · 지금 설계 §9.3 의 「기준」). 내 노트를 팀 글로 갱신할 이유가 없다.

### 3.3 C · 세션에서 저장할 곳 고르기

- 세션은 **둘 다 쓸 수 있다.** 개인 = 파일 쓰기(내 폴더에 md — 서버 없음, Claude Code 가 그냥 파일을 쓴다) · 프로젝트 = 지금 MCP `save`.
- 저장 스킬(`cdp-save`)이 저장 전에 **행선 한 줄**을 보인다 — 「→ 팀 dpms_wiki 에 기록」 또는 「→ 내 폴더 D:\notes\배포 에 메모」. 사람은 한 마디로 바꾼다(「내 메모로」 · 「팀으로」).
- 기본값 규칙(묻지 않는다): ① 사람이 말했으면 그대로 ② 작업 레포가 프로젝트에 연결돼 있으면 **팀**(지금 CDP 동작 — 팀 지식이 쌓이는 길을 줄이지 않는다) ③ 아니면 **내 폴더**.
- 둘 다에 저장은 두지 않는다 — 같은 글이 두 곳에서 따로 자란다(B 의 문제). 내 메모로 남겼다가 나중에 보내면 된다.
- 내 폴더가 어디인지는 사용자 설정 하나(`~/.cdp/me.json` 의 폴더 목록 — 이것이 화면 · 세션이 같이 보는 「내 폴더」 목록이다). 코드 레포에 개인 토큰 · 경로가 커밋되지 않는다.

### 3.4 D · 설치 없이 — 브라우저가 내 폴더를 직접 읽는다

- 팀 서버 화면에 **「내 폴더」 영역**을 더한다. [폴더 잇기] → 브라우저의 폴더 고르기(File System Access API — Chrome · Edge) → 그 폴더의 md 를 **브라우저 안에서** 읽어 같은 화면(목록 · 읽기 · 찾기 · 그래프)으로 보인다. 화면의 판정 코드는 이미 브라우저에서 돈다(I1 — 화면 Store 가 `core/` 를 쓴다).
- **파일 내용은 서버로 가지 않는다.** 브라우저가 읽고 브라우저가 그린다. 나가는 것은 사람이 [보내기] 를 누른 문서뿐이다(그때 지금의 `POST /api/<p>/records` 로). 이것이 「오프라인으로 전파되지 않는다」 의 가장 단순한 보증이다.
- 고치기도 브라우저에서 — 같은 폴더 핸들로 파일에 바로 쓴다(사용자가 쓰기 허락을 한 번). 편집기로 고쳐도 다음에 열면 그대로 보인다(사본이 없으니 맞출 일이 없다).
- 잇기는 브라우저에 기억된다(다음에 열면 「계속 볼까요」 허락 한 번 — 브라우저 정책). 폴더 목록 자체는 3.3 의 사용자 설정과 같다.
- **설치형이 필요 없다** — PC 에 깔 것: 브라우저(이미 있다) · Claude Code(세션을 쓸 때 — 이미 있다). `ctx up` · 개인 서버 · 서비스 등록 · self-update · 개인 토큰이 개인 쪽에서 모두 빠진다.

### 3.5 무엇을 잃나 — 그리고 괜찮은가

| 잃는 것 | 괜찮은가 |
|---|---|
| 개인 지식에 CDP 규칙(좌표 · 기록 불변 · 큐레이션) | 괜찮다 — 운영자 원문이 개인 지식을 「에디팅 가능」 한 자유 영역으로 봤다. 규칙은 프로젝트로 들어가는 문(보내기)에서 지킨다 |
| 내 노트의 변경 이력 | 폴더를 git 으로 두면 생긴다(원문의 「개인 깃 옵션」 이 그대로 이것 — 화면에 「이 폴더를 git 으로」 안내 한 줄). 안 쓰면 없다 |
| docx · pdf 같은 비-md | 「내 폴더」 영역은 md · txt 를 그린다. 그 밖은 파일 이름만 보이고 [md 로 바꿔 두기](지금 변환 `core/convert.js` 를 브라우저로 — 가능한 것만 · 추정) 또는 보낼 때 프로젝트 들이기(`ctx ingest`)가 변환한다 |
| 팀 서버가 없을 때(완전히 혼자) | 같은 화면 번들을 정적 페이지로 낸다(이미 있는 `npm run build` 산출물) — 열 곳만 있으면 된다. 망 없이 쓰려면 그 페이지를 브라우저가 캐시하거나 로컬 파일로 연다(파일에서 열 때 폴더 API 가 되는지는 **추정 — 스파이크**) |
| Firefox · Safari | 폴더 API 가 없다. 사내 Windows 는 Chrome · Edge 라 1차 대상에서 충분하다. 없으면 「폴더 잇기」 대신 안내 |
| 브라우저 안의 코드가 서버에서 온다 | 서버 코드가 바뀌면 그 화면이 내 파일을 읽을 수 있다 — 같은 회사 팀 서버를 믿는 범위다. CSP `connect-src 'self'` · 「내 폴더」 코드에서 보내기 외 요청 0 을 시험으로 고정 |

## 4. 바뀌는 판 순서

| 단계 | v0.2 | v0.3 권장 |
|---|---|---|
| ① | 내 kmd 가 뜬다(PC 서버 · 레포 폴더 · Windows 시작프로그램) | **내 폴더 잇기** — 화면 「내 폴더」 영역(읽기 · 찾기) · 사용자 설정 폴더 목록 · `.kmd.json` 보낼 곳 규칙 |
| ② | md 가 곧 지식(가져오기 · 고치기 · 자동 저장) | **고치기 · 세션 행선** — 브라우저에서 파일에 바로 쓰기 · `cdp-save` 행선 한 줄과 개인 = 파일 쓰기 |
| ③ | 원본과 맞추기 | **(없어진다)** — 원본이 곧 내 지식 |
| ④ | 프로젝트와 맞추기(보내기 · 받기) | **보내기 한 방향** — 고친 안 · 새 문서 제안 · 출신 표시 · 「팀 문서를 내 폴더로 복사」 |
| ⑤ | 이름 · 설치 프로그램 | 이름(Q0) · 정적 페이지 판(팀 서버 없는 사람) |

단계가 다섯에서 넷으로 줄고, 가장 위험한 장치(PC 서버 · 자동 맞추기 · o/k · 거두기 · 개인 토큰)가 모두 빠진다. v1.9.1 고침판(F1~F9)은 그대로 필요하다 — 받는 쪽 save 의 구멍이다.

| Q13 | 팀 서버 없이 혼자 쓰는 사람을 1차 대상에 넣나 | 2차. 1차는 「팀 서버가 있는 회사 · Chrome/Edge」 |
| Q14 | 프로젝트 문서를 내 폴더로 복사한 뒤, 팀 쪽이 바뀌면 알릴까 | 알림 한 줄만(「복사해 온 배포절차 가 팀에서 바뀌었다 — 팀 문서 보기」) · 자동으로 고치지 않는다 |
