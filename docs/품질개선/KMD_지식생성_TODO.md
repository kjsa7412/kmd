## 0. 설계 한 장

지식 내용을 쓰는 길은 공식 절차 하나다.

```
원천 → [코드] 같은 것 가림
     → [LLM 세션] 찾기(brief: 생성 룰 · match: 과거 결정 카드 · section: 섹션 글과 base)
     → [같은 세션] 판단 + 글(항목마다: 내용만으로 답 → 과거 결정에 따름 · 가름 · 벗어남과 까닭 → 고침 · 새 항목 · 그대로 · 뺌)
     → [코드] 짝 짓기(섹션 · 항목장부 줄 · 문서장부 줄 · 건드린 항목을 같이)
     → [코드] 검사(판단이 있었나 · 판단과 행동이 맞나 · 지문) → 오류면 세션이 걸린 자리만 고쳐 다시 냄(두 번까지)
     → [코드] 저장(한 커밋) → 측정
     사람이 넣은 것은 저장 앞에 저장 제안 승인이 낀다.
     무인에서 끝내 못 넘으면 지식에 아무것도 쓰지 않고 일감이 다시 시도한다(자동 세 번 → 실패 일감).
```

확정한 것(설계 문서의 번호):

| 무엇 | 번호 |
|---|---|
| 성격 정의는 장부가 아니라 고정 생성 룰 R1 ~ R9(두 겹)가 준다. 빈 지식은 「과거 결정 0 건」 일 뿐 따로 길이 없다 | H-D1 · H-D28 · 2절 |
| 장부는 과거 결정(판례)이다. 따를지는 LLM 이 맡고 코드는 판단이 있었나 · 판단과 행동이 맞나만 본다 | H-D12 · H-D13 · 4절 · 6절 |
| 짝은 코드가 짓는다 | H-D11 |
| 값은 근거 날짜로 견준다 | H-D27 |
| 규칙 길을 걷는다. 무인 실패는 다시 시도 | H-D29 ~ H-D31 · 8-1 |
| 가져올 곳도 공식 절차 | H-D32 |
| 사람이 직접 쓰는 채널 폐기(화면 저장 · 문서 고치기의 글 고침 · 거두기). 관리 일(되돌림 · 지움 · 이름 바꿈 · 장부 고침)과 승인은 남는다 | H-D33 · 8-4 |

- 실제 LLM 초안 표본은 아직 없다. 설계의 「LLM 이 이렇게 답한다」 는 조문에서 읽은 것이다. H0 이 처음 잰다. 숫자(문턱 · 간격 · 예산 · 한도)는 모두 처음 값이다.
- 세션은 단발보다 비싸고 느리다(지금 넣기 에이전트 값: 일감마다 2 ~ 3 달러 · 20분). H0 과 H4 뒤에 잰 값을 견준다.
- Claude 를 쓸 수 없으면 그 지식의 내용은 바뀌지 않는다(관리 일만 된다). 주인이 알고 정한 것이다.
- 틀린 따름(다른 대상을 있는 항목에 합침)과 꾸민 까닭은 코드 검사에 걸리지 않는다. 골든 셋과 사후 지표로만 드러난다.
- 팀 서버 · 팀 일꾼 · 개인 프로그램의 판이 섞이는 동안 옛 꼴 입력을 받는 유예가 필요하다(H-O9: 세션은 스킬 한 판 동안 경고 · 그 뒤 오류).
- 옛 지식(DPMS · GDI)의 옛 장부 · 옛 기록 · 옛 `들인 자료` 는 다시 쓰지 않는다.
