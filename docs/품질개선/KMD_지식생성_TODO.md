## 0. 설계 한 장

지식 내용을 쓰는 길은 공식 절차 하나다.

```
원천 → [코드] 같은 것 가림
     → [LLM 세션] 찾기(brief: 생성 룰 · match: 과거 결정 카드 · section: 섹션 글과 base)
     → [같은 세션] 판단 + 글(항목마다: 내용만으로 답 → 과거 결정에 따름 · 가름 · 벗어남과 까닭 → 고침 · 새 항목 · 그대로 · 뺌)
     → [코드] 짝 짓기(섹션 · 항목장부 줄 · 문서장부 줄 · 건드린 항목을 같이)
     → [코드] 검사(판단이 있었나 · 판단과 행동이 맞나 · 지문) → 오류면 세션이 걸린 자리만 고쳐 다시 냄(두 번까지)
     → [코드] 저장(한 커밋) → 측정
     사람이 넣은 것은 저장 앞에 저장 제안 승인이 낀다.
     무인에서 끝내 못 넘으면 지식에 아무것도 쓰지 않고 일감이 다시 시도한다(자동 세 번 → 실패 일감).
```

## 1. 일하는 법

- CLAUDE.md 를 따른다. main 에 바로 · 단계마다 커밋 · 기준 문서와 코드를 같은 커밋에서 · 바뀐 것에 걸린 `test/*.test.mjs` 만(전체 · restore 금지) · push 와 188 배포는 사람이 하라고 할 때만.

- 설계에 없는 것이 필요하면 설계 문서에 먼저 더한다(H-D 번호를 잇는다). 주인의 결정을 고치게 되면 멈추고 묻는다.
- 실제 LLM 을 돌리는 일(H0 의 평가 시험)은 돈이 든다. 돌리기 전에 원천 수 · 예상 값을 한 줄로 알리고 돌린다. 결과는 `.kmd-data/harness-eval/` 에.

- 「고치게 되는 옛 결정」 문서(저장승인 설계 P-D · 개편 설계 S-D · 권한 모델 7절 · 작성기준 · 바탕세우기 설계)는 그 결정을 코드에 넣는 단계 커밋에서 같이 고친다.
- 멈추고 묻는 곳: H8(두 주 측정 뒤에 켠다) · push · 주인 결정을 고쳐야 할 때 · 옛 `들인 자료/` 문서 지우기(H12 마).
- **한도로 멈추면 풀릴 때 묻지 않고 잇는다**(2026-11-17 주인 지시 · 이 일을 맡긴 세션이 전했다). 사용량 · rate limit 으로 멈추기 전에 이 문서 1-1절에 어디까지 했는지 적어 두고, 풀리면 하던 단계를 그대로 잇는다.
