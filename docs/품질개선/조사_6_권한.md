# 현황 조사: 권한 구조와 API 검사

> 1단계 조사(2026-10-28). 초안 + 비평(빠진 것 · 바로잡음).


표기: **[확인]** 은 코드에서 본 사실, **[추측]** 은 코드로 끝까지 따라가 보지 않은 판단이다. 줄 번호는 지금 main(c1d6200) 기준이다.

## 요약

- **[확인]** 지식 단위로 거는 권한은 사실상 없다. 판정은 `auth.json` 사람 줄의 `admin` 한 칸(관리자/일반)뿐이고, 들어온 사람은 모든 팀 지식을 읽고 기록한다.
  - 지식마다 가리는 것은 하나다: 「되살렸는데 주인이 없는 지식은 관리자만 본다」(`core/owners.js:95-100`).
  - 화면에도 「지식마다 따로 주는 권한은 없다」 고 적혀 있다(`app/main.js:3246`).
  - `server/hub.js:553-559` `roleIn` 의 주석은 「팀 지식의 권한은 관리자 · 일반 둘뿐이다」 이고, 실제 판정은 `ctx.admin ? '정리' : '기록'` 이다.
- **[확인]** 지식마다 주인(owner)과 정리하는 사람(curators) 장부는 있다(`owners.json` 과 지식 안의 `_members.md`). 그러나 팀 모드에서 이 장부가 바꾸는 것은 지식 설정을 고칠 자격(`setOwner`)뿐이다. 읽기 · 쓰기 · 관리 판정에는 쓰이지 않는다.
- **[확인]** 그룹 개념은 없다. `auth.js` · `owners.js` 어디에도 group 이나 팀 소속을 담는 칸이 없다.
- **[확인]** 지식 하나는 폴더 하나이고 git 레포 하나다(`core/knowledge.js:30-41`, `server/hub.js:323` `ensureRepo(d)`).
- 모든 지식 접근은 `hub.meta(id, ctx)` 와 `hub.visible(ctx)` 두 곳을 지난다. 여기에 레포 단위 **읽기** 판정을 넣으면 대부분의 노출 경로가 한 번에 막힌다. 다만 판정을 건너뛰는 곳이 따로 있다(3절과 6절의 「검사 빠짐」).

## 2) 서버 API 전수 표

### 표의 약호

- 접근 지식: `:k` 는 경로의 지식 id(`decodeURIComponent`), `visible*` 은 `hub.visible(ctx)` 로 거른 전체.
- 레포 검사: R 은 레포 읽기, W 는 레포 쓰기, A 는 레포 관리가 필요하다는 제안이다. G 는 전역(관리자/사람 단위)이라 레포와 무관하다.
- 마지막 칸 표시: **⚠빠짐** 은 검사가 빠졌거나 제안한 권한보다 약한 것, ○ 는 지금의 visible 판정은 지나는 것.

GET 을 받는 길 목록은 `server/http.js:388-392` 에 있다. 그 밖의 길은 POST 만 받는다(`:397`).

## 5) MCP 토큰 · 열쇠(kmd-key)와 사람의 묶임

### 열쇠의 출처와 묶임

- **[확인]** Claude Code 의 팀 연결(`kmd-team`)은 `.mcp.json` 의 `headersHelper` 로 `kmd-key <팀주소>` 를 부른다(`core/kit.js:5`).
- `kmd-key` 는 OS 자격 저장소에서 `device:<origin>` 이름의 기기 열쇠(`kmdk_…`)를 꺼내 `Authorization: Bearer` 헤더로 낸다(`server/bin/kmd-key.mjs:1-18`, `core/keystore.js:63-64`).
  - 자격 저장소는 Windows 면 DPAPI 파일 `%APPDATA%\kmd\keys\<지문>.dpapi` 다(`core/keystore.js:1-6`).
- 기기 열쇠는 사람 한 명에 묶인다. 발급 때 그 사람 줄의 `keys[]` 에 `{id, sha, host, osuser, at, yellow}` 로 들어가고(`core/auth.js:364-390`), 발급은 설치 표(`kmdt_`, 10분 · 한 번, `:359-363`) 또는 아이디 · 비밀번호로 한다.
- 서버에는 sha256 만 남는다(`core/passwd.js:307-313`).
- 90일 동안 안 쓰면 끊긴다(`core/auth.js:496-501`, `core/passwd.js:310`).
- 사람이 떠나면 지워진다(`:288`).
- 기기 열쇠의 ctx 는 `{user, admin, device, newDevice}` 이다(`core/auth.js:501`).
- 예전 열쇠(legacy)의 ctx 는 `{user, admin, legacy:true}` 다(`:503`).

### 토큰으로 오는 요청의 판정 [확인]

- `/mcp` 는 `who()`(`server/http.js:324-345`) → `need(ctx)`(`:1015`) → `mcp.call(body, ctx)` 순서로 간다. 쿠키 요청과 **같은 ctx 모양**으로 같은 `hub.meta` · `visible` · `canDirect` 판정을 받는다. 그래서 관리자 사람의 기기 열쇠로 붙은 Claude Code 는 문서에 바로 쓴다(`server/hub.js:660-664`, `server/mcp.js:128`).
- 기기 열쇠 ctx 에는 sudo 가 없다. 그래서 `admin(ctx)`(sudo 필요) 길은 열쇠로 지나가지 못한다(`server/http.js:355`).
  - 다만 `sudo:false` 인 관리 길은 관리자 기기 열쇠로 지나간다: 지식 추가(`:663`), 개요 · 사람 목록(`:586`, `:790`), 부탁(`:692`, `:697`), 백업 lost(`:646`).
- 열쇠로 다른 열쇠를 만들지는 못한다(`server/http.js:765`, `:474`).
- `/api/me/pcpass/check` 는 기기 열쇠로만 부른다(`:479`).

## 6) 레포 단위 권한으로 옮길 때 필요한 사실

### 지금 데이터의 모양

- **사람은 `auth.json` `users.<id>` 에 있다.**
  - 「일반 사람」 은 `kind` 가 `person` 이거나 비어 있고, `!off`, `!pc` 다(`core/auth.js:149` people).
  - 관리자는 `admin:true` 다.
  - 떠난 사람(`off`)과 기계 · 일꾼 줄이 같은 맵에 섞여 있다(`kind` 로 가른다).
- **지식은 `<root>` 아래 폴더 하나씩이다**(`core/knowledge.js:30-41`).
  - PC 에는 `<data>/links.json` 으로 이은 폴더도 있다(`server/hub.js:287-296`).
  - id 는 폴더 이름(NFC)이다. 팀은 공백 · 특수문자를 `-` 로 바꾼다(`server/hub.js:307`).
  - 알던 지식 목록은 `<data>/known.json` 이다(`:484-493`).
- **지식마다 사람 장부는 둘이다.**
  - `owners.json` 의 `knowledge.<id>`: `owner`, `curators`, `restored`, `check`, `tidyAt`, `tidyMode`, `noClaude`, `at`.
  - 레포 안 `_members.md`.
  - **줄이 없는 지식도 있다.** 그런 지식은 지금 「팀 모두가 읽고 기록」 한다(`core/owners.js:4`, `:97`).
  - 줄이 생기는 경우:
    - 화면에서 만든 지식: 만든 관리자가 주인이다(`server/hub.js:315-321`).
    - 동기화로 새로 놓인 지식 중 `_members.md` 가 없는 것: 누른 관리자가 주인이다(`:510`).
    - `_members.md` 가 있으면 그것을 따른다(`core/owners.js:162-185`).
- **`curators` 는 데이터는 있지만 권한 효과가 없다.** 1-1 의 근거 참고. 옮길 때 「정리하는 사람 → 레포 쓰기 또는 관리」 로 볼지 정해야 한다.
- **`restored && !owner` 줄은 지금 관리자만 본다.** 옮길 때 기본 「없음(관리자만)」 으로 두는 것이 지금 동작과 같다.
- **떠난 사람 처리:** `handOver` 가 owner 를 비우거나 넘기고 curators 에서 뺀다(`server/hub.js:2918-2941`). 새 권한 표도 떠남 때 같이 걷어야 한다. `auth.off` 는 `admin=false` 로 둔다(`core/auth.js:287`).
- **되살림 · 백업과의 관계:** `_members.md` 는 백업을 따라가서, 켤 때 · 동기화 때 장부를 되살린다(`server/hub.js:2899-2916`). 레포 권한 표를 레포 안(`_members.md` 확장)에 둘지 서버(`owners.json`)에만 둘지가 설계 결정이다.
  - **[추측]** 레포 안에 두면 레포 쓰기 권한이 있는 사람이 git 으로 고칠 위험이 있다. 다만 지금 저장 · 넣기 길은 예약 파일을 막고 있고(`core/save.js:80`, `server/hub.js:586`, `:2328`), 레포에 직접 push 하는 길은 이 서버 API 에 없다. 백업 원격(GitLab 등)에서 고친 것이 `backupAdopt`/`pull` 로 들어올 수는 있다.
- **셸과 서버가 같은 장부를 고친다.** 프로세스 사이 잠금과 mtime 으로 다시 읽기를 한다(`core/owners.js:49-73`, `server/hub.js:74-106`). `auth.json` 도 mtime 으로 다시 읽는다(`core/auth.js:88-99`). 새 권한 파일도 같은 방식이어야 셸 명령(`kmd owner` · `kmd user`, `server/bin/kmd.mjs:442-490`)과 맞는다.
- **그룹은 없다.** 사람마다 지식마다 줄을 적어야 한다. 새로 만들려면 `auth.json` 이나 새 파일에 그룹을 둬야 한다.
- **기계 열쇠는 이미 `machine.kn` 으로 지식 하나에 묶여 있다**(`core/auth.js:434`). 옮길 때 그대로 둬도 된다.
