바탕 세우기(kmd-seed) 검토

있던 문서 폴더로 지식의 구조를 잡아 세우는 공식 기능 · 2026-11-09 · 설계 3각도 → 반박 → 심사 · 합성 → 끝 검토(opus · 에이전트 8) · 상세: docs/품질개선/KMD_바탕세우기_설계.md

결론: 공식 기능으로 만든다. 다만 화면 기능이 아니라 Claude Code 세션 스킬 + 스크립트(「기록으로 다시 그리기」 kmd-migrate 와 같은 꼴)로 만든다. 지식 사본에서 구조안을 짓고 사람이 승인한 뒤, 저장 문을 거쳐 넣고, 마지막에 한 번만 서버에 붙인다(팀: push → 「백업에서 받기」 · 개인: kmd restore --practice).

원인: 지금 길로 왜 안 되나

지금 길막히는 곳
개인 「내 폴더로 지식 추가」파일 하나 = 문서 하나로 글 그대로 옮긴다(hub.js:1184-1222). 원본 폴더 · 파일 이름 · 판(최종 · v2)이 구조로 굳는다. 팀에서는 막혀 있다.
팀 대량 넣기 kmd-team-import이미 있는 문서에 조각을 넣는 전제다. 빈 지식에서는 넣을 곳이 없다. 쓰기 자리는 새 문서를 못 세운다. 갈래 장부가 서면 G4 가 장부 밖 문서를 거절한다.
빈 지식 세우기README 만 남는다. docs/ · work/ 는 git 에 실리지 않는다.
문서 짜임경로와 제목만 다룬다. 항목 글은 쓰지 않는다.

권장안: 흐름

파란 칸 = 사람 승인. 스크립트는 규칙으로 잴 수 있는 일, Claude Code 는 뜻을 읽는 일을 맡는다.

0 자리 잡기원본 · 대상 지식 · 짓는 사람. 팀은 총괄 관리자가 빈 지식을 세우고 clone
1 시작 검사문서 · 기록 · 장부가 비어 있어야 시작
2 조사파서 → manifest: 판 묶음 · 같은 글 · 스캔 · 갈래 후보 · digest
3 승인 ①걸러 두기 표: 정본 · 옛 판 · 비밀 의심 · 실패
4 구조안파일마다 카드 → plan.json(갈래 · 폴더 · 문서 · 항목 · 이름 · 차례)
5 plan-checkG1 · G4 · 별칭 충돌 · 덮임 · 크기 · 거울 지수
6 승인 ②나무 · 원본 → 항목 대응 · 경고. plan 지문 고정
7 뼈대갈래 장부(save) + 문서 짜임(restructure)
8 재료정본마다 work/ 기록(저장 문)
9 문서마다 짓기항목 글 → check(재료로만 값 대조) → put. 처음 몇 개는 하나씩 승인
10 덮임빠진 값 · 사라진 문장 · 고아 재료
11 마감「바탕 세움」 이력(save system) · audit 0
12 승인 ③끝 진단 → 팀 push + 받기 / 개인 restore

구조 최적화 기준

  • 문서 = 주제 · 대상 하나, 사건 갈래 하나, 대장 하나. 원본 폴더 나무와 파일 경계는 참고만 한다. 이름에 날짜 · 판 · 「최종」 을 쓰지 않는다.
  • 항목 = 대상 하나의 「지금」. 같은 대상의 여러 파일은 모으고 늦은 판이 이긴다. 옛 판은 기본 skip.
  • 갈래: 날짜 사건(회의 · 장애)은 「YYYY-MM-DD 무엇」, ID 대장은 패턴, 나머지는 대상 문서. 같은 꼴이 셋 넘게 되풀이될 때만 세운다.
  • 이름: 둘 넘는 곳에서 가리키는 고유물만 세운다. 종류는 8~10개 안팎.
  • 크기: 폴더 2단 · 폴더당 문서 3~12 · 문서당 항목 5~40 · 항목 300줄 안. 넘으면 plan-check 가 경고한다.
  • 덮임: 모든 정본은 어딘가에 배정되거나 까닭과 함께 skip된다. 비밀이 든 파일은 보류한다.
