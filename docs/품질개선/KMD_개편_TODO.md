## 0. 왜 바꾸나

- kmd 의 전신 CDP 는 관리문서(문서) · 작업문서(기록)를 나누고, **작업문서를 만드는 순간 관리문서를 고친다**. 정리라는 단계가 없고 사용성은 여러 서비스에서 입증됐다. 다만 CDP 는 **여러 사람이 같은 지식을 쓴 적이 없다**.
- kmd 는 여러 사람을 생각해 「기록 → (나중에 모아서) 정리 → 문서」를 넣었다. 지금 와서 보면 정리가 들어온 까닭 넷 가운데 셋은 정리 없이 저장 단계에서 풀린다.

| 까닭 | 정리 없이 풀리나 |
|---|---|
| ① 권한 문(쓰기 자리가 원본을 바로 바꾸면 안 된다) | 풀린다 — 정리는 사람 검토가 아니라 LLM + 값 검사다. 같은 검사를 저장 순간에 한다 · 값 바꿈도 검사를 넘으면 바로 넣고 이력에 남긴다(K-D13) |
| ② 동시 쓰기 | 풀린다 — 지문(base) · `E_CONFLICT` 가 이미 있다. 다시 읽고 다시 댄다 |
| ③ 여러 기록을 모아 매끄럽게 | 장부에서 거의 쓰이지 않았다 → 가끔 거는 「문서 다듬기」로 |
| ④ 쓴 사람이 없는 원천(파일 · 가져올 곳) | **이것만 Claude 가 대신 지어야 한다** → 들어온 그때 하나씩 기록 + 문서 |

- 정리는 맥락이 가장 많을 때(고친 그 세션) 쓰지 않고, 기록으로 납작하게 만든 뒤 나중에 다른 Claude 가 다시 짓는다. 장부의 둔 까닭 상위 셋(그사이 없어짐 46 · 초안 못 받음 31 · 기록 값이 글에 없음 27)이 이 구조에서 나온다. 같은 비용이면 CDP 방식이 결과가 낫다.
- 11-02 에 정한 「제안」(권한 모델 7절: 세션이 기록과 조각을 같이 보내 저장 순간에 넣는다)이 이미 CDP 모델이다. 이번 개편은 그것을 **모든 채널의 기본**으로 만든다.

## 1. 정한 것

| # | 정한 것 | 까닭 |
|---|---|---|
| K-D1 | 모든 채널은 **기록과 문서(조각)를 한 번의 저장**으로 만든다. 모아서 나중에 하는 정리는 사람 기록에서 걷는다 | 미루면 맥락을 잃고 그사이 문서가 바뀐다 · 반영 대기가 쌓여 문서가 낡는다 |
| K-D2 | 들어갈지는 채널과 상관없이 **서버의 저장 검사 한 곳**(`core/save.js` · 꼴 `E_FORMAT` · 값 대조 · 지문 · 권한 7절)이 정한다. 스킬은 글을 짓는 쪽일 뿐 | 채널이 늘어도 기준이 하나 |
| K-D3 | 팀 반영 채널은 다섯: 세션 · 고치기 · 파일넣기 · 가져올 곳 · 보내기 | — |
| K-D4 | **문서 고치기**는 Claude 없이: 고친 글 그대로 저장 + 이력(`log/`) | 원천이 이미 사람이 쓴 문서 글 |
| K-D5 | **기록 고치기**는 원래 기록을 두고 **정정 기록**을 새로 만든다. 문서 반영은 규칙(값 치환) 먼저, 안 되면 LLM(팀 구독) | 이력이 깨지지 않고 다른 기록과 같은 길을 탄다 · 단순 정정은 Claude 없이 끝난다 |
| K-D6 | 팀 화면에서 생긴 Claude 일(파일넣기 · 기록 고치기의 LLM 갈래)은 **팀 구독(팀 일꾼)** | 양이 적다 · 팀 화면은 팀 서버에만 붙는다 |
| K-D7 | **대량 파일 넣기는 내 PC 의 Claude Code 스킬 + 파서 명령**, 내 구독. 팀 서버에는 저장만 간다 | 파일 넣기 비용의 대부분은 Claude 호출 · 팀 일꾼 하나의 구독 한도가 병목 |
| K-D8 | **팀 사용자에게 개인 프로그램은 필요 없다**. 개인 프로그램은 개인 지식을 쓸 때만 | 상주 프로그램이 꼭 필요한 이유는 「팀 화면 일을 사람 없이 내 구독으로」 하나뿐이었고, 그 길은 걷었다(5절) |
| K-D9 | 파서는 **대량 넣기를 처음 할 때** 받는다(`/a/` 한 줄에 늘 넣지 않는다) | node 포함 수십 MB · 모든 팀 사용자가 받을 까닭이 없다 |
| K-D10 | 원본 파일 첨부(`docs/assets`)는 **옵션 · 기본 해제** | 대량 넣기의 바이트가 팀 서버로 몰리지 않게 |
| K-D11 | 가져올 곳은 사람이 없는 일이라 **팀 일꾼이 맡되, 들어온 그때 하나씩** 기록 + 문서 | PC 가 꺼져 있을 수 있고 DB · 서버 폴더는 서버 쪽에서 닿는다 |
| K-D12 | 「개인 구독 로그인」은 kmd 가 하지 않는다. Claude Code 자체 로그인을 **확인 · 안내만** 한다 | 로그인은 이미 PC 의 Claude Code 에 있다 |
| K-D13 | 쓰기 자리의 **값 바꿈 조각도 검사를 넘으면 바로 넣는다**(확인 대기 없음). 지식관리자 · 쓴 사람에게 따로 알리지 않고 **이력(옛 값 → 새 값 · 되돌리기)으로만** 남긴다 | 기다리는 동안 문서가 틀린 값을 들고 있지 않다 · 대기 목록이 쌓이지 않는다 (11-03 정함) |
| K-D14 | 팀 화면 파일넣기 한도는 **한 번에 20개** | 넘는 것은 Claude Code 대량 넣기로 (11-03 정함) |
| K-D15 | 대량 넣기의 git 묶음은 **파일마다 한 묶음** | 파일 하나 = 저장 하나 = 묶음 하나 · 되돌리기 단위가 맞는다 (11-03 정함) |
| K-D16 | 개인 프로그램 사용자의 팀 대량 넣기도 **Claude Code 스킬 하나(`kmd-team-import`)로 통일**. 개인 프로그램 안에 팀 넣기를 따로 두지 않는다 | 길이 하나면 스킬 · 파서 · 판 맞추기가 한 벌 (11-03 정함) |

## 2. 채널 · 시작 자리 · 구독

| 채널 | 시작 자리 | 원천 | 도는 곳 · Claude | 기록 + 문서(한 번의 저장) |
|---|---|---|---|---|
| 세션 | Claude Code | 세션 작업 | 내 PC · 내 구독 | 세션 스킬 `kmd-team-save` |
| 고치기(문서) | 팀 화면 | 사람이 고친 글 | 팀 서버 · Claude 없음 | 글 그대로 + 이력 |
| 고치기(기록) | 팀 화면 | 고친 기록 → 정정 기록 | 팀 서버 · 규칙, 안 되면 팀 구독 | 정정 기록 + 조각 |
| 파일넣기(적은 수) | 팀 화면 | 여러 꼴 파일 | 팀 서버 파서 · 팀 구독 | `claude -p` 들이기 스킬 |
| 파일넣기(대량) | Claude Code 스킬 | 여러 꼴 파일 | 내 PC 파서 · 내 구독 | 들이기 스킬 → 팀 저장 |
| 가져올 곳 | 시계(팀 서버) | 문서 폴더 · git · DB | 팀 서버 · 팀 구독 | `claude -p` 들이기 스킬(하나씩) |
| 보내기 | 개인 프로그램 | 개인 md(팀 기준과 다를 수 있음) | 내 PC · 내 구독 | `claude -p` 보내기 스킬(팀 `section` · 지문을 읽고 조각으로) |
| (개인) 파일넣기 | 개인 프로그램 | 여러 꼴 파일 | 내 PC · 내 구독 | 개인 지식 — 이미 한 번에 넣는다 · 같은 들이기 스킬 |

팀 구독은 **사람이 없는 일(가져올 곳)과 팀 화면의 적은 일**만 맡는다.
