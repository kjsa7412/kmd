## 1. 결론

- **공식 기능 하나, 이름은 「문서 짜임」 그대로.** 지금의 문서 짜임 화면(문서 옮기기 · 이름 · 새 문서 · 폴더 · 차례)을 넓혀 두 가지 일을 한 페이지에서 한다.
  - **바탕 세우기**: 있던 문서 폴더(원본)로 빈 지식의 짜임(폴더 · 문서 · 항목 · 이름 · 갈래 · 차례)을 잡고 첫 글을 지어 세운다.
  - **짜임 다시 잡기**: 있는 지식의 짜임을 바꾼다. 문서 옮기기 · 이름 · 차례에 더해 **항목 옮기기 · 항목 이름 · 나누기 · 합치기 · 빈 문서 걷기**(빈 문서 걷기는 13절 2 를 정하면 · 그 전에는 「보관」 폴더로 옮긴다).
- **구조안(plan) 하나 · 엔진 하나.** 두 일 모두 「새 짜임」 을 적은 구조안 하나를 만들고, 엔진(`core/shape.js` + 넓힌 `core/restructure.js`)이 「지금 짜임 → 새 짜임」 차이를 걸음(step)으로 풀어 넣는다. 바탕 세우기는 「지금 짜임 = 빈 지식 · 재료 = 원본」 인 특수한 경우다.
- **넣는 길은 둘로 갈린다.** 글이 그대로인 걸음(문서 · 항목 옮기기 · 이름 · 차례 · 장부 줄)은 값 검사 없이 한 커밋(지금 문서 짜임과 같은 자리 · 권한 모델 7-1). 글을 다시 쓰는 걸음(나누기 · 합치기 · 새 항목 · 문서 요약)은 저장 문(`hub.save` 의 새 `opt.shape`) + 값 대조(`checkShape`)를 지난다. 이 값 대조는 팀 · 개인 모두에서 돈다(권한 모델 7 「새 저장 검사는 팀에서만」 의 이 채널만의 예외 · 4-5).
- **입구 둘 · 엔진 하나.**
  - 화면: **페이지 1개(문서 짜임)**. 사람이 보고 고르고 승인하는 곳이다. 승인은 셋: 걸러 두기 표 · 구조안 나무(사람이 끌어 고친다 · Claude 에게 구조안 받기) · 끝 진단. Claude 일은 화면 뒤 `claude -p`(`core/claude.js` `runClaude`) 일감이다.
  - 세션 스킬 `kmd-seed`: 파일 수백 · 스캔 pdf 처럼 화면 한도를 넘는 큰 일의 재료(조사 · 글 · 카드 · 구조안)를 「짜임 꾸러미」 폴더로 만든다. 꾸러미는 같은 페이지에서 열어 같은 승인 · 같은 엔진으로 넣는다. 스킬은 지식에 직접 쓰지 않는다.
- **페이지 자리.** 같은 화면 코드 하나(`app/main.js` 의 문서 짜임 화면)를 두 프로그램이 저마다 자기 지식에 붙인다. 지금 문서 짜임이 이미 이 꼴이다(`app/main.js:753 · 756`). 그래서 페이지는 하나다.
  - 팀 화면: 팀 지식의 **짜임 다시 잡기**만. Claude 는 팀 일꾼. 걸음은 팀 서버 안에서 돈다.
  - 개인 화면: 개인 지식의 **바탕 세우기 · 짜임 다시 잡기**, 그리고 이은 팀의 **빈** 팀 지식에 대한 **바탕 세우기**(권장안 (나): 원본 조사 · 짓기는 내 PC 에서, 팀에는 구조안 · 목표 글 · 재료 글을 기기 열쇠로 팀 걸음 문에 보낸다 · 걸음은 팀 서버가 스스로 다시 만든다 · 지식 보내기와 같은 길).
  - 팀 화면에서 개인 프로그램을 부르는 길은 만들지 않는다. 빈 팀 지식의 팀 화면은 「바탕은 원본이 있는 PC 의 개인 프로그램 › 문서 짜임에서 세운다」 는 글만 보인다.
- **글 걸음이 있으면 연습 판에서 끝까지 해 본 뒤 넣는다.** 글 걸음이 있는 구조안은 지식의 사본(연습 판)에 모든 걸음을 먼저 넣어 보고 끝 진단(승인 3)을 받은 뒤, 같은 구조안을 진짜 지식에 차례로 넣는다. 글이 그대로인 바꾸기뿐이면 지금 문서 짜임처럼 [저장] 한 번(마른 실행 요약 → `ask()` → 한 커밋)이다(5-4). v1 의 「사본 push → 백업에서 받기」 는 버렸다(12절).
- **넣은 뒤 되돌리기는 짜임으로.** 짜임으로 다시 쓴 항목은 이력의 항목별 [되돌리기]를 쓰지 않는다. 넣기 직전 짜임을 남겨 두고 「되돌리기 구조안」 을 만들어 같은 엔진으로 되돌린다(4-3 · 5-3 6).

## 2. 지금 길로 왜 부족한가

**개인 폴더 들이기는 짜임을 짜지 않는다.**
- `server/hub.js:1184-1222`: 파일 하나가 그대로 문서 하나가 된다(`hub.js:1215` importFiles `asDocs`).
- 원본 폴더 나무 · 파일 이름 · 판(최종 · v2)이 지식 짜임으로 굳는다. 작성기준 7절 「파일 이름을 문서 이름으로 · 원본의 머리를 항목으로 그대로 쓰지 않는다」 에 어긋난다.
- 300 파일 · 200MB 한도(`hub.js:1205`). 팀에서는 막혀 있다(`hub.js:1185` E_FORBIDDEN).

**팀 대량 넣기는 문서가 이미 있다는 전제다.**
- 쓰기 자리는 새 문서를 세울 수 없다(`hub.js:786` gatePrepare `newDoc: hub.canDirect`).
- 갈래 장부가 생기면 G4 가 장부 밖 문서를 거절한다(`core/guard.js:225-243` guardNewDoc).
- 스킬도 「새 문서가 필요해 건너뜀」 으로 빠진다(`agent/team/skills/kmd-team-import/SKILL.md` 3단계).

**빈 지식 세우기는 뼈대만 남긴다.**
- `hub.js:1161-1166`: `empty` 면 README(+ 팀이면 `_members.md`)만 커밋한다. `empty` 가 아니면 `docs/처음.md` 자리 글이 선다(`hub.js:1165`). 팀 화면의 지식 추가는 `{ kind: 'new', name }` 만 보내므로(`app/main.js:1079`) 팀 화면에서 세운 새 지식에는 늘 `docs/처음.md` 가 선다.
- 새 팀 지식의 주인은 세운 총괄 관리자다(`hub.js:1155`). 짓는 사람이 다르면 지식관리자 자리를 먼저 받아야 한다.

**문서 짜임은 문서 단위까지만이다.**
- `core/restructure.js:134` planRestructure 는 moves · creates · titles · dirs · order 만 안다. 항목(`## 머리`)을 다른 문서로 옮기는 길이 없다.
- 링크 다시 쓰기(`restructure.js:65-104`)는 경로만 바꾸고 `#머리` 조각은 그대로 둔다(항목이 옮겨지면 링크가 깨진다).
- 자리 장부는 문서 경로 글자만 바꾼다(`restructure.js:208-219`). 항목 단위 줄(`## 머리`)을 옮길 줄 모른다.
- 새 문서는 `# 이름` 한 줄만 쓴다(`restructure.js:278`). 대장 갈래의 패턴 줄(`upsertPatternRow`)은 `core/save.js` 의 새 문서 조각에만 있다(`save.js:409-415`).
- 항목 이름 바꾸기 · 지우기 함수는 있다(`core/sections.js:295-317` removeSection · renameSection: 참고 줄도 같이 지우거나 옮긴다). 하지만 그 길은 화면 고치기(`hub.js:1629` edit · 지식관리자)뿐이고, 팀 저장 문 입력에서는 막혀 있다(`hub.js:774` · `save.js:164`).

**나누기 · 합치기를 받을 검사가 없다.**
- `core/gate.js:136` checkSection 은 항목 하나의 옛 글 대 새 글이다. 여러 항목을 하나로(합치기) · 하나를 여럿으로(나누기) 다시 쓴 글의 값을 견줄 길이 없다.
- checkSection 은 기록 본문 · 제목의 값도 근거로 센다(`gate.js:152 · 161`). 기록 본문도 Claude 가 지으면 같이 지어낸 값이 넘는다. 다듬기(`core/ingest.js:331-357` polishToSave)는 「항목마다 값 장부가 같다」 로 막는데, 이것이 이번 값 대조의 선례다.
- 팀 저장 문은 늘 gatePrepare → checkSection 을 돌리고(`hub.js:786`), 채널 목록(`hub.js:549` SAVE_CHANNELS)에 없는 채널은 null 이 되며(`hub.js:1450`), core 의 `structure` 는 `opt.edit.structure` 로만 켜진다(`hub.js:805`). 그래서 이 기능의 글 걸음을 지금 `hub.save` 로는 넣을 수 없다(8-2 에서 넓힌다).

**v1(세션 스킬 + 사본 push + 백업에서 받기)의 막힌 곳.**
- push 하는 순간부터 받기 전까지 그 지식이 팀 전체에 읽기만이다(`core/backup.js:269-275` · behind).
- 짓는 동안 서버가 `_members.md` 를 스스로 커밋하면 갈라진다(moved). 잠금으로도 못 막는다.
- 받기는 새 검사 오류만 막고 쓴 사람의 자리 · 저장 문 경유는 보지 않는다(`hub.js:4601` backupPull).
- 개인은 `kmd restore --practice` 가 없으면 스크래치 폴더가 백업 자리로 붙는다.
- 화면이 없어 사람이 보고 고르는 일(걸러 두기 · 구조안)이 터미널 표에 갇힌다.

## 3. 기능 정의

### 3-1. 바탕 세우기

| 무엇 | 정한 것 |
|---|---|
| 대상 | **빈 지식**: docs/ 문서 0 · work/ · log/ 기록 0 · `_vocab.md` · `_managed.md` · `_forms.md` · `_order.md` 없음. `docs/처음.md`(자리 글)만 있으면 빈 것으로 보고 마감 때 걷는다. 새 개인 지식은 6 넣기의 첫 걸음에서 만든다(그만두면 빈 지식이 남지 않게 · 5-3 1) |
| 재료 | 원본 폴더(이 PC 의 경로) 또는 짜임 꾸러미(세션 스킬이 만든 폴더 · 6절) |
| 결과 | 갈래 장부 · 폴더 · 문서(+ 요약) · 항목 글 · 이름 장부 · 차례 · 재료 기록(work/) · 글 기록(work/ · 태그 `shape`) · 마감 이력(log/) |
| 하지 않는 것 | 원본 파일을 지식에 싣지 않는다(출처는 재료 기록의 `ingest/<경로>` · `md/<sha16>` 표지 · 마감 이력의 원본 목록). 옛 판 · 같은 글은 기본으로 빼고, 비밀 의심 파일은 기본으로 보류한다 |
| 이어받는 길 | 넣은 뒤의 파일은 가져오기 · 파일 넣기 · 대량 넣기(`kmd-team-import`) · 개인 `kmd-build` 가 이어받는다 |

### 3-2. 짜임 다시 잡기

| 바꾸기 | 뜻 | 글 | 넣는 길 |
|---|---|---|---|
| 문서 옮기기 · 문서 이름 · 제목 맞추기 | 지금 문서 짜임 그대로 | 그대로 | 짜임 커밋(값 검사 없음) |
| 폴더 · 차례 | 지금 문서 짜임 그대로 | 그대로 | 짜임 커밋 |
| 새 문서(빈) | `# 이름` 한 줄 + 갈래 줄(+ 대장이면 패턴 줄) | 없음 | 짜임 커밋 |
| **항목 옮기기** | `## 머리` 와 그 아래 글을 다른 문서(또는 같은 문서의 다른 차례)로 | 글자 그대로 | 짜임 커밋 |
| **항목 이름** | `## 머리` 만 바꿈(`renameSection`) | 글자 그대로 | 짜임 커밋 |
| **나누기** | 항목 하나의 글을 둘 이상의 항목(같은 문서 또는 다른 문서)으로 다시 씀 | 다시 씀 | 저장 문 + 값 대조 |
| **합치기** | 둘 이상의 항목 글을 한 항목으로 다시 씀 | 다시 씀 | 저장 문 + 값 대조 |
| 문서 요약 | 문서 `# 제목` 아래 1~3문장 요약(작성기준 3절 3) | 새로 씀 | 저장 문 + 값 대조 |
| **빈 문서 걷기** | 항목 0 · 요약 0 · 들어오는 링크 0 이 된 문서를 지움 | 없음 | 걷기 커밋(13절 2 를 정하면 · 정하기 전에는 tidy 가 빈 문서를 「보관」 폴더로 옮긴다 · 작성기준 6-1) |

- **문서 나누기 · 합치기는 항목 옮기기로 풀린다.** 항목들을 그대로 두 문서로 가르거나 한 문서로 모으면 새 문서 + 항목 옮기기 + 빈 문서 걷기다(값 검사 없음). 글을 다시 쓰는 것은 항목 단위 나누기 · 합치기와 문서 요약뿐이다. 엔진은 구조안에서 이것을 스스로 가른다(4-3).
- **항목 지우기는 하지 않는다.** 지금 항목은 모두 새 짜임의 어느 항목의 출처(`from`)여야 한다. 지울 항목은 지식관리자가 문서 고치기에서 지운다(`hub.js:1629` edit). 서버가 이것을 지킨다: 걷기(remove) 조각은 엔진이 구조안에서 스스로 만든 출처 걷기뿐이고, 입력으로는 받지 않는다(4-8).
- 원본이 주인인 문서(표지 `watched`)는 문서 · 항목 모두 옮기지 않고 나누지도 합치지도 않는다.

### 3-3. 구조안(plan) 꼴

| 칸 | 뜻 |
|---|---|
| `v` · `kind` | 꼴 판 · `reshape`(다시 잡기) 또는 `seed`(바탕 세우기) |
| `base` | 구조안을 지을 때 본 지금 짜임의 지문(`shapeFp` · 4-6: 문서 id · 머리 목록 · 장부 셋. 항목 글은 넣지 않는다). 넣을 때 지금과 다르면 다시 맞추기 |
| `forms` | 새 짜임의 갈래 장부(있는 갈래는 그대로 적는다). `kind` 사건 · 대장 · 대상 · 서술(`guard.js:180`), 대장은 `pattern` |
| `dirs` | 문서가 없어도 남길 폴더 |
| `docs[].id` | 새 짜임의 문서 id(docs/ 아래 · `.md` 없이) |
| `docs[].was` | 이 문서가 지금 어느 문서인가(문서 옮기기 · 이름). 없으면 새 문서 |
| `docs[].intro` | 문서 요약(`parseDoc` 의 `intro` · `core/sections.js:260`). `null`(지금 그대로 · 새 문서면 없음) · `{ "ask": "…" }`(Claude 에게 짓게) · `{ "text": "…" }`(사람이 쓴 글) |
| `items[].h` | 새 짜임의 항목 머리 |
| `items[].from` | 이 항목의 글이 어디서 오나(지금 문서 id · 머리). 하나 = 옮기기 · 이름 · 그대로, 둘 이상 = 합치기, 같은 출처를 둘 이상의 항목이 쓰면 = 나누기 |
| `items[].part` | 나누기에서 이 항목이 가져갈 몫을 말로(Claude · 사람이 쓴 글의 길잡이 · 검사는 값으로) |

| `items[].text` | (선택) 사람이 쓴 글. 없으면 Claude 가 짓는다 |
| `names` | 새 짜임에서 이름 장부의 정확한 자리(종류:값 → 문서 · 항목). 출처 항목에 걸려 있던 이름은 모두 어딘가에 다시 놓여야 한다 |
| `order` | 폴더마다 차례(`core/order.js` 꼴) |
| `empty` | 걷을 문서(옮기기가 끝나면 빈 문서여야 한다) |
| `skip` | (바탕 세우기만) 넣지 않는 재료 `[{ "src", "why" }]` |

바탕 세우기 구조안은 `kind: "seed"` · `base` 는 빈 지식의 지문 · 문서마다 `was: null` · 항목마다 `src` 다. 예: `{ "h": "web01", "src": ["m:3f2a9c01d4e5b6a7", "m:91b0e4d2a8c3f105"] }`.

### 4-2. 단계

```
구조안 → planCheck → (글 걸음이 있으면) 연습 판에 걸음 모두 → 끝 진단(승인 3) → 진짜에 같은 구조안으로 걸음을 다시 만들어 차례로 → 마감
```

| 걸음(step) | 하는 일 | 커밋 | 기록 · 이력 | 검사 |
|---|---|---|---|---|
| `forms` 갈래 장부 | 구조안 forms 가 지금과 다르면 `hub.save({ record, forms }, { channel: 'shape', shape })`(지식관리자 곧바로) | 하나 | log/ `ledger`(`save.js:552`) | 갈래 꼴(`cleanForms`) |
| `frame` 짜임 | 문서 옮기기 · 이름 · 제목 · 새 문서(+ 갈래 줄 · 대장 패턴 줄) · 폴더 · 차례 · **항목 옮기기 · 항목 이름** · 같이 고칠 링크 · 장부 | 하나 | log/ `structure` | 이름 꼴 · 겹침 · watched · G4 · 갈래 머리 꼴 · 섞인 자리 · 글자 그대로 |

| `write` 글 | 나누기 · 합치기 · 새 항목 · 문서 요약. 한 단위(나누기 하나 · 합치기 하나 · 바탕의 문서 하나)가 한 저장 | 단위마다 하나 | **work/** `shape` | 저장 문 + `checkShape` + 지문 |
| `tidy` 걷기 | 빈 문서 걷기(13절 2 전에는 「보관」 폴더로 옮기기) · 차례 마저 맞춤 · 바탕이면 `docs/처음.md` 걷기 | 하나(없으면 0) | log/ `structure` | 빈 문서인지 다시 봄 |
| `seal` 마감 | 요약 이력(이 짜임 일의 「합치기: …」 · 「나누기: …」 줄 모음) · (바탕이면) 쓰인 재료에 reflects | 하나 | log/ `shape-done` | 서버가 reflects 를 셈(4-7) |

- 걸음 차례는 이대로 고정이다. `frame` 이 `write` 보다 앞선다: 합치기 · 나누기의 목표 문서가 먼저 서 있어야 하고, 글이 그대로인 항목은 이미 제 자리에 있어야 같은 문서 안 차례(`sections[].before`)를 정할 수 있다. 나누기 · 합치기의 출처 항목은 `frame` 에서 옮기지 않는다(그 자리에서 `write` 가 걷는다).
- 걸음마다 **멱등**이다. 걸음 id(`<work>/<n>`)를 기록 표지(`shape/<work>/<n>` · 서버가 다는 태그)로 남긴다. 같은 표지를 단 기록이 들어감(`in`)이면 그 걸음을 건너뛴다. 넣지 못함(`held`)이면 그 걸음을 다시 넣되 새 기록에 `record.fixes:[held 기록]` 을 단다(권한 모델 7 「고쳐 다시 저장」). `sameKey`(`hub.js:596-604` · held 를 빼고 찾는다)를 그대로 쓰지 않고 이 판정을 엔진이 한다. `frame` · `tidy` 는 짜임 일 장부의 「넣은 걸음」 과 이력 표지(`structure` 이력에 `shape/<work>/<n>`)로 같은 판정을 한다.
- 걸음마다 **지문**을 지닌다. `frame` · `tidy` 는 `stepFp`(그 걸음이 건드리는 문서들의 머리 목록 + 옮기는 항목 글 sha16 + 장부 셋 + docs/ 문서 id 목록), `write` 는 출처 항목의 `base`(sha16). 어긋나면 `E_CONFLICT` 로 그 걸음에서 아무것도 쓰지 않고 선다(4-6). 건드리지 않는 문서의 글이 바뀐 것으로는 서지 않는다.
- 커밋 뒤(백업 걸기 · 오늘 바뀐 것 줄 · 알림)는 던지지 않는다(try/catch + log). 지금 `hub.restructure`(`hub.js:1606-1610`)와 같다.

### 4-3. 차이 풀기 규칙(`diffPlan`)

> **걸음 입력 오류(P7 · P-D24 · KMD_저장승인_설계)**: 차이 풀기 규칙 · 걸음 번호 · 이어 넣기 · 잠금 · 그만두기 · 되돌리기는 그대로다. 저장 승인 모드 지식(새 지식)에서 걸음 재료가 저장에 걸리면 「넣지 못함」 대신 걸음 입력 오류다: 아무것도 쓰지 않고(기록 · 넣지 못함 없음) 넣기가 그 걸음에서 멈춘다(장부 `stage: 'stopped'` · `last: { n, fail }`). 끝 진단 blocker 는 「걸음 실패」 · 지식관리자가 구조안을 고쳐 다시 검사(넣다 선 일 다시 검사 · 넣은 걸음 · 넣기 직전 짜임 그대로) → 해 보기 → 넣기. 저장 승인 전(held 모드) 지식은 P11 까지 넣지 못함 그대로.

지금 짜임 `S`(문서마다 항목 머리 · 글 sha · 이름)와 구조안 `P` 를 견주어 걸음 재료를 만든다. 걸음 재료는 언제나 서버(또는 연습 판을 부르는 엔진)가 `S` 를 새로 읽어 만든다. 사람 · 화면 · PC 가 보낸 걸음 재료(ops · remove)를 받지 않는다(4-8).

| 경우 | 판단 | 걸음 |
|---|---|---|
| 문서 옮기기 · 이름 | `P.docs[i].was = a` 이고 `id ≠ a` | `frame.moves` |
| 새 문서 | `was` 없음 | `frame.creates`(갈래가 대장이면 패턴 줄도) |
| 항목 그대로 | `from` 하나 · 같은 문서(옮긴 뒤 기준) · 같은 머리 | 없음(차례만 바뀌면 `frame.items` 의 차례) |
| **항목 옮기기** | `from` 하나 · 다른 문서 · 그 출처를 다른 항목이 쓰지 않음 | `frame.items { from: {doc, h}, to: {doc, h, before} }` |
| **항목 이름** | `from` 하나 · 같은 문서 · 다른 머리 | `frame.items`(to.h 만 다름 · `renameSection`) |
| **합치기** | `from` 둘 이상 | `write` 단위 하나: 목표 새 항목 + 출처 항목들 걷기 |
| **나누기** | 같은 출처 항목을 둘 이상의 `items` 가 `from` 으로 씀 | `write` 단위 하나: 목표 항목들 + 출처 걷기(목표 하나가 출처와 같은 문서 · 같은 머리면 그 항목은 고쳐 쓰기) |
| 나누기 + 합치기가 엮임 | 출처 집합과 목표 집합이 서로 걸림 | 엮인 덩이 전체가 `write` 단위 하나(50 조각 안 · 넘으면 planCheck 걸림) |
| 문서 요약 | `intro` 가 `ask` · `text` | 그 문서의 `write` 단위에 `intros` 로 |
| 새 항목(바탕) | `src` 있음 | 문서마다 `write` 단위 하나(50 조각 넘으면 문서를 나눈 단위) |
| 빈 문서 걷기 | `P.empty` 에 있고, 옮김 · 걷기 뒤 항목 0 · 요약 0 · 들어오는 링크 0 | `tidy.drops` |
| 지금 항목이 어디에도 없음 | 덮임 빠짐 | planCheck 걸림(지우기는 이 기능이 하지 않는다) |

**항목 옮기기 · 이름(짜임 커밋 · 값 검사 없음)이 같이 고치는 것**

1. **글**: `## 머리` 줄과 그 아래 글(다음 같은 깊이 이상 머리 앞까지 · `### ` 포함)을 그대로 떼어 목표 문서의 `before` 머리 앞(없으면 참고 블록 앞 끝)에 넣는다(`moveSection`). 머리만 바뀌면 `renameSection`(머리 줄과 참고 줄 이름을 같이 옮긴다 · `sections.js:305-317`). 떼어 낸 글과 넣은 글이 글자 그대로인지 엔진이 견준다(다르면 넘어짐 · 저널 되돌림).
2. **글 속 상대 링크**: 옮긴 항목 글 안의 상대 링크(다른 문서 · 첨부)를 새 문서 자리 기준으로 다시 쓴다(`rewriteLinks` 를 항목 글에만 · 폴더 깊이가 다를 때).
3. **들어오는 링크**: 모든 문서의 `x.md#머리` · 같은 문서의 `#머리` 가 옮긴 항목을 가리키면 새 문서 · 새 머리로 바꾼다(지금 `rewriteLinks` 는 `#` 조각을 그대로 둔다 · `restructure.js:76-79` · 조각 다시 쓰기를 더한다). 옮긴 항목이 원래 문서를 `#머리` 로 가리키던 링크는 `원래.md#머리` 로 바꾼다.
4. **참고 블록**: 출처 문서 참고 블록의 그 항목 줄들을 `moveSection` 이 떼어(`splitRef`) 목표 문서 블록에 새 머리 이름으로 붙인다(`withRef` · `mergeLog`). 줄 속 `../work/<id>.md` 는 목표 문서 깊이로 다시 쓴다. 손으로 문자열을 붙이지 않는다(`core/sections.js` 로만).
5. **`applied` 표지**: 항목 글에 붙은 `<!-- applied: … -->` 는 글과 같이 옮긴다(그래서 기록 상태 넣음 · 안 넣음이 바뀌지 않는다).
6. **자리 장부(`_managed.md`)**: `placeExact` 로만 고친다.
   - 정확한 줄(`` `종류:값` | `docs/출처.md` | `## 머리` ``)은 제자리에서 문서 · 머리를 새것으로.
   - 패턴 줄(`` `종류:*` | `docs/출처.md` | `## {값}` ``)로 그 항목에 닿던 이름은, 옮긴 뒤에도 닿게 그 이름마다 정확한 줄을 패턴 줄 **위에** 더한다(위에서 먼저 걸리는 줄을 쓴다 · `core/registry.js:7 · 40-43`). 닿던 이름은 `coordsOfSection`(`core/knowledge.js:222`)으로 구한다.
   - 목표 문서에 패턴 줄이 있고 이름 값 = 새 머리면 정확한 줄을 더하지 않는다.
7. **기록의 건드린 이름(touches)**은 그대로다. 장부가 따라오므로 이름 → 항목이 그대로 닿는다.

- 목표 문서에 같은 머리가 있음, 또는 머리 앞부분이 겹침(「배포」 와 「배포 절차」: `sectionOf` 가 앞부분으로도 집기 때문 · `knowledge.js:193` · `hub.js:1648` 과 같은 규칙).
- 출처 · 목표 문서가 원본이 주인(`watched`).
- 목표 문서의 갈래가 사건 · 대장인데 머리가 그 꼴이 아님(`headingFits` · `guard.js:257`).
- 항목 글에 저절로 채우는 표가 있고 출처 · 목표의 가져올 곳(`_sources.json` `into`)이 그 항목을 가리킴(표는 가져올 곳이 채운다 · 옮기면 `into` 를 같이 고친다 · 고칠 수 없으면 거절).
- 옮긴 뒤 자리 잃는 이름이 생김(위 6 을 지나고도 닿지 않는 이름).
- 섞인 자리: 옮기거나 이름을 바꾸는 항목에 아직 안 들어간 개편 전 기록(`legacyPend`)이 걸려 있음(code `legacy-mix` · `gate.js:142` 와 같은 글 · 권한 모델 7 「섞인 자리」).

**나누기 · 합치기 · 새 항목 · 문서 요약(저장 문 · 값 대조)**

- `hub.save(ctx, kn, { record, sections, names, intros }, { channel: 'shape', shape: { work, step } })` 한 번이 단위 하나다. 채널은 서버 코드가 정한다(`http.js:1155-1162` 처럼 본문에서 받지 않는다). `hub.save` 는 새 `opt.shape` 를 받아 ① 채널 `shape` 를 받아들이고(SAVE_CHANNELS · 속도 한도는 세지 않음) ② 팀 입력 검사의 걷기 막기(`hub.js:774`)를 이 옵션에서만 건너뛰고 ③ 팀 길의 gatePrepare 대신 `checkShape` 로 가르는 prepare 를 쓰고 ④ core save 에 `structure: true` 를 넘긴다(지금은 `opt.edit.structure` 로만 켜진다 · `hub.js:805`). `opt.shape` 는 서버 안 함수(`hub.shapeStep`)만 단다.
  - `sections`: 목표 항목마다 `{ doc, heading, content, before? }`(이미 있는 항목을 고쳐 쓰면 `base`), 출처 항목마다 `{ doc, heading, remove: true, base }`. 이 조각들은 엔진이 저장 줄 안에서 새로 읽은 지식과 구조안으로 만든다. 사람 · PC 가 보낸 것은 목표 글(`content`)과 요약 글뿐이다(4-8).
  - `names`: 출처 항목에 닿던 이름을 목표 항목으로 다시 놓는다(구조안 `names` · `placeExact` · 패턴 줄 위에). 출처에 닿던 이름이 하나라도 목표 밖이면 planCheck 에서 이미 걸린다.
  - 참고 블록: 출처 항목의 참고 줄은 removeSection 이 버리므로(`sections.js:295-303` `ref.delete`) 엔진이 걷기 전에 먼저 읽어, 목표 조각의 `log`(replaceSection 의 `log` 인자 · `sections.js:323`)로 합쳐 싣고 이 저장의 기록 줄을 더한다. 같은 저장 안에서 목표를 먼저 쓰고 출처를 걷는다. 나누기면 출처의 줄을 목표마다 같이 싣는다.
  - `applied` 는 이 저장의 기록이다(`save.js:615`). 그래서 출처 항목에 아직 안 들어간 기록(`recordState` 가 `pend` 인 사람 기록 · 개편 전 기록)이 걸려 있으면 그 기록이 이 저장 한 번으로 조용히 「넣음」 이 된다(`reflectedIn` 은 applied 기록이 늦으면 넣음으로 본다 · `knowledge.js:241-249`). 그래서 **planCheck 가 그런 출처의 나누기 · 합치기를 걸림으로 한다**(「먼저 넣거나 두기로 정한다」 · 섞인 자리 `legacy-mix` 와 같은 꼴). 출처에 대기 기록이 없을 때만 옛 기록 상태가 그대로다. 저장 줄 안에서도 「단위가 닿는 이름에 걸린 기록들의 `recordState` 앞뒤 같음」 을 다시 보고, 다르면 `E_CONFLICT` 로 아무것도 쓰지 않는다.
- 기록은 **work/** 에 둔다(태그 `shape` · RESERVED_TAGS 에만 더하고 LOG_TAGS 에는 넣지 않는다). 그래서 기록 상태(`recordState` 는 work/ 기록만 셈 · `knowledge.js:178`) · 넣지 못함 목록 · 처리 길(다시 들이기 · 버리기 · 승인 · `hub.js:2475` 는 log/ 기록을 「넣지 못한 기록이 아니다」 로 거절한다)이 그대로 걸린다. 제목 「합치기: 배포 › 사전 점검 · 사후 점검 → 점검 목록」 · 「나누기: …」 · 「바탕 세움: 운영/서버」. 본문은 엔진이 짓는다(Claude 가 쓴 글을 기록 본문에 싣지 않는다 · 값 근거 구멍을 막는다 · 4-5). 건드린 이름(touches)은 목표 · 출처 항목에 닿는 이름 모두(`hub.js:1654` edit 과 같은 꼴). 바탕의 새 항목은 그 저장의 `names` coord 를 touches 로 단다(work/ 기록이므로 안 달면 「이름 없는 기록」 이 쌓인다 · `guard.js:300`). 이력 줄 모음은 마감 이력(log/ · `shape-done`)에 싣는다.
- 태그 `shape` · `shape-done` 은 `core/names.js` 의 `RESERVED_TAGS` 에, `shape-done` 은 `LOG_TAGS` 에도 더한다. 입력으로는 받지 않고(`save.js:227-228`) 저장 문이 붙인다(들이기의 `serverTags` 와 같은 길 · `save.js:233-237`). 걸음 표지 `shape/<work>/<n>` 은 `RESERVED_TAG_PREFIXES` 에 더한다.

**되돌리기와 짜임**

지금 되돌리기(`core/revert.js`)는 「표지를 처음 단 묶음」 을 `git log -S '<!-- applied: id -->' -- <지금 경로>` 로 찾고(`revert.js:16` · --follow 없음), 그 앞 판에서 머리가 같은 항목만 찾으며(`revert.js:54`), 못 찾으면 그 기록이 세운 항목으로 보고 지운다(`revert.js:58`). 쓰기 자리도 자기 기록이면 되돌린다(`hub.js:1777-1782`). 그래서 항목을 옮기거나 이름을 바꾸거나 합친 뒤 옛 기록을 되돌리면 항목 글 전체가 지워질 수 있다. 막는 법:

1. 태그 `shape` 기록(나누기 · 합치기 · 바탕 새 항목)은 이력에 [되돌리기]를 싣지 않는다(`canRevert: false` · 까닭 「짜임 일은 문서 짜임에서 되돌린다」 · 이력 줄에서 그 짜임 일로 옮겨 가는 링크만). 서버 `revert` 도 태그 `shape` 기록이면 `E_FORBIDDEN` 「짜임으로 다시 쓴 항목은 문서 짜임의 되돌리기 구조안이나 문서 고치기로 되돌린다」.
2. 표지를 단 묶음이 짜임 커밋(태그 `structure` 이력과 같은 커밋)이면 `revertPlan` 이 지우지 않는다. 짜임 이력의 「옛 문서 › 옛 머리 → 새 문서 › 새 머리」 줄로 앞 판의 자리를 찾고, 못 찾으면 `E_CONFLICT` 「짜임이 바뀐 항목이다: 문서 고치기로 고친다」. 표지를 단 묶음 판에 그 머리가 없으면(뒤에 같은 문서 안에서 이름이 바뀌었거나 — 표지 수가 그대로라 `-S` 가 짜임 커밋을 못 본다 — 그 기록의 표지가 이미 있던 문서로 옮겨 왔다) 그 뒤 짜임 이력으로 앞 자리를 찾고, 못 찾으면 지우지 않고 `E_CONFLICT`.
3. 짜임 일 전체를 되돌리는 길은 「되돌리기 구조안」 이다. 넣기 직전 짜임(`readShape` 결과 · 문서 · 항목 짜임 · `shapeFp`)을 짜임 일 장부에 남겨 두고, `undoPlan` 이 그것을 새 짜임으로 하는 역 구조안을 1단계 나무에 연다. 글이 그대로인 걸음은 그대로 되돌아가고, 나누기 · 합치기는 출처 글을 git 앞 판에서 꺼내는 `write` 단위가 된다(같은 값 대조).

### 4-4. 짜임 커밋 함수(넓힌 `applyRestructure`)

```
applyRestructure(dir, { moves, creates, titles, dirs, order, items, drops }, { user, by, base, dry, step })
  items: [{ from: { doc, h }, to: { doc, h, before } }]   항목 옮기기 · 이름 · 같은 문서 차례
  drops: ['문서 id']                                      빈 문서 걷기(항목 0 · 요약 0 · 들어오는 링크 0 일 때만 · 13절 2 전에는 「보관」 으로 옮김)
  creates: ['id' | { doc, form? }]                         대장 갈래면 guardNewDoc 의 registryRow 로 패턴 줄(upsertPatternRow)
  base: stepFp(이 걸음이 건드리는 문서 머리 + 옮기는 항목 글 + 장부 + 문서 id) · 지금 structureFp 는 그대로 받는다(옛 화면 · 옛 길)
  step: 'shape/<work>/<n>'(있으면 이력 표지 · 멱등)
```

- 지금처럼 지식마다 한 줄(`save.serial`) · 저널(`core/journal.js`) · 커밋 하나 · 이력 하나(태그 `structure`). 이력 줄에 「항목 옮김: 배포 절차 › 롤백 → 운영/배포 › 되돌리기」 · 「항목 이름: …」 · 「문서 걷음: 장애 대응」 을 더한다(4-3 되돌리기 2 가 이 줄을 읽는다).
- `dry` 는 쓰지 않고 요약 · 줄마다 바뀔 것 · 고칠 링크 수 · 장부 줄 수 · 항목 옮김 수를 돌려준다(화면의 「바뀔 것」 · 단순 [저장] 의 `ask()` 글).
- 문서 꼴: 옮긴 뒤 목표 문서 글을 `checkFormat`(E_FORMAT · `core/save.js`)에 한 번 통과시킨다. 글이 그대로라 걸릴 일은 없어야 하고, 걸리면 엔진 잘못이므로 넘어진다(저널 되돌림).
- 지금 `POST /api/k/:id/structure` 와 화면의 단순 [저장](5-4 글 다시 씀 0)은 이 함수를 그대로 쓴다(`items` · `drops` 없이 부르면 지금과 같다).

### 4-5. 값 대조(`checkShape`)

> **걸음 입력 오류(P7 · P-D24 · KMD_저장승인_설계)**: 저장 승인 모드 지식에서 짜임 판정(`judgeShape`)의 결정적 오류(꼴 · 섞인 자리 · 저절로 채우는 표 · 이름을 놓을 새 항목 없음)와 저장 문의 걸림(원본이 주인 · 문서 없음 · 꼴)이 있는 글 걸음은 넣지 못함(`holdAll` · 한 덩이 넣지 못함)이 아니라 걸음 입력 오류(`E_INPUT` · `details.stepFail` · 아무것도 안 씀) + 일 멈춤이다. 앞 넣지 못함 바로잡기(`fixes`)도 없다(넣지 못함 기록이 생기지 않는다). 값 대조(지어낸 · 잃은 값)는 막지 않고 잰다(통합 I1 · P-D2 · P-D37): 끝 진단 「볼 것」 의 「값 대조」 · 측정 줄 `warned`. 저장 승인 전 지식은 `checkShape` 그대로(값도 넣지 못함).

`checkShape` 는 팀 · 개인 모두 shape 채널에서 돈다. 권한 모델 7 「새 저장 검사는 팀에서만 돈다」(`hub.js:699`)의 예외이고, 개인 프로그램의 다른 저장은 그대로다(9절 권한 모델 7-2 에 적는다).

| 단위 | 근거 | 지어낸 값 | 잃은 값 |
|---|---|---|---|
| 합치기 | 출처 항목들의 지금 글 | 목표 글의 값 ⊂ 출처 값 합 ∪ 이름 | 출처 값 합 ⊂ 목표 글의 값 |
| 나누기 | 출처 항목의 지금 글 | 목표마다 값 ⊂ 출처 값 ∪ 이름 | 출처 값 ⊂ 목표들 값의 합 |
| 새 항목(바탕) | 그 항목 `src` 재료 기록의 본문만 | 목표 글의 값 ⊂ 재료 값 ∪ 이름 | 묻지 않음(덮임 진단이 따로 셈 · 4-7) |
| 문서 요약 | 그 문서의 (옮긴 뒤) 항목 글 + `src` 재료 | 요약 값 ⊂ 근거 | 묻지 않음 |

- 값은 `valuesOf`(`core/values.js`) 그대로 · 코드 울타리 속 글은 값 하나로 세지 않는다 · 저절로 채우는 표의 값은 견주지 않는다(`gate.js:149`).
- **기록 본문 · 제목은 근거가 아니다.** checkSection 은 기록 본문도 근거로 센다(`gate.js:152 · 161`). 이 채널의 기록은 엔진이 짓지만, 그래도 근거를 출처 글 · 재료로만 잡아 「기록에도 같이 지어 넣으면 넘는」 구멍을 닫는다.
- 꼴은 지금 검사 그대로: `draftBad`(머리 · 표지 · 표) · `checkFormat`(E_FORMAT) · 목표 문서 갈래의 머리 꼴(`headingFits`) · 빈 글 금지.
- **섞인 자리**: 출처 · 목표 항목에 아직 안 들어간 개편 전 기록(`legacyPend`)이 있으면 그 단위 전체를 넣지 않는다(code `legacy-mix` · `gate.js:142` 와 같은 글). 출처의 `pend` 사람 기록은 planCheck 가 먼저 막는다(4-3).
- 지문: 출처 항목마다 `base` 가 지금과 다르면 그 단위 전체 `E_CONFLICT`(아무것도 쓰지 않음). 바탕 세우기의 새 항목은 목표 머리가 이미 있으면 `conflict`.
- 걸린 단위는 대개 **넣기 전에** 연습 판에서 걸러진다(4-6 · 연습 판에서도 저장 승인 모드 지식은 「걸음 실패」). 진짜에 넣을 때 걸리면(그사이 바뀜 · 팀 서버가 팀 길 검사를 다시 함) 저장 승인 모드 지식은 걸음 입력 오류(아무것도 안 씀)로 넣기가 거기서 멈춘다(P7). 저장 승인 전 지식은 저장 문 규칙대로 기록(work/) + 「넣지 못함」 이 되고 넣기가 거기서 선다.
- 사라지는 문장 어림(`scripts/kmd-migrate.mjs:274` dropsOf 와 같은 꼴)은 거절하지 않고 끝 진단에 경고로 싣는다.

### 4-6. 연습 판 · 넣기 · 다시 맞추기

- **연습 판**: 프로그램 살림 폴더 `<살림>/shape/<work>/kn` 에 지식 폴더를 git 으로 복사(`git clone --local`)한 것. 지식 목록에 오르지 않고 백업 자리가 붙지 않는다(v1 의 `restore --practice` 문제가 생기지 않는다). 바탕 세우기는 빈 지식을 같은 꼴로 만든 연습 판(README 한 커밋)에서 시작한다.
- **연습 판은 hub 함수가 아니라 core 함수로 쓴다.** `hub.save` · `hub.restructure` 는 지식 id 를 `hub.meta` 로 풀고 `hub.meta` 는 지식 목록에 있는 것만 찾는다(`hub.js:1364-1366`). 그래서 연습 판에는 `applyRestructure(dir, …)` · core `save(dir, …)` · `checkShape` 를 연습 판 폴더에 바로 부른다. 진짜에 넣을 때만 `hub.shapeStep`(권한 · 백업 · 캐시 · 오늘 바뀐 것 · 저장 문 팀 길)을 지난다. 「연습 판 결과 = 진짜 결과」 가 아니라 「같은 core 검사(`checkShape` · `checkFormat` · guard)를 지난다」 가 약속이다.
- **해 보기(try)**: 연습 판에 걸음을 모두 넣는다(같은 엔진 함수 · 같은 core 검사). 걸린 걸음이 있으면 그 자리에서 서고 화면이 고칠 곳을 보인다. 끝까지 가면 끝 진단(`diagnose`)을 낸다.
- **넣기(put)**: 승인 3 뒤 진짜 지식에 넣는다. 걸음은 진짜에서 새로 읽은 지식과 같은 구조안으로 다시 만든다(연습 판의 걸음 재료를 옮겨 싣지 않는다). 걸음마다 멱등 · 지문.
  - 넣기 직전 짜임을 짜임 일 장부에 남긴다(4-3 되돌리기 3).
  - 넣는 동안 짜임 일 상태는 「넣는 중 n/m」. 다른 사람의 저장은 막지 않는다(잠금은 `_members` 커밋 같은 서버 스스로의 쓰기를 못 막고 팀 일을 세운다 · v1 반박).
  - 넘어지거나 꺼지면 「이어 넣기」 가 남은 걸음부터 한다.
- **다시 맞추기**: 넣는 중 `E_CONFLICT` 가 나면 연습 판을 지금 지식에서 다시 떠서 같은 구조안으로 다시 견준다(`diffPlan`). 출처 `base` 가 그대로인 단위의 글은 다시 쓰고, 바뀐 단위만 Claude · 사람에게 다시 묻는다. 다시 견준 걸음 목록이 앞과 같고 끝 진단의 막는 것이 0 이면 승인 3 을 다시 묻지 않고 잇는다. **바뀐 단위가 있을 때만 다시 승인**한다(끝 진단 → 승인 3).
- **지문 둘**:
  - `shapeFp`(구조안 `base`): docs/ 문서 id · 문서마다 `## 머리` 목록 · `_order.md` · `_managed.md` · `_forms.md` 를 한 해시(sha256 앞 16자). 항목 글은 넣지 않는다. 팀은 저장이 곧 반영이라 남의 저장 하나가 항목 글을 바꾸므로, 글을 넣으면 바쁜 팀에서 넣기가 끝나지 않는다.
  - `stepFp`(frame · tidy 걸음): 그 걸음이 건드리는 문서들의 머리 목록 + 옮기는 항목 글 sha16 + 장부 셋 + docs/ 문서 id 목록. 건드리지 않는 문서의 글이 바뀐 것으로는 서지 않는다. `write` 는 출처 항목마다 `base`.
- 연습 판은 넣기를 마치거나 그만두면 지운다. 열린 채 7일이 지나면 살림 정리가 지운다(로그).

  - `audit`(`guard.js:297`): 이름 없는 기록 · 장부 밖 이름 · 자리 잃은 이름(화면 말은 「항목 잃은 이름」 · 5-7)

### 4-8. 걸음 문(저장 문과의 관계)

- 진짜 지식에 넣는 걸음은 모두 `hub.shapeStep(ctx, kn, work, n)` 하나로 들어간다. 개인 프로그램이 자기 지식에 넣을 때도, 팀 서버가 팀 다시 잡기를 넣을 때도, 팀 바탕을 받을 때도 같은 함수다(자리 · 지문 · 멱등 판정이 한 곳). 연습 판은 이 함수를 지나지 않는다(4-6).
  - `forms` · `write` · `stock` · `seal` 은 `hub.save` 의 shape 채널 · 저장 문 안으로 간다(권한 모델 7절: 기록 + 조각 + 지문 한 덩이 · 커밋 뒤는 던지지 않음).
  - `frame` · `tidy` 는 `applyRestructure` 로 간다. 조각이 아니라 파일 짜임이라 저장 문 밖이다(권한 모델 7-1 과 같은 자리 · 글은 경로 · 머리 줄 · 장부 · 링크만 바뀐다).
- **걸음 문은 걸음 내용을 받지 않는다.** 받는 것은 구조안(plan)과 그 지문, write 단위의 목표 글(`{ unit, items: [{ h, content }], intro }`), (바탕) 재료 글(`{ src, path, text }`)뿐이다. 서버가 저장 줄 안에서 새로 읽은 지식으로 `planCheck` · `diffPlan` 을 다시 돌려 걸음 · 걷을 출처(remove) · 장부 줄 · 링크를 스스로 만든다. `kind` · `remove` · `structure` · ops 는 입력에서 받지 않는다(실리면 `E_INPUT`). 채널은 서버 코드가 정한다.
- 걸음 문은 모든 걸음 앞에 `hub.need(ctx, kn, 'admin')` 와 `backup.closed(meta)`(E_BEHIND · `hub.js:1600` 과 같음)를 본다.
- HTTP 걸음 문(`POST /api/k/:id/shape/step`)은 **「바탕 세우기 짜임 일」(빈 지식에서 연 것)에만** 연다. 열 때 빈 지식이었는지 서버가 봤다. 바탕 일이 아닌 지식에 걸음 문을 부르면 `E_INPUT`. 짜임 다시 잡기의 걸음은 서버 안 함수로만 둔다(팀 다시 잡기는 7-3 대로 서버가 돌리므로 HTTP 걸음 문이 필요 없다). 그래서 사람(기기 열쇠)이 보낸 값으로 걷기(remove)나 항목 옮기기가 열리지 않는다.

[모두 처음대로]는 바뀐 것을 한꺼번에 버리므로 `⋯` 안 · `ask()`(「바뀐 것 n 을 버리고 지금 짜임으로 돌린다. 되돌릴 수 없다」 · `btn.danger`)를 거친다. 「취소」 는 모달 안에서만 쓴다.
- **이어 하는 단추 글**: 조사 · 짓기는 [이어 하기], 넣기는 [이어 넣기]. 잠깐 멈춤 알림 · 꺼졌다 켜진 줄도 그 단계의 글을 그대로 쓴다.
- **도는 일 아래 고정 한 줄**: `.prog` 아래 「다른 화면으로 가도 이어 간다 · 이 PC 의 개인 프로그램을 끄면 잠깐 멈추고, 다시 켜면 [이어 하기] 로 잇는다」(팀 일꾼이면 「다른 화면으로 가도 팀 일꾼이 이어 간다」) · 남은 어림이 있으면 「남은 3 문서 · 어림 2분」.
- **주 단추 비활성 까닭**: `title` 만으로 두지 않는다(터치에서 보이지 않음). 바닥 줄 덧말 자리에 경고색 작은 글 「먼저: <까닭>」 로 보인다.
- **주 단추 글**: 단계를 넘기는 단추는 「정하고 다음: <다음 단계 이름>」 꼴 하나(예: 「정하고 다음: 구조안」 · 「정하고 다음: 바뀔 것」). 지난 단계 보기에서는 「지금 단계로: <지금 단계 이름>」. 일을 하는 단추는 그 일 이름([조사하기] · [연습 판에 해 보기] · [넣기] · [저장]).
- **단계 띠(`.stepbar`)**: 새 부품. 가져오기 일 줄의 `.st` 는 쓰지 않는다(`.st` 는 단계마다 ul 을 담은 큰 카드이고 1024 이하에서 세로로 쌓이며 · `app/kmd.css:907-926 · 1122` · `div[data-a]` 라 컨벤션 10절에도 어긋난다).
  - `.stepbar > button.step` · 지금 단계 `aria-current="step"` · 지난 단계 ✓(옆에 화면 읽기용 글 「지남」 · `aria-label` 을 span 에 달지 않는다) · 아직 안 온 단계 `aria-disabled="true"`(누를 수 없음 · `title` 「앞 단계를 정하면 열린다」). 높이 24 · 한 줄 · `overflow-x:auto` · 600 이하는 **지금 단계** ± 1 과 지금 보는 단계만 보인다(구분자 `›` 는 앞뒤 두 단계가 다 보일 때만). 번호는 숫자 글(① 같은 글자 없음).
  - 상태 표시: 「다시 해야 함」(앞 단계를 고쳐 결과가 낡음 · 경고색 점) · 「다시 볼 것 n」(2 걸러 두기 · 비밀 의심으로 보류가 늘었을 때).
  - 디자인 컨벤션 10절 부품 표 · 11절 반응형 표에 먼저 더하고 `app/styleguide.html` 견본을 만든다(9절).
- **지난 단계**: 단계 띠에서 지난 단계를 누르면 그 단계를 열어 보기만 한다(지금 단계는 그대로 · 칸 · 나무가 읽기만 · 위 줄 「지난 단계다: 읽기만」 · 주 단추 「지금 단계로: <지금 단계>」). 고치려면 그 단계 위 줄의 [이 단계부터 다시] 를 누른다(`ask()` 는 고칠 단계 뒤에서 지금 단계까지만 나열: 「1 구조안 단계를 고쳐서 2 바뀔 것 · 3 끝 진단 을 다시 한다. 바뀐 것만 다시 짓는다」). 승인을 받지 않은 앞 단계는 누를 수 없다.

### 5-3. 바탕 세우기 단계(개인 화면만)

단계 띠: 1 원본 › 2 걸러 두기 › 3 구조안 › 4 짓기 › 5 끝 진단 › 6 넣기.

**1 원본**
- 칸(`.field > label + .inp + .hint`): 「원본 폴더」 경로(꾸러미 폴더도 같은 칸에 넣는다). 힌트 「이 PC 의 폴더 경로를 넣는다」(꾸러미는 한도 경고에서만 말한다).
- 대상(하나 고르기 줄 `.trow` 목록 하나): 「새 개인 지식」(+ 이름 칸 · 진입 ② 면 받은 이름이 채워짐) · 「이 PC 의 빈 개인 지식」 줄들 · 「이은 팀의 빈 지식」 줄들(팀 이름 › 지식 이름 · 표지 `.kt.team`). 고를 수 없는 줄은 `.trow.dim` + 둘째 줄에 까닭: 「빈 지식이 아니다」 · 「지식관리자 자리가 아니다」 · 「Claude 에 보내지 않는 지식」 · 「이 PC 가 그 팀에 이어지지 않았다」 · 「팀 서버를 읽지 못했다」(+ [다시 읽기] · label 밖 형제 단추 · label 안에 누르는 것을 두지 않는다). 이은 팀 하나의 지식 목록을 통째로 못 읽으면 그 자리에 `errHtml` 한 줄 + [다시 읽기].
- 대상 힌트: 「[넣기] 전까지 지식은 생기지 않는다 · 중간에 그만두어도 남는 것이 없다」.
- 새 개인 지식은 [조사하기] 를 누를 때가 아니라 6 넣기의 첫 걸음에서 만든다(그만두면 빈 지식이 남지 않게).
- 알림(`.callout`): 「규칙에 걸린 비밀 의심 파일은 Claude 로 보내지 않는다. 규칙에 걸리지 않은 파일은 카드를 지을 때 글이 이 PC 의 Claude 로 간다」.
- 한도: 300 파일 · 200MB(폴더 들이기와 같음 · `hub.js:1205`). 넘으면 `.callout.warn` 「파일이 많다(n 파일 · 크기): 이 화면은 300 파일 · 200MB 까지 연다. Claude Code 에서 kmd-seed 스킬로 짜임 꾸러미를 만든 뒤 그 꾸러미 폴더 경로를 여기 넣는다. 꾸러미는 한도가 없다」 + 복사할 한 줄(`kmd-seed <경로>`) + [설명서: 큰 폴더로 바탕 세우기](새 탭 링크).
- 원본에 문서가 될 파일이 없음: `.callout.warn` 「문서가 될 파일이 없다(md · docx · pptx · xlsx · hwp · pdf)」.
- 주 단추 [조사하기](경로와 대상이 있어야 · 없으면 비활성 + `title`). 도는 중 `.prog` 「조사하는 중 n/m」(Claude 없음 · 파서 · 해시) · 바닥 줄 [잠깐 멈춤] · ⋯ [그만두기].

**2 걸러 두기 · 승인 1**
- 요약 줄(`.hd-sum`): 원본 n · 정본 n · 옛 판 n · 같은 글 n · 스캔 n · 큰 파일 n · 못 읽음 n · 비밀 의심 n.
- 거르기(`.fbtn`): 모두 · 정본 · 옛 판 · 같은 글 · 스캔 · 비밀 의심 · 보류 · 못 읽음.
- 고르기 띠(문서 짜임 `.sx-sel` 꼴): 줄을 하나라도 고르면 표 위에 「고른 줄 n · [넣음으로] [근거만으로] [빼기로] [보류로]」. 표 첫 칸 체크 · Shift 로 이어서 · 머리 칸 체크 「보이는 줄 모두 고르기」.
- 표(`.tblwrap > table.t`): 체크 · 파일(경로 · 말줄임은 `title` · 덧말 `small`) · 판 묶음 · 판 `.kt.role`(정본 · 옛 판 · 같은 글 · 스캔 · 비밀 의심) · 문서 갈래(어림) · 고르기(`select.inp`: 넣음 · 근거만 · 빼기 · 보류 · 못 읽음 줄만 이 칸에 `chipOf('fail', '못 읽음')`) · [글 보기](모달 · 앞 2천 자). 고른 결과 칩 칸은 두지 않는다(고르기 칸과 같은 값을 두 번 보이고 375 에서 표를 민다). 비밀 의심 줄은 줄 강조(`tr.rv`) + 덧말 「Claude 로 보내지 않는다」 로 알린다(표지 색을 빌리지 않는다).
- 표 위 풀이 한 줄: 「넣음: 글로 쓴다 · 근거만: 값을 견줄 때만 쓴다 · 빼기: 쓰지 않는다 · 보류: 이번에는 두고 나중에(세션 스킬)」.
- 기본값: 정본 넣음 · 옛 판 빼기 · 같은 글 빼기 · 스캔 보류(화면은 스캔을 글로 바꾸지 않는다 · 세션 스킬로 · 단 kmd-seed 가 글로 바꾼 판(`<이름>.md`)이 옆에 있으면 넣음이고 그 재료로 지은 항목은 「스캔 근거」) · 비밀 의심 보류 · 못 읽음 빼기.
- 비밀 의심은 1차로 규칙(열쇠 · 비밀번호 꼴 줄)이 표시한다. 3 구조안의 카드 일감이 비밀 의심을 더 표시하면 그 파일은 저절로 보류가 되고 카드 · 구조안 재료에서 빠진다. 단계 띠의 2 에 「다시 볼 것 n」 이 붙고, 3단계 검사 줄에 경고 「비밀 의심으로 빠진 재료 n」 + [가기] 가 선다. 승인 1 은 다시 묻지 않는다.
- 주 단추 「정하고 다음: 구조안」. 정하면 짜임 일 장부의 `decision` 칸에 적는다. 다시 볼 것이 생긴 뒤의 위 줄 글: 「구조안을 짓다가 <파일> 에서 비밀번호 꼴 줄을 찾아 보류로 돌렸다 · 다른 결정은 그대로다」.

**3 구조안 · 승인 2**
- 처음 열면 [Claude 에게 구조안 받기]가 돈다: 카드 일감(정본 10개씩 · digest 로 시작 · 애매한 것만 원문 앞부분) → 구조안 일감(카드 모아 plan JSON). 도는 동안 `.loading` + 「카드 n/m · 쓴 글 n 자 · 걸린 시간」 · 바닥 줄 [잠깐 멈춤] · [그만두기]. Claude 가 없으면(로그인 없음 · 한도) `.callout.danger` + [다시] 와 [손으로 짓기](빈 나무에서 시작).
- 본문 두 칸(1025 이상 · 아래 5-6):
  - 왼쪽 **나무**(`.sx-tree` 넓힘 · `role=tree`): 폴더 › 문서 › 항목. 문서 줄: 이름 · 갈래 `.kt` · 항목 수. 항목 줄: 머리 · 재료 수(「원본 3」) · 스캔 근거면 `.muted.small` 「스캔 근거」. 끌어 옮기기(문서 · 항목) · F2 이름 · Alt ↑↓ 차례 · [+ 새 문서] · [+ 폴더](`.btn`) · 여럿 고르기(Ctrl · Shift · Ctrl Space) · 줄 메뉴(`.pop` · `role=menu`: 옮기기… · 이름 · 재료 고치기… · 빼기). 바뀐 줄은 `.sx-dot.ch`(바뀜) · 새 줄은 `.sx-dot.new`.
  - Claude 가 바꾼 까닭은 새 부품 `.sx-note`(text-3 · `.muted.small` · 한 줄 말줄임 · 올리면 `title` 로 전체)로 줄 아래에 둔다. 오류 빨강 `.sx-why` 는 이름 칸 검사에만 쓴다.
  - 오른쪽 **고른 것**(`.card`): 문서면 갈래 · 요약 길잡이 · 항목 목록. 항목이면 재료 목록(파일 경로 · [글 보기]) · 이 항목에 놓일 이름(종류:값). 폴더면 안의 문서 수. 고른 것이 없으면 「나무에서 하나를 고른다」(`.muted`).
- 나무 위 탭(`.tabs`): 나무 · 원본 대응(표: 정본 → 문서 › 항목 · 빠진 정본은 위에 `chipOf('held', '빠짐')`) · 이름(표: 종류:값 · 넣을 곳 · 가리키는 재료 수) · 갈래(표: 이름 · 종류 · 폴더 · 다른 이름 · 패턴).
- 검사 줄(나무 아래 `.callout`): 걸림(`danger` · 줄마다 [가기] 가 그 줄을 고른다)과 경고(`warn`). 걸림: 이름 꼴 · G4 · 갈래 다른 이름 겹침(`formFor` · `guard.js:217-221`) · 머리 꼴 · 대소문자 겹침 · 이름 하나가 항목 둘 · 정본 덮임 빠짐 · 이름의 넣을 곳이 구조안 밖. 경고(풀어 쓴다: 「항목이 2개뿐(권장 5 ~ 40)」 · 「원본 파일을 그대로 문서로 옮긴 비율 40%(거울 지수 0.4)」): 크기 지표 · 거울 지수 · 같은 판 묶음의 옛 판과 정본이 한 항목 재료(옛 값이 값 대조를 넘는다) · 비밀 의심으로 빠진 재료 n. 검사 중이면 검사 줄 자리에 `.loading` 「검사하는 중…」.
- 고칠 때마다 `planCheck` 를 다시(서버 마른 실행 · 0.5초 묶음 · 초안 저장).
- 주 단추 「정하고 다음: 짓기」(걸림 0 일 때만 · 아니면 비활성 + 덧말 「먼저: 걸림 n 을 고친다」). 정하면 구조안 지문(sha16)을 짜임 일에 박는다. 뒤 단계는 지문이 다르면 받지 않는다. [Claude 에게 다시 받기](`.btn` · 옆 덧말 「손으로 고친 것을 「고친 점」 으로 같이 준다」)는 `ask()`(「손으로 고친 것 n 을 Claude 에게 같이 준다. 받은 안이 지금 나무를 바꾼다 · 줄마다 [이것만 되돌리기]」)를 거친다.

**4 짓기**
- 위 줄: [남은 문서 모두 짓기](처음 3 문서 승인 뒤에만 · 그 전에는 비활성 + `title` 「처음 3 문서는 하나씩 본다」 · 짓는 중 · 잠깐 멈춤 · 남은 문서 0 이면 비활성 + 까닭).
- 표(`.tblwrap > table.t`): 문서 · 항목 n · 상태 칩(`chipOf('wait', '기다림')` · `chipOf('run', '짓는 중')` · `chipOf('ok', '지음')` · `chipOf('held', '걸림')`) · 쓴 글 n 자 · [보기](모달: 항목마다 지은 글 · 근거 재료 · 걸린 까닭) · [다시 짓기](`.btn.sm`).

- **처음 3 문서**는 하나씩 [보기] 로 읽고 [이 문서 승인] 을 받는다(줄 차례 [보기] → [이 문서 승인] · [보기] 창 바닥에도 [이 문서 승인]). 그 뒤는 사람이 [남은 문서 모두 짓기] 를 고른다.
- 「스캔 근거」 항목은 줄 덧말 「스캔에서 옮긴 값 n」 + [맞다고 확인] 을 눌러야 넣는다(스캔 글은 자기 글끼리 값 대조라 근거가 약하다).
- 손으로 쓰기: [보기] 모달에서 [손으로 고치기](textarea · 같은 값 대조).
- 바닥 줄 [잠깐 멈춤] · ⋯ [그만두기]. 꺼졌다 켜지면 `.callout.warn` 「잠깐 멈춤: 프로그램이 꺼졌다」 + [이어 하기] 로 서 있다(`core/queue.js` 와 같음).
- 주 단추 [연습 판에 해 보기](모든 문서가 지음 · 걸림 0 일 때만 · 연습 판에 모든 걸음 → 5 끝 진단). 표 아래 덧말 「지식은 아직 바뀌지 않는다 · 끝나면 5 끝 진단으로 간다」.

**5 끝 진단 · 승인 3**
- 요약 줄: 문서 n · 항목 n · 이름 n · 재료 n · 넣지 못함 n · 고아 재료 n · 빠진 값 n · 이름 없는 기록 n · 항목 잃은 이름 n. 그 아래 `.muted.small` 풀이 한 줄(「항목 잃은 이름: 가리킬 항목이 없어진 이름 · 고아 재료: 넣기로 했는데 지은 글이 쓰지 않은 원본 · …」).
- 묶음(`.card` 여럿): 막는 것(`.callout.danger` · 줄마다 [구조안에서 고치기] → `ask()` 「이 단계부터 다시」(뒤 단계만 나열 · 바뀐 것만 다시 짓는다) → 그 단계 · 그 줄로) · 볼 것(`.callout.warn`: 빠진 값 · 사라지는 문장 어림 · 크기 · 줄마다 [보기](그 줄로 · 읽기만) · [그대로 두기]) · 고아 재료(줄마다 [두기](까닭 칸 · `ask()`) · [짓기로]). 고아 재료는 막는 것 목록에 두 번 넣지 않는다(제 카드 하나). 막는 것 0 · 볼 것 0 이면 `.callout` 「막는 것이 없다」.
- 주 단추 [넣기](막는 것 0 · 고아 재료 0 일 때만). 누르면 `ask()`: 「<대상>에 문서 n · 항목 n · 재료 n 을 넣는다. 팀 지식이면 넣는 동안 이 짜임이 건드리는 문서가 바뀌면 그 걸음에서 잠깐 멈추고 다시 맞추기를 묻는다」 · 확인 단추 「넣기」.

- **Z9 Claude 세션 · 나눠 받기 · 동작 내역**(2026-11-11 · 사용자 결정): 개인 프로그램의 「Claude 안」 구조안과 짓기는 재료 글 · 카드를 프롬프트에 다 붙이는 단발 `claude -p` 를 걷고 **claude 세션**(`--input-format stream-json` · 같은 세션에 말을 이어 보냄)에서 한다. 재료 94 · 원본 100MB 에서 단발은 10분 한도로 끊겨 아무것도 받지 못했고, 한 세션에 전체를 맡겨도 생각 한 덩이가 7 ~ 9분(전체 17분 · 1.5달러)이었다 — 시간을 잡아먹는 것은 입력이 아니라 「한 번에 전체를 생각」 이다. 생각 정도(`--effort`) · 생각 상한(`MAX_THINKING_TOKENS`)으로는 줄지 않았다.

### 6-1. 짜임 판단 기준(구조안 프롬프트 · 스킬 · planCheck 공통)

1. **문서는 주제 · 대상 하나 · 사건 갈래 하나 · 대장 하나.** 파일 경계 · 원본 폴더 나무는 참고만. 문서 이름에 날짜 · 판 · 최종 · 확장자를 쓰지 않는다(G4 · `restructure.js:37` nameProblem).
2. **항목은 대상 하나의 「지금」.** 같은 대상의 여러 파일은 모으고 늦은 판이 이긴다. 옛 판은 빼기가 기본.
3. **갈래**: 날짜 사건(회의 · 장애 · 주간보고)은 사건 갈래 「YYYY-MM-DD 무엇」, ID 가 붙어 되풀이되는 것은 대장 갈래(`이슈:*` 패턴), 나머지는 대상. 갈래는 같은 꼴이 셋 이상 되풀이될 때만 세운다. 다른 이름은 계획한 문서 이름과 부분 문자열로 겹치지 않게(`formFor` 가 부분 문자열로 집는다). 준비 글(안건 · 스크립트 · 체크리스트)은 문서로 만들지 않고 그 안의 확정 사실만 옮긴다.
4. **이름(종류:값)**: 둘 이상 파일 · 문서에서 가리키는 고유물만. 종류는 8~10개 안팎. 빈 `##` 머리 · 「작성 예정」 은 쓰지 않는다.
5. **크기**: 폴더 깊이 2단 · 폴더당 문서 3~12 · 문서당 항목 5~40 · 항목 300줄 안.
6. **차례**: 업무 흐름 순서. 숫자 앞붙임은 원본에 그 체계가 있을 때만. 폴더 안에서는 개요 문서가 먼저. 문서 요약 1~3문장은 `# 제목` 아래(작성기준 3절 3 · `## 개요` 항목으로 두지 않는다).
7. **덮임**: 모든 정본은 배정되거나 까닭과 함께 빠진다. 비밀이 든 파일은 보류.
8. **다시 잡기**: 지금 항목은 모두 어딘가로 간다. 글이 그대로 갈 수 있으면 옮기기를 먼저 쓰고, 나누기 · 합치기는 같은 대상이 두 곳에 갈라져 있거나 한 항목에 대상이 둘 이상 섞였을 때만. 아직 안 들어간 기록이 걸린 항목은 나누거나 합치지 않는다(먼저 넣거나 두기로).

### 7-2. 팀 바탕 세우기(권장안 (나))

1. 총괄 관리자가 팀 화면 › 지식 추가로 새 팀 지식을 세운다(`docs/처음.md` 하나 · `app/main.js:1079` 는 empty 를 보내지 않는다 · 3-1 에서 빈 지식으로 보고 바탕 마감 tidy 가 걷는다). 짓는 사람이 다르면 그 사람에게 지식관리자 자리를 준다(새 지식의 주인은 세운 총괄 관리자 · `hub.js:1155`). 백업 자리가 붙었는지(gitlabAttach 실패는 log 만 · `hub.js:1177`)는 팀 화면 백업 칸에서 본다.
2. 짓는 사람은 이 PC 를 그 팀에 이어 둔다(지식 보내기와 같은 기기 열쇠 · `hub.js:3878` teamKns).
3. 개인 화면 › 문서 짜임 › 바탕 세우기 › 1 원본의 대상 목록에서 그 빈 팀 지식을 고른다. 팀의 `GET /api/knowledge` 는 지식마다 `level` · (팀이면) `noClaude` 를 이미 싣는다(`http.js:874`). 여기에 `empty`(3-1 빈 지식 판정 · 지식관리자 이상에게만)를 더하고, `teamKns` 는 지금 id · name 만 남기는 것(`hub.js:3884`)을 넓혀 `level` · `noClaude` · `empty` 를 그대로 넘긴다.
4. 조사 · 걸러 두기 · 구조안 · 짓기 · 해 보기 · 끝 진단은 모두 이 PC 에서(연습 판도 이 PC · core 함수). 원본은 팀 서버로 가지 않는다(재료 기록 글만 간다).
5. [넣기] 는 팀의 걸음 문 `POST /api/k/:id/shape/step` 을 기기 열쇠(Bearer)로 부른다(`core/send.js:147` post 와 같은 꼴 · 429 E_RATE 는 쉬고 다시). 보내는 것은 구조안 · 구조안 지문 · 재료 글 · write 단위의 목표 글뿐이다(4-8). 팀 서버는 그 사람의 자리로 판정하고(`hub.need(ctx, kn, 'admin')`), 걸음을 스스로 다시 만들며, 지문 · 멱등 · 값 대조 · 섞인 자리를 **팀 서버가 다시** 한다(PC 의 검사를 믿지 않는다). 그래서 PC 연습 판을 넘은 단위도 팀에서 넣지 못함이 될 수 있다.
6. 첫 걸음이 팀에 「바탕 세우기 짜임 일」 을 연다. 이때 팀 서버가 빈 지식인지 본다(3-1 의 빈 지식). 빈 지식이 아니면 거절.
7. 넣는 동안 팀 화면에서 그 지식 카드에 칩 「바탕 세우는 중」(`chipOf('run')` · c-pend) · 문서 짜임 페이지에 「<사람>이 개인 프로그램에서 바탕을 세우는 중 · 걸음 n/m」.
8. **끊김.** 팀 쪽 짜임 일은 마지막 걸음 시각을 지닌다. 24시간 걸음이 없으면 팀 화면 카드 칩이 「바탕 멈춤」(`chipOf('held')`)이 되고, 문서 짜임 페이지에 「<사람>의 바탕 세우기가 걸음 n/m 에서 섰다」 + [그만두게 하기](그 지식의 지식관리자 · 총괄 관리자 · `ask()`)를 보인다. 그만두게 하면 반쯤 선 지식에 남은 것(갈래 장부 · 짜임 · 재료 n · 글 n)을 보이고, 「지식을 지우고 다시 세우기는 총괄 관리자 › 지식 지우기 · 새 지식 세우기」 를 안내한다(지식이 빈 지식이 아니므로 다시 바탕 세우기는 할 수 없다). 같은 사람의 다른 PC 에서는 이어 넣을 수 없다(짜임 일 장부 · 연습 판이 그 PC 에 있다)고 알린다. 개인 쪽 [그만두기] 가 넣기 단계에서 눌리면 「이미 들어간 걸음 n 은 남는다」 를 `ask()` 글에 넣는다(5-3 6).

v1 과 달리 push · 「백업에서 받기」 가 없다. 그래서 push ~ 받기 사이 읽기만(behind) · 짓는 동안 `_members.md` 갈라짐(moved) · 받기가 자리를 보지 않는 문제가 생기지 않는다. 걸음마다 팀 저장 문 · 짜임 함수가 자리와 검사를 본다.

### 7-3. 팀 짜임 다시 잡기를 어디서 돌리나: 팀 일꾼

- **정함: 팀 프로그램 + 팀 일꾼.** 원본(지식)이 이미 팀 서버에 있으므로 구조안 · 글 짓기는 팀 일꾼, 연습 판 · 걸음은 팀 서버 안(`hub.shapeStep` 을 서버가 부른다 · HTTP 걸음 문을 쓰지 않는다).
  - 까닭: 지식 글이 PC 로 나갔다 들어오지 않는다 · 팀 화면에서 개인 프로그램을 부르지 않는다(CLAUDE.md) · 다듬기(polish)가 이미 「지식관리자가 거는 팀 일꾼 일감 + 값 장부 같음」 의 선례다(`hub.js:2636` · `hub.js:966-991`) · 「Claude 에 보내지 않음」 지식 정책이 그대로 걸린다.
  - 버린 쪽(개인 프로그램이 팀 지식을 읽어 내 Claude 로): 팀 지식 글이 그 사람 PC 의 Claude 로 가고, 팀 화면에서 시작할 수 없어 페이지가 사실상 둘이 된다.
- 들이기 일감(`hub.openJob` · `hub.js:2599`)에 type `shape-plan`(구조안) · `shape-write`(나누기 · 합치기 · 요약 글)을 더한다. 넓힐 곳: type 목록(`hub.js:2601`) · `intakeKey`(지금은 그 밖 type 을 모두 `r:${src.rec}` 로 묶어 서로 막힌다 · `hub.js:262`)에 `shape-plan` → `s:<work>` · `shape-write` → `w:<work>/<unit>` · 재료(`g`)를 서버가 짓는 갈래 · 일꾼에게 보인 것(`seen` · `hub.js:2712`) 갈래 · 끝(`done`)에서 서버가 받은 것을 `planCheck` · `checkShape` 로 다시 본다(일꾼이 보낸 것을 믿지 않는다).
- `shape-plan` · `shape-write` 일감은 「Claude 에 보내지 않음」(`noClaude`) 지식에서 세우지 않는다(`E_FORBIDDEN` · 권한 모델 7 「모든 일감 꼴」).
- 팀 일꾼(`core/worker.js:75-80`)은 type 마다 스키마 · 프롬프트를 고른다. 새 type 을 모르는 옛 일꾼이 들이기 프롬프트로 지어 버리지 않게, 일꾼이 상태 보고에 아는 type 목록을 싣고 서버는 아는 일꾼에게만 `shape-*` 일감을 준다. 모르면 화면에 「팀 일꾼 판이 옛것이다: 손으로 짜거나 일꾼을 다시 설치한다」.
- 개인 프로그램의 다시 잡기는 같은 프롬프트 · 스키마를 이 PC 의 `claude -p` 로(`hub.askClaude` · `hub.js:2917` · pc 만).
- **Z6 에서 한 것**: 판단 기준 · 스키마 · 프롬프트 · 재료는 `core/shape.js` 한 벌(`SEED_RULES` · `RESHAPE_RULES` · `SHAPE_PLAN_SCHEMA` · `SHAPE_WRITE_SCHEMA` · `planMaterial` · `writeMaterial` · `planOfDraft` · `writeOfDraft` · `core/survey.js` 는 `SEED_RULES` 를 다시 내보냄). 길은 8-1 의 `shape/ask { plan?, note? }` · `shape/write { sources, targets }`(단위 번호 대신 출처 · 목표 — 창이 구조안에 놓기 전에도 짓는다) + `GET shape/job/:job` · `POST shape/job/:job/stop`. 열쇠는 `s:<사람>:<입력 지문>` · `w:<입력 지문>`(그만두는 중인 일은 다시 잡지 않음). 일꾼은 `/api/worker/next` 에 아는 type 을 싣고, 열 분 안에 물은 일꾼이 모두 모르면 화면 「팀 일꾼 판이 옛것이다」 · 새 일은 E_CONFLICT. 개인 프로그램은 `askClaude` 의 「Claude 로 들이기」 스위치를 따르지 않고(들이기 스위치) `claude -p` 를 바로(같은 모델 · 예산) · 메모리 안 일(다시 켜면 사라짐 · 동시에 넷). 결과는 지식에 쓰지 않는다: 구조안은 나무에 덧씌움 · 합치기 · 나누기 항목은 글이 빈 채 놓이고 [Claude 짓기 n] 이 출처가 같은 묶음마다 짓는다. 글의 꼴 오류(`judgeShape` errors)는 두 번까지 고쳐 쓰고 그래도면 「걸음 실패」(지은 글은 남긴다 · 규칙 길 없음 · P-D24), 값 대조는 알림(P-D15). 구조안의 덮임 · 겹침 걸림도 두 번까지 고쳐 쓰고(이름 자리 걸림은 화면이 놓으므로 빼고) 그래도면 걸림과 함께 나무로. 팀 일꾼이 지은 구조안은 일꾼에게 보인 지문과 지금이 다르면 버린다(「그사이 짜임이 바뀌었다」).

### 7-4. 권한 모델 맞춤

| 길 | 판정 |
|---|---|
| `GET /api/k/:id/shape` | `hub.meta(id, ctx)`(읽기 미만 404) + `hub.need(ctx, kn, 'admin')`(403) |
| `POST /api/k/:id/shape/*`(구조안 검사 · 해 보기 · 넣기 · Claude 받기 · 그만두기) | 같음 + 단계를 잇는 것은 짜임 일을 연 사람만. 그만두게 하기는 그 지식의 지식관리자 누구나(총괄 관리자 포함 · `hub.need(ctx, kn, 'admin')` 하나 · 총괄 관리자 전용 일이 아니다) |
| `POST /api/k/:id/shape/step`(걸음 문) | 같음 + `backup.closed`(E_BEHIND) + 열린 **바탕** 짜임 일 · 걸음 차례 · 지문 · 멱등. 걸음 내용(ops · remove · kind · structure)은 받지 않는다(E_INPUT) |
| `/api/shape/survey` · `/api/shape/:work/*`(바탕 조사 · 걸러 두기 · 카드 · 짓기) | 개인 프로그램만(팀이면 E_FORBIDDEN). PC 주인 |
| 이은 팀 지식 목록 | 개인 프로그램 → 팀 `GET /api/knowledge`(기기 열쇠 · 자리로 거른 목록 그대로) |
| 되돌리기 | 태그 `shape` 기록은 `canRevert: false` · 서버 revert E_FORBIDDEN(4-3) |

- 화면에서 숨기는 것으로 끝내지 않는다. 모든 길이 서버에서 `hub.need` 를 본다.
- 응답에 지식 id 를 싣는 것(짜임 일 목록 · 알림 · 오늘 바뀐 것 줄)은 자리로 거른다.
- 감사 줄: `AUDIT_RE`(`http.js:446`)에 `k/[^/]+/shape` 를 더한다.
- 채널 `shape` 는 서버 코드만 정한다(`opt.shape` 는 `hub.shapeStep` 만 단다). 사람이 보낸 `channel` · 태그 `shape` · `shape-done` · `shape/…` 는 받지 않는다.
- 총괄 관리자 일은 늘지 않는다(새 팀 지식 세우기 · 자리 주기는 지금 있는 일 · 그만두게 하기는 지식관리자 일).
