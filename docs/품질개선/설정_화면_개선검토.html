1한눈에

지금 설정은 작업 도구(가져오기 · 넣지 못함 · 문서 짜임), 설정값(일반 · 사람 · Claude 연결), 설치 안내(에이전트 설치), 점검(관리)이 묶음 없이 한 줄 메뉴 8칸에 섞여 있다. 같은 카드가 두 곳에 나오고(사람 · 묶음, 백업, 넣지 못함 수), 메뉴 정의가 코드에 세 벌 있다. 다섯 페르소나 모두 이 섞임과 겹침을 첫 문제로 꼽았고, 엔지니어는 세 벌 정의를 잦은 수정의 구조적 원인으로 짚었다.

제안은 설정을 업무 차례로 다시 놓는 것이다: 점검(매일) › 팀 서버 · 팀 지식(세우기) › 사람 · 묶음(들이기) › 에이전트 설치(붙이기) › 나. 날마다 쓰는 작업 도구 셋은 설정 밖 옆 메뉴 「지식 관리」 로 꺼내는 것을 권하되, 예전에 반대로 옮긴 이력이 있어 마지막 단계에 사람이 정하고 한다. 메뉴는 표 하나에서 나오게 하고, 서버 권한 판정과 팀/개인 화면 분리는 그대로 둔다.

2검토 방법

같은 설정 화면을 역할이 다른 다섯 사람의 눈으로 따로 본 뒤(서로의 결과를 보지 않음), 제품 책임자 역할이 합의 · 충돌을 가려 하나의 구성안으로 묶었다. 그 뒤 반대 검토자(kmd 아키텍트)가 종합안을 서버 권한 판정 · 과거 결정과 대조해 10건을 짚었고, 이 문서는 그것을 반영했다(§6 끝). 모든 지적은 코드 줄로 확인할 수 있게 적었다.

이름과 실제가 다른 것

  • 「일반」 의 안내는 「팀 서버의 것만」 인데, 저절로 하는 일 스위치는 서버 값이 아니라 사람마다의 값이다(hub.setAuto: 팀이면 users[ctx.user] 에 저장, server/hub.js:1277-1283). 내 계정 설정이 서버 설정 페이지에 있다.
  • 「이 팀 서버」 카드에 내 계정이 섞였다. 들어가기(내 아이디 · 나가기) · 나(자리)는 내 것, 백업 · 판은 서버 것.
  • 「Claude 에 보내지 않음」 은 지식마다의 정책인데 서버 일반 페이지의 표에 있다. 그 지식의 다른 정책(권한 · 저장소)은 지식 카드 ⋯ › 권한 · 관리 › 저장소 연결에 있다.

4페르소나 검토

다섯 명이 서로의 결과를 보지 않고 따로 낸 한 줄 평과 주요 지적이다. 심각도: 상 · 중 · 하.

총총괄 관리자팀 서버 운영 담당

매일 볼 것(관리)은 메뉴 맨 끝에 있다. 백업 · 사람 · Claude 연결 · 지식 설정은 일반 · 사람 · 관리 · 지식 카드 ⋯ 네 곳에 흩어져 있고, 같은 카드가 두 탭에 겹쳐 나온다.

  • 상 사람 · 묶음 카드가 사람 탭과 관리 탭에 똑같이 나온다
  • 상 백업은 일반에서 보고 관리 › 저장소 연결에서 고친다
  • 상 문제 줄이 있는 「관리」 가 맨 끝이고, 이름으로는 문제 목록인 줄 모른다
  • 상 팀 지식 하나의 설정이 일반 표 · 지식 카드 ⋯ › 권한 · 관리 › 저장소 연결 · ⋯ › 지우기 네 곳
  • 중 새 팀원 들이기가 사람 · 권한 · 에이전트 설치로 끊긴다

재구성 원칙

  1. 설정값과 작업 도구를 나눈다. 날마다 쓰는 가져오기 · 넣지 못함 · 문서 짜임은 작업, 설정은 가끔 정하는 것만.
  2. 같은 것은 한 자리. 한 카드는 한 페이지에만. 상태를 보이는 곳과 고치는 곳이 다르면 고치는 곳으로 바로 보낸다.
  3. 업무 차례대로. 지켜보기(매일) › 세우기(팀 서버 · 팀 지식) › 사람 들이기 › 작업 폴더에 붙이기 › 나.
  4. 자리에 맞는 것만 보인다. 못 하는 항목은 숨기고, 설정을 열면 자리마다 첫 화면이 다르다. 판정은 서버가 정본, 화면은 보이기만 정한다.
  5. 팀 화면과 개인 화면은 따로. 팀 화면에 개인 지식을 싣지 않는다. 개인 화면도 같은 묶음 틀로 맞춘다.
  6. 메뉴 정의는 표 하나. 왼쪽 메뉴 · 위치 줄 · 멈춤 줄 갈 곳 · 옛 길 대응이 모두 그 표에서 나온다.
  7. 바깥에 박힌 이름은 지킨다. 「에이전트 설치」 는 이미 깔린 CLAUDE.md 안내 줄이 가리키므로 이름을 바꾸지 않는다.

설정이 자주 바뀐 구조적 원인 코드 읽기로 확인

원인근거생기는 일
메뉴 정의가 셋mgItems(main.js:571-580) · viewSettings 의 ST(3584-3585) · 멈춤 줄 갈 곳 글 STOP_T(670, 680-685)메뉴 하나를 바꾸면 세 곳을 같이 고친다. 권한 조건이 어긋나 지식관리자에게 「관리」 가 보이고 열면 일반이 나온다.
길이 둘가져오기 · 넣지 못함 · 문서 짜임 · 관리는 화면(scr), 일반 · 사람 · Claude 연결 · 에이전트 설치 · 관리는 S.setTab앱 안 뒤로 가기 기록(snap, main.js:269)은 scr · kn 만 담는다. 설정 탭 사이를 옮겨도 기록되지 않아 ‹ 를 누르면 설정 밖으로 나간다. 같은 왼쪽 메뉴인데 앞 셋은 기록되고 뒤 넷은 안 된다.
관리가 화면이자 탭단독 scr 'admin'(main.js:563, MGSCR) · 설정 탭 admin(viewSettings 가 viewAdmin().main 을 끼움)멈춤 줄(팀 백업)은 scr 'admin' 으로 가는데 왼쪽 메뉴는 ['settings','admin'] 만 알아 선택 표시가 없다.
들어가는 길 셋옆 메뉴 · 레일 setArea(4364, 일반으로 되돌림) · 내 메뉴 「설정」(지난 탭 그대로) · mgGo(v 가 있을 때만 바꿈)같은 「설정」 인데 열리는 페이지가 다르다.
렌더 중 상태 바꾸기 · 죽은 코드viewMembers(2438)가 그리면서 S.setTab 을 바꾼다 · viewSettings 의 tabs(3590)는 만들고 쓰지 않는다옛 길을 걷을 때마다 흔적이 남는다.
이름과 저장 단위가 다르다일반의 「저절로 하는 일」 은 팀이면 사람마다 저장(hub.setAuto, server/hub.js:1277-1283)「팀 서버의 것만」 페이지에 내 값이 있다. 총괄 관리자가 끄면 모두가 꺼진다고 오해하기 쉽다.

고치는 방향

  1. 메뉴 표 하나. SETTINGS_MENU = [{ id, 이름, 묶음, view, 보이기(팀/개인 · 자리), 갈 곳 글 }] 에서 왼쪽 메뉴 · 페이지 제목 · 위치 줄 · 멈춤 줄 갈 곳 글을 모두 만든다. mgItems · ST · MGSCR · STOP_T 의 경로 글은 이 표에서 나온다.
  2. 길 하나. 설정 페이지는 모두 { scr: 'settings', page: id } 로 가고 snap 에 page 를 싣는다. 뒤로 가기 · 선택 표시 · 위치 줄이 한 규칙을 따른다. S.setTab 은 걷는다.
  3. 옛 길 대응표 하나. { members: 'people', admin: '오늘(점검)', tidy: 'held' } 처럼 걷은 화면 이름을 한곳에서 새 페이지로 보낸다. viewMembers 는 걷는다.
  4. 권한은 지금처럼 서버가 판정하고(hub.need · ctx.admin), 화면 노출은 메뉴 표의 보이기 함수 하나로만 정한다. 메뉴에 보이는데 페이지가 거절하는 일이 없게 한다.
  5. 화면 시험 영향. test/screen-kmd.test.mjs(mgNav 8곳 · setTitle 2곳) · test/access-ui.test.mjs(mgNav · mg-people) 가 설정 메뉴의 data-t 를 본다. 메뉴 id 를 바꾸는 단계에서 같은 커밋으로 맞춘다.
주소 경로는 따로 정할 일. 엔지니어 · 종합안은 #settings/<id> 주소를 제안했지만, kmd 는 지금 화면을 주소에 싣지 않는다(해시는 한 번용 번호 #once= 만 받고 주소를 / 로 되돌린다, main.js:180 · 5022-5036). 설정만 주소를 갖게 하면 앱 안에서 규칙이 둘이 된다. 이 검토는 앱 안 기록(snap)에 page 를 싣는 데까지만 권하고, 주소 경로 도입은 앱 전체 결정으로 남긴다(§11).

#정할 것검토 의견
1작업 도구 셋(가져오기 · 넣지 못함 · 문서 짜임)을 옆 메뉴로 꺼낼지, 설정 안 「작업」 묶음으로 둘지꺼내기를 권한다. 다만 예전에 설정 · 팀 / 설정 · 개인 안으로 넣은 까닭이 「이력 · 가져오기는 그 영역(팀 · 개인)의 지식만 본다」 였다(커밋 9a25187 · CHANGELOG). 꺼내더라도 팀 화면에는 팀 지식만 보이는 영역 거르기를 지킨다. 4단계 전에 정한다
2팀 화면 「저절로 하는 일」 을 지금처럼 사람마다 값으로 둘지, 서버 값으로 바꿀지사람마다 값이면 「나 › 내 설정」, 서버 값으로 바꾸면 「팀 서버」. 이 문서는 지금 동작대로 「나」 에 실었다
3관리의 새 이름 「점검」 이 컨벤션 9절 용어에 맞는가(다른 안: 상태)「오늘」 은 이력의 today 와 겹쳐 뺐다
4지식관리자에게 팀 지식 줄의 백업 저장소 붙이기를 열지지금 서버 판정은 총괄 관리자. 열지 않으면 그 칸은 지식관리자에게 읽기만
5가져올 곳 더하기를 가져오기 화면 창에 둘지, 팀 지식 줄 펼침에 둘지가져오기 창을 권한다(넣는 흐름 옆에서 확인)
6쓰기 자리용 넣지 못함 「모든 팀 지식 모아 보기」 를 서버에 만들지만들지 않으면 고른 지식 기준만
7쓰기 · 읽기 자리의 설정 메뉴가 2칸(에이전트 설치 · 나)이 되는데 이대로 좋은가좋다고 본다. 못 하는 항목은 숨기는 지금 원칙과 같다
8화면 주소 경로(#settings/…)를 앱 전체에 도입할지설정만 따로 하지 않는다. 앱 전체 결정으로
9개인 화면 설정을 같은 단계에서 바꿀지, 팀 화면이 끝난 뒤 따로 할지메뉴 표는 1단계에 같이 들이고, 자리 옮김은 팀 화면 뒤에
10자리마다 설정 첫 화면을 다르게 할지(Q11 은 「옆 메뉴 설정은 설정 › 일반으로 연다」 로 예측 가능성을 정했다, main.js:4362-4364)「보이는 메뉴의 첫 칸이 곧 도착 화면」 규칙으로 맞추면 Q11 의 까닭(누르면 어디로 가나 안다)을 지킨다
