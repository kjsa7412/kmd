# 문서 짜임 관리(폴더 · 파일 이름 · 제목) 검토

2026-11-06 · 요청: 지식 문서의 짜임(폴더 · 이름)과 문서 이름을 바꾸고 관리하는 화면

## 1. 지금 상태

| 무엇 | 지금 | 바꾸는 길 |
|---|---|---|
| 문서 제목 | 문서 첫 줄 `# 제목` · 옆 메뉴 · 탭 · 그래프에 보이는 이름 | 문서 고치기로 `#` 줄을 고치면 바뀐다(쓰기 자리). 따로 「이름 바꾸기」 는 없다 |
| 파일 이름 · 폴더 | `docs/` 아래 경로 = 문서 id. 링크 · 장부 · 화면 주소가 이 경로를 쓴다 | **없다.** 지식 폴더(git)를 손으로 고쳐야 한다 |
| 폴더 짜임 | 옛 폴더를 들일 때 그 짜임 그대로 섰다(DPMS 의 `1.2_사업관리` …) · 새 문서는 갈래 장부(`_forms.md`)의 폴더 칸에만 선다 | 갈래 장부의 폴더 칸만 |
| 문서 지우기 | 없다 | 없다 |

188 서버 지식을 읽어 보니(읽기만):

- **DPMS**: 문서 35 · 폴더 14 · 자리 장부의 문서 경로 207줄 · 갈래 장부 있음. 제목과 파일 이름이 다른 문서 23. 22개는 띄어쓰기만 다르고(`수행범위정의서.md` ↔ 「수행범위 정의서」), **1개는 이름 자체가 다르다**(`게이트웨이테이블정의서.md` ↔ 「테이블정의서」 · 지난번 꼬리표가 붙었던 문서).
- **GDI**: 문서 18 · 폴더 없음 · 자리 장부의 문서 경로 298줄. 제목과 파일 이름이 다른 문서 17(모두 띄어쓰기).

정해 둔 규칙이 없어서 사람이 고칠 길이 없고, 맞추려면 git 을 직접 만져야 한다.

## 2. 문서 경로에 걸린 것: 옮기면 같이 바뀌어야 하는 곳

| 걸린 곳 | 어떻게 걸렸나 | 옮길 때 할 일 |
|---|---|---|
| 다른 문서의 링크 | 상대 경로 `[x](../운영/백업.md)` · `x.md#머리`(작성기준 4절 · `server/views.js` `linkTarget`) | 그 문서를 가리키는 모든 링크를 새 상대 경로로 다시 쓴다 |
| 옮긴 문서 자신의 링크 | 상대 경로라 폴더 깊이가 바뀌면 다른 문서 · 첨부(`assets/`) · 참고 블록의 기록 링크(`../work/…`)가 모두 깨진다 | 옮긴 문서 안의 상대 링크를 새 자리 기준으로 다시 쓴다(참고 블록은 `core/sections.js` 로만) |
| 자리 장부 `_managed.md` | 이름 → `docs/문서.md` · `## 머리`(DPMS 207줄) | 그 문서 줄의 경로를 바꾼다 |
| 갈래 장부 `_forms.md` | 갈래 이름 = 문서 이름 · 폴더 칸(저장 검사 G4) | 갈래 문서를 옮기거나 이름을 바꾸면 장부 줄도 같이 바꾼다. 안 바꾸면 그 갈래의 새 항목이 거절되거나 새 문서가 엉뚱하게 선다 |
| 가져올 곳 `_sources.json` | 채울 문서(`into.doc`) | 그 문서를 가리키면 같이 바꾼다 |
| 기록(`work/`) | `touches` 는 이름(좌표)이라 경로에 **걸리지 않는다** | 할 일 없음 |
| 원본이 주인인 문서(표지 `watched`) | 원본 파일과 짝 | **옮기기를 막는다**(「내 문서로」 한 뒤에만) |
| 이름 값에 문서 이름이 든 것 | `문서:<문서>-개요` 같은 이름(DPMS · GDI) | 이름(아이디)은 그대로 둔다. 보이는 이름만 사람이 고친다 |
| 화면 · 바깥 | 열린 탭 · 폴더 접힘 · 그래프 · 찾기 캐시 · Claude 세션과 스킬이 부르는 경로 · 북마크 · 개인 프로그램이 받은 사본 | 서버가 다시 읽게 하고, 옛 경로는 이력에 남긴다(6절 Q3) |
| git · 백업 | 지식 폴더는 git · GitLab 으로 백업 | `git mv` 와 링크 · 장부 고침을 **한 커밋**으로 묶는다. 이력은 `--follow` 로 이어진다 |

결론: 파일 이름이나 폴더를 바꾸는 것은 「파일 하나 이름 바꾸기」 가 아니다. 링크 · 장부 셋 · 표지를 한꺼번에 고치는 **짜임 바꾸기**다. 하나라도 빠지면 링크가 깨지거나 저장 검사가 그 갈래를 거절한다. 그래서 손으로 하지 말고 서버가 한 덩이로 해야 한다.

## 3. 무엇을 할 수 있게 하나

| 일 | 누가 | 다루는 것 |
|---|---|---|
| **제목 바꾸기** | 쓰기 이상 | `#` 줄만. 경로 · 링크는 그대로(링크 글자는 그대로 둔다) |
| **문서 옮기기 · 파일 이름 바꾸기** | 지식관리자 | 경로가 바뀐다 → 2절 전부 |
| **폴더 만들기 · 이름 바꾸기 · 옮기기** | 지식관리자 | 폴더 안 문서 모두의 경로가 바뀐다 → 2절 전부(문서 여럿) |
| **빈 폴더 지우기** | 지식관리자 | 문서가 남은 폴더는 지우지 않는다 |
| **제목과 파일 이름 맞추기** | 지식관리자 | 지식 점검에 「제목과 파일 이름이 다른 문서 n」 · 골라서 한 번에 맞춘다(6절 Q1 규칙대로) |
| 문서 지우기 | (이번에는 넣지 않음 · 6절 Q4) | 지운 문서를 가리키는 링크 · 장부 · 이름이 남는다. 정해야 할 것이 많다 |

## 4. 서버: 저장 문 하나로

CLAUDE.md 「새 저장 길은 이 문을 지나게 한다」 를 따른다.

- `hub.save` 에 **짜임 바꾸기**를 더한다: `moves[{ from, to }]`(문서 · 폴더) + `titles[{ doc, title }]`. 채널은 서버가 정한다(`structure`).
- 권한: 옮기기 · 폴더는 `hub.need(ctx, kn, 'admin')`, 제목만이면 `'write'`.
- 한 덩이: 기록(이력 `log/` 「짜임 바꿈: A → B」 · 태그 `structure`) + 파일 옮김 + 링크 다시 쓰기 + 자리 · 갈래 장부 · `_sources.json` 줄 + **한 커밋**. 지문(문서 목록과 걸린 문서들의 지문)이 어긋나면 `E_CONFLICT` 로 아무것도 쓰지 않는다. 커밋 뒤(알림 · 백업)는 던지지 않는다.
- 검사:
  - 이름 꼴: 새 문서 검사(G4)와 같다. 파일 이름 조각(날짜 · 판 · 최종) 없음 · 40자 안.
  - 경로: `..` · 예약 이름(`_` 로 시작) · `assets` 를 막는다. 대소문자만 다른 이름(Windows)도 처리한다.
  - 대상: 같은 경로가 이미 있으면 거절한다. `watched` 문서는 거절한다.
  - 갈래 장부: 갈래 문서를 갈래 폴더 밖으로 옮기면 장부 폴더 칸을 같이 고칠지 묻는다. 묻지 않고 그냥 두지 않는다.
- **미리 보기(마른 실행)**: 같은 요청에 `dry: true` 를 주면 아무것도 쓰지 않고 「옮길 파일 n · 고칠 링크 n(문서마다) · 장부 줄 n · 걸린 갈래」 를 돌려준다. 화면은 이것을 보여 주고 승인을 받는다.
- 계산은 `core/restructure.js`(새 · 순수 함수: 계획 → 바꿀 파일 글) 하나로 한다. 링크 풀이는 `linkTarget` 과 같은 규칙을 쓰고, 참고 블록은 `core/sections.js` 로만 읽고 쓴다. 다시 그리기 스킬(`kmd-migrate`)도 같은 함수를 쓸 수 있다.
- MCP: 세션용 `restructure`(지식관리자) · 문서 목록에 옛 경로 → 새 경로(Q3).

## 5. 화면안

### 자리
**설정 › 지식 관리 메뉴에 「문서 짜임」**을 둔다(지식관리자만 보인다). 옆 메뉴 문서 나무의 폴더 · 문서 줄 ⋯ 메뉴에 「이름 바꾸기 · 옮기기 · 새 폴더」 를 두고, 고르면 이 화면으로 와서 그 줄이 열리게 한다. 쓰기 자리는 문서 ⋯ 메뉴에 「제목 바꾸기」 만 본다.

### 「문서 짜임」 화면

```
┌ 문서 짜임 · DPMS 지식 ─────────────────────────────────────────────┐
│ [찾기: 문서 · 폴더]    [+ 새 폴더]          점검: 제목≠파일 23  [맞추기…] │
├──────────────────────────────┬─────────────────────────────────────┤
│ ▾ 📁 3.3_게이트웨이설계   4  ⋯ │ 고른 것: 게이트웨이테이블정의서.md   │
│     📄 게이트웨이설계서        │  제목  [테이블정의서            ]   │
│     📄 테이블정의서 ← 고름  ⋯ │  파일  [게이트웨이테이블정의서  ].md │
│ ▸ 📁 3.4_DPMS웹설계       7  ⋯ │  폴더  [3.3_게이트웨이설계     ▾]   │
│   (끌어서 다른 폴더로)         │  걸린 것: 링크 3 · 장부 줄 27 · 갈래 없음│
│                              │  [바꿀 것에 담기]                    │
├──────────────────────────────┴─────────────────────────────────────┤
│ 바꿀 것 2                                                            │
│  · 3.3_…/게이트웨이테이블정의서.md → 제목 「게이트웨이 테이블정의서」   │
│  · 폴더 0_공통 → 00_공통 (문서 1)                                    │
│  미리 보기: 옮길 파일 1 · 고칠 링크 5(문서 3) · 장부 줄 28              │
│                                    [비우기]  [한 번에 반영]          │
└────────────────────────────────────────────────────────────────────┘
```

- 바꿀 것을 **모았다가 한 번에** 넣는다. 바꿀 것 목록 + 미리 보기(마른 실행) → `ask()` 확인 → 저장 한 번 = 커밋 하나 = 이력 한 줄. 한 건씩 바로 바꾸면 이력과 백업이 잘게 쪼개진다.
- 끌어 옮기기는 마우스 편의일 뿐이다. 키보드는 ⋯ › 옮기기 › 폴더 고르기(`.pop`)로 한다.
- 걸린 것이 있으면(갈래 문서 · `watched`) 그 줄에 까닭을 쓰고 담기를 흐리게 한다.
- 이력 화면에 갈래 「짜임」 을 더한다. 되돌리기는 반대 옮기기를 한 번 더 넣는다.
- 컨벤션: 새 부품은 없다(`.tree` · `.tn.dir` · `.fbtn` · `.inp` · `.pop` · `ask()`). 미리 보기 줄은 「어디서 어디로」(`.route`)를 쓴다.

## 6. 정할 것

| | 물음 | 권장 |
|---|---|---|
| Q1 | **파일 이름 규칙**: 파일 이름을 제목과 같게(띄어쓰기 그대로 `수행범위 정의서.md`) 둘까, 지금처럼 붙여 쓸까(`수행범위정의서.md`)? | **제목 그대로(띄어쓰기 포함)**. 「제목 = 파일 이름」 하나만 기억하면 되고, 맞추기 점검이 단순해진다. 작성기준 6절에 한 줄 더한다 |
| Q2 | 화면 자리: 설정 › 「문서 짜임」(모았다가 반영) vs 옆 메뉴에서 바로 | **설정 › 문서 짜임** + 옆 메뉴 ⋯ 는 바로가기만. 바꾸면 링크 · 장부가 같이 바뀌는 일이라 미리 보기를 거치게 한다 |
| Q3 | 옛 경로를 따라가게 둘까(옛 주소 · 세션 · 북마크) | **이력만으로 충분**(옛 경로 → 새 경로를 이력에 남기고, 찾기가 옛 경로로도 찾는다). 따로 넘겨 주는 장부(`_moved.md`)는 만들지 않는다 |
| Q4 | 문서 지우기를 같이 할까 | **이번에는 뺀다.** 지운 문서의 이름 · 링크 · 기록을 어떻게 할지 따로 정해야 한다. 대신 「보관」 폴더로 옮기기는 이 기능으로 된다 |
| Q6 | **차례**(폴더 · 문서를 줄 사이에 끼워 넣기)를 어디에 남길까. 파일 체계에는 차례가 없다 | 지식 뿌리의 차례 장부(새 예약 파일 `_order.md` · 폴더마다 형제 차례 한 줄씩 · 없으면 폴더 먼저 · 이름 차례). 옆 메뉴 나무 · 문서 짜임 화면 · 찾기 목록이 같은 차례를 쓴다. 짜임 저장과 한 커밋 |
| Q7 | 제목과 파일 이름 | **하나로 묶는다.** 제목을 바꾸면 파일 이름도 바뀐다(목업 2026-11-06 확정). 다른 문서는 「제목으로 맞추기」 |
| Q5 | 쓰기 자리에 제목 바꾸기를 열까 | **연다**(지금도 고치기로 된다 · 경로는 그대로). 옮기기 · 폴더는 지식관리자만 |

## 7. 단계

| 단계 | 할 일 | 시험 |
|---|---|---|
| R1 | `core/restructure.js`: 옮기기 계획 → 바뀔 파일 글(링크 · 장부 셋 · 참고 블록) · 검사 | 단위 시험: 상대 링크 깊이 바뀜 · `#머리` · 첨부 · 참고 블록 · 갈래 · `watched` 거절 |
| R2 | `hub.save` 짜임 바꾸기 + `dry` · 권한 · 지문 · 한 커밋 · 이력 갈래 「짜임」 · API · MCP | 서버 시험: 쓰기 자리 403 · 지문 어긋남 `E_CONFLICT` · 옮긴 뒤 링크 · 장부 · 저장 검사가 그대로 돈다 |
| R3 | 화면 「문서 짜임」(목업 먼저 확인) · 옆 메뉴 ⋯ · 제목 바꾸기 | 화면 시험 · 네 폭 |
| R4 | 지식 점검 「제목과 파일 이름이 다른 문서」 · 맞추기 | DPMS 23 · GDI 17 을 사본에서 맞춰 보고 사람 확인 뒤 188 에 넣는다 |
| R5 | 작성기준 6절 · 권한 모델 · 설명서(지식관리자) · `kmd-team` 스킬 | — |

R1 ~ R2 는 화면 없이도 쓸 수 있다(세션 · 셸 `kmd restructure`). 그래서 DPMS 의 `게이트웨이테이블정의서` 같은 급한 것은 R2 뒤에 바로 고칠 수 있다.
