## 1) md 렌더링 경로

### 1-1. markdown-it 인스턴스 전수

| # | 위치 | 설정 | 용도 |
|---|---|---|---|
| 1 | server/views.js:13 | `html:false, linkify:true, breaks:true` | 지식 문서·기록·항목 본문 전부 |
| 2 | server/http.js:86 | `html:false, linkify:true` (breaks 없음) | `/manual/…` 설명서 페이지(server/http.js:87-100) |

- **[확인]** 클라이언트에는 markdown 렌더러가 없다. 서버가 HTML로 바꿔 JSON 필드 `html`·`intro`에 담아 보내고, 클라이언트는 문자열로 끼워 넣는다(app/main.js:785-786, 793). package.json:20의 의존성은 `markdown-it` 하나이고, 플러그인 패키지는 없다.
- **[확인]** 설명서 렌더러(#2)는 링크 규칙이 따로 있다. `.md` 링크가 설명서 목록에 있으면 `/manual/<slug>`로 바꾸고, 없으면 글자만 남긴다(정규식 치환, server/http.js:93).

### 1-3. 항목(## 머리) 단위 표시

- 파싱: core/sections.js:48-61 `parseDoc`.
  - h1은 제목이다.
  - h1부터 첫 `##`까지가 intro다.
  - `##`마다 section `{h, body, applied}`가 된다. `###` 이하는 그 항목에 든다(core/sections.js:11-34). 코드 울타리 안의 `#`은 머리로 보지 않는다.
- 서버: `docView`(server/views.js:207-245)가 항목마다 아래 값을 만든다.
  - `html`: `render()` 결과.
  - `md`, `locks`: `editParts`, server/views.js:56-59.
  - `base`, `recs`(이 항목을 건드린 기록 수).
  - `pend`: 최대 8건, `PEND_MAX`(core/knowledge.js:233)와 `pendPick`(core/knowledge.js:234-237).
  - `pendMore`, `by`(마지막으로 넣은 기록), `named`.
- 클라이언트: `docPane`(app/main.js:767-796).
  - 항목마다 `<h2 data-sec>`를 쓰고(app/main.js:786), 머리 글자는 `esc(s.h)` 그대로다. 머리 안의 md(굵게, 링크 등)는 렌더되지 않는다 **[확인]**.
  - 본문은 `linkify(s.html, …)`를 거친다(app/main.js:785).
  - 찾기로 열었으면 `.lit`으로 감싼다(app/main.js:786, CSS app/kmd.css:246-247).
- intro는 `<p class="muted small">`로 바뀌어 h1 아래에 붙는다(app/main.js:793).
  - **[확인]** intro는 항목 이름 자동 링크(`linkify`)를 거치지 않는다.
  - **[확인]** intro를 `render()`할 때 `src`를 넘기지 않아(server/views.js:239), intro 안 기준선 블록의 확인 시각이 늘 「아직」이다.
- 개요(오른쪽 칸): `docAside`의 `.olr` 줄을 누르면 `scrollSec`로 해당 h2까지 스크롤한다(app/main.js:750, 4129).

### 1-4. 편집 UI

- 「고치기」 단추: app/main.js:790. 원본이 주인인(watched) 문서와 나란히 보기에서는 숨긴다. 핸들러는 `editDoc`(app/main.js:4050-4059)이고, sessionStorage에 남은 초안이 있으면 되살린다.
- 편집기(app/main.js:776-778, CSS app/kmd.css:262-268)
  - 문서 전체를 textarea 하나에 넣는다. 원문은 `edOrig`가 `## h\n` + `s.md`를 이어 만든다(app/main.js:1449).
  - 미리보기, 항목별 편집, 툴바 서식 단추가 없다. 단추는 「항목 더하기」(app/main.js:4061-4069) 하나뿐이다.
  - 기준선 블록은 textarea에서 빼고, 아래에 회색 잠금 표로 보인다(`.lockh` + `locks`).
- 저장: `saveDoc`(app/main.js:1460-1500)
  - `## `로 다시 갈라 바뀐 항목, 지울 항목, 이름 바꿀 항목을 가린다. 지우기나 이름 바꾸기가 있으면 `confirm` 후 `POST /api/k/:k/edit`.
  - 팀 지식(`direct:false`)이면 저장이 기록(pend)으로 남는다(server/http.js:915, app/main.js:778).
- **[확인]** intro는 편집기에 나오지 않는다(edOrig가 sections만 쓴다). 첫 `##` 앞에 글을 쓰면 「머리말」이라는 새 항목이 된다(app/main.js:1469).
- **[확인]** `**경과**` 꼬리(아래 2-3)도 textarea에 그대로 보이지만, 저장할 때 옛 줄은 지켜진다(core/save.js:305-311). 지워도 되살아난다.

## 3) 링크 종류 전수

변환 규칙은 모두 server/views.js:19-28 `linkTarget`과 :61-75 `link_open`에 있다. 화면의 클릭은 `data-a`가 있는 요소만 처리한다(app/main.js:4148-4157). `<a>`이면 `preventDefault`한다.

추가로 확인한 것:

- **[확인]** 본문 안의 dlink에는 `data-pv`(미리보기 카드)가 없다. 오른쪽 칸의 줄과 ilink에는 있다.
- **[확인]** 내 PC 지식을 팀 화면에서 볼 때: 서버(PC)가 `data-k`에 맨 id(`~` 없음)를 넣는데(server/views.js:65), 클라이언트는 받은 HTML에서 `data-ak`만 `~`로 바꾼다(app/main.js:69). 화면은 PC 지식 id를 `'~'+id`로 다룬다(app/main.js:3173).
  - **[추측]** 그래서 팀 화면에서 PC 지식 본문의 문서·기록 링크를 누르면 팀 서버 쪽 같은 id 지식을 찾는다(없으면 오류). 실행으로 확인하지 않았다.
- **[확인·실행 미검증]** `linkTarget`의 `decodeURIComponent`(server/views.js:21)에 try가 없다. `[x](a%ZZ.md)`처럼 % 인코딩이 깨진 href가 있으면 URIError가 나서 `render()`, `linksOf`, `citesOf`가 던진다. 문서나 기록 요청 하나가 통째로 실패할 수 있다. 그림 규칙(server/views.js:80)은 try로 감쌌다.
- 그래프와 백링크 계산(정규식 `\]\(([^)\s]+)…\)`, server/views.js:87-104)
  - `citesOf`도 `work/`만 세므로 log 기록 인용은 그래프의 「근거」 선에서 빠진다 **[확인]**.
  - 꺾쇠 `<…>` 표기나 참조식 링크 `[x][ref]`는 세지 않는다 **[확인]**. 렌더는 markdown-it이 하므로 동작한다.

## 4) 비표준 문법과 깨진 링크

- **[확인]** `[[...]]` 위키링크 문법은 없다. core·server·app 전체를 찾아봐도 파서나 규칙이 없다. `[[`가 나오는 곳은 모두 JS 배열 리터럴이다. 비슷한 역할은 화면의 「항목 이름 자동 링크」(ilink)가 한다.
- 다른 비표준 문법: `<!-- applied -->`, `<!-- watched -->`, `<!-- baseline -->` 블록, `**경과**` 꼬리(core/sections.js:118-127)뿐이다.
- 깨진 링크 처리
  - 대상 존재 여부를 **렌더 때 보지 않는다**. 없는 문서나 기록을 가리켜도 정상 dlink로 그린다(server/views.js:19-28).
  - 누르면 문서는 「이 문서는 이제 없다. 지워졌거나 이름이 바뀌었다 · 탭 닫기」(app/main.js:770), 기록은 「이 기록은 이제 없다…」(app/main.js:800)가 탭 안에 나온다.
  - 하단 「이 문서가 가리키는 문서」 목록은 있는 문서만 걸러 보여 준다(server/views.js:233). 깨진 문서 링크는 목록에서만 조용히 빠진다.
  - 분류되지 않는 링크(앵커, mailto, 내부 파일, log 기록, `#/`)는 동작하는 dlink와 **모양이 같은데 눌러도 반응이 없다**(href 제거, data-a 없음, server/views.js:66-68).
  - 이름 바꾸기 때 다른 문서의 링크를 고쳐 주는 기능은 찾지 못했다. 다만 이번에는 renameSection(core/sections.js:79-85, 머리 줄만 바꾼다)만 확인했다.

**렌더와 연결 계산이 서로 다르게 보는 것**

- **[확인]** `linksOf`·`citesOf`는 렌더된 결과가 아니라 **날 md 글**에 정규식을 건다(server/views.js:87-104).
  - 코드 울타리(```` ``` ````)나 `` `code` `` 안의 링크 예시도 셈에 들어간다. 「이 문서가 가리키는 문서」, 오른쪽 칸의 「연결 > 문서」, 그래프 선에 다 들어간다.
  - 그림 `![a](b.md)`도 링크로 센다.
  - 괄호가 든 파일 이름(`[x](설계(초안).md)`)은 정규식 `[^)\s]+`가 `)`에서 끊어서 세지 못한다. 렌더는 markdown-it가 하므로 동작한다. `logLine`은 이 문제를 피하려고 괄호를 `%28`·`%29`로 바꾼다(core/sections.js:129).
- **[확인]** 깨진 `%` 인코딩이 미치는 범위는 초안보다 넓다.
  - `linksOf`는 `backlinks()`가 지식 안 **모든 문서**에 대해 부른다(server/views.js:152).
  - 그래서 문서 하나에 `[x](a%ZZ.md)`가 있으면 그 지식의 **어느 문서를 열어도** `docView`가 실패한다. 경로: `docView`(:208) → `backlinks`(:240) → `linksOf`(:152) → `decodeURIComponent`(:21) 예외. 그래프 자료(:347)도 같이 실패한다.
  - 렌더 쪽에서 실제로 던지는 경우는 아래 「바로잡음」에 적었다.

**같은 렌더와 linkify를 쓰는 다른 화면** (초안은 문서 화면만 적었다)

- 기록 한 장: `recView`가 `render(k, w.path, w.body)`를 부른다(server/views.js:261). 화면은 `linkify(r.html, k, null)`이다(app/main.js:803).
  - 기록 경로는 `work/<id>.md`다. 그래서 `[x](other.md)`가 `work/other.md`로 풀려 **기록 링크**가 된다. 문서 링크가 되려면 `../docs/…`로 써야 한다.
  - `src`를 넘기지 않아 기준선 표의 확인 시각도 늘 「아직」이다.
- 항목 화면 「지금」: `render(k, d.path, s.body, { src })`(server/views.js:402)와 `linkify(v.html, k, it.key)`(app/main.js:1066). 오늘 넣은 `hchip`도 여기에 있다.
- 미리보기 카드 `pvHtml`(app/main.js:1396-1403)은 HTML이 아니라 `esc(d.first)`·`esc(r.body)` 글자만 쓴다. 링크와 서식이 보이지 않는다.

**그 밖의 화면 사실** (모두 [확인])

- 오른쪽 칸 「연결 > 언급」 줄은 `data-h`를 단다(app/main.js:754).

- 본문 아래 「이 문서가 가리키는 문서」의 `span.dlink`에도 `data-pv`가 없다(app/main.js:794).

- 문서 파일 이름 바꾸기나 옮기기 기능은 없다. core·server·app/main.js에서 `renameDoc`·`moveDoc`·`/rename`을 찾아도 나오지 않는다. 그래서 「이름 바꿀 때 링크 고치기」는 항목 머리(`renameSection`, core/sections.js:77-85)에만 해당하고, 그것도 링크는 고치지 않는다.
