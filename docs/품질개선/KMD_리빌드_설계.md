- 다시 그리기는 「기록을 원천으로 쓰는 다듬기」 다. 다듬기는 값을 바꾸지 않고, 다시 그리기는 기록이 말한 대로 값을 바꾸고 경위를 걷는다.
- 근거 없는 항목(이어진 기록 0)은 다시 그리지 않는다. 진단에서 세기만 한다.

### 1-2. 읽은 것

1. **가장 큰 어긋남은 근거 없음이다.** 그러나 이 항목은 원천이 지금 글뿐이다. 다시 그려도 얻을 것이 없고 잃을 것만 있다.
2. **다시 그릴 가치는 기록이 쌓인 항목에 있다.** 조각조각 들어간 저장이 한 항목에 10건 넘게 쌓였다. 여기를 한 번에 다시 쓰고 「사라지는 사실」 을 걸면 된다.
3. **복제 · 일지형은 리빌드 일이 아니다.** 복제 대부분은 틀 문장이라 지식 점검 규칙 쪽 일이고, 일지형은 거의 없다.
4. **CDP 의 교훈 셋을 가져간다.** 진단은 계산만(경고에 섞지 않음) · 원천층에 합성을 섞지 않음 · 「사라지는 사실」 은 LLM 자기 보고가 아니라 기계 대조.

### 1-3. kmd 에 이미 있는 것

| 있는 것 | 쓰는 법 |
|---|---|
| 다듬기 일감(`polishG` · `polishPromptOf` · `polishToSave` · `polishDone`) | 다시 그리기의 짓기 · 받기 틀 |
| `hub.checkSave`(prepare 만 · 마른 검사) | 승인 전 미리 보기 |
| gate `checkSection`(missing · invented · lost) | 값 쪽 「사라지는 사실」 을 저장 줄 안에서 다시 지킨다 |
| `revertPlan` · `hub.diff` · `hub.history` | 항목마다 applied · put 줄이 남으면 고치지 않고 붙는다 |
| 지식 점검 카드(`GUARD_ROWS`) | 진단 합계 자리 |

## 3. 데이터 꼴

### 3-1. `recordsOfItem(k, doc, heading)` — core/knowledge.js

- **모으기(합집합, works + logs)**
  1. touches → 이름 장부 → `coordsOfSection` 이 이 항목
  2. `parsePut` 줄의 doc · heading 이 이 항목(`## 넣은 것`)
  3. 참고 블록 `sec.log` 의 기록 href
  4. 항목 표지 `applied`
  5. 문서 단위 참고 줄(그 문서 전체를 건드린 기록) — `scope: 'doc'` 로 표시
- **빼기**: `k.superseded` · `k.reverted` · `k.kept` · `k.revertedItems` 에 이 항목이 있는 기록.
- **표시만(`mark`)**: `held`(넣지 못함) · `memo` · `legacy`(cutover 앞 · 아직 안 들어감) · `derived`(R-D6).
- **차례**: date 오름차순, 같으면 id 오름차순.
- **돌려주는 것**: `[{ id, kind: 'work'|'log', date, title, state, mark: [], scope, put: [{ from, to }], src: '## 원천 인용' | null }]`.
- 머리 이름이 바뀌어 끊긴 기록(DPMS 5건)은 잇지 않는다. 진단 「닿지 않은 기록」 에 보인다.

### 3-2. 재료 `rebuildG(k, doc, heading)` — server/hub.js

```
{ doc, heading, base,                       // 지금 글 지문
  form: '대상'|'서술'|'사건'|'대장',          // 문서 서식 종류
  siblings: [머리 …],                         // 이웃 머리 — 항목 링크에만 쓴다
  current: '지금 글(원천 0)',
  records: [{ id, date, title, put, body?, src?, derived }],   // 오래된 순 · held · memo 뺌
  cut: n }                                    // 본문을 접은 기록 수
```

- 60,000자를 넘으면 **오래된 기록부터 본문을 접는다**(id · 제목 · put 줄만 남김). put 줄은 끝까지 지킨다(값 근거).
- 그래도 넘으면 일감을 세우지 않는다(`E_TOOBIG` 「이어진 기록이 너무 많다」).
- 파생 기록(R-D6)은 put 줄만 싣고 본문은 싣지 않는다.

### 3-3. 일감 · 승인 파일

- `jobs.json` 의 일감: `{ id, type: 'rebuild', doc, heading, by, state, at, why? }`.
- state: `queued` → `building` → **`review`** → `saved` | `kept` | `dropped` | `stale` | `failed` | `expired`.
- 지은 글과 검사 결과는 `<data>/rebuild/<jid>.json` 에 원자 쓰기(임시 파일 뒤 이름 바꾸기):

```
{ jid, doc, heading, base, content, hash,     // hash = sha16(content)
  lostValues: [{ v, line }],                   // 막음 — 짚어야 넣는다
  lostRows:   [{ key, row }],                  // 막음
  lostLines:  [{ text, best }],                // 확인 — 짚어야 넣는다
  changed:    [{ from, to, by: [rec] }],       // 기록이 바꾼 값(접은 사슬)
  dry: { ok, code?, why? },                    // checkSave 결과
  drift: '진단 전 합계 한 줄',
  sources: [rec id …] }
```

- 끝난 일감의 파일은 30일 뒤 지운다(일 줄 정리와 같이).

### 3-4. 다시 그림 기록 (log/, 서버가 짓는다)

```
---
title: 다시 그림: <문서 제목> › <머리>
tags: [rebuild, job/<jid>]
---
## 바뀐 것
- 포트: 8080 → 9191
- 담당: 김철수 → (뺌)

## 근거
- 이어진 기록: 2026-0912-… · 2026-0930-… · …(12)
- 기록의 값: 8080 · 9191 · 김철수 · 이영희 …

## 까닭
- 건 사람: kjsa · 넣은 사람: kjsa
- 진단(전): 이어진 기록 12 · 줄 41 · 같은 글 1 · 날짜 줄 0
- 걷은 문장: 「…」 · 「…」
```

- `## 바뀐 것` 에는 이 항목 줄만(R-D2 · R-D16). 「(뺌)」 은 값이 없어 요구 값이 되지 않는다.
- 저장 문이 그대로 `## 넣은 것` 칸 · `put` 태그 · 항목 표지 `applied` · 참고 블록 경과 줄을 단다.
- 본문 끝 진단 합계는 다음 진단이 「지난번보다 늘었다」 를 셀 수 있게 남긴다(CDP).

### 3-5. 진단 `drift(k)` — core/drift.js

| 신호 | 정의 | 문턱(판 1 · R2 에서 188 로 다듬음) |
|---|---|---|
| `rich` 다시 그릴 만함 | 이어진 기록(파생 · held · memo 뺌 · cutover 앞 포함) 수 | 5 이상 |
| `unsourced` 근거 없음 | 이어진 기록 0(문서 단위 참고 줄도 0) | 0 |

| `dup` 같은 글 | 코드 · 표 · 머리 · 인용 · 링크를 뺀 40자↑ 산문 줄이 두 항목 이상 | 지식 항목의 5%(최소 20) 이상에 퍼진 줄은 「틀 문장」 으로 따로 셈 |

- `reach` 는 사용자 목표에 얼마나 닿는지 숫자로 보인다(GDI 지금 17%).

## 4. 길

### 4-1. HTTP

| 길 | 자리 | 하는 일 |
|---|---|---|
| `GET /api/k/:id/drift` | `hub.meta(id, ctx)`(read 미만 404) · 목록은 admin, 아니면 합계만 | 진단 |
| `GET /api/k/:id/trail?doc=&h=` | `hub.meta(id, ctx)` | `recordsOfItem` + 지금 글 · base(자리로 거름) |
| `POST /api/k/:id/rebuild { doc, headings[≤10] }` | `hub.need(ctx, kn, 'admin')` | 항목마다 일감. 항목마다 결과 `{ heading, jid } | { heading, code }`(E_NOSOURCE · E_BUSY · E_TOOBIG · E_WATCHED · E_NOCLAUDE) |
| `GET /api/k/:id/rebuild/:jid` | admin | 승인 파일 + base 다시 견줌(`stale: true` 면 바로 알림) |
| `POST /api/k/:id/rebuild/:jid/put { hash, lostValues, lostRows, lostLines }` | **승인자** admin | R-D11 · R-D12 · R-D13 → `hub.save(channel 'rebuild')` |
| `POST /api/k/:id/rebuild/:jid/keep` | admin | `kept` · 아무것도 안 씀 |
| `POST /api/k/:id/rebuild/:jid/again { note }` | admin | 옛 일감 `dropped` · 새 일감(R-D21) |

- 경로 조각 `:jid` · `doc` · `h` 는 `decodeURIComponent` 를 감싸 400. 모양 검사(jid `^[A-Za-z0-9_-]{1,64}$` · 머리 한 줄 120자).
- 지식 id 를 싣는 응답(drift · 일 줄)은 자리로 거른다.

### 4-2. 저장 흐름 (put)

1. 승인자 `need(admin)` → 일감 state 가 `review` 인지 → 승인 파일 해시 = 보낸 `hash` · 보낸 목록 ⊇ 서버 목록(빠짐 없이 짚음).
2. 기록 본문을 서버가 짓는다(3-4). `## 바뀐 것` 의 「(뺌)」 은 짚은 `lostValues` 만.
3. `hub.save(ctx = 승인자, { record, sections: [{ doc, heading, base, content }] }, { channel: 'rebuild' })`.
4. 저장 줄 안 prepare: 새로 읽은 지식 · `checkSection`(gate 그대로) · reverts 브레이크.
   - stale → 저장 전체 그침 → 일감 `stale`.
   - held 하나라도 → 저장 전체 그침 → 일감 `failed`(까닭).
5. 넣으면 일감 `saved` · 기록 id 를 일감에 적는다. 커밋 뒤 일(알림 · 측정 줄)은 던지지 않는다.

### 4-3. MCP · 스킬

- MCP `section` 에 `trail: true` 를 더한다. `recordsOfItem` 을 오래된 순으로 · 본문 2,000자로 잘라 · 30건까지. `hub.meta(id, ctx)` 로 거른다. 새 도구는 만들지 않는다.
- 다시 그리기를 거는 MCP 길은 두지 않는다(R-D19).
- `kmd-team-work` 스킬에 한 줄: 「항목이 기록과 어긋나 보이면 section trail 로 흐름을 읽고, 지식관리자에게 [다시 그리기] 를 부탁한다」. 판(`TEAM_KIT_REV`)을 올린다.
- 새 스킬은 만들지 않는다.

## 5. 화면

컨벤션 v0.2 부품만. 상태는 읽는 중 · 빈 상태 · 오류(+ 「다시 읽기」)를 가른다. 네 폭(1280 · 1024 · 600 · 375)에서 잘림 0.

### 5-1. 지식 점검 카드 (지식관리자)

- `GUARD_ROWS` 아래 「다시 그리기」 묶음 다섯 줄: 다시 그릴 만한 항목 n · 기록 없는 항목 n · 큰 항목 n · 같은 글 n(틀 문장 m 따로) · 닿지 않은 기록 n. 끝에 「다시 그릴 수 있는 항목 17%」 한 줄.
- 줄의 수를 누르면(`.lk`) `.tblwrap` 표가 열린다: 문서 › 항목 · 기록 수 · 줄 수 · 신호. 「다시 그릴 만한 항목」 표의 행에는 [다시 그리기](`.btn`).
- 기록 없는 항목 행은 단추 없이 「이어진 기록이 없다」.

### 5-2. 문서 화면

- 문서 머리에 [다시 그리기](`.btn`)를 [다듬기] 옆에 둔다. 조건은 다듬기와 같다(팀 · 지식관리자 · watched 아님 · noClaude 면 비활성 + 까닭).
- 누르면 모달(`.scrim.fix>.modal`, role=dialog · 첫 칸 초점 · Tab 가둠 · Esc · 바깥 누름)에 그 문서의 항목 목록: 확인칸 · 머리 · 이어진 기록 수 · 줄 수. 기록 0 · 열린 일감 · 다듬기 중인 항목은 확인칸 비활성 + 까닭. 10개까지.
- 항목 머리 옆 칩은 두지 않는다(「후보」 는 상태가 아니라 권고 · `.chip` 은 상태만).

### 5-3. 일 줄 · 승인 창

- 일 줄에 rebuild 일감: 단계 「모으기 › 짓기 › 검사 › 승인 기다림 › 넣기」. 상태 칩 「승인 기다림」(`c-pend`) · 「그사이 바뀜」(`c-warn`) · 「넣음」(`c-ok`).
- 「살펴볼 일 n」 탭 수에 승인 기다림을 더한다.
- 승인 창(`.scrim.fix>.modal`):
  - `.tabs`: 바뀐 글(지금 글 / 새 글 비교) · 사라지는 값 n · 사라지는 문장 n · 이어진 기록 n.
  - 사라지는 값 · 표 행 · 문장은 줄마다 확인칸 「빼도 된다」. 모두 짚어야 [넣기] 가 살아난다.
  - 열 때 base 가 어긋났으면 「그사이 항목이 바뀌었다: 다시 짓는다」 와 [다시 짓기] 만.
  - 단추: [넣기](`.btn.pri`) · [다시 짓기](`.btn`, 한 줄 지시 칸) · [그대로 두기](`.btn.ghost`, `ask()` 확인) · [취소](창 닫기).

### 5-4. 이력

- `HIST_KINDS` 에 갈래 「다시 그림」. 줄을 펼치면 항목 한 줄(옛 값 → 새 값 · 걷은 문장 n) · 서버가 준 `canRevert` 면 [되돌리기].
- 리빌드 뒤 다른 저장이 있으면 지금처럼 「그 뒤 다시 바뀜」(되돌리기 없음).

## 6. 안전

### 6-1. 사라지는 사실 (`core/rebuild.js`, 기계)

| 대상 | 판정 | 등급 |
|---|---|---|
| 값: `valuesOf(옛) − valuesOf(새)` | 이어진 기록(파생 포함)의 「옛 → 새」 사슬로 설명되면 `changed`, 아니면 **사라지는 값** | 막음: 짚어야 넣고 「옛 → (뺌)」 으로 기록에 남는다 |
| 지어낸 값: `valuesOf(새) − (옛 ∪ 기록 본문 · 제목 · 원천 인용 ∪ 같은 문서 머리 · 이름 장부)` | 하나라도 있으면 `{fix}` 로 돌려보냄 · 두 번 넘게 남으면 `failed` | 막음(사람에게 오지 않는다) |
| 표 행: 옛 글 표의 키 열(첫 열, 같은 값이 없을 때) | 새 글에 그 키의 행이 없으면 **사라지는 행** | 막음 |
| 문장: 옛 글 산문 줄(정규화 · 20자↑ · 표 · 코드 · 머리 · 인용 뺌) | 새 글 어느 줄과도 3-gram Jaccard < 0.6 이고 이어진 기록(파생 뺌)에서도 대체되지 않으면 **사라지는 문장** | 확인: 짚어야 넣고 `## 까닭` 「걷은 문장」 에 남는다 |
| 마른 검사 `hub.checkSave(dry, channel 'rebuild')` | gate 결과(꼴 · missing · invented · lost · legacy-mix · reverts) | 걸리면 `{fix}` 로 돌려보냄 · 남으면 `failed` |

- 일꾼의 `dropped` 는 승인 창 「사라지는 값」 옆 참고 글로만 보인다.
- 문장 대조 문턱(0.6 · 20자)은 R6 시범에서 오탐 · 미탐을 세어 한 번 다듬는다.

### 6-2. 값 대조 (저장 줄 안 · gate 그대로)

- missing: `## 바뀐 것` 의 새 값만 요구(R-D15 · R-D16).
- invented: `## 근거` 의 값 목록이 근거가 된다.
- lost: `## 바뀐 것` 의 「옛 → 새 / (뺌)」 만 허용(R-D17 로 근거 칸은 허용을 열지 못한다).
- 한 기록 = 한 항목이라 허용이 다른 항목으로 새지 않는다(R-D2).

### 6-3. 되돌리기

- 항목 표지 applied 가 다시 그림 기록을 가리키는 동안 [되돌리기](`revertPlan({doc, heading})`)와 비교(`hub.diff`)가 지금 코드 그대로 된다.
- 그 뒤 다른 저장이 있으면 되돌리기는 막힌다(지금 규칙). 「다시 그리기 전 글로 새 저장」 길은 9절 ③ 에서 정한다.
- 7일 안에 두 번 되돌린 문서는 값 바꿈이 reverts 로 걸리고, R-D14 로 일감이 `failed` 「7일 안에 두 번 되돌린 문서」 가 된다. 되돌린 항목을 곧바로 다시 그리지 못하는 브레이크로 둔다.

### 6-4. 권한

| 할 일 | 자리 | 판정 |
|---|---|---|
| 진단 합계 · trail 읽기 | 읽기 이상 | `hub.meta(id, ctx)` |
| 진단 목록 · 걸기 · 승인 창 · 넣기 · 그대로 두기 · 다시 짓기 | 지식관리자 | `hub.need(ctx, kn, 'admin')`(403) · 넣기는 승인자 ctx |
| 일 줄 멈춤 · 동시에 도는 수 | 총괄 관리자 | 기존 `ctx.admin` 그대로 |
| MCP · HTTP `/save` 로 rebuild 채널 | 없음 | 열지 않는다 |

- 쓰기 자리는 이력에서 결과만 본다.
- noClaude 지식은 걸 수 없다(`E_NOCLAUDE`). 일꾼이 쉬면 `queued` 로 기다리고 24시간 넘으면 `failed`(기록 남기지 않음 · 원천이 지식 안에 있다).

### 6-5. 대상에서 빼는 것

watched 문서 · 저절로 채우는 표 블록(값 대조에서 빼고 저장이 되붙인다) · `## 넣은 것` 같은 kmd 칸 · `##` 항목이 없는 문서 · 근거 없는 항목(R-D3) · 열린 일감이 있는 항목 · 다듬기 중인 문서(R-D20).

| 문서 화면에 항목 메뉴 `.pop` 이 없다(2) | 사소 | 확인함(없음). 문서 머리 [다시 그리기] + 항목 고르기 모달로 바꿈 |
| `## 바탕 항목` 줄이 put 꼴과 닮았다(1) | 사소 | 바탕 기록을 걷어 해당 없음 · R7 에서 꼴을 따로 정한다 |

### 10-2. 걷은 안

| 안 | 걷은 까닭 |
|---|---|
| B 세션 스킬 · `kmd-team-rebuild` · `rebuild_check` · ticket | 서버가 사람 승인을 확인할 수 없다 · 채널을 사람 요청 값으로 고르게 된다 · 판정표가 화면 · 이력에 남지 않는다. `trail` 읽기와 E_NOSOURCE 는 살렸다 |
| C 의 「원천 put 줄 옮겨 싣기로 gate 무변경」 | 요구 값이 되어 늘 막힌다. gate 무변경은 R-D15 꼴로 살렸다 |
| 문서 · 지식 통째 다시 그리기 | 묶음이 크면 E_CONFLICT · 허용 누출 · 사람이 보는 비용(CDP: 묶음 20 안팎) |
| 항목 나누기 · 합치기 · 머리 바꾸기 | 머리 고정. 큰 항목(대부분 기록 0)은 「구조 고침」 으로 따로 |
| 끊긴 머리 이어 주기(DPMS 5건) | 수가 적다. 기존 기록 고치기(touches-fix)로 |
| 일정 · 자동 다시 그리기 | CDP RB10. 진단만 늘 계산 |

### 10-3. 남는 약점

1. 다시 그릴 수 있는 항목은 DPMS 62% · GDI 17% 가운데서도 기록이 쌓인 수십 개다. GDI 처럼 통째로 옮겨 세운 지식에서 「기록으로 다시 그리기」 는 거의 일어나지 않는다(9절 ①).
2. 문장 대조는 어림이다. 말만 바꾼 줄은 오탐, 값 없는 서술의 뜻 바뀜은 미탐이다. R6 에서 재서 판을 올린다.
3. 기록이 자주 쌓이는 항목일수록 승인 사이에 stale 이 난다. 창을 열 때 알리고 [다시 짓기] 로 잇는 것까지만 한다.
