## 3. 앱 프레임이 좁은 폭에서 어떻게 되나

- 구조 [확인]: `aside.side` + `.col` 입니다. `.col` 안은 `header.hdr` → `.band` → `.body`, `.body` 안은 `.center`(`.tabbar` + `.panes > .main` [+ `.main.rp`]) 와 `.aside` 입니다 (`app/main.js:235`, `:243`).
- 접기/숨김 JS [확인]: **없습니다.**
  - `matchMedia` 는 `prefers-reduced-motion` 판정에만 씁니다 (`app/main.js:1316`).
  - resize 리스너는 두 개뿐입니다: 그래프 다시 그리기 (`app/main.js:1444`), 팝업 위치 다시 재기 (`app/main.js:4193`).
  - 옆 메뉴 접기 · 햄버거 · aside 토글 단추가 없습니다. 반응형은 CSS 900px 끊는 점 하나에 기댑니다.
- **901px 이상** [확인 + 계산]:
  - 데스크톱 3단(side 248 + main + aside 300)이 그대로입니다.
  - 1024px 에서 문서·항목 보기(aside 있음)의 `.main` 은 1024 − 548 = 476px 이고, 여백 44px 를 빼면 내용 폭은 **약 432px** 입니다.
  - `.paper` 여백 40px 까지 빼면 글 폭은 **약 390px** 입니다.
  - 오른쪽 창을 나눠 열면(aside 는 사라짐) 776 / 2 = **약 388px 씩** 입니다.
  - 901px 에서는 내용 폭이 약 310px 로 모바일보다 좁습니다. → **위험 높음.**
- **900px 이하** [확인]:
  - `.app` 이 세로 쌓기로 바뀌고 높이가 auto 라 문서 전체가 스크롤됩니다 (`:551`, `:573`).
  - `.side` 는 위쪽 가로 띠가 됩니다. sb-top, 지식 고르기, ktabs, `.lp`(최대 260px), 관리 nav 가 모두 이 띠 안에서 줄바꿈되며 쌓입니다 (`:552-558`, `:607-609`).
  - [추정] 600px 에서 이 띠가 300px 이상 차지해 본문이 첫 화면 아래로 밀립니다. → **중간–높음 (사용성).**
  - `.aside` 는 본문 아래로 갑니다 (`:560`).
- 상단 바 [확인 + 계산]:
  - `.hdr` 는 46px 고정이고 줄바꿈하지 않습니다.

3. **`app/main.js:3581` 의 부모가 wrap 하지 않음을 확인**. 초안은 "부모의 wrap 여부를 확인 못 함" 이라고 했다.
   - `.row` (`flex:1;min-width:260px`) 은 `<ul class="plain pl">` (`app/main.js:3585` 부근) 의 `li` 안에 있다.
   - `.plain li{display:flex;...}` (`app/kmd.css:150`) 와 `.pl li` (`app/kmd.css:354`) 어디에도 `flex-wrap` 이 없다.
   - 그래서 [추정] 이 아니라 [확인]: li 폭이 `.tx` 와 260px 를 합친 것보다 좁으면 넘친다. 이 줄은 `S.repoEdit` 로 주소를 고칠 때만 나온다.
4. **폭이 900px 보다 넓은 프레임도 `.app{height:100vh}` 와 `.body{overflow:hidden}` 에 묶임** (`app/kmd.css:568`, `:570`) [확인].
   - 초안 22번은 `100vh` 문제를 `.modal .mb` 에서만 짚었다.
   - [추정] 901px 이상인 태블릿(가로 1024/1180)의 모바일 브라우저에서는 주소창 높이만큼 아래가 잘린다. 앱 전체 높이가 걸린 문제라 `.mb` 보다 크다. `100dvh` 를 같이 쓰는 것을 제안한다.
5. **`.pal{max-height:calc(100% - 20px)}` (`app/kmd.css:272`)** [확인].
   - 이 100% 의 기준은 `.pscrim` 이다. 900px 이하에서는 scrim 이 문서 전체 높이라서 찾기 창의 높이 상한이 사실상 사라진다.
   - 초안 4절의 `.pscrim` 위험에 이 원인도 함께 적어야 한다.
6. **설명서 페이지 `/manual` (`server/http.js:97-99`) 은 반응형 처리가 되어 있음** [확인]. 초안은 이 페이지를 viewport 표에만 넣었다.
   - `main{max-width:820px;padding:22px 16px}`.
   - `table{display:block;overflow-x:auto}`: 앱 안에서 유일하게 가로로 스크롤되는 표다.
   - `pre{overflow-x:auto;white-space:pre-wrap}`.
   - 다만 `img` 규칙이 없어서 [추정] 큰 그림은 넘친다.
   - okPage (`server/http.js:174-175`) 는 `max-width:640px;padding:0 16px` 이고, `pre` 에 `word-break:break-all` 이 있다.
7. **문서 그림** [확인]: `.paper img{max-width:100%;height:auto}` (`app/kmd.css:675`). 초안의 「줄바꿈 처리가 되어 있는 곳」 목록에 함께 넣을 만하다.
8. **`/dl` 페이지 상세** (`server/http.js:1002`) [확인]. viewport meta 가 없는 것에 더해 `body style="margin:40px;max-width:760px"` 고정 여백이다.
