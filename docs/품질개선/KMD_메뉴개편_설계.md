## 1. 결론

1. **화면에 보이는 글은 제목 · 칸 이름 · 단추 · 상태 · 오류 · 숫자만.** 덧말 · 힌트 · 문단(`.lead` · `.hint` · `<small>` 덧말 · `.note`)은 새 부품 **정보 단추 `.tipb`(「!」 · `aria-label="도움말"`)** 를 눌러 여는 툴팁(`.pop.tipp`)으로 옮긴다. 오류 · 위험 경고 · 멈춤 줄은 숨기지 않는다.
2. **이름은 2 ~ 4자 명사.** 사람이 준 이름을 그대로 쓴다: 생성 · 수기수집 · 자동수집 · 공유 · 문서 · 이력 · 확인 · 지식관리 · 모든 지식 · 불러오기 · 저장소 · 기초 세우기 · 설정 · 지식백업 · Claude 연결 · 에이전트 설치 · 서버 정보 · 개인 프로그램 설치.
3. **옆 메뉴는 두 층.** 위: 지식 고르기 + **그 지식의 메뉴**(개인: 생성 · 공유 · 문서 · 이력 / 팀: 확인 · 생성 · 문서 · 이력). 아래: **공통 메뉴**(지식관리 · 설정). 「관리 줄 아이콘 다섯」 과 「설정 › 팀 지식」 · 「지식 관리 페이지」 가 이 둘로 모인다.
4. **보기(문서 · 항목 · 기록 · 그래프)와 나무는 「문서」 메뉴 안**에 둔다. 「문서」 를 고르면(처음 값) 옆 메뉴 아래가 지금처럼 보기 탭 + 찾기 + 나무이고, 나무 머리 [구조] 단추가 문서 구조 바꾸기를 연다.
5. **새 지식은 셋으로 쪼갠다.** 모든 지식 › [생성](빈 지식) · [불러오기](저장소 주소 + 가지로 그대로 들임 · 옛 「백업에서 되살리기」) · 지식관리 › **기초 세우기**(빈 지식 + 재료 → 구조안 → 짓기). 「파일을 그대로 문서로」 는 메뉴에서 걷고 기초 세우기 구조안 단계의 고르기 하나(「폴더 그대로」)가 된다.
6. **저장소(지식마다 git 주소 + 가지)와 지식백업(이 PC 의 모든 지식 사본 경로)은 다른 것**으로 나눈다. 가지는 저장소 칸 옆에 접어 둔다(처음 값 main).
7. **팀 기초 세우기는 팀 화면 안에서**: 브라우저로 폴더 올리기 → 팀 서버 `fileToMd` → 팀 일꾼이 구조안 · 짓기. 바탕 설계 7-2(개인 프로그램이 이은 팀의 빈 지식에 짓기)는 걷는다.
8. 팀에는 「공유」 가 없다(팀이 받는 쪽이다). 대신 맨 앞에 「확인」(넣지 못함 · 지식 점검 · 승인 기다림)이 있다.
9. 권한 판정 함수(`hub.levelOf` · `hub.meta` · `hub.need` · `ctx.admin`)는 그대로다. 새 길이 둘 생긴다: 팀 기초 세우기 올리기 `POST /api/k/:id/seed/upload`(8-2) · 지식관리자 저장소 보기 `GET /api/k/:id/backup`(6-4). 메뉴는 서버 판정과 같은 자리로만 보이고 숨긴다(6-4 표).
10. 새 지식 첫 걸음은 이어진다: 생성 창 끝 「다음 걸음」 카드 [기초 세우기] · [수기수집](5-2). 기초 세우기는 빈 지식에서만 되므로, 빈 지식의 수기수집 판에는 늘 한 줄 「빈 지식이다 · 폴더째라면 [기초 세우기]」 를 보인다.

## 3. 설명 정책

### 3-1. 규칙

| 무엇 | 화면에 늘 보임 | (!) 안으로 |
|---|---|---|
| 페이지 제목 · 카드 제목 · 칸 이름 · 단추 · 탭 | 보임 | |
| 상태(칩) · 숫자 · 지금 값(경로 · 주소 · 가지) | 보임 | |
| 오류(`formErr` · `errHtml` · `.callout.danger`) | 보임(숨기지 않는다) | |
| 위험 경고(되돌릴 수 없음 · 비밀이 나감 · Claude 로 글이 감 · 한도 넘음 · 원본이 주인) | 보임(`.callout.warn` 한 줄 · 한 줄을 넘는 까닭만 그 줄 끝 (!)) | |
| 멈춤 줄(`.stop`) · 넣지 못함 수 | 보임 | |
| 빈 상태 | 굵은 한 줄 + 다음 단추 하나 | 까닭 · 방법 |
| 페이지 머리 문단(`.lead`) | 없음 | 제목 옆 (!) 하나 |
| 칸 아래 도움말(`.hint`) | 없음. 단 꼴이 정해진 칸은 `placeholder` 예(「main」 · 「git@…」) | 칸 이름 옆 (!) |
| 카드 머리 덧말(`.ch small`) | 상태 · 수만(「붙음 3/4」) | 그 밖은 카드 제목 옆 (!) |
| 단추 옆 설명(`.note`) | 없음 | 단추 묶음 끝 (!) 하나 |
| 「설명서」 링크 | 머리 줄 「설명서」 하나만 | 툴팁 끝 「설명서」 링크(그 절로) |

- **한 화면 (!) 는 다섯까지**(페이지 머리 하나 + 카드 · 칸 넷). 넘으면 글을 줄이거나 그 화면의 (!) 를 페이지 머리 하나에 모은다.
- **툴팁 글은 세 줄까지 · 문장 둘까지.** 넘는 것은 설명서 절 링크로.
- **이름이 설명을 대신한다.** (!) 를 달기 전에 이름을 고쳐 덧말이 필요 없게 할 수 있는지 먼저 본다(4절).
- 표 칸 머리 · 메뉴 줄에는 (!) 를 달지 않는다(줄이 흔들린다). 필요하면 `title`.

### 3-2. 새 부품 `.tipb` · `.tipp`(컨벤션 4절에 더함)

이름은 `.tip` 을 쓰지 않는다. `.pal .tip`(명령 창 안내 · `app/kmd.css:336` · `app/main.js:1737`)이 이미 있다.

| 무엇 | 정한 것 |
|---|---|
| 단추 | `<button type="button" class="tipb" aria-label="<붙은 이름> 도움말" aria-expanded="false" data-a="tip" data-v="<id>">!</button>`(`aria-controls` 는 열린 동안만) · **칸 이름 · 제목의 형제**로 둔다(`<label>` · `<h1>` · `<h2>` 안에 넣지 않는다: label 이 단추를 묶거나 제목 글에 「!」 가 섞임 · `.lbrow` · `.pt` · `.shr` 줄) · 원 `var(--ctl-xs)`(새 토큰 18px · `--fs-xs` 글 · 모서리 `--r-pill` · 테두리 `--border-input` · 글 `--text-3`) · 붙는 글 바로 뒤 `--sp-2` |
| 새 토큰 | `--ctl-xs`(18px · 정보 단추 원) · `--w-tip`(320px · 툴팁 폭). `app/kmd.css` `:root` 와 컨벤션 토큰 표에 먼저 더하고 `var()` 로만 쓴다(CLAUDE.md 화면 절: 새 px 를 부품에 바로 쓰지 않는다) |

### 6-3. 「서버 정보: 정보 + 로그인」 풀이

### 6-5. 팀에 「공유」 가 없는 까닭

1. 공유는 「내 것을 남에게」 다. 팀 지식은 이미 팀원 모두의 것이고, 팀 → 팀 보내기 길은 없다(서버 길 `send` 는 개인 → 팀 · `core/send.js`).
2. 팀 화면에서 개인 지식을 부르지 않는다(CLAUDE.md 화면). 받는 쪽 일(넣지 못함 · 승인)은 확인에 있다.
3. 다른 팀원에게 문서를 알리는 것은 문서 주소 복사(`x.md#머리`)로 된다. 메뉴로 세울 만큼 크지 않다.

- **층 2 지식 메뉴**(`.kmn > button.kmi[aria-current]`): 아이콘 위 + 글 아래(2자) 넷 · 248px 에 넷이 들어간다(62px 씩). 지금 화면은 `aria-current="page"` + 밑줄. 「확인」 배지는 넣지 못함 수(지금 `heldBadge` · `app/main.js:847`) · 0 이면 없음. 「이력」 배지는 값 바뀜 수(지금 `histBadge`). 둘의 뜻은 6-1 끝 줄(지식 단위 · 사람 단위).
- **층 3** 은 고른 메뉴가 정한다. 문서(처음 값)는 지금 A 안 그대로(보기 탭 한 줄 · 찾기 + 도구 · 나무 · 옆메뉴 검토 3절 · 컨벤션 5절 `:103`). 「문서」 낱말이 메뉴 층 2 와 보기 탭에 둘 생긴다(옆메뉴 검토 P2). 처리: 보기 탭 첫 칸을 「문서」 대신 **아이콘 + 「목차」**(문서 나무를 펴 보는 뜻 · 다른 곳에 쓰지 않는 말)로 바꾼다(11절 4). 「폴더」 는 수기수집 [폴더] · 자동수집 종류 「폴더」 · 기초 세우기 「폴더 그대로」 와 넷으로 겹쳐 쓰지 않는다. 컨벤션 9절 용어집에 「목차」 를 더한다. 나무 머리 도구에 **[구조]**(연필 아이콘 · 지식관리자 · 주인)를 더한다.
- **하위가 둘 셋인 메뉴(생성 · 확인)는 층 3 줄을 두지 않고 본문 머리 `.tabs`**(생성: 수기수집 · 자동수집 / 확인: 넣지 못함 · 점검 · 승인)로 그린다. 모든 폭에서 같고, 메뉴 깊이(층 2 › 층 3 › 페이지 탭)가 하나 줄며, 탭 줄은 가로 스크롤 규칙(CLAUDE.md 반응형)을 따른다. 사람이 정한 하위(수기수집 · 자동수집)는 이름 · 차례 그대로 탭이 된다. 층 3 은 문서(나무)에만(이력 거르기는 본문 머리 select 한 곳 · 두 곳에 두지 않는다). 생성 · 확인을 고르면 층 3 자리는 비고(나무를 접음), 나무는 다시 「문서」 를 누르면 돌아온다. 가운데 문서 탭(열어 둔 문서)은 그대로 남는다.

## 8. 기초 세우기 · 불러오기 · 저장소 절차

### 8-1. 개인 기초 세우기(단계 띠 일곱)

관리 설계 4-1 · 4-3 과 바탕 설계 5-3 을 짧게 다시 쓴다. 엔진(구조안 · 차이 적용 · 값 대조 · 연습 판 · 되돌리기 구조안)은 그대로.

| 단계 | 이름 | 화면에 보이는 것 | 주 단추 |
|---|---|---|---|
| a | 지식 | 빈 지식 고르기(`.trow` · 빈 지식만 · 없으면 [+ 생성] 이 같은 자리에서 창). 빈 지식이 아닌 줄도 보이되 고를 수 없고 까닭 칩 「문서 n」 을 단다(먼저 수기수집으로 넣은 지식은 기초 세우기를 다시 할 수 없음을 보이게) | 다음 |
| b | 재료 | 경로 칸(`.inp.mono`) · 파일 n · 크기 · 한도 칩(300 파일 · 200MB · `core/importer.js:25-26`) · Claude 로 글이 간다는 `.callout.warn` 한 줄 | 조사 |
| c | 거르기 | 파일 줄(넣음 · 뺌 · 비밀 의심 칩) · [모두 넣기] | 다음 |
| d | 구조안 | 고르기 둘 **「Claude 안 · 폴더 그대로」**(폴더 그대로 = 옛 「파일을 그대로 문서로」 · Claude 를 부르지 않는다) · 구조안 나무(고칠 수 있음) | 다음 |
| e | 짓기 | 처음 문서 n(≤ 3) [승인] · 진행 수 · [연습 판] | 연습 판 |
| f | 진단 | 끝 진단 수(넣지 못함 · 빠진 값 · 값 남음 · 바탕 설계 4-6 의 「거울 지수」) | 넣기 |
| g | 넣기 | 걸음 목록(칩) · 끝 카드 [지식 열기] | (끝) |

- 덧말은 단계마다 (!) 하나. 바닥 줄 「먼저: <까닭>」 은 오류 성격이라 보인다.
- 「폴더 그대로」 를 고르면 e 짓기는 파일마다 글로 바꾸기만(Claude 를 부르지 않음) · 단계 띠는 그대로. 나오는 문서 꼴은 지금 `kind: 'folder'`(`server/hub.js:1184-1224`)와 같지만 **쓰는 길은 다르다**: 그 길은 `importFiles` 의 `asDocs` 로 `fs.writeFile` 뒤 `commitPaths` 를 바로 하고(`server/hub.js:3751 · 3784`) 장부도 `fs.writeFile`(`server/hub.js:1216-1219`)이라 저장 문 밖이다(그래서 팀에서 막혀 있다 · `server/hub.js:1185`).
- **폴더 그대로도 저장 문으로**: 짓기 결과는 문서마다 `hub.save` 한 덩이(기록 + `sections[{ doc, content }]` + 지문)로 넣는다. 채널은 서버 코드가 정한 `'seed'`. `asDocs` · `commitPaths` 를 바로 쓰는 길은 개인의 옛 `kind: 'folder'` 에만 남기고 기초 세우기에서는 쓰지 않는다. 장부(`_vocab.md` · `_managed.md`)도 장부 쓰기 길(원자 쓰기 · 저장 문 안)로 넣는다(CLAUDE.md 「새 저장 길은 이 문을 지나게 한다」).

### 8-2. 팀 기초 세우기(팀 화면 안)

| 단계 | 팀에서 다른 것 |
|---|---|
| a 지식 | 빈 팀 지식(지식관리자 자리부터). 총괄 관리자는 [+ 생성] 도 |
| b 재료 | **브라우저로 폴더 · 파일 올리기**(`<input type=file webkitdirectory>` · 끌어다 놓기). 팀 서버가 받은 파일마다 `fileToMd`(`core/importer.js:159`)로 글로 바꿔 짜임 일 장부에 둔다(원본은 첨부로 두지 않는다 · 고를 때만). 한도: 한 묶음 **300 파일 · 200MB**(`MAX_FILES` · `MAX_BYTES` · `core/importer.js:25-26` · 수기수집의 20 파일 `TEAM_IMPORT_MAX` 과 따로 · 기초 세우기 일 하나에만) · 한도 칩은 늘 보임 · 넘으면 「kmd-seed 대량」 (!). **서버 길**(새로): 지금 팀 파일 길은 요청 하나 64MB · 20 파일(`server/http.js:1053-1066`)이고 그 밖의 본문은 2MB(`MAX_BODY` · `server/http.js:43`)라 받을 수 없다. `POST /api/k/:id/seed/upload { group:{ id, total, last }, files[] }` 를 더한다: `readBody` 전에 `hub.meta(id, ctx)` · `hub.need(ctx, id, 'admin')` · 그 지식이 빈 지식인지 본다(`/import` 처럼 자리부터) · 요청 하나 64MB · 묶음 누계 300 파일 · 200MB 를 서버가 센다 · 하루 들이기 한도(`intakeDaily`)는 짓기 일감을 열 때 센다 |
| c 거르기 | 같음(팀 서버가 비밀 의심 줄을 센다) |
| d 구조안 | 「Claude 안」 = 팀 일꾼 일감 `shape-plan`(바탕 설계 7-3) · 「폴더 그대로」 = Claude 없음(짓기 결과는 8-1 끝 점처럼 `hub.save` 로 · 채널 `'seed'`). 지식이 「Claude 에 보내지 않음」 이면 Claude 안을 끄고 폴더 그대로 · 손 구조안만 |
| e 짓기 | 팀 일꾼 일감 `shape-write`(문서마다) · 연습 판은 팀 서버 안(바탕 설계 7-3 · `hub.shapeStep` 을 서버가 부른다) |

- **비용**: d 단계 앞에서 「파일 n · 글 n 자 · 팀 일꾼 일 n(구조안 1 + 문서 m)」 을 숫자로 보인다(쓴 글 n 자 · 용어집). 하루 들이기 한도(`intakeDaily` · 운영 값)를 넘으면 [짓기] 비활성 + 「오늘 한도 n 남음」.
- **도는 곳**: 팀 일꾼이 없거나 옛 판이면(바탕 설계 7-3 아는 type) d 의 Claude 안이 꺼지고 「팀 일꾼 없음」 칩.
- **끊김**: 브라우저를 닫아도 팀 서버에서 이어 돈다(일 줄 · 진행). 24시간 걸음이 없으면 「멈춤」(바탕 설계 7-2 8 을 팀 안 일로 바꿔 씀).
- 팀 화면은 개인 프로그램을 부르지 않는다(CLAUDE.md 화면). 원본은 팀 서버로 간다는 것을 b 의 경고 한 줄로 보인다(개인 길과 달라지는 점).

### 8-3. 생성 · 불러오기 · 저장소

| 일 | 칸 | 서버 길 |
|---|---|---|
| 생성 | 이름 · 저장소(접힘 · 열면 「GitLab 새로(그룹 · 이름) / 있는 주소 / 나중에」 · 가지 main ▸) | `POST /api/knowledge/add { kind: 'new', name, empty: true, backup: false }` → 저장소 고른 대로(관리 설계 4-5 · 9-2) |
| 불러오기 | 저장소 주소 · 가지 main ▸ · 이름(주소 끝) · 「연습」 체크(팀) | `POST /api/restore`(가지 받기를 더함) |
| 저장소 | 주소 · 가지 main ▸ · 상태 칩 · [붙이기 / 바꾸기 / 떼기] | `POST /api/k/:id/backup { url, branch }` · `backup/gitlab { group, name, branch }`(관리 설계 6 · 9-2) |
| 지식백업(개인 설정) | 경로 · [지금 백업] | 지금 PC 백업 자리 길 |

- **가지 접기**: 저장소 칸 오른쪽 작은 단추 「가지 main ▸」(`.btn.ghost.sm` · `aria-expanded`). 누르면 아래 칸 「가지」(`.inp.mono` · placeholder 「main」). 처음 값 main · 바꾼 값이면 접혀도 「가지 dev ▸」 로 보인다.
- **저장소와 지식백업을 나누면 엔진이 바뀐다**: 지금은 지식마다 원격 하나(`REMOTE` · `core/backup.js:72-82`)이고, PC 백업 자리(`autoBackup` · `server/hub.js:1178`)가 그 원격을 쓴다. 두 길을 같이 쓰려면 원격 둘(예 `kmd-copy` · `kmd-repo`)로 나누거나, 지식백업을 git 원격이 아닌 폴더 사본으로 바꾼다. 권장: 원격 둘(보냄 · 상태 · 멈춤 줄을 원격마다) · 10절 G1 · 11절 5. 나누지 않기로 하면 「저장소를 붙이면 지식백업이 그 원격을 쓴다」 경고를 지식백업 페이지와 지식 상세 › 저장소 두 화면 모두에 `.callout.warn` 으로 늘 보인다.
- **두 곳을 화면에서 구별**: 지식백업은 「경로 + 사본 n/m 지식」, 저장소는 「주소 + 가지 main」 을 늘 값으로 보인다. 이름의 차이를 툴팁에만 두지 않는다(5-2).
