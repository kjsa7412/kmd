# 현황 조사: 「지금 하는 일」 팝업과 지식관리 화면

> 1단계 조사(2026-10-28). 초안 + 비평(빠진 것 · 바로잡음).


코드는 읽기만 했다. 고친 것, git 상태 변경, 테스트 실행은 없다. 아래에서 **[확인]** 은 코드를 직접 읽은 것이고, **[추정]** 은 코드 흐름을 따라가 내린 판단으로 실제 화면에서 확인하지 않았다.

### 1-5. 이동에서 보이는 틈

- **[추정]** 팀 화면에서 내 PC 쪽 항목(kn 이 `~…` 인 run, source)을 누르면 `S.setArea` 를 `'me'` 로 바꾸지 않는다. 그러면 `pcSide()` (main.js:40) 가 false 일 때 `pollRuns()` 가 팀의 `/api/queue` 를 읽는다 (main.js:2741). 고른 run id 가 그 목록에 없으니 `impPicked` 가 첫 번째 도는 일로 넘어가 엉뚱한 일이 보일 수 있다 (main.js:2658). 반대로 `busyGo` 의 run id 는 `~` 를 붙이지 않은 원래 id 다.
- **[확인]** curate 일은 일 줄에 `kind:'curate'` 로 실제로 서 있다 (hub.js:2270). 그런데 팝업은 일 줄이 아니라 문서 화면으로 보낸다.
- **[확인]** 이 PC 모드에서는 tidy 가 문서 화면으로 간다. `viewOf` 가 이 PC 에서 `tidy` 를 home 으로 돌리기 때문이다 (main.js:276). 다만 이 PC 모드에서 `jobs` 에 정리 일감이 생기는지는 따로 보지 않았다.
- **[확인]** 팝업 항목에 일 줄 id 가 없다 (source, tidy, curate). 그래서 「바로 그 일」을 고를 수 없고 지식 단위로만 이동한다.
- **[확인]** 팝업에 아예 없는 일: 파일 묶음 (`group`, hub.js:1684), 일 줄에서 `pause`, `check`, `fail` 상태인 일, 지식 보내기의 대기·저절로 다시 (`sendState` hub.js:257-262, `retrying` hub.js:264). 전체 다시 맞추기(`resyncs`, hub.js:966)는 source 의 `full` 표시로만 보인다.

## 4) 항목의 지식 이름과 레포 정보 (권한 거르기용) [확인]

- 모든 항목에 **`kn` (지식 id)** 과 **`knName`** 이 있다 (hub.js:1810-1817).
- 거르기는 이미 서버에서 한다. `hub.visible(ctx)` 에 없는 지식의 항목은 빠지고 (hub.js:1807-1808, 523-526), run 은 `runOk` 를 한 번 더 통과해야 한다 (hub.js:1811, 1651).
- 팀 화면에서 합친 내 PC 항목은 kn 앞에 `~` 가 붙는다 (main.js:3407). 그 항목의 권한은 내 PC 쪽 kmd 가 판단한다.
- 레포와 가져오는 곳:
  - `source` 항목에는 가져오는 곳 **이름 `name`** 만 있다. 저장소 주소(`s.at`)와 종류 원문(`kind` 는 `small` 에 사람 말로만)은 없다 (hub.js:898, 1810).
  - `run` 은 `title` (예: `<가져오는 곳> › <파일>`, hub.js:900) 뿐이다.
  - `tidy` 와 `curate` 에는 레포 정보가 없다.
- 일 줄 `queueItem` 은 `src: spec.name`, `rec: spec.recId`, `by`, `origin` 을 준다 (hub.js:1721-1723).
- **[추정]** 지식 단위 권한 거르기에는 지금 들어 있는 `kn` 으로 충분하다. 가져오는 곳이나 레포 단위로 거르거나 보이려면 busy 항목에 Q 일 id, `origin`, `src` 를 더해야 한다.
