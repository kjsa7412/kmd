한 줄: 지식은 초안 하나로 기록 · 문서를 한 번에 넣고, 넣겠다는 재료는 바로 반영한다. 세션에서는 서버가 만든 【저장 제안】을 보이고 대화로 조절한 뒤 승인받는다(승인이 경고 받아들임을 포함). 무인 일은 사람을 기다리지 않고 FIX 고리 → 규칙 길로 늘 들어간다. 저장 결과는 들어감 하나이고, 입력 오류는 아무것도 쓰지 않고 보낸 쪽이 곧 고쳐 다시 보낸다. 품질은 저장 뒤 사람 검토가 아니라 측정 → 로직 개선으로 올린다. 「넣지 못함」 · 「승인 받고 넣기」 · 「세울 이름」 · 메모를 걷는다. 개인 프로그램도 같다: 메모 · 「넣는 중(pend)」 · 바로 넣기 · 「둠」 을 걷고, 기록과 문서를 한 번에 넣는다.

원칙 셋(사람이 정함): (1) 항목(문서 안 ## 머리)이 모든 지식을 잇는 원자다. (2) 모든 기록은 문서(의 항목)에 남는다. (3) 문서는 최신 글과 이력을 가진다. 지식관리자는 사후 조정자이지 사전 허가자가 아니다.

원칙 다섯(사람이 정함 2026-11-10)

  • N1 지식을 들일 때 기록과 문서 대응은 한 번에. 초안을 만들고 기록 · 문서를 같이 한 번에 저장한다.
  • N2 지식으로 만들겠다는 재료는 바로 반영한다(낡음을 막는다). 반영을 미루거나 문서 밖에 세워 두는 상태를 두지 않는다.
  • N3 세션이 정리한 내용을 사람이 저장 뒤에 다시 검토하지 않는다. 품질은 로직을 정립하고 시스템을 꾸준히 개편해 올린다(측정 → 로직 개선).
  • N4 세션에서는 스킬로 초안(저장 제안)을 보이고 승인받는다. 초안은 대화로 세밀하게 조절한다(넣을 · 뺄 항목, 값 · 문장, 기록 범위, 다시 제안을 되풀이). 긴 세션은 일부만 골라 정리한다.
  • N5 「넣지 못함」 과 같은 개념인 기다림 상태(옛 설계 초안의 「확정 전」, 기록 없이 기다리는 일감 상태 「초안 보기」)는 두지 않는다.

이 원칙은 팀 서버와 개인 프로그램(PC)에 똑같이 걸린다(2026-11-10 확정).

1. 원인

서버가 저장 뒤에 판정한다

팀 저장 문(gatePrepare · saveIn)이 조각마다 값 대조 · 꼴을 검사한다(checkSection · checkProposal). 걸린 조각은 기록 끝 ## 넣지 못함 칸에 남아 문서 밖에 머문다.

Claude 초안용 문지기를 사람에게도 씌웠다

지어냄을 막던 값 대조(checkSectionDraft)를 개편 S4 에서 사람 · 세션 저장에도 씌웠다. 그래서 사람이 승인할 자리를 서버 판정이 차지했다.

같은 뿌리에서 나온 넷

  • 메모 = 기록만(saveIn 의 autoMemo)
  • 승인 받고 넣기 = 사전 허가(saveIn 의 review 분기)
  • 세울 이름 대기(saveIn 의 extraHeld)
  • 새 문서는 지식관리자만(hub.canDirect)

개인 프로그램도 같은 뿌리

세션 저장은 기록만 서도 되고(pend), 저장 뒤 뒤에서 「바로 넣기」(curatePending · placeGroup)가 넣는다. 기록과 문서가 두 커밋으로 갈린다. 바로 넣기의 Claude 가 둔 기록은 「둠(kept)」 으로 문서 밖에 남는다. 넣은 파일도 기록을 먼저 세운다.

사람은 저장 전에 거의 보지 못한다

kmd-team-save 는 「어느 지식」과 「확정이냐」만 묻는다. CDP 는 【좌표 판정】(넣는다 · 뺀다)과 기록을 보이고 승인받는 것이 필수였다.

3. 원칙 대조

원칙 · 역할지금정한 뒤
(1) 항목은 지식을 잇는 원자어긋남 새 이름이 「세울 이름」 칸에만. 새 문서는 쓰기 자리가 못 세움. legacy-mix맞음 모든 기록이 저장 순간 항목에 이어짐(고침 · 신설 · 잇기). 없으면 기록 모음 달 항목
(2) 모든 기록은 문서(의 항목)에어긋남 넣지 못함 · 메모 · review 기다림은 문서 밖맞음 기록만 서는 상태가 없다. 무인 일은 규칙 길까지 가서 늘 들어감
(3) 문서 = 최신 글 + 이력흩어짐 이력이 기록함과 넣지 못함 화면으로 갈림맞음 항목 이력 하나. 같은 항목을 고치는 새 기록이 곧 최신 글
N1 기록 · 문서 한 번에어긋남 기록만 서고 조각은 나중(held · memo)맞음 제안서 하나 = 기록 + 조각 한 덩이. 무인도 한 덩이
N2 바로 반영어긋남 메모 · 넣지 못함 · review 로 미룸맞음 승인하면 들어감. 무인은 값 경고여도, 꼴이 안 되면 규칙 길로 들어감
N3 사후 검토 없음 · 측정 → 개선사후 처리 지식관리자가 넣지 못함을 풀어 줌맞음 지표(받아들인 경고 · 무인 값 경고 · 규칙 길 · FIX · 다시 제안) → 정기 점검 → 로직 고침
N4 세션 제안 · 승인 · 대화 조절없음 저장 뒤 note 로 앎맞음 propose → 대화로 여러 번 조절 → 승인 → save(proposal)
N5 확정 전 · 초안 보기 걷음—맞음 「확정 전」 · resolves · 「초안 보기」 · [제안서 보기] · 메모를 두지 않음
개인 프로그램도 같은 원칙어긋남 기록만 서고 뒤에서 바로 넣기(pend) · 둠(kept) · 메모맞음 같은 저장 문 · 제안서 승인 · 들이기 규칙 길 · 한 벌 안내
지식관리자 = 사후 조정사전 허가 승인 받고 넣기 · 이름 세우기 · 새 문서 · 넣지 못함 처리사후 조정(선택) 저장 흐름에 대기 · 승인 단계 없음. 원하면 합치기 · 옮기기 · 되돌리기

4. 바뀌는 흐름

무인 채널에는 사람 검토 대기열 · 「초안 보기」 · 결과를 고르는 단추가 없다. 일꾼 실패 · 하루 상한 · 24시간이면 Claude 없이 곧바로 규칙 길로 넣는다. 잘못 들어간 글은 기록마다 되돌리기로 고친다.

원본 첨부

무인 기록마다 원본이 붙어 지식 안에 남는다. 들어간 글을 원본과 대 볼 수 있다.

기록마다 되돌리기

잘못 들어간 글은 그 기록 앞 글로 되돌리는 새 기록(저장 문)으로 걷는다. 기록 하나 단위가 기본이고, 묶음 되돌리기는 지식관리자(개인은 주인) 일이다.

측정 지표

무인 값 경고 · 규칙 길 떨어짐 · FIX 번 수를 채널 · 지식별로 센다.

개선 고리

총괄 관리자가 두 주마다 지표를 보고, 문턱(규칙 길 10% · 무인 값 경고 20%)을 넘는 곳부터 프롬프트 · FIX 규칙 · 규칙 길 · 검사 기준을 고치고 전후 지표를 남긴다.

9. 원칙과 아직 부딪칠 수 있는 곳 · 남은 위험

규칙 길의 글 품질

원문 인용이 다듬어지지 않은 채 본문에 들어간다(작성기준 「본문에는 확정된 지식만」 과 경계). 떨어진 수를 재고 FIX · 프롬프트를 고쳐 줄인다.

무인 지어냄이 본문에

값 경고여도 들어간다. 원본 첨부 · 되돌리기 · 지표 · 개선 고리로 대신한다. 개선 고리가 돌지 않으면 품질이 떨어진 채 남는다.

사후 조정과 N3

지식관리자의 조정은 선택이고 저장 흐름의 단계가 아니다. 대기 배지 · 「검토」 말을 쓰지 않는다.

개인 프로그램은 PC 마다 판이 다르다

새 판을 올리고 이행이 끝나기 전까지 그 PC 의 개인 지식은 옛 길(메모 · pend · 바로 넣기)이다. 옛 개인 스킬 세션은 E_APPROVE 로 막혀 다시 설치를 받는다. PC6 판에서 옛 길을 걷으면 그때까지 이행 못한 지식은 저장이 닫힌다.

개인 지표는 PC 밖으로 안 나감

총괄 관리자의 두 주 점검에 개인 쪽 품질이 직접 잡히지 않는다. 공유 core 로 같은 고침이 실리고, 사람이 자기 지표로 이슈를 내는 길만 있다.

옛 개인 메모의 값

이행은 메모 값을 본문에 넣지 않고 이력에만 잇는다. 이미 정해진 값이면 본문에 빠진다. 이행 알림에 수를 세어 보이고 주인이 세션에서 다시 제안한다.

이행 전 지식백업

백업 자리(예: K: 드라이브)가 빠져 백업이 실패하면 이행이 멈추고 그 PC 는 옛 길에 머문다. 멈춤 줄로 알린다.

held 모드 지식

이행 전 지식은 P11 까지 넣지 못함이 남는다. 이행을 늦추면 N5 가 늦어진다.

자리 잃은 사람의 무인 일

아무것도 쓰지 않고 끝나 N2 의 예외가 된다(권한 규칙을 앞세움, 팀만).

이슈 갈래 없는 풀리지 않은 물음

넣지 않으므로 「열려 있다」 는 지식이 남지 않는다. 쓰기 자리가 제안서로 이슈 갈래를 세울 수 있다.

입력 오류 뒤 다시 안 보냄

지식 상태는 아니지만 일이 지식에 닿지 않는다. 스킬에 「꼭 다시」 를 강제하고 다시 보낸 비율을 지표로 본다.

승인이 형식이 됨

서버는 사람이 정말 봤는지 증명하지 못한다. 경고를 늘 보이고 받아들인 경고 비율 · 다시 제안 수로 지켜본다.

held · approve 동안 코드와 시험이 두 벌이다. 188 에 쌓인 넣지 못함 · 메모 · 개편 전 기록 수를 모른다. held-scan 이 먼저다.
