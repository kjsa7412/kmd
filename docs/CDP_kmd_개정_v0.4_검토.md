## 0. 운영자의 말 · 한 줄 결론

> cdp 범용 프로그램이 있고 공유 지식문서는 git으로 세우고 나머지는 git이던 로컬이던 세우는걸로 하고 프로그램에는 개인 로그인 후 경로만 세팅하거나 공유 받으면 되는 걸로 프로그램 1개를 어디든 세우고 개인이든 공유든 등록해서 사용할 수 있는 형태로 하자. 이방식을 검토해봐. cdp 서비스 자체는 어디든 누구든 1개만 세우면 된다. 여러개를 써도 지식문서 세우는 행위만 같다면 cdp 프로그램 자체는 문제가 안된다. 지금 cdp 라고 이야기하는건 kmd를 이야기하는 것이다. — 운영자, 2026-10-21

**한 줄 결론 — 받아들인다.**

> **kmd 는 프로그램 하나이고 어디든 몇 개든 세워도 된다. 공유 지식의 정본은 git 이다. 어느 kmd 든 같은 save(같은 검사 · 같은 판정)로 쓰고 곧 git 에 올린다. 그사이 다른 kmd 가 먼저 올렸으면 kmd 가 최신 글 위에서 내 save 를 한 번 더 돌린다(두 글을 합치지 않는다). 그래도 안 되는 한 건만 「그사이 다른 사람이 같은 곳을 고쳤다」 로 멈춘다.** 로그인과 권한은 회사 git(GitLab) 계정 하나가 정한다. 로컬은 내 폴더 그대로다 — kmd 가 같은 PC 에 있으면 kmd 가, 다른 기계에 있으면 브라우저가 그 폴더를 읽는다.

**풀이** — 누구든 kmd 하나만 세우면 혼자든 같이든 쓸 수 있다. 여럿이 있어도 같은 지식을 같이 쓴다.

> **쉬운 말로 — 다섯 줄**
> 1. kmd 는 **같은 프로그램 하나**다. 내 PC 든 팀 서버든 깔면 되고, 「개인용 / 팀용」 을 고르지 않는다.
> 2. 들어갈 때는 **회사 GitLab 계정 하나**. 내 PC 에서 내 폴더만 쓸 때는 로그인도 없다.
> 3. **[잇기] 칸 하나**에 폴더 경로 · git 주소 · 받은 링크 중 아무거나 붙이면 끝이다. 개인인지 공유인지는 묻지 않는다. 지식을 **세운 사람이 그 지식의 주인**이고, kmd 안에서 정리하는 사람을 정한다(그 명단은 지식 안에 있어 어느 kmd 에서 봐도 같다 · §5.4). 공유하기는 GitLab 에 사람을 더해 git 에 들어오게 하는 일이다.
> 4. 공유 지식은 **git 이 정본**이라 kmd 가 여러 개여도 같은 지식을 같이 쓴다. 두 사람이 거의 같이 저장하면 뒤의 kmd 가 최신 글 위에서 **같은 검사로 다시 저장**한다(두 글을 기계가 섞지 않는다). 정말 같은 곳을 고쳤을 때만 「그사이 다른 사람이 같은 곳을 고쳤다 — 내 글은 따로 두었다」 한 줄이 뜬다.
> 5. 지킬 것 하나 — 같은 공유 지식을 쓰는 kmd 는 **같은 형식 판**이어야 한다. 지식이 더 새 형식이면 옛 kmd 는 읽기만 한다(「올리면 고쳐진다」).

**불변조건** — 문장을 고치는 것은 I12 하나다(뜻 「기계는 두 글을 합치지 않는다」 는 그대로). I2 · I6 · I13 에는 좁은 예외를 적고, 설명서 · 설계서 · 코드 머리말의 말을 고치고, 거부 설계 하나(지식 폴더 자동 최신화)를 kmd 가 소유한 사본에 한해 연다(§4.6). 「하나도 안 풀린다」 가 아니다.

| 원문의 말 | 지금 CDP 코드로 | v0.4 권장으로 |
|---|---|---|
| 프로그램 1개를 어디든 | 반쯤 — 같은 tar 이지만 개인 서버는 레포 하나 · 레포마다 포트 · 서비스(`ctx-up.mjs:33` · `ctx-mcp-serve.mjs:2669-2690`) · Windows 늘 켜 두기 없음(`ctx-up.mjs:249-251`) | 맞다 — 등록표 하나 · 도는 자리(이 PC / 서버)로 저절로 갈린다 |

### 2.1 구조

```
                 [사내 GitLab]  공유 지식의 정본 — main 하나 · ff 로만 움직인다 · force · 삭제 금지
                  dpms_wiki.git   gdi.git        kim/notes.git (개인 원격 · 선택)
                    ▲ │  push · fetch — 그 사람의 자격        ▲ │
                    │ ▼                                       │ ▼
 [팀 kmd · 서버]                                   [김의 PC kmd]
  사본: dpms_wiki · gdi (같은 save · 곧 올림)        사본: dpms_wiki (같은 save · 곧 올림)
  이 · 박의 kmd 안 지식(주인만)                      내 폴더: D:\kmd\배포노트 · 받은편지함
        ▲                                                    ▲
  이 · 박: 브라우저(설치 0)                          김: 브라우저 · Claude Code(/mcp 하나)
  이의 PC 폴더는 브라우저가 읽는다(서버로 안 간다)
```

하나인 것 — 사람마다 GitLab 계정 · `/mcp` 하나, 공유 지식마다 git 의 main 하나, 로컬 폴더마다 쓰는 kmd 하나(다른 기계의 kmd 는 읽기만 · §3.3). 여럿이어도 되는 것 — kmd 와 kmd 마다의 사본.

```json
{ "kim.notes": { "title": "배포노트", "path": "D:\\kmd\\배포노트", "owner": "kim",
                 "hist": "<data>/hist/kim.notes.git" },
  "dpms_wiki": { "title": "DPMS 지식", "git": "git@gitlab…/dpms_wiki.git", "copy": "<data>/git/dpms_wiki" } }
```

등록표는 kmd 마다 하나(`<data>/repos.json`)다. `makeStore.refresh` 는 등록표를 먼저 읽고 옛 root 훑기를 뒤에 덧붙인다(`ctx-mcp-serve.mjs:115-160`). 캐시 · 화면 Store · allow 는 id 키 그대로 쓴다.

**그대로인 층과 바뀌는 층.** 판정 · 검사 · 큐레이션 계산(curation · check · vocab · managed · validity)은 그대로다 — 「세우는 행위는 같다」 를 지키는 층이 이것이다. 바뀌는 것은 셋이다. ① git 층 — `git.js` 의 `run` · `isRepo` · `status` · `lastFetchAt` · `waitIndexUnlocked` · `restoreTree`, 그리고 `reponew.connectOrigin`. ② save 입구 — 레포 종류 · 이력 자리 · 읽기만 거절 · 큐레이션 `date`. ③ 미러 — 「갈라지면 멈춤」 이 다시 돌리기로 바뀌고, 레포마다 켠다. 근거 — `isRepo` 는 `<root>/.git` 이 있는지만 본다(`git.js:56-57`). 그래서 폴더 밖 이력을 그대로 넣으면 `status` 가 `{repo:false}` 를 내고, save 의 더러운 트리 거절(`save.js:671-672` · `1278-1279` 의 `st.repo && st.dirty > 0`)이 오류 없이 꺼진다(실측 `critic-safety\probe.mjs`). 「core 는 그대로」 라고 적으면 이 위험이 가려진다.

### 3.1 한 칸 [잇기] — 붙인 글자로 저절로 가른다

| 내 PC 폴더(팀 kmd) | 「이 폴더는 브라우저가 읽는다 — 내용은 서버로 가지 않는다」 | 로컬 · 나만 · 이력 없음 |
| 비어 있는 git 주소 | 「gitlab…/kim/notes · 비어 있음 — 새 지식으로 세운다 · 누가 쓰나는 그 git 의 사람들」 | git |
| 지식이 든 git 주소 · 받은 링크 | 「DPMS 지식 · 팀 · 나: 기록」(사람 수는 세지 않는다 — §5.4) | git |
| 이름 하나 | 「kmd 안에 새 지식 — 나만 본다」 | kmd 안 |

개인 · 공유는 묻지 않는다. 그 지식의 명단(§5.4)에서 내가 정리하는 사람이면 내 저장은 곧 반영이고(기록 + 섹션 한 번), 아니면 기록만 올라가 대기열에 선다. 사람 수를 세지 않는다 — GitLab 을 묻지 않는다. 틀 파일 · 루트로 잇기는 [잇기] 안에서 저절로 한다(옛 「만들기」 화면을 걷는다).

**같은 폴더는 한 행.** 등록표는 `fs.realpath.native` 를 대소문자 접기한 값으로 한 폴더 한 행만 둔다(겹치면 「이미 이었다 — 배포노트」). 이 PC 에서도 `세정아~1` 과 `세정아이앤씨` 가 같은 곳이다. save 뮤텍스 키도 그 값이다 — 지금은 `path.resolve` 문자열이고 한 프로세스 안에서만 먹는다(`lock.js:10-20` · `save.js:401` · `1219`).

### 3.2 도는 자리 — 경로는 누가 읽나

| kmd | 내 PC 경로 | git 주소 · 링크 | kmd 안 새 지식 |
|---|---|---|---|
| 내 PC kmd(주인 하나) | kmd 가 읽고 쓴다 — 내 홈 아래 | 받는다 | 루트에 |
| 팀 kmd · 일반 사용자 | **브라우저가 읽는다**(v0.3 §3.4 · File System Access — Chrome · Edge · 설치 0 · 내용은 서버로 가지 않는다). 서버 경로는 받지 않는다 | 받는다 | 받는다(나만 봄) |
| 팀 kmd · 주인(셸을 가진 사람) | 서버 경로는 허용 루트 아래만 · realpath 뒤 다시 검사 · 링크 · junction · UNC 거절 | 받는다 | 받는다 |

까닭 — 서버 경로를 아무나 이으면 남의 지식 · `auth.json` · `<data>/secret` · 배포 키를 읽는 길이 열린다. **읽기 전용 `git status` 하나로 그 폴더 `.git/config` 의 `core.fsmonitor` 명령이 돈다**(실측 · git 2.37 · `-c core.fsmonitor=false` 면 안 돈다 · `git.js:54` · `80`).

**브라우저 길의 폴더** — 보기 · 찾기 · 화면에서 고치기(같은 core 검사 뒤 파일에 쓴다)는 v0.3 §3.4 그대로다. 이력 · 되돌리기 · 세션 저장은 없다(세션의 행선은 받은편지함이나 git 지식). 그 폴더에 세션까지 저장하려면 내 PC 에 kmd 를 세운다(선택). 로컬 판(K5)에서 v0.3 TODO V1 스파이크 ①③부터 한다.

### 3.3 내 PC kmd 의 로컬 폴더 — 사람의 폴더다

| 경우 | 하는 일 |
|---|---|
| 폴더에 `.git` 이 없다 · 남의 git 레포 안이다(toplevel 이 그 폴더가 아니다) | 되돌리기용 판을 `<data>/hist/<id>.git` 에 숨긴다(폴더에 `.git` 이 생기지 않는다 · 실측). 틀 파일만 더하고 md 는 옮기지 않는다(v0.3 §3.6). 줄끝은 git-dir 의 `info/attributes` 에(추정 — 스파이크). 바깥 코드 레포에 커밋하지 않는다(지금은 한다 · 실측) |
| 폴더가 그 자체로 git 레포(toplevel 이 같다) | 그 `.git` 에 커밋만 한다. push · 받기 · 되감기는 하지 않는다(사람의 몫). 같이 쓰려면 git 주소로 이어 kmd 자리에 둔다 |
| git 부르기 | 레포마다 `{ gitDir, workTree }` 를 받아 env(`GIT_DIR` · `GIT_WORK_TREE`)로 넘기고 `-C` 에 기대지 않는다(지금 `run` 은 `-C cwd` · `git.js:29-35` 라 위로 올라가 바깥 코드 레포를 찾는다). `isRepo` 는 gitDir 로 판정하고, 이력 자리를 모르면 save 는 `E_GIT not-a-repo` 로 거절한다. `.git` 을 직접 짚는 `lastFetchAt`(`git.js:208`) · `waitIndexUnlocked`(`:410`) · `connectOrigin`(`reponew.js:193`)도 같이 고친다. 사용자 폴더의 git 은 `-c core.fsmonitor=false -c core.hooksPath=<빈 폴더>` · 커밋 훅은 save 가 이미 끈다(`save.js:487-488`) |
| 세는 파일 | hist 의 `info/exclude` 를 `*` 로 두고 `!*/` `!*.md` `!work/**` `!docs/**` `!_vocab.md` `!_managed.md` `!README.md` 만 연다. 사람의 다른 파일(pdf · 메모 · 그림 · 비밀)은 세지도, 커밋하지도, 지우지도 않는다. 지금은 `--untracked-files=all` 이라 모두 dirty 로 센다(`git.js:80`) |
| 파괴 연산 | 경로 폴더에는 없다. 콘솔 「트리 되돌리기」(`checkout -- .` · `clean -fd` · `git.js:312-323`)는 화면에서 숨기고 core 에서도 거절한다. 「치우기」 는 잇기 끊기 — 등록표 행과 hist 만 휴지통으로, 폴더는 그대로(지금 `trashRepo` 는 폴더째 옮기고 드라이브가 다르면 복사 뒤 `rm -rf` · `reponew.js:222-241` · 콘솔 `ctx-mcp-serve.mjs:1474-1533`). save 실패 뒤 되돌림(`Snap.restore` · `save.js:124-134`)은 그 파일의 해시가 save 가 쓴 것과 같을 때만 하고, 다르면 두고 `E_GIT` 「편집기가 그사이 고쳤다」 |
| 다른 기계 · 다른 프로세스 | 폴더의 `.kmd.json` 에 주인 설치 id(`<data>/instance.json` 의 uuid)를 적는다. OneDrive 등으로 다른 기계의 kmd 가 같은 폴더를 이으면 거두기를 끄고 읽기만으로 연다 — 「두 PC 에서 같이 쓰려면 git 으로」 한 줄. hist 에 잠금 파일(pid · 시작 시각 · 설치 id)을 두고, 다른 프로세스(옛 `ctx up --personal` 포함)가 쥐고 있으면 읽기만으로 연다 |

**거두기 — 편집기로 고친 것.** 거두기는 save 와 같은 뮤텍스 안에서, 그 save 바로 앞에 한 번 한다. 열 때나 몇 분마다 거두지는 않는다. 지금은 더러운 트리가 save 를 모두 막는다(`save.js:668-678`).

| 고친 것 | 거두는 법 |
|---|---|
| `docs/` · `_vocab.md` · `_managed.md` 손 편집 | 주인 = 정리하는 사람이므로 큐레이터 save(edits · vocab op)로 거둔다. I10 `newErrors` 에 걸리면 두고 한 줄로 알린다. 되돌리지 않는다. 덤으로 [되돌리기] 가 생긴다 |
| `work/` 고친 파일 | ① 고친 글로 `supersedes` 를 단 정정 기록을 save 한다 → 성공한 뒤에만 ② 원래 글로 되돌린다(I3 — `work/` 는 불변 · 설계서 :37). ①이 실패하면 아무것도 바꾸지 않고 한 줄로 알린다 |
| `work/` 새 파일 | 기록으로 들인다(saveRecords · skipExisting). 지우지 않는다 |
| 무엇이든 되돌리기 전 | `<data>/hist/<id>.kept/<시각>/` 에 사본을 둔다 |

### 3.4 git 주소 · 링크 · 공유하기

- **clone** — 지금 `cloneRepo` 그대로다(`reponew.js:155-176`). 자리는 `<data>/git/<id>` 이고, kmd 가 소유한 트리라 사람이 편집하지 않는다.
- **자격** — 받기와 올리기는 그 사람의 자격으로 한다. 내 PC 는 그 PC 의 git 자격(Git Credential Manager 등)을 그대로 쓰고, 팀 kmd 는 그 사람이 들어갈 때 준 PAT 를 쓴다(§5.1). 팀 kmd 의 배포 키로 남의 git 을 받지 않는다(권한 세탁). 늘 `GIT_TERMINAL_PROMPT=0` · `GCM_INTERACTIVE=never`.
- **링크** — `<kmd 주소>/join#repo=<git 주소>&from=<보낸 이>`. **비밀이 없다** — git 주소를 실어 나를 뿐이다. 받는 사람은 자기 kmd 의 [잇기] 에 붙이고(링크째 붙여도 git 주소를 꺼낸다) 권한은 GitLab 이 정한다. 들어갈 수 없으면 「아직 이 지식의 사람이 아니다 — 박에게」 한 줄 · 단추 없음. 묶음 API 는 두지 않는다.
- **공유하기** — GitLab 프로젝트에 사람을 더하는 일과 kmd 의 [링크 복사] 하나다. 「공유로 바꾸기」 는 없다. 보호 설정(main force · 삭제 금지 · Developer push 허용)은 관리자 설명서로 옮긴다.
- **로컬 폴더를 git 으로 올리기**(⋯) — 빈 GitLab 프로젝트 주소 하나를 받는다. `connectOrigin` 은 gitDir 을 받게 한다(지금은 폴더에 `.git` 이 있어야 한다 · `reponew.js:193`). 세울 때는 `init -b main`, push 는 `HEAD:main` 으로 고정한다(지금 `push -u origin HEAD` · `reponew.js:209` 라 hist 가지가 master 면 main 이 아닌 가지가 생긴다). 올린 뒤 그 폴더는 「내 폴더 + git 거울」 이다 — save 뒤 올리고 받기는 ff 만, 갈라지면 멈추고 한 줄(사람의 폴더는 되감지 않는다). 두 PC 가 번갈아 쓰려면 둘 다 git 주소로 잇는다.
- **GitLab 새 프로젝트** — 초기화를 끈 채 연다(가능하면 링크 파라미터 · 사내 판에서 Q22 로 확인 · 추정). origin 에 GitLab 이 만든 커밋 하나(README)만 있으면 「빈 프로젝트로 다시 만들라」 한 줄 · 단추 없음.

### 3.5 이름

- **id**(주소 조각 `/r` · `/mcp` · `/api`)는 ASCII · `REPO_NAME_RE` 그대로이고 저절로 짓는다 — 폴더 이름이 ASCII 면 그것, 아니면 `k-<짧은 해시>`. 로컬 · kmd 안 지식은 `<아이디>.` 를 앞에 붙인다. **표시 이름**은 README 첫 제목 → 폴더 이름(한글 그대로).
- **데이터 키**는 id 다. 지금은 폴더 이름(basename)이라 경로가 다른 같은 이름 폴더가 명부 · 토큰 · `up.json` 을 같이 쓴다(추정 · `ctx-mcp-serve.mjs:2672-2674` · `ctx-up.mjs:52-60`).
- **치운 id** — 등록표에 묘비(id · 치운 때)를 남겨 같은 id 를 다시 짓지 않는다(다시 이으면 `-2`). id 가 결정적이라 묘비가 없으면 같은 이름 폴더가 옛 권한을 이어받는다.
- **git 지식의 바깥 이름**은 git 원격 주소다 — kmd 마다 id 가 달라도 이것은 같다. 비교할 때는 호스트 소문자 · 경로 · 끝의 `.git` 떼기 · ssh/https 를 같은 꼴로 정규화한다(규칙 한 곳 · 시험 표).

## 4. 같은 공유 지식을 여러 kmd 가 쓸 때 — 다시 돌리기

### 4.1 무엇이 깨지고 무엇으로 막나 — 실측

bare origin 하나에 kmd 둘(A · B)을 두고 core 의 save 를 직접 불렀다.

| # | 경우 | 지금 코드에서 | git 으로 합치면(rebase · union) | v0.4 에서 |
|---|---|---|---|---|
| T1 | 두 kmd 가 같은 origin 에 save(같은 섹션) | B 커밋 성공 · 미러 `diverged` · B 의 「맞추기」 거절 · 갈라진 채 save 가 계속 커밋(ahead 2) | 같은 섹션 충돌(「could not apply …B1」) | B 의 push 가 밀리면 받고, 최신 위에서 B 의 save 를 다시 돌린다 → `E_CONFLICT` 로 그 한 건만 멈춘다 |
| S1 | 같은 id 기록(같은 날 같은 주제) | 둘 다 로컬 커밋 · `E_EXISTS` 는 그 트리의 `work/` 만 본다(`save.js:661-666`) | add/add 충돌 | 다시 돌리면 `E_EXISTS` → 보류(작성자가 다시 짓는다) |
| S2 | 같은 원본을 두 곳이 들임 | 원천 이름이 달라 경로가 안 겹친다 | **깨끗하게 붙고 중복 기록 둘 · check 오류 0** | 다시 돌리면 skipExisting(F3) → 「이미 있다」 |
| S3 | 어휘 더하기 둘 | 늘 타입 절 끝에 붙는다(`vocabops.js:113-134`) | 늘 충돌 · union 이면 같은 좌표 label 이 **조용히** 뒤의 것으로(`vocab.js:42-45`) | `planVocab` 을 최신 글 위에서 다시 — 단일 서버와 같은 판정 |

| S5 | 같은 섹션 · 두 큐레이터 | applied 잠금(`save.js:959-983`)은 같은 트리에서만 | 충돌(이웃 섹션은 깨끗) | 정리 save 는 닿을 때만 · 최신 위에서 applied + base(F4) → 그 세션에 `E_CONFLICT` |
| S6 | 같은 기록 판정 엇갈림(반영 ↔ 기록으로 둠) | 대상의 존재 · 종류만 본다(`save.js:749-753`) | **깨끗하게 붙고 모순**(상태 kept 인데 섹션 applied = 그 기록) · 오류 0 | `expect` compare-and-swap(§4.4) |
| S8 | 실패를 건너뛰고 다음을 계속 | — | 이의 판정이 김의 기록에 조용히 붙는다 | 결과 가르기(§4.3) — 의미 거절은 보류함, 뒤는 S8 규칙으로만 |
| I6 | 개인 kmd 는 나를 admin(모든 레포의 큐레이터)으로 만든다(`ctx-mcp-serve.mjs:2681` · `auth.js:59-64`) | 공유를 쓰기로 받으면 「관리 문서는 큐레이터만」 이 git push 권한으로만 지켜진다 | — | `*` 는 git 지식에 닿지 않는다 · 역할은 GitLab 에서(§5.2) |

**요점** — 지금의 막음(`E_EXISTS` · 같은 원본 · applied 잠금 · `curatorOnly`)은 모두 **그 kmd 의 트리와 명부 안에서만** 먹고, git 으로 합치면 일부가 조용히 틀린다. 그래서 텍스트 합치기는 쓰지 않고 막음을 최신 글 위에서 다시 돌린다. 실측은 아홉 경우 모두 merge 커밋 0 · 오프라인 셋을 9.3초에 일직선 · 같은 id 는 `E_EXISTS` · 같은 원본은 skipped 였다(`sync-multi\out.json` 의 replay).

### 4.2 save 의 차례

| 차례 | 하는 일 |
|---|---|
| ① | 뮤텍스 안에서 지금처럼 검사하고 커밋한다. 일지(입력 · user · 시각 · 읽은 base · 첨부 사본 · 항목 키 `item`(uuid))는 커밋 **전에** `<data>/journal/<id>/` 에 쓴다. 커밋에는 꼬리말 `Kmd-Item: <item>` · `Kmd-Version: x.y.z` 를 단다. 거두기 save 와 시스템 save 도 같다 |
| ② | 곧 push 한다(레포당 줄 하나) |
| ③ | non-ff 면 fetch 하고, 뮤텍스 안에서 일지의 각 항목과 같은 `Kmd-Item` 이 origin 에 이미 있는지 먼저 본다. 있으면 앞선 push 가 실은 성공한 것이라 처음 결과를 그대로 돌려준다(F3 에 기대지 않는다 — skipExisting 은 묶음에만 있고 · `save.js:1294-1312`, 섹션 save 는 자기 변경과 부딪혀 거짓 `E_CONFLICT` 를 낸다) |
| ④ | 없으면 origin/main 으로 옮기고, 일지를 원래 user 로 **같은 core save** 에 차례대로 다시 넣는다. 옮기기(reset)는 `git log origin/main..HEAD` 의 모든 커밋에 `Kmd-Item` 이 있고 그 항목이 일지에 있을 때만 한다. 하나라도 없으면 멈추고 「이 kmd 가 모르는 커밋이 있다」 한 줄 |
| ⑤ | push 한다. ③ ~ ⑤ 는 무작위 지연을 두고 3번까지 |

**응답** — git 에 닿으면 save 호출 안에서 ① ~ ⑤ 를 끝내고 최종 결과(main 에 올라간 sha · warnings · `E_*`)를 그대로 돌려준다. 상한(기록 save 5초 · 추정)을 넘기거나 닿지 않을 때만 `state: 'local'` 로 답하고(「저장됨 · 아직 안 올림」 · sha 는 바뀔 수 있다) 뒤에서 이어 간다. 다시 올리는 계기는 다음 save · 받기 성공 · 1 · 5 · 15분이다.

**다시 돌리는 자리** — kmd 가 소유한 트리(`<data>/git/<id>` · 팀 kmd 의 `<root>`)에서만 한다. 사람의 폴더(§3.3)는 되감지 않는다.

### 4.3 결과 가르기 — 무엇에서 멈추나

| 결과 | 하는 일 |
|---|---|
| 망 · 인증 · 5xx | 다시 보내고 뒤는 기다린다. 사유가 auth 면 다시 시도하지 않고 「다시 들어가기」 한 줄 |
| 다시 돌리다 의미 거절(`E_CHECK` · `E_FORBIDDEN` · `E_CONFLICT` · `E_EXISTS` differs · 형식 다름) | 다시 보내지 않는다. 보류함으로 옮기고 원문은 받은편지함에 기록으로 남긴다(잃지 않는다). 작성자의 다음 brief 에 한 줄 + 「다시 하기」(에이전트가 지금 글 위에서 다시 짓는다). 뒤 항목은 S8 규칙(기록만 쓴 save · 뒤가 그 id 를 안 씀)으로만 계속 |
| 같은 원본(blob) | 건너뛰고 「이미 있다」 |
| 같은 id | 보류 — 작성자가 다시 짓는다. id 를 저절로 바꾸지 않는다(이미 다른 지식 · 커밋 메시지 · 뒤 일지의 `applied` 에 들어갔을 수 있다) |
| 늦게 간 항목의 warnings | 결과에 남기고 「오늘 바뀐 것」 에 한 줄. 어휘 label 이 달라 건너뛴 것(`save.js:719-726` — 지금은 경고만)은 보류로 친다 |

### 4.4 정리(큐레이션) save — 세션 안에서 끝난다

- **닿을 때만** — 정리 입력(`curatorOnly` 목록 · `save.js:519-535`)이 든 save 는 git 에 닿을 때만 받고, ① ~ ⑤ 를 save 호출 안에서 끝낸다. 밀려서 다시 돌리다 `E_CONFLICT` 가 나면 그 섹션의 지금 글(`detail.content` · `save.js:959-983`)과 함께 그 세션에 돌려준다. 닿지 않으면 `E_OFFLINE` 「정리는 git 에 닿을 때만」 — 일지로 미루지 않는다. 섹션 새로 읽기 · applied/base 잠금 · 다시 짓기가 한 세션 안에서 돌아야 안전하다.
- **판정 겹침** — `curates[]` 마다 `expect: { state, by }`(queue materials 의 status 그대로)를 싣고, save 는 지금의 `statusOf(id)` 와 비교만 한다(compare-and-swap · 옛 커밋을 다시 계산하지 않는다). 다르면 `E_CONFLICT { kind: 'curated', id, now: { state, by, author, date } }` — S6 을 막는다(단일 서버에도 있던 틈). `curates` 항목은 `.strict()` 라(`ctx-mcp.mjs:362-372`) `expect` 를 모르는 kmd 는 `E_INPUT` 으로 거절한다 — 조용히 버리지 않는다(W12).
- **판정 시각** — 선후는 커밋 순서가 아니라 `date` 글자로 정해진다(date 오름차순으로 덮어 「가장 늦은 판정이 이긴다」 · `curation.js:196` · `219` · `validity.js:17-24`). 그런데 `date` 는 클라이언트가 주는 자유 문자열 40자다(`ctx-mcp.mjs:354`). 그래서 큐레이션 기록의 `date` 는 커밋하는 kmd 가 커밋 때(다시 돌릴 때 포함) 자기 시계로 찍고, 클라이언트 값은 버리고 경고 한 줄. 같은 기록의 가장 늦은 판정보다 이르면 `E_CONFLICT { kind: 'curated' }` + 「이 PC 의 시계가 늦다」. 계산식은 그대로이고 입력만 바뀌어 형식 1 안에서 된다. 작업 기록은 원래 시각을 지킨다.
- **도구 노출** — 정리 도구(queue 등)와 큐레이터 save 명함은 그 레포에서 그 사람의 역할이 정리일 때만 낸다(§5.2 · 지금 `ctx-mcp-serve.mjs:700-701`).
- **막는 자리** — 읽기만 레포(Reporter · 더 새 형식 · 다른 기계의 폴더)에 쓰는 것은 core save 입구 한 곳에서 거절한다(레포 종류를 옵션으로 받는다). `ctx-mcp-serve` 의 doSave · saveRecords 호출 일곱 곳에 흩지 않는다. 미러도 서버 전체 `opt.mirror` 가 아니라 레포마다 켠다(지금 `mirror: !!opt.mirror` 8곳).

### 4.5 받기

- 화면이나 세션이 열려 있는 동안 1분마다, 그리고 올리다 밀리면 받는다. save 앞에는 받지 않는다(사내망 fetch 19.5초 — `sync.js:8`). 맞춘 때는 FETCH_HEAD 에서 계산한다(`git.js:205-210`). 실패하면 마지막 것으로 읽고 늦을 때만 「어제 17:00 판으로 보는 중」.
- 새 tip 이 마지막 tip 의 자손일 때만 받는다. 아니면 「git 의 이력이 바뀌었다 — 관리자」 한 줄 · 마지막 것으로 읽는다.
- 받을 때마다 새 머리를 core check 한다. 꼬리말 `Kmd-Item` 이 없는 커밋은 「kmd 밖에서 고친 것이 들어왔다 · 누가 · 오류 n」 한 줄로 보인다(손 push · 옛 CDP · 고친 kmd).
- 이 지식에 더 새 `Kmd-Version` 이 쓴 커밋이 있으면, 대기열 머리에 「이 kmd 판 x.y 로 셌다 — 더 새 kmd 가 있다」 한 줄(§7).

### 4.6 정정 상자 — 문서의 말 · 불변조건의 좁은 예외

> **관리자 설명서 :267 「한 레포를 두 서버가 쓰지 않는다」** → 「kmd 는 몇 개를 세워도 된다. 한 지식에 여러 kmd 가 같은 save 로 쓰고, main 은 ff 로만 움직인다. 밀리면 최신 위에서 다시 돌리고, 안 되는 한 건만 멈춘다.」
>
> **설계서 :505 「서버가 유일한 작성자다」 · `git.js:13-16` 「로컬형의 작업 트리에는 절대 쓰지 않는다」 · `save.js:10` 「클라이언트에 작업 트리가 없다」 · `:668` 「미커밋 변경은 언제나 사고」** → kmd 가 소유한 트리(`<data>/…` · 팀 `<root>`)에만 참이다. 경로로 이은 폴더는 사람의 폴더이고 편집기가 두 번째 작성자다(§3.3).
>
> **I12(설계서 :46)** → 「기계는 두 글을 합치지 않는다. 밀리면 내 save 를 최신 위에서 같은 검사로 다시 돌릴 뿐이고, 통과 못 하면 멈춘다. main 은 ff 로만 움직인다(merge 커밋 0). 올라가기까지가 save 다.」 kmd 가 소유한 트리에서 안 올린 자기 커밋을 버리는 reset 은 `undoLastCommit`(`git.js:428-431`)과 같은 급의 좁은 예외로 `git.js` 머리말에 적는다. 조건은 §4.2 ④ 다. 미러의 「갈라지면 멈춤」(`mirror.js:17`)은 다시 돌리기로 바뀐다.
>
> **I2(설계서 :36) 「한 번의 save 가 한 커밋」** — 그 커밋은 main 에 올라간 것이다. `state: 'local'` 의 sha 는 다시 돌리면 바뀐다. 표지 · 형식은 시스템 save 로만 쓴다(사람의 save 에 끼우지 않는다). 편집기는 내 폴더의 두 번째 쓰기 길이고 거두기 save 가 그것을 save 로 바꾼다. 브라우저 길의 폴더는 kmd 가 맡은 레포가 아니다(v0.3 §3.4).
>
> **I13(설계서 :47 · 예외 :65)** — 예외를 하나 더한다: GitLab PAT. 내 PC 는 OS 자격 저장소에, 팀 kmd 는 `<data>/secret` 으로 암호화해(범위 둘 · 만료 필수 · 사람이 지울 수 있음). 그 밖에는 해시만.
>
> **I6(설계서 :40)** — kmd admin 의 `*`(`auth.js:59-62`)는 남의 로컬 · kmd 안 지식과 git 지식에 닿지 않는다. git 지식의 정리 권한은 지식 안 명단에서 온다(§5.4).
>
> **미러 「주기 · 시작 시 push 없음」(`mirror.js:17-18`)** — 다시 올리기 · 다시 돌리기는 사람이 고른 행선의 save 를 늦게 배달할 뿐 새 내용을 짓지 않는다.
>
> **거부 설계 「지식 폴더 자동 최신화」(설계서 :712)** — kmd 가 소유한 git 사본에 한해 연다(ff 만 · 실패는 한 줄). 사람의 폴더에는 받기가 없다.

## 5. 로그인 · 권한

### 5.1 로그인 — GitLab 계정 하나

| kmd | 1차 | 2차 |
|---|---|---|
| 내 PC | 로그인 화면이 없다(지금 개인 서버의 자동 로그인 · `ctx-mcp-serve.mjs:939-948`). git 주소 · 링크를 처음 이을 때 한 번 [GitLab 로 들어가기] — PAT 한 칸(`read_user` + `write_repository` — 신원과 올리기만 · 멤버 수준은 읽지 않는다 · §5.4). 로컬만 쓰는 동안 작성자는 OS 사용자(ASCII) · **`me` 는 쓰지 않는다**(한글 계정이면 지금 `me` — 실측 `ctx-mcp-serve.mjs:2680`) | [GitLab 로 들어가기] 단추(OAuth) |
| 팀 kmd | [GitLab 로 들어가기] — PAT → `/api/v4/user` 로 username · 표시 이름 · 커밋 이메일 → 명부에 그림자 계정이 저절로 선다 · 관리자 발급 없음 · `api` 범위는 받지 않는다 | 회사가 OAuth 앱을 등록하면 단추 하나 |
| 주인 정하기 | 지금 부트스트랩(셸을 가진 사람 · `auth.js:389-426`) 그대로. 「GitLab 첫 로그인 = 주인」 은 하지 않는다(먼저 닿은 아무나 주인이 된다) | 같음 |
| 쿠키 | 이름에 kmd id(`kmd_s_<8자>`) — 지금 `cdp_s` · `cdp_su` 는 같은 호스트의 두 kmd 가 서로 덮는다(v0.1 E8) | 같음 · 재인증은 GitLab 로 |

신원 — kmd 밖에서도 같은 신원은 git 호스트 계정뿐이다. 기록 author 는 GitLab username, 커밋은 `username <GitLab 커밋 이메일>`(`git.js:343-344` · 지금은 `<이름>@cdp`). 옛 기록의 이름은 고치지 않는다(I3). 「팀 토큰」 을 따로 들지 않는다 — 어느 kmd 든 그 사람의 GitLab 자격으로 git 에 직접 쓴다.

### 5.3 강제의 한계 — 솔직히

| 층 | 막는 것 | 못 막는 것 |
|---|---|---|
| L0 kmd 검사 | 같은 형식 kmd 의 save — 형식 · 어휘 · `curatorOnly` · `E_CONFLICT` · `expect` | 고친 kmd · 옛 CDP(≤ v1.9) · 손 git |
| L1 git 호스트 권한 | 들어오지 못한 사람의 읽기 · 올리기 | 올릴 수 있는 사람이 손 git 으로 관리 문서 · 명단을 고치는 것 |
| L2 보호 브랜치 | main force · 삭제(이력이 고쳐 쓰이지 않는다) | Developer · Maintainer 의 손 push |
| L3 Premium push rule · 서버 훅 | 꼬리말 · 서명 · pre-receive 에서 `ctx check`(추정 · 회사가 고를 일) | — |
| 탐지 | 받을 때마다 core check · `Kmd-Item` 없는 커밋 → 「kmd 밖에서 고친 것이 들어왔다 · 누가 · 오류 n」 | 막지는 못한다 |

**운영자 전제** — 같은 kmd 를 쓰면 I6 는 kmd 검사가 지킨다. 고친 kmd 의 커밋은 받을 때 「밖에서 들어온 변경」 으로 드러나고, 정리하는 사람이 되돌린다. 더 막아야 하는 회사는 L3 이나 엄격 모드(부록 A — 한 kmd 만 쓴다)를 쓴다. 명단을 주인 아닌 사람이 바꾼 커밋은 받을 때 무시한다(§5.4).

- 팀 kmd 의 관리자 · 서버 운영자는 디스크의 kmd 안 지식과 사람마다의 PAT 를 읽을 수 있다(PAT 는 추정 — 암호화 키가 같은 서버에 있다). 화면은 「팀 서버에서 돈다 — 여기 둔 내 지식은 관리자가 볼 수 있다」 한 줄. 정말 나만은 내 PC 폴더(브라우저 길 포함)나 내 PC kmd.

### 5.4 정정 — 정리 권한은 지식을 세운 사람이 kmd 안에서 정한다(운영자)

> 멤버 수준을 왜 읽어야 하나. 그걸 가능한 사람이 지식 레포를 세우고 kmd 내 권한을 가져가는 거 아닌가? — 운영자, 2026-10-21

**맞다.** 앞 판이 GitLab 의 멤버 수준을 읽으려던 까닭은 하나였다 — kmd 가 여러 개면 한 kmd 의 명부(`auth.json`)를 다른 kmd 가 못 본다. 그래서 「어느 kmd 에서 봐도 같은 답」 을 GitLab 에서 빌리려 했다. 그런데 같은 답은 **명단을 지식 안에 두면** 얻는다 — git 이 정본이니 모든 kmd 가 같은 명단을 받는다. GitLab API 범위(`read_api`) · 「Maintainer = 정리」 같은 엉뚱한 묶음 · GitLab 아닌 git 에서 안 되는 문제가 함께 사라진다.

| 무엇 | 누가 정하나 | 어디에 |
|---|---|---|
| 그 지식을 읽을 수 있나 · 기록을 올릴 수 있나 | **git 호스트**(GitLab 에 사람을 더한다 — 공유하기) | git 호스트 |
| 누가 주인 · 정리하는 사람인가 | **지식을 세운 사람(첫 주인)** — kmd 의 「이 지식의 사람」 에서 고른다 | 지식 안 `_members.md`(사람 · 역할 두 칸 — 주인 · 정리) |
| 그 밖에 올릴 수 있는 사람 | (명단에 없어도 된다) | — 기록을 올리면 대기열에 선다 |

- **세울 때** — 지식을 세우는 시스템 save 하나가 `_format.json` 과 함께 `_members.md`(첫 주인 = 세운 사람)를 쓴다. 로컬 · kmd 안 지식은 주인 하나(나)뿐이다.
- **kmd 가 지키는 것** — 정리 입력(`curatorOnly` 목록)은 지금 들어온 사람이 그 지식 명단의 주인 · 정리일 때만 받는다. 명단 고치기는 주인의 save 로만 한다.
- **받을 때 검증** — 명단을 바꾼 커밋마다 「그 앞 명단의 주인이 쓴 kmd save(`Kmd-Item`)인가」 를 사슬로 본다. 아니면 그 변경을 **무시하고** 앞의 명단으로 읽으며 「주인이 아닌 사람이 명단을 바꿨다 — 무시했다」 한 줄. 계산이다(I8) — 저장하지 않는다.
- **한계는 앞과 같다** — 올릴 수 있는 사람은 손 git 으로 관리 문서를 고칠 수 있고 커밋 작성자도 꾸밀 수 있다. 받을 때 드러내고(§4.5 · §5.3), 더 막으려면 호스트의 작성자 검사 · 서명 커밋(L3)이나 엄격 모드(부록 A). GitLab 멤버 수준을 읽어도 이 한계는 같았다 — Developer 도 손 push 를 할 수 있다.
- **신원** — 「들어온 사람이 누구인가」 는 여전히 필요하다. 팀 kmd 는 GitLab 로그인(신원만 · `read_user`)이 이름을 정해 주고, 내 PC kmd 는 그 PC 의 git 사용자다. 명단의 사람 칸은 그 이름이다.
- **덤** — GitLab 이 아닌 git(GitHub · 사내 SSH 서버)에서도 같다(Q30 을 넓힐 수 있다).

## 7. 형식 — 「세우는 행위만 같다면」 의 보증

지금 레포에는 형식 표지가 없다(`skeleton.js` · core 어디에도 없음). 판이 섞여 난 사고가 이미 있다. 2026-10-12 실서버 v1.2.1 이 `_seed.json` 을 몰라 dpms_wiki 를 암묵 전환으로 읽었고, 옛 번들 훅이 옛 규칙으로 커밋을 막았다(H9 · 설계서 :43).

- **표지 · 문턱** — 레포 뿌리 `_format.json { "format": 1 }`(없으면 1). 레포가 더 새 형식이면 **읽기만** + 「이 지식은 더 새 kmd 로 만들어졌다 — 올리면 고쳐진다」. push 직전에도 origin 의 표지를 다시 본다. 지식 모양의 선언이라 I9 의 허용으로 본다. 올림은 새 판의 첫 시작에 migrate 가 지은 시스템 save 하나(`migrate.js:9` · I2)이고 곧 올린다. 옛 규칙 · 새 규칙을 갈래로 돌리지 않는다(거부 설계 「레포 플래그」 · 설계서 :717).
- **형식을 올리는 때** — error 검사 · 입력 모양 · 판정 규칙(문서에 적힌 뜻)이 바뀔 때만 올린다. 구현 고침(예 `curation.js:197-201` 의 암묵 전환 판정 — dpms_wiki 세팅 때 「대기 22 → 1」)은 꼬리말 `Kmd-Version` 으로만 표기한다. 고침판마다 형식을 올리면 처진 kmd 가 모두 읽기만이 된다. 판이 다른 kmd 사이의 셈 차이는 §4.5 의 한 줄로 보인다.
- **못 막는 것** — 표지를 모르는 옛 CDP(≤ v1.9)와 손 push. 설명서에 「v1.10 미만은 git 지식에 쓰지 않는다」 를 적고, 탐지 줄로 뒤에 보이게 한다. 능력 이름 · 적합성 시험 · 안전망 검사는 나중이다(부록 B).

## 부록 A — 엄격 모드: 이 지식은 한 kmd 만 쓴다(회사가 고르는 선택)

초안의 1차였던 「쓰는 곳 하나 + 보낼 줄」 이다. 고친 kmd · 손 push 까지 호스트로 막아야 하거나, Q22 ②(올릴 사람의 main push)가 안 되면 고른다. 고를 때 지킬 것은 아래와 같다.

- **쓰는 곳 판정** — 표지 `_format.json { format, home: { id: <설치 id>, url: <힌트> } }` · 「나」 판정은 id 로만(127.0.0.1 kmd 는 모두 같은 주소다). 표지 없고 비어 있지 않은 origin 은 「쓰는 곳 모름 — 읽기만」. 빈 origin 은 자리 잡기 push(틀 + 표지 커밋 하나)가 성공한 뒤에만 save 를 받는다(진 쪽은 버릴 커밋이 0). 옛 레포는 그 판의 첫 시작에 시스템 save 하나로 표지를 싣는다. PC 가 쓰는 곳인 지식을 다른 PC 가 이으면 「다른 PC 가 쓴다 — 여기서는 읽기만」 · 보낼 줄을 두지 않는다.
- **보호** — main 의 Allowed to push 는 쓰는 곳의 배포 키 하나다(사람은 Maintainer 를 포함해 No one) · force · 삭제 금지 · 사람의 고침은 save 로. 쓰는 곳 미러가 diverged 면 받는 줄에 「쓰는 곳과 git 이 갈라졌다 — 관리자」. 보낸 것의 sha 를 origin 에서 못 찾으면 「보냈지만 아직 공유에 안 보인다」.
- **보낼 줄** — 쓰는 곳에 닿으면 동기로 대신 부르고 응답(sha · warnings · `E_*`)을 그대로 돌려준다. 닿지 않을 때만 `state: 'queued'`(sha 없음). 항목 키는 `Kmd-Item`, 결과 가르기는 §4.3 표, 정리 입력은 닿을 때만(§4.4)이다. 받는 쪽의 정리 읽기(queue · materials · section 의 pending)는 쓰는 곳의 계산을 받아 그대로 낸다. 쓰는 곳 save 의 `date` 는 쓰는 곳 시계로 찍는다.
- **옮기기** — ① 옛 쓰는 곳이 그 지식의 save 를 닫는다(새 쓰기는 보낼 줄로) ② 표지 `home.id` 를 새 곳으로 고친 마지막 save 와 push ③ 새 곳은 clone 뒤 표지의 id 가 자기일 때만 쓰기를 연다 ④ 옛 곳은 `origin..HEAD` 가 0 인지 보고 받아 읽기로 바뀐다. 0 이 아니면 멈추고 한 줄로 알린다.
- **I13** — PC 가 쓰는 곳 kmd 의 토큰을 OS 자격 저장소에 둔다(그 PC 주인 한 사람). 받아 읽는 팀 kmd 에는 보낼 줄을 두지 않는다(KM24 와 맞춘다).

## 부록 — 검토 경과

비평 둘(정합 18건 · 단순 13건)의 높음은 모두 반영했다. 반영한 것은 본문에 녹였다. 아래는 모양을 바꿔 반영했거나, 일부만 반영했거나, 반영하지 않은 것이다.

**모양을 바꿔 반영** — 단순 1(쓰기를 어느 kmd 든으로 뒤집음)을 받아들여, 「세운 곳」 을 전제로 한 정합 고침안이 자리를 옮겼다.
- 정합 2 — 기본 모델에 세운 곳이 없어 구멍 셋이 사라졌다. 고침안(설치 id 판정 · 표지 없는 origin 은 읽기만 · 자리 잡기 push)은 부록 A 로 옮겼다.
- 정합 3 — 보낼 줄이 「안 올린 내 save」 일지가 되어 §4.2 · §4.3 에 넣었다. 응답 이름은 기본 모델에서 `state: 'local'`, 부록 A 에서 `queued` 다.
- 정합 4 — 「세운 곳 `/site/info` 의 role 캐시」 를 「GitLab 멤버 수준 캐시」 로 바꿨다(단순 2).
- 정합 7 — 「사람은 No one」 은 부록 A 에만 둔다. 기본 모델은 Developer 가 main 에 올려야 기록을 쓰므로 force · 삭제 금지만 두고 손 push 는 탐지로 드러낸다(그 위에 다시 돌리기가 얹혀 갈라진 채 멈추지 않는다). 배포 키 확인은 Q22 ③이다. (뒤에 운영자 정정으로 멤버 수준 조회를 걷었다 — 첫 갈림길은 ②, §5.4.)
- 정합 8 — 「공유로 바꾸기」 가 없어져(단순 6) 옮기기 차례는 부록 A 에, `connectOrigin` 의 gitDir · `init -b main` · `HEAD:main` 은 §3.4 에 넣었다.
- 정합 14 — 「세운 곳의 계산을 대신 받는다」 는 부록 A 에만. 형식 올리는 조건 좁힘 · `Kmd-Version` · 한 줄 경고는 본문에 반영했다.

**일부만 반영 · 반영하지 않음**
- 정합 10 의 features 갈래 — features 를 부록 B 로 옮겨(단순 7) 본문에는 「`expect` 를 모르는 kmd 는 `E_INPUT`(조용하지 않다)」 만 둔다.
- 정합 16 의 받기 두 자리(A · B) — 안 함. 잠깐의 거짓 미반영이고 다음 읽기에 맞는다 · 부록 B 후보. 자손 검사는 반영했다.
- 정합 17 — 안전망 검사를 부록 B 로 옮겼고(단순 7) `registry-order` · `vocab-dup-coord` 한 줄은 그 안에 넣었다.
- 정합 5 — `info/exclude` 에 `!*/` 를 더했다(git 은 제외된 폴더 안의 파일을 다시 넣지 못한다 · 비평 원문에 없음).
- 정합 3 의 동기 응답 상한 「5초」 — 비평에 없던 수치 · (추정). 사내망 fetch 19.5초(`sync.js:8`) 때문에 상한을 두었다.
- 단순 4 의 「`work/` 를 되돌리지 않는다」 — 안 함. I3(설계서 :37)과 정합 6(높음)을 따라 정정 기록이 성공한 뒤에만 되돌리고 사본을 둔다.
- 단순 4 의 「주인 기계 칸을 지운다」 — 안 함. OneDrive 로 두 PC 가 같은 폴더를 보면 서로의 기록을 거둘 수 있어(정합 6 · 높음) 설치 id 로 남기고 다른 기계면 읽기만. 「열 때 · 몇 분마다 거두기 없음」 은 반영했다.
- 단순 7 의 「§0 · §1 · §2 · 부록 넷으로 접기」 — 일부. 결정 일곱 · 형식 세 줄 · 받기 한 줄 · 묶음 API 걷기 · 부록 B 는 반영. 높음 비평(정합 1 ~ 8)의 표 · 시험이 본문 자리를 필요로 해 §3 ~ §10 을 남겼다. 꼬리말 `Kmd-Item` · `Kmd-Version` 은 멱등 · reset 조건(정합 3 · 11)과 판 한 줄(정합 14)에 필요해 본문에 둔다. 결정 번호는 앞 판들과 잇도록 KM40 ~ KM46.
- 단순 2 의 「`me` · email 짐작 걷기」 — email 짐작은 걷고, 로컬만 쓰는 동안의 작성자 이름 OS 사용자(ASCII)는 남겼다(GitLab 앞에도 기록에 이름이 있어야 한다).
- 단순 3 — 브라우저 길 폴더의 세션 저장은 비평의 빈칸이라 「그 폴더에는 세션이 쓰지 않는다(MCP 하나)」 로 닫았다.
- 단순 6 — `kind` 는 걷고 `owner` 는 남겼다(admin `*` 가림 · 묘비 · 정합 13).
- 단순 8 — 화면 번호를 다시 매기지 않고 걷은 N5 · N11 · N12 는 비웠다(앞 판 목업과 대조하기 쉽다).
- 정합 12 의 「받아 읽는 팀 kmd 에는 보낼 줄을 두지 않는다」 — 기본 모델에 받아 읽는 쪽이 없어 부록 A 에만. KM24 와의 모순은 §12 의 행으로 닫았다.
