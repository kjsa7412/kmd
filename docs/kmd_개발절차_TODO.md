3. **화면은 목업과 똑같은 디자인으로 나와야 한다** — [그림 16장](kmd_목업.html) · [인터랙션](kmd_목업_인터랙션.html) 의 배치 · 색 · 글꼴 · 간격 · 글자 · 단추 수를 그대로. 목업의 CSS · 마크업을 바탕으로 짓고, 목업과 다르게 하고 싶으면 하지 않는다.
4. **설계 근거는 이 레포의 검토 문서와 목업이다** — v0.7 · v0.6 · v0.5 검토 · 구체화 v0.1 · 목업 둘 · kmd 한눈에.
5. **시험은 필수 기능만 · 최소로.** 판마다 그 판의 필수 기능을 보는 시험 파일 몇 개만 돌린다. **멀티 에이전트 검토(Workflow)는 하지 않는다.** 시험은 한 번에 하나(이 PC 는 다른 세션과 같이 쓰여 부하가 크다).
6. 보고는 늘 한국어 · 결정이 필요하면 묻지 말고 권장안으로 정해 「나온 것」 에 적는다 · **커밋까지만**(push · 태그 · 배포는 사람이).

## 2. 엔진 줄

### E0 백업이 조용히 멈추지 않는다(v0.5 §4 · L0)

> E0 ~ E2 의 항목 글은 CDP 위에서 고치는 말(「걷기」 · 「고침」)로 적혀 있다. kmd 에서는 **처음부터 그렇게 만든다**는 뜻으로 읽는다 — 예: F1 · F4 · F12 · I7 은 CDP 의 버그를 고치는 일이었지만 kmd 에서는 처음 짤 때의 요구다. CDP 에서 한 번 짠 모양은 참고 패치(맨 위)에 있다.

- [x] 상태 파일 `<data>/backup/<지식>.json { url, branch, pushed, at }` — `core/mirror.js`
- [x] 판정은 `ls-remote` 로 본 원격 sha — ok · lag · gone · rewound · behind · moved(`core/git.js` 의 `ahead===0 → skipped` 걷기)
- [x] push 대상 명시 `HEAD:refs/heads/<가지>` · 다시 보내기(1 · 5 · 15 · 60분 · 그 뒤 시간마다) · 시작할 때 한 번 · 매일
- [x] 「붙인 백업에만 민다」 — 받아 온 원격은 백업이 아니다(F5 · `ctx-up.mjs` 의 미러 저절로 켜짐 고침)
- [x] behind · moved 면 그 지식의 save 를 닫는다(`E_BEHIND` · 읽기만) · [백업에서 받기] (ff 만 · 받은 머리를 check)
- [x] 나이 경보 6시간 warn · 24시간 bad — 화면 띠 · 콘솔 · healthz · **MCP save 응답 warnings · 세션 시작 brief**
