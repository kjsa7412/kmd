## 목표
팀 화면이 개인 프로그램(이 PC 의 kmd · 127.0.0.1:7373)에 붙어 개인 지식을 같이 보여 주는 길을 걷어 낸다.
팀 프로그램은 팀 지식만, 개인 프로그램은 개인 지식만 다룬다. 권한은 네 자리로 정리한다.

## 먼저 읽을 것
1. CLAUDE.md — 작업 규칙(main 에서 · push 금지 · 테스트 범위 · 화면 네 폭 · 권한 · 저장 규칙 · 보고 형식)
2. docs/kmd_팀_개인_분리_검토.html — 결정과 전체 그림. 코드 위치는 475e40b 기준이라 다시 찾는다
3. docs/kmd_권한_모델.md · docs/kmd_디자인_컨벤션.md · docs/kmd_서비스_TODO.md(v0.5 L4)
4. docs/설명서_사용자.md · 설명서_관리자.md · 설명서_정리하는사람.md

## 정한 것 (바꾸지 않는다)
1. 팀 화면에 개인 지식은 아예 보이지 않는다. 지식 목록 · 찾기 · 지금 하는 일 · 멈춤 줄 · 이력 · 설정 어디에도.
   팀 화면은 팀 서버에만, 개인 화면은 개인 프로그램에만 붙는다.
2. 지식 보내기(개인 → 팀)는 개인 화면에서만 시작한다. 팀 서버의 받기는 그대로.
3. 권한은 넷: 총괄 관리자 › 지식관리자 › 쓰기 › 읽기. 받지 않은 지식은 「없음」(보이지 않음)이 기본.
   - 총괄 관리자 = 지금의 전역 관리자(auth admin). 사람 만들기 · 묶음 · 떠남 · 지식 세우기/지우기/되살리기 ·
     백업 · Claude 연결 · 일 줄 멈춤 · 서버 자원 가져올 곳(서버 폴더 · ssh · 허락 목록 밖 호스트) · 주인 넘기기
   - 지식관리자 = 지금의 지식마다 「관리」 자리(주인 포함). 문서 바로 고치기 · 정리 · 되돌리기 ·
     가져올 곳(허락된 호스트의 https git · DB) · 지금 가져오기 · 지식 설정 · 그 지식의 권한 주기
   - 쓰기 · 읽기 = 지금 그대로. 쓰기는 기록 남기기 · 일 줄에 파일/폴더 넣기 · 부탁 · 자기 기록 되돌리기
   - 판정 로직(hub.levelOf)은 그대로. 바뀌는 것은 이름 · 기본 자리 · 사람 만들 때 자리 고르기
4. 기본 자리를 「모두: 쓰기」 → 「없음」으로. 옛 지식은 바꾸는 날 그때 있는 사람(떠난 사람 · 기계 · 일꾼 제외)
   모두에게 그 지식의 쓰기 자리를 적어 준 뒤 기본을 없음으로 한다. 이미 그보다 높은 자리는 낮추지 않는다. 한 번만 돈다.
5. 총괄 관리자가 사람을 더할 때 팀 지식마다 자리(없음 · 읽기 · 쓰기 · 지식관리자)를 고른다.
   접속 계정 전달은 지금처럼 아이디 + 처음 들어오기 링크(24시간 · 한 번). 비밀번호는 사용자가 정한다.
6. 개인 프로그램 설치는 팀 화면의 별도 자리 「개인 프로그램 설치」에 둔다(누구나).
   설치 · 잇기 한 줄(/api/device/ticket) · 작업 폴더에 팀 지식 붙이기 한 줄 · 내 기기 목록.
   개인 지식 · 개인 폴더 내용은 보여 주지 않는다. 연결 상태는 팀 서버가 아는 기기 목록으로만(PC 에 묻지 않는다).
   지식 폴더 경로는 깐 뒤 개인 화면에서 정한다.
7. 사람 몫 PC 일꾼 열쇠(auth workerAdd owner)는 걷는다. 사람 카드 「PC 일꾼 n」 · 떠남 · 새 링크 · 기기 끊기 문구도.
   팀 정리 일꾼과 개인 프로그램 자신의 일꾼은 그대로.
8. 「정리하는 사람」은 이미 지식관리자로 흡수되어 있다. 낱말만 「지식관리자」로 고친다(설명서 · kmd owner --curators 안내).

## 커밋 방식
- 기준 문서 고침은 0단계에서 모두 써 두되 따로 커밋하지 않는다. 그 고침을 단계 1~8 에 나눠, 해당 코드와 같은 커밋에 넣는다
  (CLAUDE.md: 기준과 코드를 같은 커밋에서 맞춘다). 단계마다 커밋 하나.

## 단계
0. 기준 문서 써 두기(커밋하지 않음): 권한 모델(네 자리 · 기본 없음 · 옛 지식 옮기기) ·
   서비스 TODO(KM52 · v0.5 §5 · L4 거둠, 분리 항목 새로) · CLAUDE.md 용어(「이 PC 의 kmd」 · 자리 「읽기 · 쓰기 · 관리」 → 새 이름) ·
   디자인 컨벤션 9절 용어집 · 설명서 셋.
   **여기서 멈춘다.** 고친 기준 문서의 차이(git diff)와 요약을 보고하고, 사람의 확인을 받은 뒤 1단계로 간다.
   확인 때 고치라는 것이 있으면 고친 뒤 다시 보고한다.
1. 개인 화면 대조: 팀 화면에서 하던 개인 일(지식 만들기 · 지식 폴더 · 가져오기 · 설정 · 에이전트 설치 · Claude 로그인 ·
   지식 보내기 · 받는 팀 지식 고르기)이 개인 화면에 다 있는지 확인. 빠진 것만 개인 화면에 더한다
2. 팀 화면 걷기(app/main.js): pcConnect · reqTo 의 ~ 길 · S.pc · pcSide() · /pc/api/* 합쳐 보기 ·
   개인 칸 · 「내 PC 지식 폴더」 띠 · 새 지식 팝업의 개인 영역 · 팀 화면의 지식 보내기 · 설정 › 개인 ·
   「내 PC」 꼬리표 · kmdPcKns 기억. 빈 상태 · 오류 문구도 팀 지식만 말하게
3. 팀 서버 걷기(server/http.js): /api/me 의 pcUrl · /api/me/pcpass(·check) · CSP connect-src PC 예외 · serve.json pcUrl
4. 개인 프로그램 짝짓기 걷기: /pair · 짝 열쇠 ctx · /api/pair/forget · 팀 화면만 쓰던 확인 길. 개인 화면의 확인 창은 둔다
5. 권한: 이름(화면 · 오류 문구 · 설명서) · 기본 없음 · 옛 지식 한 번 옮기기(owners.json 에 판 표시, 원자 쓰기, _members.md 도) ·
   사람 더하기 창과 사람 카드에 지식마다 자리 표
6. 개인 프로그램 설치 자리(팀 화면): 한 줄 복사 · 팀 지식 붙이기 한 줄 · 내 기기 목록. 지금 개인 칸 띠 · 설정 › 에이전트 설치에
   흩어진 것을 이 한 곳으로
7. PC 일꾼 열쇠 걷기
8. 정리하는 사람 낱말 정리
9. 테스트 · 화면 확인 · 보고. 0단계에서 써 둔 기준 문서 고침이 모두 어느 커밋엔가 들어갔는지(git status 깨끗) 확인

## 지킬 것
- main 에서 바로. 새 브랜치 · worktree 금지. push 는 하지 않는다.
- 테스트는 바뀐 것에 걸린 test/*.test.mjs 만. npm test 전체 · restore 테스트 · 공유 폴더 stash 금지.
  걸릴 것: pair · pc-confirm · kit-area · open · settings · watch2 · screen-kmd · 권한 · auth 관련. 걷은 기능의 테스트는 지우고 까닭을 커밋에 적는다.
- 화면을 바꾸면 screen-kmd 등 화면 테스트를 돌리고 1280 · 1024 · 600 · 375 에서 잘린 요소 0 · 가로 스크롤 0 을 확인한다.
- 권한은 hub.levelOf 하나 · 읽기 길 hub.meta(id, ctx) · 쓰기/관리 길 hub.need. 화면에서 숨기는 것으로 끝내지 않는다.
  지식 id 를 싣는 응답(목록 · 찾기 · 지금 하는 일 · 일 줄 · 이력 · 알림 · MCP)은 자리로 거른다. 기본 없음이 모든 길에서 지켜지는지 본다.
- 장부 · 설정은 원자 쓰기. 깨진 파일을 빈 것으로 덮지 않는다. .catch(() => {}) 로 삼키지 않는다.
- 화면은 kmd.css 토큰 · 컨벤션 부품만.
