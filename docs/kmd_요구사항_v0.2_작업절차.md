## 1. 요구 검토 — 무엇을 원하나 · 지금은 어떤가 · 어떻게 한다

### R1 지식 목록 — 「지식 만들기」 단추 걷기

- **지금** — 지식 목록 아래에 `+ 지식 추가` · `+ 지식 만들기` 두 링크. 「지식 만들기」(가져오기 화면)는 옆 메뉴 지식 관리에 이미 있다.
- **정함** — 목록의 `+ 지식 만들기` 를 걷는다. 옆 메뉴의 「지식 만들기」(파일 넣기 · 지켜보며 맞추기)는 그대로 둔다(요구의 [지식만들기] 절이 그 화면을 고치라고 하므로).

### R3 지식 만들기 — 「DPMS_회의록_261021_HNC_통화.md」 가 회의록이 아니라 파일 이름 문서로 섰다 · Claude 가 돌았나

- **확인함**(로컬 환경 `.kmd-data/local/pc/test1` · `옛자료` 의 이력):
  1. Claude 는 **돌았다** — `claude -p` 한 번(도구 없음 · JSON 초안). 그러나 초안이 kmd 의 값 대조 검사를 넘지 못했다 — 이력 「정리 — … 들임」 에 `Claude 로 하지 못한 까닭 — 검사를 넘지 못했다 — 파일의 값이 글에 없다 — 21 · 0.2 · 9`.
  2. 그래서 **규칙으로** 들였는데, 그때(00:20 · 00:51)의 규칙은 갈래(회의록)를 몰라 파일 이름 그대로 새 문서를 세웠다(갈래 규칙은 08:13 `f5a3ffa` 에 들어왔다).
  3. 다음 파일(10-16 통화)은 Claude 가 넘겼지만 「같은 갈래 문서」 로 앞의 잘못 지은 문서(`DPMS_회의록_261021_HNC_통화`)를 골라 그 안에 넣었다 — 잘못된 이름이 굳는다.
  4. 사람은 이 과정을 볼 길이 없었다 — 「최근 넣은 것」 한 줄뿐.
- **원인** — 파일 하나를 JSON 초안 한 번으로 옮기는 길은 세션이 하는 일(지식을 둘러보고 · 이름을 맞추고 · 갈래 문서를 고르고 · 항목을 나누고 · 이름 장부에 이름을 세우고 · 기록을 남긴다)에 못 미친다. 검사에 걸리면 규칙으로 떨어져 결과가 더 나빠진다.
- **정함** — R7(에이전트로 지식 세우기)로 바꾼다. 규칙 길은 Claude 가 아예 없을 때만.

### R4 지켜보며 맞추기 — 「언제」 팝업이 영역 안에 갇힌다 · 줄을 누르면 보고 · 고치고 · 지운다

- **지금** — 가져오는 곳 표가 `overflow-x:auto` 상자 안이라 ⋯ 메뉴가 상자 밖으로 못 나간다(스크린샷). 줄을 눌러도 아무 일이 없고, 고치기 · 지우기 길이 서버에도 없다(언제 · 뜻 갱신만).
- **정함**
  - 팝업은 늘 맨 위 층(`.pop` — 화면 기준 자리 · 상자에 잘리지 않는다)으로 띄운다 — 컨벤션 C-팝업.
  - 줄을 누르면 「가져오는 곳」 상세 팝업(모달) — 유형 · 주소(경로 / git / DB 접속) · 넣는 곳 · 언제(매일이면 시각) · 뜻 갱신(git) · 상태(마지막 확인 · 다음 · 마지막 바뀜 · 메모) · 단추 [지금 가져오기] [전체 다시 맞추기] [고친 것 저장] [지우기].
  - 고칠 수 있는 것 — 주소 · 넣을 문서 · 언제 · 뜻 갱신 · DB 접속(호스트 · 포트 · DB · 스키마 · 계정 · 비밀번호) · git 계정 · 토큰. 이름은 고치지 않는다(상태 · 자격 이름의 열쇠라서).
  - 지우기 — 확인 한 번 「들어온 문서는 그대로 둔다」 · 감시 · 상태 · 장부 · 자격을 걷는다.
  - 서버 — `POST /api/k/:id/sources/edit` · `POST /api/k/:id/sources/remove`(`hub.sourceEdit` · `hub.sourceRemove`) · 권한은 더하기와 같다.

### R5 지켜보며 맞추기 — 기능이 많아 복잡하다 · 단추는 단추로

- **지금** — 표 한 줄에 ⋯ · 「지금 가져오기」 · 「전체 다시 맞추기」 가 글 링크로 섞이고, 더하기 칸이 늘 펼쳐져 화면이 길다.
- **정함** — 영역을 다시 짠다:
  - 머리 줄: 제목 · 한 줄 설명 · 오른쪽 단추 [지금 모두 가져오기] [+ 가져올 곳 더하기].
  - 목록: 가져오는 곳마다 한 줄 카드 — 유형 표지 · 이름 · 넣는 곳 · 언제 칩 · 상태 칩(그대로 / 바뀜 n / 멈춤 / 못 가져옴 / 도는 중) · 오른쪽 작은 단추 [지금 가져오기]. 줄을 누르면 상세(R4).
  - 「전체 다시 맞추기」 · 「뜻 갱신」 · 지우기는 상세 안으로(드물게 쓰는 일).
  - 더하기는 [+ 가져올 곳 더하기] 를 누르면 팝업으로(지금 칸 그대로 · 유형 탭 · [연결 확인] · [더하기]).
  - 글 링크로 일을 하는 곳은 모두 `.btn` 으로(컨벤션 C-단추).

### R6 문서 폴더에 PDF — 첨부로만 들어오고 기록 · 문서가 없다

- **지금** — 넣기(`importer.js`) · 문서 폴더 감시(`docwatch`) 모두 pdf · hwpx · hwp 는 원본 첨부만. 첨부에 이어진 기록도 문서도 없다.
- **정함** — 「여러 문서를 md 로 바꾸기」 를 한 곳(`core/convert.js`)에 모은다(§3 설계):
  - md · docx · pptx · xlsx — 지금처럼 kmd 안에서(ooxml).
  - hwpx — kmd 안에서(zip 속 `Contents/section*.xml` 의 글 · 표).
  - pdf · hwp · 그림 — **Claude Code 가 원본을 직접 읽어**(Read 도구는 PDF · 그림을 읽는다) md 로 옮긴다 — 에이전트 길(R7)의 첫 단계. 같은 파일(지문)은 다시 바꾸지 않는다(바꾼 글 보관).
  - Claude 가 없으면 — 첨부 + 「글로 바꾸지 못한 파일」 기록 하나(첨부 경로 · 까닭)를 남겨 이어지게(이력에 보인다). 나중에 [다시 하기].
  - 문서 폴더 감시의 pdf 는 바꾼 글로 원본이 주인인 문서(`watched` 표지)를 세운다 — md · docx 와 같은 길.

### R7 DB 가져오기 — 테이블이 다 「항목」 으로 들어갔다

- **지금** — 테이블 정의 규칙(`runDb`)이 「테이블 정의」 문서에 테이블마다 항목은 쓰지만 이름 장부(`_vocab.md`) · 자리 장부(`_managed.md`)에 `table:<이름>` 을 세우지 않는다. 그래서 항목으로 보기의 종류가 모두 「항목」 이다.
- **정함** — DB 를 가져올 때 테이블마다 `table:<테이블>`(보이는 이름 = 설명이 있으면 「테이블 — 설명」 · 다른 이름 = 설명) 을 이름 장부에, 그 항목 자리를 자리 장부에 같은 묶음으로 세운다. 이미 들어와 있고 이름이 빠진 지식은 다음 확인 때 이름만 채운다. 없어진 테이블의 이름은 지우지 않고 그대로(기록이 그 이름을 쓸 수 있다).
- 이를 위해 저장(`core/save.js`)이 **이름 세우기**(`names: [{coord, label, aliases, doc, heading}]`)를 받는다 — MCP `save` 도 같은 칸을 받아 세션 · 에이전트가 이름을 세운다.

### R8 [공통] 지식 가져오기가 세션 작업에 못 미친다 — 터미널로 보이고 세션처럼 정확하게

- **지금** — 넣은 파일 하나 = `claude -p` 한 번(도구 0 · MCP 0 · JSON 초안) → 검사 → 못 넘으면 규칙. 지식을 둘러보지 못하고 · 이름 장부를 모르고 · 이름을 세우지 못하고 · 사람은 볼 길이 없다.
- **CDP · kmd 세션은** — 스킬(일하는 순서) + MCP 도구(brief · match · search · section · save)로 지식을 둘러보고, 이름을 맞추고, 문서 · 항목을 고르고, 이름을 세우고, 기록을 남긴다.
- **정함** — 「에이전트로 지식 세우기」(§3):
  - kmd 가 Claude Code 를 **세션처럼** 띄운다 — `claude -p --output-format stream-json` · MCP 는 kmd 자신 하나(그 지식 · 그 일감에만 쓰는 단기 열쇠 `kmda_`) · 내장 도구는 Read · Glob · Grep(원본 파일을 둔 빈 일 폴더 안만) · 그 밖은 모두 거절(`--permission-mode dontAsk`) · 일하는 순서는 스킬 `kmd-build`(새로 · 세션의 kmd-work · kmd-save 와 같은 말).
  - 하는 일 — ① 원본을 읽어 md 로(필요하면) ② brief 로 지식을 보고 ③ 글 속 이름(테이블 · 화면 · API · 절차 · 용어)을 match 로 맞추고 ④ 갈래 · 주제 문서를 고르거나 세우고(파일 이름이 아니라 갈래 · 주제 — 회의록 › 「2026-10-21 HNC 통화」) ⑤ 새 이름은 이름 장부에 세우고 ⑥ save 로 항목 글 + 기록(무엇을 왜 어디에)을 남긴다. 넣은 파일의 기록은 「넣음」 으로.
  - **터미널** — 일마다 줄(생각 · 도구 부름 · 결과 · 비용)을 서버가 모으고 화면이 받아 그린다: 지식 만들기 › 「최근 넣은 것」 줄의 [터미널] · 도는 동안 저절로 펼침 · 끝나면 「무엇을 어디에 넣었다」 한 줄과 [보기].
  - 넣기는 바로 돌려주고 일은 뒤에서(지식마다 한 줄) — 화면이 기다리지 않는다.
  - Claude 가 없거나 꺼 둔 지식(「Claude 에 보내지 않음」)이면 지금 규칙 길.
  - 팀 지식 — 같은 에이전트를 팀 서버의 정리 일꾼(`kmd worker` · 정리 전용 로그인)이 띄운다(MCP 는 팀 서버 · 단기 열쇠 · 줄은 서버로 올린다). 팀 서버의 개인 지식은 그 사람의 PC 일꾼.
  - 안전 — 들인 문서 속 주입 문장이 움직일 수 있는 것은 그 지식의 MCP 도구(읽기 · save)뿐이다. save 는 사람 · 세션과 같은 검사(원본이 주인인 문서 · kmd 가 쓰는 파일 · 지문)를 탄다 · 단기 열쇠는 그 지식 하나 · 일이 끝나면 끝난다 · 예산 상한.

### R9 [공통] 디자인 통일 — 컨벤션을 두고 그대로 짓는다

- **정함** — [kmd_디자인_컨벤션.md](kmd_디자인_컨벤션.md) 를 먼저 쓰고, 이번에 고치는 화면(지식 목록 · 지식 만들기)은 그것대로 짓는다. 다른 화면은 다음 판에 하나씩(남음).

## 2. 순서

```
D0 컨벤션 문서 · 공통 부품(CSS)     ─┐
A  지식 목록 통합                    ├─ 화면
B  지켜보며 맞추기                   ─┘
C  이름 세우기(save · MCP) · DB 테이블 이름
E  에이전트로 지식 세우기 · 터미널 · md 바꾸기(PDF · hwpx)
F  팀 일꾼도 같은 에이전트
T  시험 · 브라우저 확인 · 설명서 · CHANGELOG · 커밋
```

## 3. 설계 — 에이전트로 지식 세우기 · md 바꾸기

### 3.1 흐름

```
파일 넣기 / 문서 폴더의 새 · 바뀐 파일
  └ convert(파일)            md · docx · pptx · xlsx · hwpx → kmd 안에서 md
                             pdf · hwp · 그림              → 「바꿀 것」 표시(에이전트가 원본을 읽는다)
  └ 기록 하나(ingest/<경로>) — 원본은 첨부로(바꾸지 못하는 것도 이어짐)
  └ 일감(지식마다 한 줄)  ── Claude 쓰나? ── 아니오 → 규칙(지금 길)
                                └ 예 → agent run
                                        일 폴더: 원본 사본 · 바꾼 md · 일 설명(task.md)
                                        claude -p --output-format stream-json --verbose
                                          --tools Read,Glob,Grep  --allowedTools Read,Glob,Grep,mcp__kmd__*
                                          --permission-mode dontAsk  --strict-mcp-config
                                          --mcp-config {kmd: http <서버>/mcp · Bearer kmda_…}
                                          --append-system-prompt <kmd-build 스킬>  --max-budget-usd
                                        → 줄마다 run.lines 에(터미널)
                                        → save(…) 들은 kmda_ 열쇠로 — 작성자 kmd-auto · 태그 curate-llm · reflects 넣은 파일 기록
                                  끝: 넣은 파일 기록이 「넣음」 인가? 아니면 규칙으로(까닭 줄)
```

### 3.2 열쇠 `kmda_`

- 서버가 일감마다 만든다(무작위 · 메모리 · 30분 · 일이 끝나면 지움). ctx = `{ user: 'kmd-auto', agent: { kn, rec, run } }`.
- MCP 만 받는다(`/api/*` 는 거절). brief · match · search · section 은 그 지식만(다른 지식 id 는 거절 · 지식 목록 brief 는 그 지식 하나).
- save — 그 지식만 · 태그 `curate-llm` 를 서버가 붙이고(그래서 log/ 이력) · reflects 에 넣은 파일 기록을 붙인다 · system 아님(원본이 주인인 문서 · kmd 파일은 거절).

### 3.3 이름 세우기(`names`)

- save 입력 `names: [{ coord: '종류:값', label, aliases?: [], doc?, heading? }]`.
- `_vocab.md` — `## 종류` 아래 `- \`종류:값\` — 보이는 이름` (+ `aliases:`) · 이미 있으면 다른 이름만 더한다.
- `_managed.md` — doc · heading 이 있으면 `| \`종류:값\` | \`docs/문서.md\` | \`## 머리\` |` (같은 이름 줄이 있으면 바꾼다) · 표가 없으면 머리째 세운다.
- 종류는 영문 소문자(table · screen · api · proc · term · code · module · batch · req · func …) — 화면의 종류 이름표(views.js `KIND`)와 같다.
- 같은 묶음(커밋)에 든다 · 실패하면 같이 되돌린다.

### 3.4 터미널 줄

- `hub.runs` — `{ id, kn, title, file, state: run|done|fail|rule, startedAt, endedAt, lines: [{ t, k, x }] (k = say · tool · ok · err · cost · sys), result: { docs[], names, msg } }` · 지식마다 최근 20 · 서버를 다시 켜면 비운다(이력은 log/ 에 남는다).
- 화면 — `GET /api/runs?kn=` (요약) · `GET /api/runs/:id?from=n` (줄) · 도는 동안 0.8초마다.
- 터미널 모양 — 컨벤션 C-터미널(어두운 바탕 · 모노 · 자동 아래로 · 도구는 `▸ save docs/회의록 › 2026-10-21 HNC 통화` 처럼 짧게 · 결과는 `✓` / `✗`).

### 3.5 md 바꾸기(`core/convert.js`)

| 원본 | 바꾸는 곳 | 실패하면 |
|---|---|---|
| md · markdown | 그대로 | — |
| docx · pptx · xlsx | kmd(ooxml) | 첨부 + 「바꾸지 못한 파일」 기록 |
| hwpx | kmd(zip 속 section xml — 문단 · 표) | 같음 |
| pdf · hwp · 그림 | 에이전트(Read 로 원본 · 쪽마다 · 표는 md 표 · 그림 속 글) | 같음 · Claude 없으면 그 까닭 |

- 바꾼 글은 `<살림>/convert/<sha>.md` 에 둔다 — 같은 파일을 두 번 바꾸지 않는다(문서 폴더 감시 · 다시 맞추기).
- 문서 폴더 감시의 pdf · hwp — 바꾼 글이 있으면 원본이 주인인 문서로(바꾼 글이 없으면 그 파일 하나만 에이전트에 「바꾸기만」 일감).
