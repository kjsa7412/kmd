> 이 글을 새 세션(작업 폴더 `C:\project\kmd`)의 첫 메시지로 그대로 붙여 넣는다. 2026-10-23.

---

## ★ 최초 요구사항 — 무엇보다 먼저 지킨다

1. **kmd 는 CDP 와 별도의 서비스다.** CDP 의 사상(지식 레포 · 좌표 · 작업 기록과 정리 · MCP · 화면)은 가져가되, **구현은 kmd 레포 `C:\project\kmd` 에서 새로 짠다.**
2. **CDP 코드(`C:\project\CDP`)는 참고만 한다.** 읽고 배우되 통째로 복사해 출발하지 않는다. **CDP 레포는 고치지도 커밋하지도 않는다.**
3. **프로그램 화면은 목업과 똑같은 디자인으로 나와야 한다** — `docs/kmd_목업.html`(그림 16장) · `docs/kmd_목업_인터랙션.html` 의 배치 · 색 · 글꼴 · 간격 · 글자 · 단추 수 그대로. 목업의 CSS 변수 · 클래스 · 마크업을 화면 코드의 바탕으로 옮긴다. 목업에 없는 화면 · 단추를 더하지 않는다. 목업끼리 다르면 인터랙션 목업을 따른다.
4. **설계 근거는 kmd 레포 `docs/` 의 검토 문서와 목업이다** — `CDP_kmd_개정_v0.7_검토.md` · `v0.6` · `v0.5` · `CDP_kmd_서비스_구체화_검토_v0.1.md` · 목업 둘 · `kmd_한눈에.html`.
5. **시험은 필수 기능만 · 최소로.** 판마다 그 판의 필수 기능을 보는 시험 파일 몇 개만 돌린다. **멀티 에이전트 검토(Workflow)는 하지 않는다.** 시험은 한 번에 하나만 — 이 PC 는 다른 세션과 같이 쓰여 부하가 크다.
6. 보고는 늘 한국어 · 결정이 필요하면 묻지 말고 권장안으로 정해 절차서 「나온 것」 에 적는다 · **커밋까지만**(push · 태그 · 배포는 사람이).

## 할 일

절차서 `docs/kmd_개발절차_TODO.md` 의 순서대로 kmd 를 구현한다 — **K0 뼈대 → E0 ~ E9(엔진) · S1 ~ S8(화면) → P5(꾸러미)**. 절차서 맨 위의 「최초 요구사항」 과 §0 「일하는 규칙」(코드 자리 · 기술 권장안 · 판의 끝 · 시험 방침 · 화면 모양 · 화면 말)을 먼저 읽는다.

- **K0 뼈대부터** — kmd 레포 뿌리에 `package.json` · 코드 폴더(권장 `server/` · `core/` · `app/` · `test/`) · `kmd` 명령(`kmd serve` · `kmd up`) · 지식 하나 읽기 · save 하나(기록 + 섹션 · git 커밋) · MCP 최소 도구(brief · match · section · save) · 화면 셸(목업 M4 · M5 — 리본 · 나무 · 탭)을 **목업과 같은 모양**으로. 끝은 「지식 하나를 띄워 화면에서 문서를 읽고 MCP save 로 기록이 커밋된다」 + 화면 스크린샷이 목업과 나란히 같다.
- 판 하나의 끝 = 그 판의 필수 시험 파일 통과 + (화면 판이면) 목업과 같은지 스크린샷으로 한 번 + `CHANGELOG.md` 「(다음 판)」 + kmd 레포 커밋(「무엇을 한다 — 왜」 한 줄 한국어) + 절차서 체크 상자 · 「나온 것」 갱신.
- 판 하나를 마칠 때마다 운영자에게 짧게 한국어로 보고한다(무엇 · 커밋 · 시험 결과 · 남은 것 · 사람이 할 일) — 그리고 다음 판으로 간다.
- 운영자 결정은 그대로 지킨다 — 정리는 승인 없이 바로(KM81) · 자료 가져오기는 따로 한 화면(KM82) · 「지식 추가」 / 「자료 가져오기」 이름(KM83) · 팀 정리는 팀 서버의 정리 전용 Claude Code 로그인(KM84) · 보는 법 셋(문서 · 항목 · 그래프 — KM90 ~ KM95) · 화면은 자동이 기본 · 단추 적게 · 쉬운 말(금지어 0).
- 사람 실측(절차서 §5 — 특히 **S9 정리 전용 Claude Code 로그인의 약관 · 반출 · 한도 · 서버 로그인 흐름은 E5 앞**)이 막으면 운영자에게 알리고 막히지 않는 다음 판을 한다.
