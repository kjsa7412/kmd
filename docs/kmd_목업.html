개요

배포 서버의 도커 네트워크를 정리한다 — 사내 대역과 겹치지 않게.

네트워크

배포 서버는 사용자 정의 브리지 dpms-net 을 쓴다.

컨테이너끼리는 서비스 이름으로 부른다(내장 DNS). IP 는 재시작마다 바뀐다 — 설정에 박지 않는다.

기본 브리지 172.17.0.0/16 은 사내 VPN 대역과 겹친다. daemon.json 의 bip 를 10.210.0.1/24 로, default-address-pools 를 10.211.0.0/16 으로 둔다.

포트

앱은 호스트에 열지 않는다 — nginx 만 80 · 443. 관리 포트 9090 은 127.0.0.1 에만 묶는다.

배포절차

배포 · 롤백 · 헬스 체크 · 카나리 · 태그 규칙을 한 곳에 둔다.

롤백

배포 뒤 10분 안에 오류율이 2% 를 넘으면 롤백한다. 롤백은 직전 이미지 태그로 되돌리는 한 줄이다 — deploy.sh --tag <직전 태그>.

마이그레이션이 든 배포는 down 스크립트를 먼저 돌고, 롤백 전에 DBA 에게 확인한다.

헬스-체크 — 헬스 체크 (배포 직후)

각 서버의 /health 를 30초마다 부른다. 시간 초과는 5초다.

세 번 연속 실패하면 그 서버를 로드밸런서에서 뺀다. 빠진 서버는 사람이 확인하고 다시 넣는다.

카나리

카나리는 전체의 10% 로 시작한다. 10분 동안 오류율이 0.5% 를 넘지 않으면 25% → 100% 로 넓힌다. 넘으면 바로 롤백한다(배포절차:롤백).

야간(22~07시)에는 카나리를 열지 않는다.
