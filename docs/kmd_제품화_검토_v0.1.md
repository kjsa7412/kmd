# kmd 제품화 검토 v0.1 — 팀 · 개인 서비스 전체

- 날짜 2026-10-25 · 기준 `main` 7dcdfc6(v0.1.0) · 검토 대상: 팀 서비스(팀 서버 · mode team), 개인 서비스(내 PC 프로그램 · mode pc), 두 서비스의 연계, MCP 길
- 목적: 「기능이 구현된 MVP」가 「설명 없이 쓰는 제품」이 되려면 무엇을 고쳐야 하는지 찾는다. 버그 목록이 아니라 우선순위를 정하는 문서다.
- 발견 178건의 문제 · 근거 · 재현 · 권고 · 검증 메모는 [발견 목록(상세)](kmd_제품화_검토_v0.1_발견목록.md)에 있다. 이 문서의 번호(F-… · G-…)는 그 목록의 번호다.

## 0. 결론

**지금은 「기능이 구현된 MVP」다.** 읽기 · 고치기 · 정리 · 보내기의 기본 흐름이 돌고, 그 바탕 설계는 단단하다. 쓰는 길이 하나(`core/save.js`)이고, 단기 열쇠의 범위가 좁고, 내 PC 지식 요청은 팀 서버로 새지 않으며(fail-closed), 서버가 정리 초안을 그대로 믿지 않는다. 기준 시험은 96개 중 95개가 통과한다.

**하지만 실제 사용자가 설명 없이 쓰기에는 다섯 가지 벽이 있다.**

1. **들어오는 길이 막힌다.** 설치 한 줄로 깐 PC 사용자에게는 PC 화면에 들어갈 길이 없다(F-001). 늘 켜기 작업은 창을 열지 않고, 번호를 다시 받는 명령이 없으며, 번호 없는 주소는 PC 에 있지도 않은 팀 로그인 양식을 보인다. 새 PC 에서 설치 한 줄은 실제로 설치하지 않고(F-037), `kmd pc update` 는 도는 프로그램을 바꾸지 않는다(F-038). 개인 서비스의 핵심 기능(파일 넣기 · 지켜보며 맞추기 · 보내기 · 설정)이 첫날부터 막힌다.
2. **「나만」 약속이 조건에 따라 깨진다.** 두 사람이 거의 같은 때 개인 지식을 만들면 앞사람의 「나만」 줄이 지워져 팀 전체에 보이고, 다시 켜도 그대로다(G1-2). 지운 개인 지식의 넣은 파일 이름과 터미널 줄이 팀원 모두에게 열린다(F-003). 셸 `kmd owner` · `kmd restore` · 살림 자리 되돌리기 뒤에도 개인 지식이 풀린다(F-013 · G3-1 · G3-2). 원인은 하나다. 주인 장부(owners.json)가 메모리 사본 하나에 직렬화 없이 쓰이고, 줄이 없으면 「보인다」로 여긴다.
3. **실패가 조용히 멈춘다.** 보내기가 한 번 거절되면 까닭과 상관없이 영원히 「닿지 않는다」 대기가 되고, 대기 하나가 모든 지식의 보내기를 막는다(F-002). 정리 일감은 메모리에만 있고 기한이 없어, 일꾼이 한 번 넘어지면 그 지식의 정리가 다시 켤 때까지 멈춘다(F-006). 팀 서버를 설치해도 정리 일꾼이 없다(F-007). 남은 `.git/index.lock` 하나가 그 지식의 쓰기를 영영 막는다(G1-3). 화면은 그동안 「정리하는 중」 · 「닿으면 저절로 보낸다」 · 「오늘은 문제가 없다」를 보인다.
4. **사람 · 지식 · 백업의 생애 주기를 다룰 수 없다.** 관리 화면에 사람 관리가 없다(F-014). 떠난 사람을 끝낼 길이 없어 그 사람의 Claude Code 가 팀 지식을 계속 읽고 쓴다(G4-1). 아이디를 되쓰면 새 사람이 옛 사람의 개인 지식을 물려받는다(G4-3). 팀 지식을 화면에서 세울 수 없다(F-016). 운영 문서의 「되살리기 연습」을 그대로 하면 운영 지식이 「읽기만」이 된다(G3-3).
5. **쓴 글이 사라진다.** 고치는 중에 찾기를 열거나 옆 메뉴를 접으면 쓰던 글이 원래 글로 돌아간다(F-004). 세션이 끝나면 [저장]은 토스트만 내고 글을 버린다(G4-5). 항목을 지우거나 이름을 바꾼 고침은 무시되거나 두 벌이 된다(F-035). 편집기로 고친 글을 kmd 가 알리지 않고 되돌린다(F-025).

**권고.** MVP 필수 87건을 아래 §7 의 작업 묶음 9개로 고친 뒤에 실제 사용자에게 연다. 그 가운데 1단계(들어가기 · 「나만」 경계 · 요청 안전 · 사람 관리 — WP1 ~ WP4)는 지금 쓰는 사람이 있다면 바로 할 일이다. 제품화 단계 91건은 정보 구조 · 처음 경험 · 접근성 · 운영 순으로 이어서 한다.

## 1. 검토 방법과 한계

### 방법

- **10 관점으로 나눠 찾았다.** 정적 코드 검토 6(팀 기능 · 개인 기능 · 팀↔개인 연계 · 예외와 보안 · 제품화 구조 · UI 일관성)과 실제 화면 시나리오 4(새 팀원 · 관리자와 정리하는 사람 · 개인 PC 사용자 · 반응형과 상태)다.
- **실제로 돌려 봤다.** `scripts/local.mjs` 로 팀 서버 + PC 프로그램 4쌍을 따로 띄우고(가짜 Claude), 시나리오 관점마다 한 쌍씩 맡겨 playwright(이 PC 의 Chrome)로 1300 · 760 · 420px 화면을 걸었다. 쓰기 재현은 시험처럼 임시 폴더에 격리 서버를 띄워 했다.
- **반박 검증을 거쳤다.** 1차 발견 218건을 136건으로 합친 뒤, 회의적인 검증자가 코드를 읽고 재현해 반박을 시도했다. Critical · High 는 한 건씩, Medium · Low 는 7건씩 묶어 검증했다. 그 뒤 완결성 비평이 빈 곳 4개(예외 · 견고성 다시 하기, MCP 길, 되살리기 왕복, 사람이 떠난 뒤의 생애 주기)를 골라 42건을 더 찾고 같은 방식으로 검증했다.
- **결과.** 178건이다. 검증 결과는 확인 126 · 일부 확인 52 · 반박 0 이다. 검증이 심각도를 바꾼 것이 32건이다(예: F-036 High → Critical, G3-4 Critical → Medium, G1-1 Critical → High). 「일부 확인」 은 주장의 범위나 숫자를 바로잡은 것이라 고칠 때 검증 메모를 먼저 본다.
- **기준 시험.** `npm test` 는 96개 중 95개 통과, 실패 0, 건너뜀 1(DB 시험은 `KMD_TEST_PG` 가 있어야 돈다)이고 약 4.6분 걸렸다.
- **Critical 9건은 직접 다시 대조했다.** 해당 file:line 을 읽어 주장과 맞는지 확인했다.

### 한계 — 이번에 보지 못한 것

- **Claude 결과물의 질.** 모든 환경이 가짜 Claude 였다. 정리 초안 · 들이기 결과의 문서 이름 · 갈래 판단은 판단하지 않았다(요구사항 L4).
- **이 PC 를 바꾸는 일.** 설치 한 줄, `kmd up` · `kmd connect` · `kmd pc task`, 작업 스케줄러, 진짜 Claude 로그인은 실행하지 않았다. 관련 발견(F-001 · F-037 · F-038)은 코드와 꾸러미(`dist/`) 읽기, 지난 주소 재현에 근거한다.
- **실제 바깥 환경.** Linux 팀 서버 · systemd · https 역프록시 · GitLab 봇 · 실제 PostgreSQL · 원격 git 백업은 구성하지 않았다.
- **시간이 흘러야 보이는 것.** 세션 12시간/7일, 링크 24시간, 기기 열쇠 90일, 개인 지식 하루 대기, 백업 6/24시간 경고 줄은 코드와 시뮬레이션으로만 봤다.
- **화면 환경.** Chrome headless 만 썼다. 실제 화면 읽기 프로그램 · 휴대폰 · Firefox · Safari 는 보지 않았다.
- **1차 「예외 · 보안」 관점.** 이 관점의 결과는 출력 단계에서 유실됐다. 그 범위는 2차 빈 곳 G1 에서 다시 했다(8건).

## 3. 핵심 문제 묶음

발견 178건을 원인으로 묶으면 아홉 갈래다. 갈래마다 무엇이 문제이고, 왜 중요한지, 어떤 방향으로 고칠지를 적는다.

### T1. 들어가기 · 설치 · 판 — 첫날이 막힌다

- **무엇이.** PC 화면은 60초짜리 한 번용 번호로만 열리는데, 설치 경로(늘 켜기 `--no-open`)에서는 번호가 만들어지지 않는다. 번호 없는 · 지난 주소는 팀 로그인 양식으로 떨어지고, 같은 탭에 새 번호를 붙여도 들어가지지 않는다. PC 쿠키는 30일 고정이라 쓰던 사람도 30일 뒤 막힌다(F-001). 새 PC 에서 설치 한 줄은 「먼저 깐다 …/dl」 로 끝나고 꾸러미 받기 · PATH 는 사람이 손으로 한다(F-037). `kmd pc update` 는 current.json 만 바꾼다(F-038). 팀 화면은 PC 가 늦으면 첫 화면을 그리지 못한다(F-044).
- **왜.** 개인 서비스의 모든 기능이 이 문 뒤에 있다. 설치 출력의 「✓ 넷」 · 「새 판 저절로」는 사실이 아닌 성공 표시다.
- **방향.** `kmd open`(도는 PC 서버에서 번호를 받아 연다)과 시작 메뉴 바로가기 · 설치 끝 「화면 열기」. PC 모드의 미로그인 화면을 전용 안내로. hashchange 처리 · 쓰는 동안 쿠키 늘림. 설치 한 줄이 꾸러미 받기부터 connect 까지. 실행기가 current.json 을 읽게. 팀 화면의 PC 연결은 뒤에서 · 시간 제한.
- **발견.** F-001 · F-037 · F-038 · F-044 · F-060 · F-061 · F-062 · F-116 · F-096 · F-134 · F-059 · G2-7 · G4-13

### T2. 「나만」 경계와 권한 — 하나의 장부, 여러 쓰는 손

- **무엇이.** 주인 장부(owners.json)를 서버 메모리 사본이 들고 직렬화 없이 통째로 쓰고, 셸 명령은 다른 프로세스에서 같은 파일을 쓰며, 서버는 다시 읽지 않는다. 줄이 없는 지식은 「보인다」 로 여긴다(owners.js:43). 그래서 동시 생성(G1-2) · 지운 지식의 일 기록(F-003) · 셸 owner/restore(F-013 · G3-1) · 살림 자리 되돌리기(G3-2) · 되살리기(G3-5 · G3-6)에서 개인 지식이 팀에 열리거나 설정을 잃는다. 권한 쪽에서는 주인이 API 로 팀 지식을 개인으로 감출 수 있고(F-009), 일반 팀원이 `names` 로 팀 지식의 이름 · 자리 장부를 바꿀 수 있다(G1-4 · G2-4). 기록만 한 사람이 남의 기록까지 든 정리를 되돌린다(F-047).
- **왜.** 「나만」 은 팀 서버 개인 지식의 존재 이유다. 한 번 새면 신뢰를 되돌릴 수 없다. 모두 조건부지만 그 조건(동시에 만들기 · 지우기 · 운영 문서대로 되살리기)은 평범한 동작이다.
- **방향.** 장부를 하나의 직렬 큐 · 유일한 임시 파일 원자 쓰기로. 셸은 도는 서버 API 를 부르거나 mtime 으로 다시 읽기. 켤 때 · 동기화 때 `_members.md` 와 맞춰 「더 엄격한 쪽」을 따르기. 모르는 id 는 닫힘으로. 지식별 살림 파일을 한 폴더로 모아 지우기를 한 번에. `private` 전환 · 주인 넘기기는 관리자(재인증)만. `names` 도 canDirect 로 묶기. 정리 · 생성 · 지우기 · 되살리기 뒤 「나만」 이 지켜지는지 시험을 더한다.
- **발견.** G1-2 · F-003 · F-013 · G3-1 · G3-2 · G3-5 · G3-6 · F-009 · G1-4 · G2-4 · F-047 · F-055 · F-084 · G3-4 · F-110

### T3. 요청 · 짝 · 열쇠 — 문은 있는데 잠금이 헐겁다

- **무엇이.** 상태를 바꾸는 API 가 method 를 보지 않아 GET 으로도 돈다. 그래서 글 속 그림 한 줄(`![](/api/…)`)이 그 글을 연 사람의 쿠키로 「모든 기기에서 나가기」를, 재인증 중인 관리자라면 「비밀번호 다시 정하기 · 관리자 해제」를 부른다(G1-1). 팀 화면의 「내 PC 지식」 짝짓기는 지금 들어온 팀 사람을 대조하지 않아, 같은 PC 브라우저의 다른 팀원이 내 PC 지식을 읽고 내 이름으로 쓴다(F-011). PC 의 [허락] 창은 아무 출처나 영구 등록하고 지울 곳이 없다(F-012). 기기를 끊고 비밀번호를 다시 정해도 PC 일꾼 열쇠(kmdw_)는 산다(F-010). 「Claude 에 보내지 않기」 지식도 MCP 를 거쳐 Claude Code 세션으로 그대로 나간다(G2-1).
- **왜.** 하나하나는 조건이 있지만 고치기가 작고(method 강제 · 사람 대조 · 허락 목록), 그대로 두면 「팀 지식 · 내 지식을 안전하게 Claude 와 쓴다」 는 약속이 흔들린다.
- **방향.** 상태를 바꾸는 길은 POST 만 · CSRF 토큰(또는 Sec-Fetch-Site). 그림 src 는 그 지식 첨부 경로만. 짝 열쇠는 팀 서버가 서명한 「지금 사람」 이 맞을 때만 · 짝 ctx 에서 admin 빼기. 허락은 `kmd connect` 가 적은 팀만 · PC 설정에 허락 목록과 [끊기]. 일꾼 열쇠를 기기에 묶어 함께 걷기. MCP 응답에 noClaude · private 반영.
- **발견.** G1-1 · F-011 · F-012 · F-010 · G2-1 · F-087 · G2-3 · F-083 · F-079 · G1-5 · F-057 · G2-8 · G4-11

### T4. 조용히 멈추는 일 — 일감 · 대기에 상태와 기한이 없다

- **무엇이.** 보내기 실패는 404 · 400 · 403 · 401 을 가리지 않고 wait 에 넣고, 실패해도 「보낸 것」 으로 표시해 변경사항에서 지운다. wait 를 버릴 길이 없고, 하나가 모든 지식의 보내기 단추를 끈다(F-002). 보낼 곳 칸은 [저장] 한 번에 팀 주소를 지운다(F-023). 보내기는 10초에 끊겨 팀은 받았는데 PC 는 「닿지 않는다」 고 한다(F-024). 정리 일감은 메모리에만 있고 임대 기한이 없다(F-006). 설치해도 일꾼이 없고(F-007), noClaude 팀 지식은 영영 정리되지 않으며 「0건」 카드만 쌓인다(F-008 · F-046). git lock 하나가 그 지식의 쓰기를 영영 막는다(G1-3). 개인 지식은 PC 일꾼이 한 번 받은 뒤로는 「하루 뒤 규칙으로」 가 다시 걸리지 않는다(G4-6). 정리 시각은 KST 에서 02:30 이 아니라 09:00 에 돈다(F-005).
- **왜.** 사용자는 기다리면 될 줄 안다. 실제로는 사람이 손대기 전까지 영영 멈춰 있고, 그 사실을 아무도 모른다. 멈춤 줄(stopline)이라는 좋은 부품이 있는데 이 상태들이 거기에 올라오지 않는다.
- **방향.** 일감 · 대기를 파일(또는 SQLite)에 상태(기다림 · 도는 중 · 실패 · 끝)와 임대 기한, 재시도 수, 까닭과 함께 둔다. 연결 실패만 자동 재시도, 4xx 는 「못 보냄 — 까닭 · 고칠 곳 · [다시] [버리기]」. 일꾼 heartbeat 와 「일꾼이 N분째 받지 않는다」 멈춤 줄. 설치가 일꾼 서비스까지 띄우기. 오래된 index.lock 감지. 정리 시각의 시간대를 정하고 마지막 정리를 파일에 남기기.
- **발견.** F-002 · F-023 · F-024 · F-006 · F-007 · F-008 · F-046 · G1-3 · G4-6 · F-043 · F-005 · F-053 · F-090 · G4-7 · F-041

### T5. 쓴 글과 데이터가 사라진다

- **무엇이.** 화면은 그릴 때마다 `#app` 을 통째로 바꾸고 편집기 textarea 를 서버 원문으로 다시 채운다. 쓰던 글을 따로 들고 있지 않다(F-004). POST 401 을 다루지 않아 세션이 끝나면 글이 사라진다(G4-5). 항목 지우기 · 이름 바꾸기는 편집기에서 보이지만 저장은 그것을 모른다(F-035). 장부에 없는 항목을 고치면 「넣을 곳 없는 메모」 가 되어 영영 문서에 들어가지 않는다(F-036, 검증이 Critical 로 올렸다). 편집기 고침 거두기가 기록 · 장부 · 원본이 주인인 문서의 고침을 알리지 않고 되돌린다(F-025). 저장이 10~15초 걸리는데 두 번 누름을 막지 않아 같은 기록이 겹친다(F-034). 갈라짐에서 유일한 단추 「이 백업 이어 쓰기」 는 서버에만 있는 커밋을 확인 없이 치운다(F-017).
- **왜.** 지식 도구에서 쓴 글을 잃는 경험은 한 번이면 충분히 치명적이다. 사용자는 kmd 를 믿지 않고 다른 곳에 먼저 쓰게 된다.
- **방향.** 편집 초안을 상태와 sessionStorage 에 두고 이동 · 닫기 · 새로 고침에서 묻는다. 401 은 그 자리에서 다시 들어가기 창을 띄우고 같은 요청을 다시 보낸다. edit 에 delete · rename 을 더한다. 화면 고침 기록에는 늘 문서 + 머리를 대상으로 적는다. 되돌리기 전에 사본(`.kmd/rescued/`)과 「확인할 것」 줄을 둔다. 공통 busy 패턴과 서버 쪽 같은 본문 중복 막기. 갈라짐에서는 사라질 기록 목록과 세 가지 선택지(다시 얹기 · 서버 유지 · 백업 유지).

### T6. 사람 · 지식 · 백업의 생애 주기를 화면에서 다룰 수 없다

- **무엇이.** 관리 화면의 사람은 이름 한 줄뿐이다. 더하기 · 새 링크 · 관리자 지정 · 기기 끊기는 셸이나 API 로만 한다(F-014). 재인증이 필요한 [풀기] · [링크 만들기] · [백업에서 받기] 는 비밀번호 칸 없이 실패하고, 유일한 재인증 길은 팀 Claude 로그인을 시작해 버린다(F-015). 「떠남」 이 없다(G4-1). 떠난 사람의 개인 지식은 관리자도 셸도 다룰 수 없다(G4-2). 아이디를 되쓰면 옛 사람의 개인 지식 · 일꾼이 붙는다(G4-3). 관리자가 [지식 추가] 를 눌러도 늘 개인 지식이 생기고, 팀 지식은 서버 디스크에 폴더를 놓고 [동기화] 해야만 생긴다(F-016). 「더해 달라」 부탁은 처리해도 사라지지 않는다(F-019). 개인 지식 · PC 새 지식에는 백업을 붙일 길이 없다(F-020 · F-021 · G3-8). 백업 붙이기는 `.git` 이 없는 지식에서 바깥 저장소를 민다(F-022 — 이번 검토 중에도 실제로 일어났다, §10). 운영 문서의 되살리기 연습은 운영 백업을 덮는다(G3-3).
- **왜.** 팀 서비스는 사람이 들어오고 떠나고, 지식이 생기고 넘어가고, 언젠가 복구하는 것을 전제로 한다. 지금은 그 일을 관리자 한 사람의 셸 지식에 기대고, 설명서는 그 셸 명령도 다 알려 주지 않는다.
- **방향.** 관리에 「사람」 카드(더하기 · 링크 복사 · 관리자 켜고 끄기 · 기기 · 일꾼 열쇠 · 떠남)를 두고, 떠남은 세션 · 기기 · 일꾼 열쇠 끊기 · 아이디 예약 · 개인 지식 넘김/보관/지움을 한 번에. 재인증을 공통 모달로. 지식 추가에 「팀 지식 / 내 지식」 고르기와 [주인 넘기기]. 개인 지식 · PC 새 지식에 백업 자리 저절로 붙이기. restore 에 「백업 붙이지 않기」(연습 기본값). 백업 git 호출은 저장소 뿌리가 지식 폴더인지 먼저 본다.

### T7. 상태와 다음 행동이 보이지 않는다

- **무엇이.** 기록한 사람은 자기 기록이 언제 문서에 들어가는지, 「그대로 둔 것」 이 되었는지 모른다(F-052 · F-051). 이력의 「저장」 줄은 문서에 들어간 뒤에도 「정리 때 들어간다」 로 남는다(F-064). 「확인할 것」 을 확인했다고 끝낼 길이 없다(F-049). 파일을 여러 개 넣으면 못 넣은 파일과 까닭이 화면에서 사라진다(F-029). 보낸 것의 결과는 보낸 PC 로 돌아오지 않는다(F-080). 다시 들어오면 늘 지식 목록이고(F-063), 주소가 화면을 기억하지 않아 새로 고침 · 뒤로 가기 · 링크 공유가 안 된다(F-042).
- **왜.** 「입력 → 처리 → 결과 → 다음 행동」 의 결과 단계가 끊겨 있다. kmd 는 기다림(정리 · 들이기 · 보내기)이 많은 제품이라 이 고리가 특히 중요하다.
- **방향.** 내 기록 상태(기다림 · 들어감 · 그대로 둠 · 되돌림)를 한 곳에. 넣기 · 보내기 결과를 묶음 한 줄 + 펼치기로. 재방문 첫 화면을 「확인할 것 · 내 대기 · 지난 뒤 바뀐 것」 으로. 해시 라우팅과 [링크 복사].

### T8. 말 · 정보 구조의 복잡도

- **무엇이.** 「지식 만들기」 와 「지식 추가」 가 같은 뜻 이름인데 하는 일이 다르다(F-032). 정리 · 기록 · 이력 · 받은 것 · 확인할 것이 여러 뜻으로 쓰인다(F-070). 옆 메뉴 「지식 관리」 는 고른 지식에 따라 줄이 바뀌고 지식과 상관없는 전체 일까지 담는다(F-071). 「개인 지식」 이 두 가지(내 PC 지식 · 팀 서버 개인 지식)이고 화면마다 이름이 다르다(F-081). 한 화면 안에서 「지금 지식」 을 두 기준으로 정해, 옆 메뉴는 DPMS 인데 [정리] · 파일 넣기는 받은편지함으로 간다(F-030 · F-031). 안쪽 말(kmd-auto · 기록 번호 · 「검사 … — 00」)과 금지어(원천 · 토큰)가 화면에 남아 있다(F-058 · F-069).
- **왜.** 쉬운 우리말 원칙은 잘 지켜지지만, 새로 지은 말이 많고 같은 말이 여러 뜻을 가져 처음 쓰는 사람이 지도를 그리기 어렵다. 동작이 화면 한국어 글에 묶여 있어(F-101) 말을 바꾸면 기능이 꺼질 수 있다.

### D. 두 화면을 오가는 사람(팀 화면 ↔ 내 PC)

- ✓ 팀 화면에서 내 PC 지식을 그 자리에서 읽고 고치면 PC 파일이 바로 바뀐다. 이력 · 지식 만들기 · 보내기는 「내 PC 프로그램 화면에서 한다 · 팀 서버에는 한 조각도 가지 않는다」 한 장으로 갈래가 분명하다. 지식 고르기의 갈래 수(「팀 2 · 개인 1 · 내 PC 3」)도 좋다.
- ✗ [내 PC 화면 열기] 는 번호 없는 주소라 막다른 길이다(F-001). PC 가 늦으면 팀 화면이 통째로 멈춘다(F-044). PC 를 다시 켜도 새로 고침 전까지 다시 붙지 않는다(F-077). 지식 추가 · 동기화 뒤 내 PC 지식이 사라진다(F-075). 찾기가 내 PC 지식을 찾지 못한다(F-078). 그림 첨부 요청이 팀 서버로 간다(F-079). PC 화면에는 팀으로 가는 링크가 없고 끊겨도 「이어짐」 이다(F-082). Claude Code 에 두 연결(kmd-team · kmd)이 같이 붙는데 어디에 남길지 규칙이 없다(F-085).

## 5. 팀 서비스 / 개인 서비스 관점

### 목적과 구분

| | 팀 서비스(팀 서버) | 개인 서비스(내 PC 프로그램) |
|---|---|---|
| 목적 | 팀이 같이 쓰는 지식을, 기록 → 정리(승인 없이) → 문서로 굳히고 권한으로 지킨다 | 내 지식을 내 PC 에 두고, Claude Code 와 같이 쓰고, 만든 지식만 팀으로 보낸다 |
| 잘 갈린 것 | 역할별 메뉴(일반 팀원에게 정리 · 이 지식의 사람 · 관리 없음) · 서버 쪽 권한 검사 · 개인 지식은 관리자에게도 가려짐 | 팀 화면에서 내 PC 지식 요청은 PC 로만(fail-closed) · 짝 열쇠는 읽기 · 저장만 · 정리 없이 곧바로 문서로 |
| 모자란 것 | 사람 관리 · 떠남 · 팀 지식 세우기 · 주인 넘기기 · 일꾼 상태 | 화면 들어가기 · 백업 자리 고르기 · 되살리기 · 판 바꾸기 · 로그 |
| 넘치는 것 | 정리 방식 셋 · 실시간 정리 · 받은편지함 특수 동작 · 기계 열쇠 · search-check | DB 감시를 모든 설치에 · 그래프 · 명령 창(빨리 열기와 비슷한 팔레트가 셋) |

### 「개인 지식」 이 두 가지다

가장 큰 구조 문제다. 내 PC 지식과 팀 서버의 개인 지식(나만)은 이름이 같은 계열인데 할 수 있는 일이 다르다(F-081).

- **팀 서버 개인 지식에서 막히는 것.** pdf · hwp 넣기, 지켜보며 맞추기(부탁해도 관리자가 볼 수 없어 처리하지 못한다 — F-019), 백업(F-020 · G3-9).
- **정리 일꾼.** 그 사람 PC 의 일꾼에 기대는데, 일꾼 상태를 볼 곳이 없고(F-053), 한 번 받은 뒤로는 하루 뒤 규칙이 걸리지 않는다(G4-6).
- **떠난 사람.** 떠나면 관리자도 다룰 수 없다(G4-2).
- **「나만」 이 깨지는 곳.** T2 의 누출이 대부분 이 갈래에서 난다.

**권고.**
- 팀 서버 개인 지식은 「PC 가 없는 사람을 위한 대안」 으로 범위를 줄인다(읽기 · 쓰기 · 보내기만).
- 지식 추가는 PC 가 이어져 있으면 기본을 내 PC 로 둔다.
- 갈래 이름은 모든 화면에서 「팀 지식 · 내 PC 지식 · 팀 서버의 내 지식」 으로 같게 쓴다.
- 「나만」 의 진실은 한 곳(`_members.md` 와 맞춰진 장부)에 둔다.

### 같은 기능이 서비스마다 다르게 나오는 곳

- **보내기 결과.** 정리됨 · 값 바뀜 · 되돌리기는 팀 화면 이력에만 오고, 보낸 PC 이력에는 오지 않는다(F-080).
- **내 기기 · Claude 연결 · 받은편지함.** 같은 정보가 두 탭 · 두 화면에 다른 능력과 다른 말로 나온다(F-121).
- **찾기.** 팀 화면 찾기는 내 PC 지식을 찾지 못하고, PC 지식 안에서는 「조각」 오류를 낸다(F-078).
- **멈춤 줄 · 안내.** PC 화면에서도 팀 서비스의 말(「관리 › Claude 연결」 · 「관리자가 백업 자리를」)을 쓴다(F-074).
- **넣기 위치.** 받은편지함이 서버마다 생겨 같은 이름이 두 곳에 남는다(F-030).

### 이동과 연계

- **두 화면 사이의 길이 한쪽뿐이다.** 팀 → PC 는 [내 PC 화면 열기] 하나인데 그마저 막다른 길이다(F-001). PC → 팀은 링크가 없다(F-082).
- **권고.** 팀 화면에서 PC 화면을 열 때는 짝 열쇠로 번호를 받아 연다. PC 화면 머리에는 「팀 kmd ↗」 를 둔다. 연결 상태는 실제 응답으로 보인다.

## 6. 제품화 구조 — 지킬 것 · 줄일 것 · 바꿀 것

### 반드시 지킬 핵심

- **쓰는 길 하나.** `core/save.js` — 같은 지식의 저장은 한 줄로 서고, 실패하면 되돌리며, 저장마다 git 묶음이 생긴다. 이력 · 되돌리기 · 백업의 바탕이다.
- **단기 열쇠 설계.** 초안 kmdd_(30분 · 그 일감), 에이전트 kmda_(40분 · 그 지식 MCP 만), 짝 kmdp_(12시간 · 읽기/저장만).
- **팀 서버는 Claude 를 직접 부르지 않는다.** 개인 지식은 주인의 PC 일꾼만 받는다.
- **서버가 정리 초안을 믿지 않는다.** 묶음을 지금 지식에서 다시 만들고, 값 · 이름 대조를 넘은 것만 넣는다.
- **fail-closed 와 기본 보안.** 내 PC 지식 요청은 팀 서버로 가지 않는다. markdown-it `html:false` · CSP · nosniff · no-referrer.
- **MCP 다섯 도구와 스킬 셋.** brief · match · search · section · save 와 kmd-work · kmd-save · kmd-build.
- **멈춤 한 줄(stopline).** 한 모양으로 운영 신호를 모은다. T4 의 상태들을 여기에 올리면 된다.
- **말 규칙과 금지어 시험, 디자인 컨벤션 문서와 부품.**
- **문서 읽기 도구.** 탭 · 미리보기 · 이 문서를 가리키는 것 · 항목 화면.
- **보내기의 기본 흐름.** 변경사항만 고르기 · 받는 쪽 중복 막기.
- **작은 의존성 · 빌드 없음 · 꾸러미에 node 포함.**

### 바꿀 구조

1. **상태 저장소.**
   - 지금: 주인 장부 · 일감 · 보내기 대기 · 부탁 · 마지막 정리가 메모리나 제각각의 JSON 에 흩어져 있다.

2. **진실은 한 곳.**
   - 지금: owners.json 과 `_members.md` 가 서로 어긋난다.
   - 바꿀 것: 켤 때 · 동기화 · 되살리기 · reapply 때 맞춘다. 셸 명령은 도는 서버 API 를 부른다(T2).
3. **서버 모듈.**
   - 바꿀 것: hub 를 지식 · 사람 · 정리 · 넣기 · 보내기 · 백업 도메인 모듈로 나눈다. HTTP 는 라우트 표로 만들고, method 와 권한 검사를 한 곳에 둔다(F-097 · G1-1).
4. **화면 모듈.**
   - 바꿀 것: 화면별 ES 모듈, 해시 라우터, 부분 그리기로 나눈다. 편집 초안은 상태로 따로 둔다. 문구 표를 따로 둔다(F-042 · F-004 · F-101).
5. **설치 · 판.**
   - 바꿀 것: 실행기가 current.json 을 읽게 한다. 팀 서버가 PC 판을 보고 「새 판 있음」 을 알린다. 빌드 출처를 남긴다. 팀 설치에는 일꾼 서비스까지 넣는다(F-038 · F-096 · F-007).
6. **관측성.**
   - 바꿀 것: PC 로그 파일을 남긴다. 오류를 삼키는 곳을 줄인다. 일꾼 heartbeat 를 둔다(F-099).
7. **시험.**
   - 바꿀 것: 시간 주입(TZ · 만료), 두 프로세스(셸 + 서버), 동시성, 규모, 설치/업데이트 실제 흐름을 덮는 시험 칸을 더한다(F-102). 이번 Critical 9건 가운데 다섯이 지금의 시험 칸 밖에서 나왔다.

## 8. 잘 된 점 — 고치면서도 지킬 것

- **들어가기.**
  - 실패는 없는 아이디 · 틀린 비밀번호 · 잠김을 같은 글 · 같은 시간으로 답한다.
  - 비밀번호는 브라우저에서 미리 해시한다.
  - 잠금은 사람+자리마다 · 사람마다 두 겹이다. 전에 들어온 브라우저는 남의 오입력에 막히지 않는다.
  - 처음 들어오기 링크는 한 번 · 24시간이다.
- **권한이 서버에서 지켜진다.** 일반 팀원의 관리 API 는 403 이다. 정리 방식 바꾸기는 「주인이나 관리자만」 이다. 개인 지식은 관리자에게도 403 이다.
- **정리 결과.**
  - 넣은 것 · 값 바뀜 · 그대로 둔 것으로 갈린다.
  - 비교는 줄 단위다.
  - 되돌리기는 그 항목만 정확히 넣기 전으로 돌린다.
  - 값이 바뀌면 쓴 사람의 「확인할 것」 으로 간다.
  - 되돌린 기록은 바로 다시 들어가지 않는다.
- **넣기 · 가져오기.**
  - 같은 파일은 다시 넣지 않는다.
  - pdf · hwp 변환 글은 지문으로 보관한다.
  - 에이전트가 못 넣으면 규칙으로 넘어가 결과가 늘 남는다.
  - git 감시는 묶음마다 「바뀐 값」 기록을 남긴다.
  - 문서 폴더는 바뀐 것만 가져온다.
  - 많이 사라지면 멈춘다.
- **보내기.** 고친 항목만 골라져 있다. 받는 쪽은 지문 태그로 같은 것을 두 번 넣지 않는다.
- **화면 품질.**
  - 세 폭(1300 · 760 · 420px), 팀 11 · PC 8 화면 모두 가로 스크롤 0 이다.
  - 모든 여정에서 자바스크립트 오류 0 이다.
  - 시험 크기에서 첫 로딩은 요청 7개 · 0.7초, 다시 그리기는 11~20ms 다.
  - 한글 입력 중 칸을 다시 그리지 않는다.
  - 같은 화면을 다시 그릴 때 스크롤 위치를 지킨다.
- **빈 상태 · 안내 말.** 「이 말로는 못 찾았다 — 없다는 뜻은 아니다 · 다른 말로 다시 ›」 · 「탭이 둘 있어야 나란히 본다 — Ctrl O 로 하나 더 연다」 처럼 다음 행동을 알려 주는 말이 많다.
- **지식 지우기.** 이름을 다시 쳐야 지워진다. 무엇이 사라지고 무엇이 남는지 목록으로 보인다. 팀 지식은 비밀번호를 한 번 더 묻는다.
- **디자인 컨벤션.** 문서와 CSS 「컨벤션 부품」 이 있어 무엇을 기준으로 고칠지 분명하다. 모달은 Esc · 바깥 · × 로 닫히고, 도는 중이면 닫히지 않는다.

## 10. 검토 중 생긴 일

- **F-022 가 실제로 일어났다.** `scripts/local.mjs` 로 검토 환경을 세울 때, `.git` 이 없는 PC 지식에 백업을 붙이자 git 이 위로 올라가 **이 개발 저장소(C:\project\kmd)** 를 잡았다.
  - `.git/config` 의 `kmd-backup` 원격 주소가 검토용 스크래치 경로로 바뀌었다. 검토 뒤 세션 전 값(`C:\project\kmd\.kmd-data\local\pc-bk\받은편지함.git`)으로 되돌렸다.
  - 이 원격과 `remotes/kmd-backup/main` 은 이번 검토 전, 처음 `scripts/local.mjs` 를 돌렸을 때 같은 버그로 생긴 것으로 보인다. `.kmd-data/local/pc-bk/받은편지함.git` 안에 kmd 소스 커밋이 들어 있다.
  - 필요 없으면 `git remote remove kmd-backup` 으로 지운다.
- **스크래치 자료.** 검토 스크립트 · 스크린샷 · 재현 출력은 `.kmd-data/review/`(무시 목록)에 있다. 발견 목록의 `review/…` 근거 경로가 가리키는 곳이다.
- **저장소.** `main` 의 커밋과 작업 트리는 바뀌지 않았다. 이 문서와 발견 목록 두 파일만 새로 생겼다.
