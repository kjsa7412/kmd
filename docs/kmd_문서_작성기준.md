# kmd 문서 작성 기준 v1.1

지식 문서(`docs/**.md`)를 사람 · 세션 · 정리(Claude) · 가져오기가 만들거나 고칠 때 따르는 기준이다. 프로그램(`core/docformat.js`)이 이 기준으로 읽고 쓰고 검사한다. 템플릿은 [`docs/템플릿/`](템플릿/)에 있다.

## 1. 문서 안 정보는 세 가지다

| 갈래 | 무엇 | 어디에 | 누가 쓰나 |
|---|---|---|---|
| **본문** | 사람이 읽는 확정된 지식: 설명 · 결정 · 절차 · 값 | `# 제목` 아래 요약, `## 항목` 아래 글 | 사람 · 세션 · 정리 |
| **문서 간 연결** | 다른 지식 문서나 항목으로 가는 링크 | 본문 안 | 사람 · 세션 · 정리 |
| **시스템 참고 정보** | 출처 기록 · 넣은 이력 · 상태 · 자동 생성 표식 · 내부 id · 기록 링크 | **문서 끝 참고 블록** 하나, 그리고 아래 「표지」 셋 | kmd 만 |

「아직 문서에 안 넣은 기록」은 **문서에 쓰지 않는다**. 화면이 항목 옆에 「반영 대기 n」 으로 따로 보인다.

## 2. 시스템 참고 영역의 문법

### 2-1. 참고 블록(문서 끝, 하나)

```md
<!-- kmd:참고 · kmd 가 적고 고친다. 손으로 고치지 않는다 -->
**참고**

- 준비
  - 2026-10-21 [배포 창은 화 · 목](../work/2026-1021-배포-창.md)
  - 2026-10-26 [정리](../log/2026-1026-정리.md)
- 롤백
  - 2026-10-22 [롤백 순서](../work/2026-1022-롤백.md)
<!-- /kmd:참고 -->
```

- 문서 맨 끝에 하나만 둔다. 첫 줄은 `<!-- kmd:참고` 로 시작하고 마지막 줄은 `<!-- /kmd:참고 -->` 다.
- 안의 짜임: `- <항목 이름>` 아래 들여 쓴 줄. 줄은 (가) 기록 줄 `- YYYY-MM-DD [기록 제목](../work|log/<id>.md)[ · 한 마디]`: 「이 항목에 무엇이 언제 어느 기록에서 들어왔나」(옛 「경과」): 또는 (나) 메모 줄(옛 경과 줄을 그대로 옮긴 것 · `표 출처: <src> · <asof>` · `표식: <옛 주석 글>`). 문서 전체에 걸린 것은 예약 이름 `- (문서)` 아래에 두고 블록 맨 앞에 쓴다.
- kmd 가 저장할 때마다 블록을 문서 끝에 다시 쓴다. 항목을 지우면 그 줄도, 항목 이름을 바꾸면 줄 이름도 같이 바뀌고, 문서에 없는 항목의 줄은 걷힌다. 사람이 고친 줄은 그대로 읽히므로(따로 둔 원본이 없다) 손으로 고치지 않는다.
- 옛 꼴(항목 끝 `**경과**` 아래 kmd 꼴 줄 `- YYYY-MM-DD [제목](…/work|log/<id>.md)`)은 읽을 때 참고로 받아 주고, 그 항목을 쓸 때 블록으로 옮긴다. 이 꼴이 아닌 줄이 섞인 `**경과**` 목록은 사람이 쓴 본문으로 둔다.
- 화면은 이 블록을 본문에 그리지 않는다. 항목 옆 「출처 n」 칩과 오른쪽 「참고」 칸에 따로 보인다.

### 2-2. 표지(눈에 안 보이는 주석, 정해진 자리에만)

| 표지 | 자리 | 뜻 |
|---|---|---|
| `<!-- applied: <기록 id> -->` | `## 항목` 머리 바로 다음 줄 | 이 항목에 마지막으로 넣은 기록 |
| `<!-- watched: src="…" path="…" rec="…" -->` | 문서 첫 줄(`# 제목` 위) | 원본이 주인인 문서. 옛 문서 폴더 사본에만 남는다: 지금 문서 폴더 가져오기는 파일마다 기록으로 들이고(7절) 이 표지를 새로 달지 않는다. 남은 표지는 저장 · 고치기 · 정리 · 제안이 그대로 지킨다(「내 문서로」 로 걷는다) |
| `<!-- baseline: … -->` 표 `<!-- /baseline -->` | 항목 글 안 | 가져오는 곳이 저절로 채우는 표(표 자체는 본문이다) |

이 넷(참고 블록 + 표지 셋) 밖에 `<!-- -->` 주석 · 기록 링크 · 시스템 표식을 두지 않는다.

## 3. 본문 규칙

1. **확정된 내용만 쓴다.** 아직 반영되지 않은 기록, 검토 중인 초안, 「~ 했다는 기록이 있다」 같은 경위는 쓰지 않는다. 항목은 「대상 하나의 지금」 이다.
2. **본문의 링크는 지식 문서 · 항목 · 바깥 주소만.** 기록 링크(`work/` · `log/`), 내부 경로(`/api/…`, 서버 폴더), 시스템 화면 주소는 본문에 두지 않는다.
3. **머리 짜임**: `# 제목` 하나 → 요약(1~3문장) → `## 항목` 들. 항목 안 소제목은 `###` · `####` 까지.
4. 본문에 `**경과**` 꼬리 · `<!-- -->` 주석(표지 셋 밖) · `#`/`##` 줄을 항목 글로 보내지 않는다(항목 글은 머리 아래 내용만).
5. **옛 글의 값은 기록이 바꾼 것만 바뀐다.** 기록이 「옛 값 → 새 값」 으로 말했거나 초안이 뺀 값으로 적은(`drop`) 값만 글에서 빠진다. 그 밖의 옛 글 값(버전 · 포트 · 이름 · 수)이 빠지면 확정된 사실을 잃은 것이라 넣지 않는다. 기록이 바꾼 값은 더 늦은 기록이 이긴다(쓴 사람에게 「값 바뀜」 으로 알린다). 옛 기록(지금 글에 더 늦은 기록이 이미 든 항목)은 값을 바꾸지 못한다.

## 4. 링크 표기(종류마다 하나)

| 종류 | 쓰는 꼴 | 화면 모양 |
|---|---|---|
| 지식 문서 | `[배포 절차](배포절차.md)` · 다른 폴더면 `[x](../운영/백업.md)` (이 문서에서 본 상대 경로 · `.md` 붙임) | 문서 아이콘 + 강조색 |
| 항목 | `[준비](배포절차.md#준비)` · 같은 문서면 `[준비](#준비)` | 항목 아이콘(#) + 강조색 · 누르면 그 항목으로 |
| 바깥 | `[이름](https://…)` 또는 `<https://…>` | 바깥 아이콘(↗) · 새 창 |
| 기록 · 이력 | 참고 블록 안에서만 `[제목](../work/<id>.md)` | 「출처」 칩 |

없는 문서를 가리키면 화면이 「없는 문서」 로 흐리게 보인다.

## 5. 읽기 쉽게 쓰기

| 무엇 | 기준 |
|---|---|
| 요약 | 제목 바로 아래 1~3문장. 이 문서가 무엇을 다루고 지금 결론이 무엇인지 |
| 항목 | 이름은 대상의 이름(「준비」 · 「rp_mst: 연구과제마스터」). 날짜 · 「수정」 · 「추가」 를 이름에 넣지 않는다(회의록 · 사건 문서만 「YYYY-MM-DD 주제」) |
| 문단 | 한 문단 다섯 줄까지. 한 문단에 한 생각 |
| 목록 | 나란한 것이 셋 이상이면 목록. 순서가 있으면 번호 목록 |
| 표 | 둘 이상의 속성을 견줄 때. 칸은 다섯까지가 좋다 |
| 말 | 「…한다」 체. 같은 것은 같은 이름으로([용어집](kmd_디자인_컨벤션.md#9-말)) |
| 줄표 | 줄표 「—」 를 쓰지 않는다(본문 · 머리 · 기록 · 장부). 풀이 · 설명은 쌍점(「쓰임: DB 는 …」), 문장 끊기는 마침표(「…않는다. 옮기려면 …」), 표의 빈 칸은 「-」 |
| 코드 · 경로 · 이름 | `` `백틱` `` (코드 · 파일 경로 · 테이블 이름 · 값) |
| 되풀이 글 | 같은 출처 · 상태 문장(「아래는 사용자 매뉴얼에서 옮긴 것이다」 · 「운영 DB 에 없다」)을 항목마다 되풀이하지 않는다. 글 출처는 참고 블록 `- (문서)` 의 메모 줄(`글 출처: 사용자 매뉴얼`)에 한 번, 여러 항목에 같은 설명(공통 감사 컬럼 등)은 한 항목에 두고 항목 링크로. 같은 인용 줄이 다섯 번 이상이면 짜임 알림(`repeat-note`) |
| 길이 | 항목 하나 300줄 안. 넘으면 그 안의 대상(요구사항 하나 · 업무 하나 · 시험 케이스 하나)마다 항목으로 나누고 항목마다 이름을 세운다. 문서는 갈래 하나 · 주제 하나면 길어도 한 문서다(화면은 항목 단위로 열고, 문서를 나누면 갈래 · 자리 장부가 갈린다). 한 문서에 주제가 둘 이상 섞였으면 주제별로 나눈다 |

## 6. 문서 종류와 템플릿

| 종류 | 파일 | 쓰는 때 |
|---|---|---|
| 지식 문서(대상 · 정의 · 절차) | [템플릿/지식문서.md](템플릿/지식문서.md) | 시스템 · 테이블 · 절차처럼 「지금」 을 적는 문서 |
| 결정 기록 | [템플릿/결정기록.md](템플릿/결정기록.md) | 「무엇을 왜 그렇게 정했나」. 항목 하나가 결정 하나 |
| 작업 기록(사건 · 회의) | [템플릿/작업기록.md](템플릿/작업기록.md) | 회의록 · 장애 대응 · 작업 일지. 항목 이름이 「YYYY-MM-DD 주제」 |
| 기록(`work/`) | [템플릿/기록.md](템플릿/기록.md) | 세션 · 사람이 남기는 바뀐 것. 머리말(frontmatter)은 kmd 가 쓴다. 세션(MCP save)의 글은 칸(`changes` 바뀐 것 · `why` 까닭 · `dropped` 버린 안 · `impact` 영향 · `refs` 근거 + `body` 한두 문장 요약)으로만 받고 kmd 가 칸마다 머리를 달아 엮는다(`core/guard.js` `recordBody` · 바뀐 것이 없거나 요약이 300자 · 문단 하나를 넘으면 `E_INPUT`) |

**갈래 장부(`_forms.md`)**: 지식마다 「새 문서가 설 수 있는 갈래」 를 적는다. 문서 이름은 파일 이름이 아니라 갈래다(전화통화기록.md → 회의록 문서의 항목).

| 갈래 | 다른 이름 | 폴더 | 종류 | 이름 | 서식 |
|---|---|---|---|---|---|
| 회의록 | 회의, 미팅, 통화, 면담, 전화 | 1.2_사업관리 | 사건 | - | 작업기록 |
| 위험및이슈관리대장 | 이슈, 위험 | 1.2_사업관리 | 대장 | `이슈:*` | 결정기록 |

- 종류: **대상**(「지금」 을 적는 문서) · **서술** · **사건**(항목 머리가 「YYYY-MM-DD 무엇」) · **대장**(항목 하나가 이름 하나 · 머리 「값: 설명」 · 예: `## OPS-001: 결재 알림 오류`). 머리는 값으로 찾는다(`core/sections.js` headingMatches: 「값」 · 「값:」 · 「값 」 으로 시작하는 머리). 옛 꼴 「값 — 설명」 은 읽기만 하고 새로 쓰지 않는다.
- 이름: 그 문서의 항목 이름 패턴. 있으면 새 문서를 세울 때 자리 장부 행(`패턴` → 그 문서의 `## {값}`)을 같이 세운다.
- 서식: 위 표의 템플릿 셋 가운데 하나. 서식의 안내는 본문에 넣지 않는다(3절).
- 장부가 없는 지식은 기본 갈래(회의록 · 장애 대응 · 보고서)만 알고, 그 밖의 새 문서는 이름에 파일 이름 조각(날짜 · 판 · 최종 · 확장자)이 없으면 받는다.
- 갈래 장부는 지식관리자가 save 의 `forms` 로 고친다(편집기로 고친 것은 되돌린다 · 이름 장부와 같다). 쓰기 자리의 `forms` 는 기록에 「세울 갈래」 로 실려 정리 때 지식관리자가 세운다.

## 7. 경로마다 지키는 법

| 경로 | 지키는 법 |
|---|---|
| 저장(세션 · 사람 · MCP save · 화면 고치기) | 항목 글을 검사한다(8절). 어기면 거절하고 어디가 틀렸는지 말한다. 참고 줄은 kmd 가 단다. 지식 생성 가드는 거절형(9절). 세션 기록 글은 기록 서식(6절). 팀 지식에서 세션이 보낸 항목 글은 자리와 상관없이 기록에 실리고 정리가 넣는다 |
| 정리 · 들이기(Claude 초안) | 프롬프트에 이 기준과 예시를 넣는다. 초안을 같은 검사로 거른다. 참고 줄은 kmd 가 단다. 넣은 파일은 통째로 옮기지 않고 대상의 지금으로 요약 · 정리한다(파일 전체 옮기기 `from "*"` 는 kmd 가 거절 · 원문 그대로는 표 · 값 덩이 하나만). 인사말 · 진행 멘트 · 시간 배분 · 묻는 말 · 빈 칸 양식 · 준비 체크 상태는 기록에만 남는다. 회의록은 열린 회의 · 통화의 정한 것 · 할 일만이고, 준비하는 글(스크립트 · 안건 · 준비 TODO)의 확정 사실은 그 주제 문서로. 서식대로 쓴 기록은 바뀐 것 칸의 값만 글에 꼭 옮길 값이다(프롬프트에 「글에 꼭 옮길 값」 으로 적어 주고 초안 검사가 대조한다). 요약 · 영향의 값은 글에 넣어도 되지만 요구하지 않는다: 요약은 바뀐 것을 다시 말하고 「어디에 배포했다」 같은 경위가 섞이며, 영향은 「누가 알아야 하나」 라 그 항목의 지식이 아닐 때가 많다(요구하면 「187 환경에 배포돼 있다」 같은 경위가 지식 글에 들어간다). 까닭 · 버린 안 · 근거의 날짜 · 판 · 커밋은 경위라 옮기지 않는다. 초안이 고칠 수 있는 까닭(빠진 값 · 근거에 없는 값 · 옛 글의 값이 빠짐(3절 5) · 크기 · 머리)으로 걸리면 그 까닭을 붙여 한 번만 다시 쓰게 하고, 그래도 걸리면 넣지 않고 둔다. 긴 항목(다시 쓸 글이 3천 자 넘는 것)은 글 전체를 다시 쓰지 않고 **조각**(바꿀 곳마다 「지금 글에 꼭 한 번 나오는 글 → 바꿀 글」)으로 받는다. kmd 가 조각을 지금 글에 대어 새 글을 만든 뒤 전체 초안과 같은 검사(값 · 크기 · 꼴)를 거친다. 조각이 지금 글에 맞지 않거나 여러 곳에 맞으면 넣지 않고 그 까닭으로 한 번 고쳐 쓰게 한다(찾을 글을 더 길게 잡거나 새 글 전체). 지금 글이 비었거나 절반 넘게 바뀌면 새 글 전체를 받는다. 같은 기록을 세 번 두면 자동 정리에서 빼고 그 지식의 지식관리자에게 「사람이 볼 것」 으로 한 번 알린다(손 정리는 그대로 된다). 코드 울타리(```) 속 글은 값 하나로 세지 않는다 |
| 규칙 정리(Claude 없이) | 기록 글을 본문에 넣되 「기록 그대로」 줄과 기록 링크는 참고 블록으로. 줄표 「 — 」 는 쌍점으로 |
| 제안(세션이 기록과 함께 보낸 바꿀 조각) | 조각은 지금 글에 꼭 한 번 나오는 글을 찾아 바꾼다. 덧붙이지 않고 그 문장을 고쳐 쓴다. 조각을 댄 새 글을 8절 검사와 정리 검사(값 · 크기 · 지문)로 거른다. 넣는 자리 · 때는 권한 모델 7절 |
| 받은 기록 · 가져오기 | 기록으로만 남는다. 문서에는 정리가 넣는다 |
| 표 채우기 | 표지(baseline)만 쓴다 |
| 문서 폴더 가져오기 | 받은 기록 · 가져오기와 같다. 파일마다 기록(반영 대기)으로 들이고 문서에는 정리가 자리를 골라 넣는다. 파일 이름을 문서 이름으로 · 원본의 머리를 항목으로 그대로 쓰지 않는다. 예전 사본 문서(표지 watched)는 고치지 않는다 |

## 8. 저장 때 검사(`E_FORMAT`)

사람 · 세션의 항목 글에 아래가 있으면 받지 않는다(kmd 자신의 쓰기는 고쳐서 넣는다).

| 검사 | 예 |
|---|---|
| 기록 · 이력 링크 | `[x](../work/2026-…md)` |
| 시스템 주소 | `/api/…` · `#/…` · `http://<이 서버>/…` |
| 표지 밖 주석 | `<!-- 메모 -->` |
| 경과 꼬리 · 참고 블록 | `**경과**` 아래 목록 · `<!-- kmd:참고` |
| 머리 줄 | 항목 글 안의 `# ` · `## ` 줄 |

## 9. 지식 생성 가드

지식이 들어오는 **모든 길**이 `core/guard.js` 하나를 거친다. 팀 프로그램과 개인 프로그램이 같은 판정을 쓴다. 판정의 권위는 서버(core)이고, 세션의 스킬 · MCP 설명 · brief 는 미리 알리는 것이다.

| 가드 | 지키는 것 |
|---|---|
| G1 모양 | 이름은 `종류:값`. 새 이름의 종류는 영문 소문자 또는 한글로 시작하는 24자 안 낱말 · 값은 빈칸 · 제어 글자 · `` ` `` · `|` 없는 60자 안 열쇠(문장 금지 · 설명은 보이는 이름에). 이미 장부에 있는 옛 이름(값에 빈칸)은 그대로 둔다 |
| G2 등재 | 기록이 건드린 이름(touches)은 이름 장부에 있거나 같은 묶음 `names` 로 세운 것. 폐기된 이름은 이어 둔 새 이름으로 · 다른 이름(같은 말)은 정본 이름으로 |
| G3 자리 | 이름도 자리(화면의 항목 고침 `at/` · 넣은 파일 `ingest/`)도 없는 기록은 까닭(`touchesEmpty`)이 있어야 한다. 까닭은 기록 머리말에 남고 「이름 없음」 으로 보인다 |
| G4 새 문서 | 갈래 장부(6절)의 갈래 · 폴더 · 머리 꼴로만. 갈래의 다른 이름에 걸리는 새 문서는 그 갈래 문서의 항목으로. 문서 이름에 파일 이름 조각을 쓰지 않는다 |

길은 셋이다.

- **거절형**: 사람 · 세션이 그 자리에서 고칠 수 있는 길. 어기면 `E_INPUT` 으로 받지 않고 까닭 · 가까운 이름을 말한다.
- **붙잡아 두기**: 밖에서 온 것 · kmd 자신의 쓰기. 거절하면 잃으므로 받는다: 폐기 · 같은 말 이름은 바꿔 달고(`fixes`) · 장부 밖 이름은 「장부 밖 이름」 · 이름 없는 기록은 kmd 가 까닭을 달아 「이름 없음」 으로. 정리의 이름 바로잡기와 지식 점검이 이어받는다.
- **검사만**: 파일을 바로 쓰는 길. 쓴 뒤 같은 가드로 보고 어긴 것을 이력 · 지식 점검에 남긴다(글은 그대로).

| 길 | 코드 | 정책 |
|---|---|---|
| 세션 MCP save · 화면 기록 남기기 | server/mcp.js · `POST /api/k/:id/save` → hub.save(`guard: 'strict'`) | 거절형 |
| 화면에서 고치기(쓰기 자리) | hub.edit | 거절형(항목 고침은 `at/` 자리) |
| 화면에서 고치기(지식관리자) · 되돌리기 | hub.edit · hub.revert(system) | 붙잡아 두기(이력) |
| 이름 바로잡기 | hub.setTouches | 거절형(이름 장부의 살아 있는 이름만) |
| 받은편지함 정리 · 옮기기 | hub.inboxTidy · inboxSend | 붙잡아 두기(받기와 같다) |
| 받기(개인 → 팀) | hub.receive → saveRecords | 붙잡아 두기: **받은 쪽 장부로** 다시 맞춘다 · 이름 없는 수를 보낸 쪽에 돌려준다 |
| 보내기(개인) | hub.send · sendPicked · sendPreview | 「보내기 확인」 창이 받는 쪽 장부로 미리 맞춰 본다(`POST /api/k/:id/receive/preview` · 쓰지 않는다) · 보낸 뒤 받은 쪽이 돌려준 「이름 없음」 수를 보내기 기록 · 알림에 보인다 |
| 파일 · 폴더 넣기 | hub.importFiles · ingest* | 붙잡아 두기(기록은 `ingest/` 자리) · 정리 초안의 새 문서는 G4 |
| 가져올 곳(git · DB · 서버 폴더) · 코드 바뀜 | core/sources.js · codechange | 붙잡아 두기 · 세우는 이름은 G1 |
| 정리 일꾼 · 규칙 정리 | hub.putDrafts · placeGroup · core/tidy.js | 초안 검사에서 G4(어기면 초안을 버린다) · 저장은 붙잡아 두기 · 이름 고르기에서 맞는 이름이 없으면 지식관리자의 「오늘 바뀐 것」 에 알린다(지식 점검으로 이어짐) · 프롬프트에 갈래의 머리 꼴 · 짜임 |
| 편집기에서 바로 고친 것 수집 | core/collect.js | 검사만(새 문서 G4 → 이력) · 장부(`_vocab.md` · `_managed.md` · `_forms.md`) 손 고침은 되돌린다 |

**지식 점검**: `kmd guard <지식> [--list]` · 화면(지식관리자) · `GET /api/k/:id/guard` 가 같은 계산(core/guard.js `audit`)을 쓴다: 이름 없는 기록 · 장부 밖 이름을 단 기록 · 폐기된 이름을 단 반영 대기 기록 · 자리 잃은 이름 · 이름 없는 항목 · 다른 이름 겹침(다른 이름이 다른 이름의 값 · 보이는 이름 · 다른 이름과 같다: 고친다) · 같은 보이는 이름(알림: 문서마다 있는 「변경 이력」 처럼 서로 다른 항목) · 깨진 머리 · 값에 빈칸이 든 옛 이름.

새 길을 만들면 이 표에 줄을 더하고 같은 가드를 부른다.

## 10. 옛 문서 옮기기

`kmd docfmt <지식>`(서버: `kmd docfmt --all`)이 옛 꼴을 새 꼴로 옮긴다.

- 항목 끝 `**경과**` 목록 → 참고 블록
- 「`> 기록 그대로: [제목](../work/…) · Claude 로 다듬지 못했다`」 줄 → 참고 블록(「다듬지 못함」 표시)
- 옛 CDP 경과: `**경과**` 아래 목록의 줄마다 날짜로 시작하고 기록 링크(`../work` · `../log`)나 `` `YYYY-MM-DD` `` 백틱 날짜가 있으면 → 줄 그대로 메모. 날짜만 있는 목록(사람이 쓴 장애 · 회의 타임라인)은 본문에 둔다
- `<!-- cdp:baseline … -->` · `<!-- /cdp:baseline -->` 두 줄 → 걷고 `표 출처` 메모(표는 본문에 그대로)
- 그 밖의 표지 밖 주석(`cdp:form` · `gen:` 등) → `표식` 메모: 첫 `##` 위의 것은 `(문서)`, 그 밖은 있던 항목. `gen:`(「이 줄 아래는 다시 쓴다」)만 바로 아래 항목
- 본문 문장 안에 사람이 쓴 출처 링크(`출처 [x.md](../../work/…)`)는 옮기지 않는다(문장의 일부다). 그 항목을 다음에 고칠 때 저장 검사가 「이미 있던 기록 링크」 로 알린다
- 옮기기 앞뒤로 「본문 글(참고 · 표지를 뺀 것)」 이 한 글자도 줄지 않았는지 비교하고, 다르면 그 문서는 옮기지 않는다.
- 옮긴 것은 기록(`log/`, 태그 `docfmt`) 하나로 남는다.
