# kmd 설명서 — 관리자

팀 서버를 세우고 사람 · 백업 · 정리 로그인을 돌본다. 밤 묶음 · 되살리기는 [kmd_운영.md](kmd_운영.md).

## 세우기

```bash
sudo sh kmd-install.sh --team --url http://kmd.team.local --gitlab-group team --gitlab-api https://gitlab.team.local
```

- node 22 · git 이 있어야 한다. `/opt/kmd` 에 깔고 systemd(kmd.service)로 늘 켠다. 지식은 `/srv/kmd/<지식>/`.
- GitLab 열쇠는 숨김 입력으로만 받는다 — **만들기 권한만** 있는 봇 열쇠(지우기 · 보호 해제 없음). 지식마다 저장소를 저절로 만들어 백업 자리로 붙인다.
- 끝에 찍힌 **첫 설정 주소**를 브라우저로 연다 → 관리자 아이디 · 비밀번호 두 칸.
- 팀 꾸러미(`kmd-<판>-team.tgz`) 안의 PC 꾸러미(`kmd-<판>-pc.zip`)를 설치가 받기 자리 `/srv/kmd/.kmd/dl/` 에 둔다. 사람들이 붙여 넣는 설치 한 줄이 kmd 가 없는 Windows PC 에 그것을 받아 깐다(`<팀 주소>/dl` 에서 보인다). 설치 한 줄은 서버와 같은 판의 PC zip 을 먼저, 없으면 가장 높은 판을 준다 — 그래서 새 판은 팀 꾸러미째 올린다(`kmd-install.sh` 를 다시 돌리면 서버도 새 판으로 다시 켜지고 같은 판 PC zip 이 놓인다 · [운영 §5](kmd_운영.md)). 서버를 그대로 두고 PC zip 만 바꾸려면 서버 판의 zip 을 받기 자리에서 치운다. 이미 깐 PC 는 저절로 바뀌지 않는다(각 PC 에서 `kmd pc update`).
- 설치는 셸 명령 `kmd`(`/usr/local/bin/kmd`)도 둔다 — 어느 사용자로 쳐도 kmd 사용자로 · 이 지식 폴더로 돈다.
- 화면 오른쪽 위 「설명서」 는 `<팀 주소>/manual` — 쓰는 사람 · 정리하는 사람 · 관리자 · 운영 설명서를 들어오지 않아도 본다.

## 관리 화면 — 문제 줄만

- **비밀번호를 안 정한 사람** — [링크 만들기] 로 처음 들어오기 링크를 한꺼번에(24시간 · 한 번). 메신저로 사람마다 따로 보낸다.
- **잠김** — 여러 번 틀린 자리는 잠시 막힌다(맞는 사람은 그대로 쓴다). [풀기].
- **관리자에게 부탁** — 사람이 더해 달라는 가져오는 곳. [더하기].
- **자동 정리가 쉬고 있다** — 정리 전용 Claude 로그인이 끝났거나 한도. 아래 Claude 연결에서 다시.
- **백업이 앞섰다 · 갈라졌다** — 어느 쪽이 맞는지 정한다. [백업에서 받기](앞으로만) · [이 백업 이어 쓰기](지금 것은 가지로 남는다).

## Claude 연결 — 정리 전용 로그인

1. 관리 › Claude 연결 › [로그인 시작] → 비밀번호 한 번 더.
2. 팀 서버가 **화면 있는 PC**(Windows · macOS · 화면 있는 Linux)면 그 PC 에 「kmd — Claude 로그인」 창(`claude auth login`)이 뜬다 — 그 창에서 로그인하면 관리 화면이 몇 초마다 저절로 확인한다(번호 붙여 넣기 없음 · [지금 확인]).
3. **화면 없는 서버**(헤드리스 Linux)만 claude.ai · claude.com 로그인 주소가 화면에 나온다 → 그 주소를 열어 받은 번호를 붙여 넣는다(한 번용 · 저장하지 않는다). 오래 가는 열쇠는 서버 비밀에만 있다(화면 · 로그에 없다). 가짜 터미널을 못 다는 서버는 `kmd secret set claude-token`.
4. 「로그인됨 · 정리 전용」 · 시작을 못 하면 쉬운 말 한 줄과 셸 한 줄이 나온다(오류 글 속 주소를 로그인 주소로 보이지 않는다).
5. 정리 일꾼은 서버에서 `kmd worker <팀 주소> --data /srv/kmd/.kmd` 로 띄운다(정리 전용 OS 사용자 · 일꾼 열쇠는 `kmd worker add`).

사내 https 가 생기면 그 뒤에서 하길 권한다.

## 셸 명령

팀 서버에서 그냥 `kmd …` 로 친다 — 설치가 둔 `/usr/local/bin/kmd` 가 kmd 사용자(`sudo -u kmd`)로 · 지식 폴더 `--root /srv/kmd` 를 붙여 돌린다(root 로 바로 `node …/kmd.mjs` 를 돌리지 않는다 — 살림 자리 파일이 root 것이 되어 서버가 읽지 못한다). 정리 일꾼 셋(`kmd worker …`)만은 정리용 OS 사용자로 `node /opt/kmd/server/bin/kmd.mjs worker …` 를 친다. 전체 목록은 `kmd help` — 이 표는 그 가운데 팀 서버의 것이다.

| 명령 | 하는 것 |
|---|---|
| `kmd user` | 사람 목록 — 관리자 · 비밀번호를 정했나 · 기기 수 |
| `kmd user add <아이디> [--admin] [--url <팀 주소>]` | 사람 더하기 — 처음 들어오기 링크를 찍는다(`--url` 을 주면 그 주소로) |
| `kmd user reset <아이디> [--url <팀 주소>]` | 비밀번호 다시 정하기 링크(마지막 관리자가 잊었을 때도) |
| `kmd owner <지식> [사람] [--private \| --team] [--curators 가,나]` | 지식의 주인 · 개인 · 정리하는 사람 — 도는 서버에도 곧 보인다 · 화면에서 감춰진 지식(개인)도 되찾는다 · 개인이면 주인을 함께 정한다 |
| `kmd worker add` | 정리 일꾼 열쇠 만들기(한 번만 보인다) |
| `kmd worker key set <팀 주소>` | 정리용 OS 사용자로 — 그 열쇠를 자격 저장소에(숨김 입력) |
| `kmd worker <팀 주소> --data /srv/kmd/.kmd` | 정리 일꾼 — 늘 돈다(정리용 OS 사용자의 Claude Code 로그인으로) |
| `kmd backup` · `kmd backup add <지식> <주소>` · `kmd backup pull <지식>` | 백업 상태 · 백업 자리 붙이기 · 백업에서 받기(앞으로만) |
| `kmd secret set <이름>` | 비밀 넣기(gitlab · 원천 git 자격 등) — 숨김 입력 |
| `kmd machine add <지식> <원천>` | 바깥 생성기용 기계 열쇠(그 지식 · 그 표만 · 1년) |
| `kmd search-check <지식>` | 찾기 점검 — 얼린 시험지 위에서 나빠진 문항 |
| `kmd restore <백업 주소> [이름]` | 지식 되살리기 |
| `kmd auth reapply <auth.log>` | 옛 명부로 되살린 뒤 늦은 일 다시 적용 |
