# kmd 설명서 — 관리자

팀 서버를 세우고 사람 · 백업 · 정리 로그인을 돌본다. 밤 묶음 · 되살리기는 [kmd_운영.md](kmd_운영.md).

## 세우기

```bash
sudo sh kmd-install.sh --team --url http://kmd.team.local --gitlab-group team --gitlab-api https://gitlab.team.local
```

- node 22 · git 이 있어야 한다. `/opt/kmd` 에 깔고 systemd(kmd.service)로 늘 켠다. 지식은 `/srv/kmd/<지식>/`.
- GitLab 열쇠는 숨김 입력으로만 받는다 — **만들기 권한만** 있는 봇 열쇠(지우기 · 보호 해제 없음). 지식마다 저장소를 저절로 만들어 백업 자리로 붙인다.
- 끝에 찍힌 **첫 설정 주소**를 브라우저로 연다 → 관리자 아이디 · 비밀번호 두 칸.
- 팀 꾸러미(`kmd-<판>-team.tgz`) 안의 PC 꾸러미(`kmd-<판>-pc.zip`)를 설치가 받기 자리 `/srv/kmd/.kmd/dl/` 에 둔다. 사람들이 붙여 넣는 설치 한 줄이 kmd 가 없는 Windows PC 에 그것을 받아 깐다(`<팀 주소>/dl` 에서 보인다). 설치 한 줄은 서버와 같은 판의 PC zip 을 먼저, 없으면 가장 높은 판을 준다 — 그래서 새 판은 팀 꾸러미째 올린다(`kmd-install.sh` 를 다시 돌리면 서버도 새 판으로 다시 켜지고 같은 판 PC zip 이 놓인다 · [운영 §5](kmd_운영.md)). 서버를 그대로 두고 PC zip 만 바꾸려면 서버 판의 zip 을 받기 자리에서 치운다. 이미 깐 PC 는 저절로 바뀌지 않는다(각 PC 에서 `kmd pc update`).
- 설치는 셸 명령 `kmd`(`/usr/local/bin/kmd`)도 둔다 — 어느 사용자로 쳐도 kmd 사용자로 · 이 지식 폴더로 돈다.
- 화면 오른쪽 위 「설명서」 는 `<팀 주소>/manual` — 쓰는 사람 · 정리하는 사람 · 관리자 · 운영 설명서를 들어오지 않아도 본다.

## 관리 화면 — 문제 줄만

- **비밀번호를 안 정한 사람** — 아래 사람 카드에서 그 사람의 ⋯ › [새 링크](이 사람만 · 24시간 · 한 번). 메신저로 그 사람에게만 보낸다. 떠난 사람이면 ⋯ › [떠남].
- **잠김** — 여러 번 틀린 자리는 잠시 막힌다(맞는 사람은 그대로 쓴다). [풀기].
- **관리자에게 부탁** — 사람이 더해 달라는 가져오는 곳(같은 부탁은 한 줄로 합친다 · 개인 지식에는 받지 않는다). [더하기] 하면 닫히고 · [거절] 은 까닭과 함께 — 어느 쪽이든 부탁한 사람의 이력에 남는다.
- 비밀번호를 한 번 더 넣어야 하는 일([풀기] · 새 링크 · 사람 더하기 · 떠남 · 백업 맞추기 · 주인 넘기기 · 팀 지식 지우기)은 그 자리에서 비밀번호 칸이 뜨고, 맞으면 하던 일을 이어서 한다(15분).

## 사람

관리 › 사람 카드. 사람마다 상태(들어온다 · 링크 보냄 · 비밀번호를 안 정함) · 기기 · PC 일꾼 · 주인인 지식 · 정리하는 지식의 수.

- **사람 더하기** — 아이디(영문 · 숫자 · . _ -) · 관리자 여부 → 처음 들어오기 링크가 나온다 → 그 사람에게만 보낸다.
- ⋯ **새 링크** — 비밀번호를 잊은 사람. 지금 비밀번호 · 들어온 곳 · 그 사람의 PC 일꾼 열쇠는 끊긴다(기기 열쇠는 그대로 — 끊으려면 기기 모두 끊기).
- ⋯ **관리자로 · 관리자 아님으로** — 마지막 관리자는 내리지 못한다.
- ⋯ **기기 모두 끊기** — Claude Code · 내 PC 프로그램 · 그 기기로 받은 PC 일꾼이 함께 끊긴다(잃어버린 노트북).

### 사람이 떠날 때

⋯ **떠남** 한 번이 다 한다 — 들어가기 · 기기 · PC 일꾼 · 예전 열쇠를 끊고, 그 사람을 정리하는 사람에서 빼고, 아이디는 남겨 둔다(같은 아이디로 새 사람을 더하지 못한다 · 새 링크도 막는다 — 성이 같은 새 사람은 `lee2` 처럼 다른 아이디로).

그 사람이 주인인 지식은 고른다 —

- **내가 주인을 잇는다** — 개인 지식은 이제 나만 본다.
- **주인 칸을 비운다** — 팀 지식은 주인 없이 팀 모두 · 개인 지식은 **관리자만** 본다. 그 지식을 열어 이 지식의 사람 › 주인 · 갈래에서 넘기거나(인수인계) 지운다.

셸로는 `kmd user off <아이디> [--to <받을 사람>]`.

## 지식 — 팀 지식 세우기 · 주인 넘기기

- 새 지식에서 **내 PC / 팀 지식 / 팀 서버 · 나만** 을 고른다. 팀 서버에 지식을 세우는 것은 관리자만 한다 — 사람들의 내 지식은 각자의 내 PC 프로그램 지식 폴더에 선다(팀 화면의 새 지식 › 내 PC · 폴더 경로도). 팀 지식은 이름 그대로 서고 팀 모두 읽고 기록한다 — 주인은 만든 관리자.
- 이 지식의 사람 › **주인 · 갈래**(관리자만) — 주인 넘기기 · 「팀 지식으로 내놓기」 · 「개인으로 돌리기」. 비밀번호 한 번 더.
- 팀 지식 지우기는 주인이어도 비밀번호 한 번 더(보관하지 않고 완전히 지운다 — 되살리기는 백업에서).
- **자동 정리가 쉬고 있다** — 정리 전용 Claude 로그인이 끝났거나 한도. 아래 Claude 연결에서 다시.
- **백업이 앞섰다 · 갈라졌다** — 어느 쪽이 맞는지 정한다. [백업에서 받기](앞으로만) · [이 백업 이어 쓰기](누르기 전에 빠질 기록을 보인다 · 지금 것은 가지로 남고 쓴 사람에게 알린다) · [서버 것으로 백업 덮기](갈라졌을 때).

## Claude 연결 — 정리 전용 로그인

1. 관리 › Claude 연결 › [로그인 시작] → 비밀번호 한 번 더.
2. 팀 서버가 **화면 있는 PC**(Windows · macOS · 화면 있는 Linux)면 그 PC 에 「kmd — Claude 로그인」 창(`claude auth login`)이 뜬다 — 그 창에서 로그인하면 관리 화면이 몇 초마다 저절로 확인한다(번호 붙여 넣기 없음 · [지금 확인]).
3. **화면 없는 서버**(헤드리스 Linux)만 claude.ai · claude.com 로그인 주소가 화면에 나온다 → 그 주소를 열어 받은 번호를 붙여 넣는다(한 번용 · 저장하지 않는다). 오래 가는 열쇠는 서버 비밀에만 있다(화면 · 로그에 없다). 가짜 터미널을 못 다는 서버는 `kmd secret set claude-token`.
4. 「로그인됨 · 정리 전용」 · 시작을 못 하면 쉬운 말 한 줄과 셸 한 줄이 나온다(오류 글 속 주소를 로그인 주소로 보이지 않는다).
5. 정리 일꾼은 설치가 함께 늘 켠다(`kmd-worker.service` · 열쇠는 root 만 읽는 `/etc/kmd/worker.env`). 서버에 `claude`(Claude Code)가 깔려 있어야 한다. 손으로 띄우려면 `kmd worker <팀 주소> --data /srv/kmd/.kmd`(일꾼 열쇠는 `kmd worker add`).
6. 일꾼이 10분 넘게 일감을 받지 않으면 관리 화면 · 띠에 「정리 일꾼이 일감을 받지 않는다 · 기다리는 정리 n」. 일꾼이 쉬는 동안(로그인 끝 · 한도)과 「자동 정리에 Claude 쓰지 않는」 지식은 서버가 규칙으로 넣는다(기록 글을 그 항목 끝에 붙인다). 맡은 일감은 40분 안에 끝나지 않으면 다시 기다림으로 — 세 번이면 「정리하지 못했다 — 까닭」.

사내 https 가 생기면 그 뒤에서 하길 권한다.

## 백업 자리

- 팀 지식 — GitLab 봇(`serve.json` 의 `gitlab`)이 저절로 붙이거나 `kmd backup add <지식> <주소>`(`backupRoots` 안의 폴더 · https · ssh).
- **개인 지식** — 관리자는 그 지식을 보지 못하므로 손으로 붙이지 않는다. `serve.json` 에 `"privateBackup": "<backupRoots 안의 폴더>"` 를 두면 주인마다 `<그 폴더>/<주인>/<지식>.git` 에 저절로 붙는다(새 개인 지식 · 켤 때 붙지 않은 것). GitLab 봇은 개인 지식을 팀 그룹에 두지 않는다 — 두려면 `gitlab.privateGroup`(그룹 사람만 읽는 곳)을 따로 정한다. 관리 화면은 「백업 없는 개인 지식 n」 을 수로만 보인다.
- `kmd backup` 은 개인 지식을 포함해 지식마다 상태를 찍는다(하나가 막혀도 나머지를 찍는다).

## 셸 명령

팀 서버에서 그냥 `kmd …` 로 친다 — 설치가 둔 `/usr/local/bin/kmd` 가 kmd 사용자(`sudo -u kmd`)로 · 지식 폴더 `--root /srv/kmd` 를 붙여 돌린다(root 로 바로 `node …/kmd.mjs` 를 돌리지 않는다 — 살림 자리 파일이 root 것이 되어 서버가 읽지 못한다). 정리 일꾼 셋(`kmd worker …`)만은 정리용 OS 사용자로 `node /opt/kmd/server/bin/kmd.mjs worker …` 를 친다. 전체 목록은 `kmd help` — 이 표는 그 가운데 팀 서버의 것이다.

| 명령 | 하는 것 |
|---|---|
| `kmd user` | 사람 목록 — 관리자 · 비밀번호를 정했나 · 기기 · PC 일꾼 수 · 떠남 |
| `kmd user add <아이디> [--admin] [--url <팀 주소>]` | 사람 더하기 — 처음 들어오기 링크를 찍는다(`--url` 을 주면 그 주소로) |
| `kmd user reset <아이디> [--url <팀 주소>]` | 비밀번호 다시 정하기 링크(마지막 관리자가 잊었을 때도) · 그 사람의 PC 일꾼 열쇠는 걷는다 |
| `kmd user off <아이디> [--to <받을 사람>]` | 떠남 — 들어가기 · 기기 · PC 일꾼을 끊고 아이디를 남긴다 · 주인인 지식은 받을 사람에게, 없으면 주인 칸을 비운다(개인 지식은 관리자만) |
| `kmd owner <지식> [사람] [--private \| --team] [--curators 가,나]` | 지식의 주인 · 개인 · 정리하는 사람 — 도는 서버에도 곧 보인다 · 화면에서 감춰진 지식(개인)도 되찾는다 · 개인이면 주인을 함께 정한다 |
| `kmd worker add` | 정리 일꾼 열쇠 만들기(한 번만 보인다) |
| `kmd worker key set <팀 주소>` | 정리용 OS 사용자로 — 그 열쇠를 자격 저장소에(숨김 입력) |
| `kmd worker <팀 주소> --data /srv/kmd/.kmd` | 정리 일꾼 — 늘 돈다(정리용 OS 사용자의 Claude Code 로그인으로) |
| `kmd backup` · `kmd backup add <지식> <주소>` · `kmd backup pull <지식>` | 백업 상태 · 백업 자리 붙이기 · 백업에서 받기(앞으로만) |
| `kmd secret set <이름>` | 비밀 넣기(gitlab · 원천 git 자격 등) — 숨김 입력 |
| `kmd machine add <지식> <원천>` | 바깥 생성기용 기계 열쇠(그 지식 · 그 표만 · 1년) |
| `kmd search-check <지식>` | 찾기 점검 — 얼린 시험지 위에서 나빠진 문항 |
| `kmd restore <백업 주소> [이름] [--practice \| --attach]` | 지식 되살리기 — 원래 이름이면 같은 백업으로 이어 보낸다 · 다른 이름 · `--practice` 는 읽기만 사본 |
| `kmd auth reapply <auth.log>` | 옛 명부로 되살린 뒤 늦은 일 다시 적용 |
