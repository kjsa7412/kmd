1전체 구조

왼쪽은 사용자 PC, 오른쪽은 팀 서버, 아래는 kmd 가 읽기만 하는 원천이다. 두 곳 모두 같은 순서로 일한다. 들이는 곳에서 기록이 되고, 정리를 거쳐 문서가 된다. 두 곳을 잇는 선은 셋이다. 세션의 MCP(kmd-team), 브라우저의 팀 화면, 지식 보내기.

① 세션② 이 PC kmd 의 Claude③ 팀 정리 일꾼의 Claude 기록문서사람이 많아지면 느려지는 곳(7절)

2Claude 를 쓰는 곳 셋

Claude 를 부르는 일은 모두 이 셋 중 하나다. 팀 서버 프로세스(kmd serve)는 Claude 를 직접 부르지 않고 로그인도 읽지 않는다. ①과 ②는 같은 사용자 로그인을 쓰고, ③만 팀 자원을 쓴다.

3들이는 곳마다 거치는 길

한 줄이 들이는 곳 하나다. 칸은 거치는 단계이고, 칸 안의 색이 그 단계를 누가 하는지 나타낸다. 점선 칸은 그 단계를 거치지 않는다는 뜻이다. 칸에 둘이 있으면 위가 개인, 아래가 팀이다.

① 세션② 이 PC kmd③ 팀 정리 일꾼kmd 규칙 · 사람기록이 생기는 자리

DB 테이블 정의만 기록을 거치지 않는 예외다. 옛 폴더로 새 지식을 세울 때는 기록을 남긴 뒤 글을 그대로 문서로 쓴다. 나머지는 모두 「기록 → 문서」 순서다.

4기록 하나의 상태

정리는 「기다림」과 「자리 없음」 기록만 집는다. 검사를 넘지 못한 기록은 기다림으로 남아 다음 정리 때 다시 쓴다.

5팀: 기록이 문서가 되기까지

팀 서버는 일감을 세우고 검사 · 넣기만 한다. Claude 를 부르는 것은 서버 밖의 정리 일꾼(③)이다. 일꾼은 초안만 올린다.

6이 PC: 기록이 남는 즉시

개인 지식에는 따로 정리 일감이 없다. 기록이 남으면 뒤에서 ②가 바로 다듬어 넣고, 안 되면 규칙으로 넣는다. 검사는 팀과 같다.

7넣은 파일 한 개가 들어가는 길

파일 넣기와 문서 폴더가 같이 쓰는 길이다. 일 줄의 네 단계와 같다. 개인과 팀은 Claude 를 쓰는 칸이 다르다.

파일 글은 kmd 가 원문 그대로 옮긴다. 모델은 자리와 잇는 말, 바뀐 값만 쓴다(excerpt). 파일 이름으로 문서를 세우지 않는다.

8사람이 많아지면 느려지는 곳

1절과 5절 그림의 빨간 번호와 같다. 1번부터 차례로 손볼 만하다.

1실시간 정리가 시작되지 않는다

저장마다 5분 타이머를 처음부터 다시 건다. 기록이 계속 들어오면 정리가 시작되지 않는다. 「최대 대기」를 더하면 풀린다.

server/hub.js liveSoon

2일감이 지식 하나 전체다

도는 동안 들어온 기록은 상관없는 문서의 것이라도 기다린다. 큰 지식 하나가 일꾼을 붙잡는다.

server/hub.js tidyNow · workerNext

3호출마다 드는 고정 비용

claude -p 를 부를 때마다 프로세스를 새로 띄우고 같은 규칙 프롬프트를 다시 보낸다.

core/claude.js runClaude

지식을 읽을 때마다 모든 파일을 stat 하고 기록 상태를 다시 판정한다. work/ 는 계속 늘어난다.
