# kmd 감시 — 문서 · 소스 · DB 의 바뀐 것만 지식에 (검토 v0.1)

2026-10-23 · 운영자 제안을 검토한 것. 아직 짓지 않았다 — 「정할 것」 넷이 정해지면 단계 1 부터.

## 0. 제안

> 지정한 곳(폴더 · 저장소 · DB)을 계속 지켜보다가 바뀐 것을 저절로 알아채 지식에 반영한다. 대상은 **문서 · 소스 · 데이터베이스** 로 가른다. **변경을 감지하는 것**과 **바뀐 부분만 보는 것**이 핵심이다. 전체를 한 번에 다시 맞추는 기능도 있으면 좋다(오래 걸리더라도).

**결론** — 방향이 맞고, 지금의 「자동으로 가져오는 곳」(E6)을 이 그림으로 키우는 것이 자연스럽다. 다만 지금 코드는 「**바뀌었나**」 는 알아도 「**무엇이 바뀌었나**」 는 모른다. 핵심인 증분 처리에는 감시 엔진을 새로 세워야 하고, 전체 다시 맞추기는 그 엔진 위에서 거의 공짜로 생긴다.

## 1. 지금 코드(출발점)

| | 변경 감지 | 처리 | 쓰기 | 자리 |
|---|---|---|---|---|
| 지식 자신의 문서(편집기 거두기) | 실시간 감시 · 30초 조용하면 | 바뀐 파일만 | 바뀐 항목만 | `core/collect.js` |
| 소스 — 폴더 | 정한 때마다 폴더 전체를 훑어 경로 · 크기 · 시각 지문 하나 → 「뭔가 바뀌었나」 만 | **바뀌면 전부 다시 읽고 전부 다시 계산** | 바뀐 표만 | `core/sources.js` `readFolder` |
| 소스 — git | 정한 때마다 `fetch --depth=1` → 커밋이 같은가만 | **전부 다시 읽음** | 바뀐 표만 | `core/sources.js` `readSource` |
| DB | 없음(S10 계정 대기) — 지금은 연결 정보 저장 · [연결 확인] 만 | — | — | — |

이미 있는 것 — 지식에 쓰는 쪽은 바뀐 항목만 쓴다(같으면 묶음 0) · 한꺼번에 크게 바뀌면 멈춘다(새것 10 초과 · 사라짐 10% 초과) · 「원천에 없다」 표시 · 멈춤 한 줄.
없는 것 — **어느 파일 · 어느 테이블이 바뀌었나를 아는 장부**, 그리고 **바뀐 것만 다시 처리하는 길**.

## 2. 구조 — 공통 감시 엔진 하나 + 유형 셋

```
감시 대상 ──▶ ① 변경 감지 ──────▶ ② 바뀐 것 목록 ──▶ ③ 유형별 처리 ──▶ ④ 지식에 쓰기
(문서·소스·DB)  (이벤트 + 주기 훑기)   (더함·고침·사라짐)   (그 항목만)         (바뀐 항목만 · 브레이크 · 되돌리기)
                       ▲
             지문 장부 — 항목마다 지문(파일 = 크기 · 시각 · 내용 해시 / 테이블 = 컬럼 해시)
```

- **지문 장부가 핵심이다.** 지난번에 본 것을 항목 단위로 기억하고(`<data>/watch/<지식>/<감시 이름>.json`), 이번에 본 것과 견줘 「더함 · 고침 · 사라짐」 목록을 낸다.
- **감지는 두 겹** — 실시간 신호(폴더 감시 · git 푸시 알림)로 빨리 반응하고, 놓쳐도 주기 훑기가 잡는다. 신호가 안 오는 곳(네트워크 드라이브)도 주기 훑기로 덮인다.
- **전체 다시 맞추기** = 지문 장부를 비우고 같은 길을 한 번 도는 것. 쓰는 쪽이 「다른 것만 쓴다」 라서 전체를 돌려도 실제로 바뀌는 것은 다른 부분뿐이다. 오래 걸리므로
  - 뒤에서 일감으로 돌고 진행률(「312 / 1,200 파일」)을 보인다
  - 끊겨도 이어서 한다(어디까지 했나를 장부에)
  - 밤 시간에 돌리게 할 수 있다

## 3. 유형별

### 3.1 문서(폴더 안의 md · docx · pptx · xlsx · hwpx · pdf · 그림)

- **감지** — 폴더 실시간 감시 + 주기 훑기. 파일 지문은 크기 → 시각 → 내용 해시 순으로 비교해 내용이 다른 것만 「고침」.
- **처리** — 바뀐 파일만 다시 문서로 바꿔 지식 안의 같은 자리 문서를 갈아 끼운다(지금의 「파일 넣기」 를 계속 도는 판으로).
- 원본은 건드리지 않고 지식 폴더 안에 사본을 둔다 — 앞선 결정 「지식은 지식 폴더 안에만」 과 맞다.
- **정할 것 ①** — kmd 에서 고쳐도 되나 → 권장 **「원본이 주인」**: 감시로 들어온 문서는 화면에서 읽기만(저절로 채우는 표처럼) · 덧붙일 말은 기록으로.
- **정할 것 ②** — 원본에서 지운 파일 → 권장 **바로 지우지 않고 「원본에 없다」 표시**(많이 사라지면 브레이크).

### 3.2 소스(코드 폴더 · git)

- **감지**
  - 폴더 — 3.1 과 같다.
  - git — 지난 커밋과 새 커밋을 견줘(`git diff --name-status 옛..새`) 바뀐 파일 목록을 바로 얻는다. 전체를 다시 읽지 않는다.
  - 선택 — GitLab 푸시 알림(웹훅)을 받으면 정한 시각을 기다리지 않고 바로.
- **처리는 두 층**
  - **(가) 규칙 표 — 결정적 · 쌈.** 바뀐 파일이 닿는 규칙 · 표만 다시(예: `package.json` 이 바뀔 때만 라이브러리 버전 표). 지금의 세 규칙(꾸러미 판 · 표 파일 · 파일 목록)은 이 층의 예시다 — 같이 정리할 것: 「파일 목록」 은 걷고, 「표 파일」 은 사람이 고른 파일 · 폴더만, 「꾸러미 판」 은 「라이브러리 버전」 으로.
  - **(나) 뜻 갱신 — 값짐 · 비쌈.** 바뀐 소스 파일마다 「코드가 바뀌었다 — RetryPolicy.java (+12 −3)」 기록을 남기고, 이어진 항목 이름을 달아 정리 일꾼(Claude)이 관련 항목 글을 고친다. 이미 있는 정리 검사(숫자 · 이름 대조 · 값 바뀜 노랑 · 줄마다 되돌리기)를 그대로 탄다.
- 진짜 「지식 갱신」 은 (나) 층이다.
- **정할 것 ③** — (나) 를 할지 → 권장 **단계 4 · 지식마다 켬/끔** · 「Claude 에 보내지 않음」 지식은 제외.

### 3.3 DB

- **감지** — 카탈로그(테이블 · 컬럼 · 키)를 짧은 질의 한 번으로 읽어 **테이블마다 지문**. 244 개 테이블도 질의 한 번이라 자주 봐도 부담이 없다. DB 쪽 변경 알림 장치(이벤트 트리거)는 높은 권한이 필요해 읽기 전용 원칙과 맞지 않아 쓰지 않는다.
- **처리** — 지문이 바뀐 테이블의 정의 표만 갈아 끼운다 · 새 테이블은 새 항목 · 사라진 테이블은 「DB 에 없다」.
- **데이터(행)** — 코드그룹처럼 관리자가 고른 작은 표만 행 해시로. 큰 표는 다루지 않는다.
- **선결** — S10 읽기 전용 계정(권한 카탈로그로 읽기 전용 확인 — v0.6 §5).

## 4. 공통으로 지킬 것

- **쓰기** — 작성자 kmd · 한 번 돌 때 한 묶음 · 그 묶음째 되돌리기 · 「오늘 바뀐 것」 에 「dpms-api 에서 바뀐 것 3」.
- **브레이크** — 지금 규칙(새것 10 초과 · 사라짐 10% 초과 → 쓰지 않고 멈춤 · 관리자 [그대로 반영])을 세 유형 모두에.
- **자격** — git 토큰 · DB 비밀번호는 팀 화면으로 받지 않는다(셸 `kmd secret set`) · PC 화면만 받는다(v0.6 정정 ③).
- **팀 지식이 PC 폴더를 감시하는 경우** — 팀 서버는 PC 폴더를 볼 수 없다. 내 PC 프로그램이 감시하고 바뀐 것만 기계 열쇠로 팀에 보내야 한다(길은 이미 있다 — `POST /api/k/<지식>/baseline`).
  - **정할 것 ④** — 이 경우를 허용할지 → 권장 **단계 2 · 관리자가 허락한 것만**.
- **화면** — 자료 가져오기 ② 를 **문서 · 소스 · DB** 셋으로 정리 · 줄마다 감시 방식(실시간 · 주기) · 마지막 변화 · 바뀐 것 n · [지금 확인] · [전체 다시 맞추기](진행률).
