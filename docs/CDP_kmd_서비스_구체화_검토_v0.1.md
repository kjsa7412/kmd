## 0. 한 줄

**내 PC 에서 md 를 그대로 내 지식으로 쓰고 고친다. 원본이 바뀌면 맞추고, 골라서 프로젝트로 보내고, 프로젝트가 바뀌면 받는다. 내가 보내거나 켜기 전에는 아무것도 이 PC 밖으로 나가지 않는다.**

kmd 는 새 엔진이 아니다. CDP 는 이미 「한 사람의 서버」(개인 서버)와 「팀의 서버」 를 같은 코드로 갖고 있다. kmd 는 그 둘을 **개인 kmd · 프로젝트 kmd** 로 이름 붙이고, 그 사이에 빈 길 넷을 놓는다.

| 빈 길 | 지금 |
|---|---|
| 내 md 를 **그대로** 지식으로 · 화면과 편집기로 고치기 | 들이면 작업 기록만 된다 · 화면에 편집기가 없다 · 손으로 고치면 save 가 막힌다 |
| 원본 파일 · 폴더와 다시 맞추기 | 기록으로 들인 것만 「이전 판」 새 기록이 된다 |
| 개인 ↔ 프로젝트 보내기 · 받기 | 길이 없고, 한 PC 에 토큰 · 서버가 하나씩뿐이라 둘이 같이 살지 못한다 |
| 개인 서버 하나에 레포 여럿 · Windows 에서 늘 떠 있기 | 레포마다 서버 하나 · Windows 는 터미널을 닫으면 죽는다 |

**권장안의 뼈대**

- **엔진 · 레포 · 판 줄은 하나다.** 개인 kmd 는 개인 서버를 「레포 폴더」 로 넓힌 것이고, 프로젝트 kmd 는 팀 서버 그대로다. 이름을 어디까지 kmd 로 바꿀지는 운영자가 정한다(Q0).
- **일반 md 가 1급이다.** 개인 kmd 는 md 를 바이트 그대로 관리 문서로 들인다(등록부 밖 문서). 좌표는 사람이 고른 문서에만 단다.
- **고치기 · 거두기 · 맞추기 · 보내기 · 받기는 모두 save 입력이다.** save 한 번이 커밋 하나다(I2). 불변조건 I1~I13 은 하나도 풀지 않는다. 다만 이미 닫은 결정 셋(G5 · S8 · S13)을 개인 범위에서 이름 붙여 연다(부록 A).
- **개인 → 프로젝트로 가는 것은 언제나 작업 기록이다.** 관리 문서는 「제안」 으로 싸서 프로젝트 대기열에 세우고, 프로젝트 큐레이터가 반영한다(I6).
- **판 순서는 사용자 가치 순서다.** 먼저 kmd 와 상관없는 지금 CDP 의 결함을 v1.9.1 고침판으로 막는다(§12.0 — writer 가 큐레이터 판정을 위조할 수 있는 P0 가 하나 새로 나왔다). 그다음 ① 내 kmd 가 뜬다 → ② md 가 곧 지식 → ③ 원본과 맞추기 → ④ 프로젝트와 맞추기 → ⑤ kmd 이름 · 설치 프로그램 순이다.

## 1. 운영자의 말

> cdp를 베이스로 kmd 서비스를 만드려고 한다. 아래와 같이 아이디어 수준의 안을 제공한다. kmd 서비스에 대해 구체화해봐
>
> knowledge md (kmd)
> - md를 기반으로 지식문서를 구축하고 공유하는 서비스
>
> - md를 지식문서로 만든다.
> - 개인별로 지식문서를 만들 수 있다. 해당 작업내용은 오프라인으로 전파되지 않는다. (로컬 서비스 실행용 프로그램 제공)
> - 프로젝트 지식문서를 세울 수 있다. 기존 서버형 cdp와 마찬가지
> - 개인별로 관리하고 있는 지식문서에서 관리문서 또는 작업문서를 프로젝트로 보내고 프로젝트에서는 받은 내용은 큐레이션 진행
> - 지식문서 세울 때 다양한 방법으로 세운다.
>     - 세션
>     - 단일문서
>     - 폴더
> - 지식문서를 업데이트를 다양한 방법으로 한다. (싱크 맞추기)
>     - 기존 단일문서
>     - 기존 폴더
> - 개인 지식관리를 개인 깃으로 등록 하게 할 수도 있게 옵션 제공
>
> \* 개인 지식은 에디팅이 가능하게하고 관리문서 싱크를 맞출 수 있는 기능을 제공

## 2. kmd 가 무엇인가

### 2.1 두 자리

| | 개인 kmd | 프로젝트 kmd |
|---|---|---|
| 무엇 | 내 PC 에서만 도는 kmd. 사용자는 나 하나이고, 내가 모든 레포의 큐레이터다 | 팀이 같이 쓰는 kmd. 받은 것을 큐레이터가 반영한다 |
| CDP 에서 | 개인 서버(`ctx up` · `ctx serve --personal`)를 레포 하나에서 **레포 폴더**로 넓힌 것 | 팀 서버(`ctx serve`) 그대로 |
| 하는 일 | md 를 들인다 · 고친다 · 원본과 맞춘다 · 골라서 보낸다 · 프로젝트 정본을 받는다 | 받은 것을 큐레이션 · 정본을 낸다 · 사람 · 권한 |
| 글을 쓰는 사람 | 나(주인 = admin = 큐레이터 · `auth.js:59-61`) | writer 는 기록, 큐레이터는 관리 문서(I6) |

### 2.2 CDP 와의 관계

| | 결정 | 까닭 |
|---|---|---|
| 엔진 | CDP 그대로 — `core/` · save · 큐레이션 · HTTP MCP · 화면 번들. 불변조건 정본(시스템 설계서 §1)과 말의 정본(용어.md)도 그대로 | 개인 서버가 「같은 코드 · 같은 save · 같은 화면」(시스템 설계서 §7.7 · `ctx-mcp-serve.mjs:519-531`)이라는 것이 kmd 의 바탕 보증이다 |
| 레포 | 이 레포 하나. 포크하지 않는다 | 코드 두 벌은 V1 이 걷은 사고다(쓰는 길 둘 · 로컬 뷰어 ≈2,170줄 · 하네스 111) |
| 판 | 한 줄. kmd 단계는 v1.10 부터 쌓고, 판 번호를 어떻게 묶을지(단계마다 · 몇 단계를 한 판으로)는 사람이 태그 때 정한다 | v1.6~v1.9 네 단계를 v1.9.0 한 판으로 낸 관례(`CHANGELOG.md`) |
| 이름 | **Q0 — 운영자가 정한다.** 권장은 「kmd 는 서비스 이름(개인 kmd + 프로젝트 kmd)이고, 엔진 · 명령 `ctx` · 데이터 `~/.cdp` · MCP 키 `cdp` · `CDP_TOKEN` 은 그대로」 다. 개인 쪽에 새로 생기는 식별자는 개인을 뜻하는 이름을 쓴다(`me` · `CDP_ME_TOKEN`) | 이미 설치된 작업 레포의 `.mcp.json` · kit · 실서버 · dpms_wiki 를 움직이지 않는다. 새 식별자를 `kmd` 로 지으면 「kmd = 개인뿐」 으로 읽혀 이름이 뜻을 거꾸로 가리킨다 |

### 2.3 「오프라인으로 전파되지 않는다」 — 두 겹

원문은 이 말을 「(로컬 서비스 실행용 프로그램 제공)」 과 같은 줄에 두었다. 그래서 두 겹으로 읽는다(KM3).

| 겹 | 뜻 | 코드가 지키는 자리 |
|---|---|---|
| (a) 혼자 돈다 | 네트워크를 끊어도 개인 kmd 의 들이기(`--no-llm`) · 고치기 · 찾기 · 원본 맞추기 · 거두기가 된다 | 개인 서버는 127.0.0.1 강제(`ctx-mcp-serve.mjs:529`) · 화면 번들은 외부 자원을 부르지 않는다(I11). 단계 ① 시험에 「망 끊고 하루」 를 넣는다 |
| (b) 저절로 퍼지지 않는다 | **사람이 켜지 않은 바깥 길은 0** 이다. 나가는 것은 사람이 돌린 보내기 · 사람이 켠 개인 git · 사람이 연 Claude 세션(`--analyze` 포함)뿐이다 | 지금은 `ctx up` 이 origin 이 있으면 묻지 않고 미러를 켠다(E1) — v1.9.1 에서 걷는다. 개인 서버가 여는 바깥 연결은 {켠 레포의 미러 push/fetch · 원천 연결 fetch · 사람이 누른 보내기/받기} 로 목록이 정해지고, 머리 띠 · `ctx up` 시작 안내가 같은 목록을 보인다 |

「네트워크를 전혀 안 쓴다」 로 좁히면 세션으로 세우기(Claude Code)와 `--analyze` 가 막힌다. 「회사 밖 반출 통제」 로 넓히면 원문에 없는 장치가 커진다. 그래서 LLM 공급자로 가는 길은 사용자의 선택으로 두고(레포별 `noLlmIngest` · `ctx-mcp-serve.mjs:539-540` 그대로), 보이게만 한다.

### 2.4 안 하는 것

| 안 한다 | 까닭 |
|---|---|
| 실시간 양방향 동기 · 자동 최신화 · 기계가 글을 합치기 | v1.0 거부 설계 「지식 폴더 자동 최신화」 를 유지한다 — 맞추기는 사람이 누른다. 합치는 글은 사람이나 큐레이터의 에이전트 세션이 쓴다(I11 · I12) |
| 개인 섹션을 프로젝트 섹션에 바로 쓰기 | I6 — 프로젝트 정본의 작성자는 프로젝트 큐레이터다 |
| 지식 → 원본 md 되쓰기 | 원천에는 쓰지 않는다(`sourcerepo.js:4`). 꺼낼 때는 내려받기 zip(`viewer/server/adapter/read-api.js:242-266`) |
| 별도 로컬 화면 · 별도 로컬 코드(옛 로컬 뷰어 · `cdp.exe`) | V1 이 걷은 것은 **쓰는 길이 둘이던 별도 코드**다. 같은 개인 서버를 띄우는 설치 · 실행 프로그램(⑤)은 이것과 다르다 |
| 두 PC 가 같은 개인 레포에 동시에 쓰기 | 「한 레포를 두 서버가 쓰지 않는다」(`manual/관리자_설명서.md:267` · I12). PC 를 옮기는 절차만 둔다(§10) |
| 여러 사람이 한 개인 지식을 같이 쓰기 | 그것은 프로젝트 kmd 의 일이다 |

## 4. 말

원문의 말을 CDP 말로 옮긴다. **버린 말(지식공유문서 · 작업문서 · 모드 A/B · 로컬형 · 로컬 뷰어 · `cdp.exe` · 트레이 앱 · `sync`)은 되살리지 않는다**(용어.md §4). 「싱크」 는 원문 인용에만 둔다.

### 4.1 원문의 말 → CDP 말

| 원문 | CDP 말 | 화면 · 명령에서 |
|---|---|---|
| 지식문서 | **지식 레포** 하나(관리 문서 + 작업 기록 + `_vocab.md` + `_managed.md`) | 「내 지식」 · 「프로젝트」 |
| 관리문서 | **관리 문서** · 섹션 | 그대로 |
| 작업문서 | **작업 기록** — 개인에서도 불변(I3). 계속 고치는 노트는 관리 문서로 둔다 | 「기록」 |
| 에디팅 | **고치기**(화면) · **거두기**(편집기로 고친 것) | 단추 이름 |
| 업데이트(싱크 맞추기) | **원본 맞추기** | 단추 「원본 맞추기」 |
| 관리문서 싱크 | **프로젝트와 맞추기**(받기 · 보내기) + 거두기 — §8.1 | 화면 「프로젝트와 맞추기」 |
| 로컬 서비스 실행용 프로그램 | **개인 kmd**(개인 서버) | `ctx up` · ⑤ 의 설치 프로그램 |
| 개인 깃 | **개인 git**(레포별 미러를 켬) | 「개인 git 켜기」 |

### 4.2 새 말 — 용어.md 에 올리는 것(열 개)

| 새 말 | 뜻 | 이어지는 말 · 다른 점 |
|---|---|---|
| **kmd** | 서비스 이름 — 개인 kmd + 프로젝트 kmd + 둘 사이 | 「얼굴」(사이트 · 레포 · 콘솔)과 다른 층이다 |
| **개인 kmd** | 내 PC 의 개인 서버 하나 · 레포 폴더 하나 · 레포 여럿 | 「개인 서버」 를 넓힌 것 |
| **문서로 들이기** | md 를 바이트 그대로 관리 문서로(등록부 밖) — 큐레이터만 | 「들이기」(`ctx ingest` · 결과는 작업 기록)의 다른 갈래. 「문서 레포에서 세우기」(seed)와 다르다 |
| **좌표 달기** | 등록부 밖 문서를 등록부 문서로 올리는 일 — 사람이 타입 이름을 정한다 | 「찍기」(서식에서 빈 문서)와 짝 |
| **원본 맞추기** | 원본 파일 · 폴더의 새 판을 지식에 들이는 일 | G11 의 「이전 판」 관례를 잇는다 |
| **고치기** · **고친 기록** | 화면 · 세션에서 관리 문서를 사람이 고치는 일 · 그 save 의 작업 기록(태그 `edit`) — 계산상 **자기 반영** | 「반영」 은 판정이고 고치기는 판정이 아니다. 대기 기록을 같이 닫으면 반영이다 |
| **거두기** | 편집기로 직접 고친 `docs/` 를 save 한 번으로 들이는 일 | 「트리 되돌리기」 의 반대쪽 |
| **프로젝트와 맞추기** | 짝 프로젝트와 받기 · 보내기를 한 자리에서 | 「origin 과 맞추기」(ff)와 한 가족 · 「내려받기」(zip)와 다르다 |
| **보내기** · **제안 기록** | 고른 작업 기록 · 관리 문서를 프로젝트 대기열로 · 관리 문서를 싼 작업 기록(태그 `proposal`) | 「정본 스냅샷」 과 다르다 — 언제나 대기열에 선다 |
| **짝 프로젝트** | 개인 레포 하나와 짝인 프로젝트 레포(0..1) | 「연결된 작업 레포」 · 「원천 연결」 과 다른 말을 쓰려고 「연결」 을 피했다 |

필드 · 라벨일 뿐인 것(개인 레포 폴더 · `--to me` · 머리 띠 · 받은 것 칩 · 보낸 장부)은 용어에 올리지 않는다. 각 절의 설명으로 둔다. **말은 그 말이 쓰이는 단계에서 용어.md 에 더한다.**

### 5.3 두 서버가 한 PC 에

지금 한 PC 에는 토큰 한 칸(`CDP_TOKEN`) · 붙을 서버 하나(`login.json`) · 작업 레포 MCP 키 하나(`cdp`)뿐이다(`tokenstore.js:32-48` · `ctx-login.mjs:20-25 · 34-38` · `setup.js:206-220`). 두 번째 서버에 붙인 작업 레포는 401 이 난다(`auth.js:96-98`로 확인).

| | 프로젝트 | 개인 |
|---|---|---|
| CLI | 지금처럼 `login.json` · `CDP_TOKEN` | **`--to me`** — `~/.cdp/personal/<레포 폴더>/up.json` 의 포트와 `personal.token` 을 읽는다. 새 설정 파일 · 이행 없음(`resolveClient` 한 곳 · `ctx-login.mjs:34-39`) |
| 행선 | 개인 레포 폴더와 `login.json` 이 둘 다 있으면 `ingest` · `send` · `pull-docs` 는 `--to` 가 있어야 돈다. 돌기 전에 「→ 서버 · 레포」 한 줄을 찍는다 | |
| MCP | 작업 레포 `.mcp.json` 의 `cdp` · `${CDP_TOKEN}`(그대로) | **개인 큐레이터 폴더**(`ctx up --curator <폴더>` — 있음 · `ctx-up.mjs:307-313`)의 `.mcp.json` 키 `cdp` · 헤더 `${CDP_ME_TOKEN}` |
| 토큰 저장 | 그대로 | `CDP_ME_TOKEN` — Windows 저장(`saveTokenWindows` · `tokenstore.js:75`)에만 있는 이름 인자를 `loadToken` · `saveTokenPosix` 에도 더한다. 그러지 않으면 POSIX 에서 개인 토큰이 `~/.config/cdp/token` 을 덮는다 |
| 세션의 행선 | 작업 레포에서 연 세션은 프로젝트로, 개인 큐레이터 폴더에서 연 세션은 개인으로 간다 — **폴더가 가른다.** 스킬 사본을 더 두지 않는다 | |

`.mcp.json` 헤더의 `${VAR}` 펼침은 프로젝트 범위에서 이미 쓰는 길이다(`setup.js:263`). 값은 Claude Code 를 띄울 때의 프로세스 환경에서만 온다 — Windows 는 사용자 환경변수 + Claude Code 재시작이 필요하다. 변수가 없으면 `Bearer ${CDP_ME_TOKEN}` 글자 그대로 가서 401 이다. 사용자 범위 MCP 로 「코드 레포 세션에서 개인에 남기기」 를 여는 일은 요구가 확인되면 한다.

### 5.4 경계 — 무엇이 어디로 가나

| 방향 | 무엇 | 누가 · 언제 | 받는 쪽에서 |
|---|---|---|---|
| 개인 → 프로젝트 | 고른 작업 기록 · 제안 기록 · 그 첨부 | 사람이 누른 [보내기] · `ctx send` | 보낸 사람의 writer save → 대기열 |
| 프로젝트 → 개인 | 프로젝트 관리 문서 정본(읽기) | 사람이 누른 [받기] · `ctx pull-docs` | 개인 레포에 큐레이터(나) save |
| 개인 → 개인 origin | 개인 레포 커밋 | 사람이 켠 레포만 · save 뒤 미러 | — |
| 개인 → LLM 공급자 | 세션이 읽은 것 · `--analyze` 의 파일 본문 | 사용자의 Claude 세션 · CLI | — |
| 프로젝트 → 개인 서버 · 개인 화면 → 다른 서버 | **없다** — 루프백이라 닿지 않는다 · CORS 없음 · 프로젝트 화면은 새 탭 링크 | — | — |

## 6. 세우기 — 세션 · 단일문서 · 폴더

### 6.1 세 길

| 길 | 개인 kmd | 프로젝트 kmd |
|---|---|---|
| **세션** | 개인 큐레이터 폴더의 Claude Code 세션 — `cdp-curate` 의 새 절 「직접 쓰기」: 대화에서 정한 기록 + 섹션(또는 새 등록부 밖 문서)을 **save 한 번**에, 태그 `edit` 로 자기 반영(대기 0). 폴더 하나를 세션이 읽어 문서로 세우는 것도 같은 길(파일마다 save 하나) | 지금처럼 `cdp-save` 첫째 길 · 편입(`편입.md:11` 「여러 문서는 하나씩」) → 대기열 |
| **단일문서** | 화면 지식 생성 [지금 실행] 또는 `ctx ingest <파일> --to me --as docs` — **문서로 들이기가 화면의 기본**(§6.2). `--as records`(작업 기록)도 고를 수 있다 | `ctx ingest <파일>` — 작업 기록(그대로). 큐레이터는 `--as docs` 도 된다 |
| **폴더** | 같은 명령에 폴더 · 하위를 펴서 파일마다. `--as docs` 는 파일마다 save 하나 · 기록은 20건 묶음(`saveRecords`) | 같다 · git 문서 레포를 섹션째 세우는 것은 `ctx seed`(그대로) |

변환은 지금 것을 그대로 쓴다 — md · txt 는 그대로, docx · xlsx · pptx · hwpx 는 Node 로, pdf 는 `pdftotext`(`core/convert.js`). 변환한 문서를 문서로 들이면 원본 대신 **변환한 md** 가 관리 문서가 되고 원본은 첨부로 남는다.

git 원천은 커밋 기준으로 읽는다는 결정(지식생성 검토 §5.2)이 있는데, 지금 `ingest.js` 는 `openSource` 를 쓰지 않고 작업 트리를 fs 로 읽는다(`ingest.js:64-73` · grep 0). 지식생성 TODO B3 은 「openSource 재사용」 을 완료로 적었다. 원본 맞추기(③)가 이 차이에 기대므로 단계 ③ 에서 바로잡는다 — 작업 트리는 `--worktree` 일 때만.

### 6.2 일반 md 가 1급 — 문서로 들이기

**기본은 등록부 밖 문서다.** md 를 바이트 그대로 `docs/<하위 폴더>/<파일>.md` 로 둔다. 헤딩도 주석도 건드리지 않는다. 좌표가 없으니 어휘 · 등록부에 아무것도 쌓이지 않는다. 등록부 밖 문서는 이미 CDP 에 있는 꼴이다 — 회의록 같은 날짜축 문서를 `edits` 가 받고(`edits.js:4`), check 는 오류를 내지 않는다.

| 사용자 md 에서 | 문서로 들이기(기본) | 좌표 달기 뒤 |
|---|---|---|
| 파일 자리 | `docs/<원본 상대 경로>` | 그대로 |
| 헤딩 줄 | 그대로 | `## <값> — <원 헤딩>` 이 된다. 원 헤딩과 값이 `normValue` 로 같으면 그대로 둔다 |
| 주석 | 없음 | 섹션마다 `<!-- applied: <id> -->` |
| 파일 이름 | 그대로 | 그대로 — 타입 이름은 사람이 정한다(좌표 정규식 `RE_COORD` · `vocab.js:27` 은 소문자 영문 · 한글로 시작해야 해서 `README` · `2026-회의-메모` · `My-Notes` 는 타입이 될 수 없다 — 실측) |
| `_vocab.md` · `_managed.md` | 그대로 | 타입 하나 · 좌표 n · 등록부 행 하나가 같은 save 로 |
| 원본 파일 | 그대로(원천에는 쓰지 않는다) | 그대로 |

**쓰는 길.** 지금 save 로는 새 등록부 밖 문서를 만들 수 없다 — `edits` 는 **이미 있는** `docs/**.md` 만 받고(`edits.js:28-31`), 등록부 `add` 는 `pattern` 을 요구한다(`managedops.js`). `edits` 로 문서를 통째 바꾸는 것도 안 된다 — `old` 가 2만 자까지다(`edits.js:19 · 45`). 그래서 큐레이터 전용 save 입력 하나를 더한다 — **등록부 밖 문서 통째 쓰기 `{ file, body, base? }`**. `base` 가 없으면 새로 만들고(있는 파일이면 거절), 있으면 지금 글의 sha 가 `base` 와 같을 때만 갈아 끼운다(낙관 잠금 · §8.4 와 같은 뜻). `docs/` 아래 · 등록부 행에 걸리지 않는 파일만 · 크기 상한 · 이름은 구현 때 정한다. 같은 save 의 작업 기록은 **짧은 고친 기록**이다 — 제목 「들임 — <파일>」 · 정형 출처 `<원천>@<commit|->/<경로>#blob:<sha>` · 태그 `edit`. 전문을 기록에 겹쳐 두지 않는다. 그때의 원문은 그 커밋의 문서 글(`git show`)이 곧 그것이다.

**권한.** 문서로 들이기는 **그 레포의 큐레이터만** 한다(writer 면 `E_FORBIDDEN { need: 'curate' }`). 개인 · 팀을 save 가 가르지 않는다 — 같은 코드다(V14). 개인에서는 주인이 큐레이터라 늘 된다. 쓰는 길은 `ctx seed` 처럼 MCP save 단건 · 파일마다(`ctx-seed.mjs:44`)다. `/records`(`saveRecords`)는 섹션 · 문서를 받지 않는다(`ctx-ingest.mjs:468`).

**좌표 달기**(고치기 화면의 단추) — 사람이 타입 이름을 정한다 → 헤딩마다 값 후보(헤딩 글의 슬러그) → 헤딩이 어떻게 바뀌나를 미리보기 → 승인하면 `vocab` add + `managed` add + 문서 갈아 끼우기를 save 한 번. 노트 300개를 들여도 어휘가 300 타입으로 불지 않는다 — 사람이 고른 문서만 오른다.

### 6.3 세션

- 개인 큐레이터 폴더는 이미 있다(`ctx up --curator`). 그 폴더의 `.mcp.json` 이 개인 kmd 를 가리킨다(§5.3).
- `cdp-curate` 에 「직접 쓰기」 절을 더한다 — 「개인 kmd 이거나, 대기 기록과 상관없이 내가 아는 것을 바로 정본으로 쓸 때: 기록(왜 · 무엇) + sections(또는 새 등록부 밖 문서)를 한 save 에, 태그 `edit`. 판정표 대신 diff 를 보이고 승인받는다」. `cdp-save` 는 바뀌지 않는다.
- 세션은 ctx 를 부르지 않는다(M1). 폴더 수백 개를 한꺼번에 들이는 일은 들이기가 한다.

### 6.4 개인 서버의 [지금 실행]

지금 지식 생성 화면은 명령만 복사해 준다. 팀 서버는 사람 PC 의 경로를 읽을 수 없기 때문이다(`Ingest.jsx:196`). 개인 서버는 **같은 PC · 같은 OS 사용자**로 돈다. 그래서 개인 서버에서만 [지금 실행] 단추를 둔다. 서버가 CLI 와 같은 core 함수(`core/ingest.js` 계획 → 사람 승인 → 적용)를 잡으로 돈다.

| 화면 [지금 실행] 이 되는 것 | 명령 복사로 남는 것 |
|---|---|
| 들이기 `--no-llm` · 문서로 들이기 · 원본 맞추기 · 거두기 | `--analyze`(사용자 PC 의 `claude -p` — 서버는 LLM 을 부르지 않는다 · I11 · G18) |
| 프로젝트와 맞추기의 [보내기] · [받기] (단계 ④ — §9.1) | 팀 서버의 모든 들이기 |

판정은 여전히 core 한 곳이다(I1). 달라지는 것은 부르는 쪽뿐이다. 팀 서버에는 이 단추가 없다 — 개인 표식(§5.2)으로 가른다.

## 7. 업데이트 — 원본 맞추기(기존 단일문서 · 기존 폴더)

같은 명령 · 같은 단추를 다시 돌린다. 원본의 지금 blob 이 마지막 맞춘 blob 과 같으면 아무것도 하지 않는다. 다시 돌려도 커밋은 0 이다(멱등).

### 7.1 기록으로 들인 것

지금처럼 새 판 기록을 짓는다 — 머리줄 「이전 판 `<id>`」(G11 · supersedes 아님). 고칠 것이 둘이다(v1.9.1 · §12.0).

- **이전 판 = 사슬 끝**을 레포에서 계산한다 — 같은 원천 · 같은 경로의 기록 가운데 다른 기록의 「이전 판」 으로 걸리지 않은 것. 지금은 경로의 첫 항목이라 바로 앞 판이 아닐 수 있다(`ingest.js:231` · `repo.js:37`). 장부는 필요 없다.
- **새 판의 date 는 그 판이 바뀐 날**이다. 날짜 근거가 git 첫 커밋 · 파일명 · 프론트매터면 지금은 모든 판의 date 가 같아, 판 순서가 blob 해시 순이 된다(`ingest.js:88-94 · 307`). 옛 판을 applied 로 둬도 later 가 0 이라 경고만 난다.

옛 blob 으로 **되돌린** 원본은 「이미 들임」 으로 건너뛰지 않는다. 사슬 끝과 다르니 새 판이다.

### 7.2 문서로 들인 것 — 판정 넷

섹션마다 셋을 견준다. **S0** = 마지막 맞춘 커밋에서의 그 섹션 글(`git show <커밋>:docs/<파일>` 을 같은 규칙으로 쪼갠 것 — 장부 없음 · I8 · I9) · **S원본** = 새 원본을 같은 규칙으로 쪼갠 글 · **S지식** = 지금 섹션 글. 등록부 밖 문서는 `##` 마다, 헤딩이 없으면 문서 통째가 한 칸이다.

| 경우 | 판정 | 하는 일 |
|---|---|---|
| S원본 = S0 · S지식 = S0 | 같음 | 없음 |
| S원본 ≠ S0 · S지식 = S0 | **원본만** | 갈아 끼운다 — `base = sha(S지식)` 잠금 · 고친 기록(`edit`)으로 자기 반영 |
| S원본 = S0 · S지식 ≠ S0 | **지식만** | 없음 · 「지식이 앞섬」 표시 |
| 둘 다 S0 와 다름 | **둘 다** | **건드리지 않는다.** 보통 업데이트 기록이 그 좌표를 touches 해 「미반영 1」 로 남는다(I7). 화면에 S0 · 원본 · 지식 세 칸 → 「원본 판으로 · 내 판 두기(keep) · 고치기에서 합치기」 를 사람이 고른다. 등록부 밖 문서는 좌표가 없으니 원본 판을 `docs/` 밖이 아니라 업데이트 기록 본문에 싣고 「원본 바뀜 · 둘 다」 칩으로 보인다 |
| 원본에 섹션이 없어짐 · 새로 생김 | 표시만 | 지우지 않는다(I3) · 새 좌표는 좌표 달기와 같은 승인 |

**한 파일의 save 는 최대 둘이다.** ① 갈아 끼운 섹션만 touches 하는 고친 기록(`edit`) + sections ② 「둘 다」 섹션을 touches 하는 보통 업데이트 기록(대기 → 미반영). 둘을 한 기록에 넣으면 「`edit` 의 touches ⊆ sections」 검사(§8.3)와 「둘 다 = 미반영」 이 서로 막는다.

이 판정은 **core 순수 함수 하나** `syncSections({ incoming, base, current })` 가 낸다. 정본 맞추기(§9.6)가 같은 함수를 쓴다. 시험은 순수 함수 행렬 하나로 둘을 덮는다.

### 7.3 기존 폴더

하위 파일마다 §7.1 · §7.2 를 돈다. 폴더 단위로는 **표시만** 한다(첫 판).

| 갈래 | 판정 | 하는 일 |
|---|---|---|
| 새것 | 거름에 맞는데 들인 적 없다 | 계획 표의 후보 — 체크해야 들인다(자동 최신화 거부 유지) |
| 없어짐 | 들였는데 파일이 없다 | 「원본 없음」 표시. 지식은 안 건드린다 |
| 이름 바뀜 | 없어진 것의 마지막 blob 이 새 경로에 있다 | 같은 blob 일 때만 같은 원본으로 잇는다 — 기록 0 |
| 폴더째 안 보임 | 드라이브 빠짐 · 경로 바뀜 | 「원본 폴더 없음」 하나로 멈춘다 — 파일 n 개를 없어짐으로 쏟지 않는다 |

「이름 + 내용이 같이 바뀜」 은 없어짐 1 + 새것 1 로 보인다. 유사도로 잇지 않는다. 「같은 문서로 잇기」 · 지워진 원본의 정정 기록은 요구가 나오면 더한다.

## 8. 개인 편집 · 관리 문서 맞추기

### 8.1 「관리문서 싱크」 를 어떻게 읽나

원문은 원본과 맞추기를 이미 「지식문서를 업데이트를 다양한 방법으로 한다(싱크 맞추기) — 기존 단일문서 · 기존 폴더」 줄에 따로 적었다. 그러니 각주의 「관리문서 싱크」 는 그것(§7)이 아니다. 「개인 지식은 에디팅이 가능」 과 짝이므로 **개인이 고친 관리 문서를 무엇과 맞추나**의 이야기다. 뜻이 둘 남는다.

| 읽기 | 무엇과 맞추나 | 길 | 단계 |
|---|---|---|---|
| **(다) 프로젝트와 맞추기 — 주된 뜻(권장)** | 내 관리 문서 ↔ 짝 프로젝트의 정본 | 받기 · 보내기 한 자리(§9) | ④ |
| **(라) 손 편집 거두기** | 편집기로 고친 md ↔ 지식(관리 문서 · 커밋) | 거두기(§8.5) | ② |

둘 다 둔다. (다)가 없으면 개인 판은 프로젝트 정본에서 영원히 멀어지고, 보내는 제안이 낡은 기준 위에 쌓인다. (라)가 없으면 「에디팅 가능」 이 화면 편집기 하나로 좁아진다. 운영자가 (다)를 더 급히 원하면 단계 ④ 의 받기 · 보내기를 단계 ③ 앞으로 당긴다(Q1). 「내 관리 문서 ↔ 내 작업 기록」(미반영 · 어긋남)은 지금의 대기열 · 진단 화면이 하고 있어 따로 이름을 두지 않는다 — 고치기 화면이 그 섹션의 미반영을 같이 보일 뿐이다.

### 8.2 고치기 — 화면 편집기

| 자리 | 결정 |
|---|---|
| 화면 | 작업실 › 정리한다 › **고치기** — `/r/<r>/manage/edit[/<문서>][?at=<좌표>]` · need `curate`. 개인 · 팀이 같은 코드다. **보기에는 쓰는 단추가 없다**(G2 유지 · 개인 보기의 「고치기」 링크 하나는 Q7) |
| 구성 | 왼쪽 글(textarea) · 가운데 같은 `renderMarkdown` 미리보기 · 오른쪽 그 섹션의 미반영 기록(I7) · 서식 단추 몇 개(제목 · 표 · 링크 · 그림 붙이기 → `/assets`) |
| 등록부 밖 문서 | 문서 통째를 고친다 → 등록부 밖 문서 통째 쓰기(`{ file, body, base }` · §6.2). 문서 일부만 바꾸는 작은 고침은 지금의 `edits`(old 가 곧 낙관 잠금 · `edits.js:6-7`)로도 된다 |
| 좌표 문서 | 섹션의 `content`(헤딩 · applied · 기준선 블록을 뺀 글 — `tools.js:95-115 · 326-338`) + `base = sha(content)`. 좌표 밖 산문은 `edits` · 새 헤딩은 「항목 더하기」(vocab add + 섹션 · 같은 save) · 헤딩 줄을 본문에 넣으면 거절(`save.js:920-936`) |
| 저장 | `POST /api/<r>/edit` → 서버가 save 를 짓는다. **그냥 고침**: `{ work: { title, body, touches: [고친 좌표], tags: ['edit'] }, sections | edits | 통째 쓰기 }` · **반영하며 저장**: 오른쪽에서 체크한 대기 기록을 같이 닫으면 `{ work: { curates: [{ id, verdict: 'reflect', into }] … }, sections }` — 큐레이션 기록이 된다(`/curate` 와 같은 꼴 · I2) |
| 까닭 | 팀은 필수(Prompt 모달 · save 가 work 를 요구 — `save.js:150-155`). **개인은 선택** — 비우면 제목이 「고침 · <문서> › <섹션>」 으로 찍힌다(산문을 짓는 것이 아니라 라벨이다) |
| 여러 섹션 | 한 저장으로 묶는다 — 기록 하나 · 커밋 하나 |
| 충돌 | `E_CONFLICT` 면 지금 본문과 누가 바꿨나(`save.js:959-985`)를 받아 내 글을 지우지 않고 나란히 보인다(I12) |
| 작업 기록 | 고치지 않는다(I3) — 「정정 기록 쓰기」(supersedes 를 단 새 기록) |

「반영하며 저장」 은 에이전트 없는 큐레이션을 연다. 화면 관례 「산문은 화면이 쓰지 않는다」(`Queue.jsx:9-10` · `Docs.jsx:8` · `VocabView.jsx:3-4`)는 「**화면은 사람이 쓴 글만 save 한다 — 화면이 글을 짓지는 않는다**」 로 고쳐 적는다. `cdp-curate` 의 판정표 + diff 승인(K12)은 세션의 규칙이다. 화면에서는 저장 전 「바뀌는 것」 diff(커밋 전 미리보기 — `dryRun`)를 한 번 보이는 것으로 대신한다.

### 8.3 고친 기록 — 태그 `edit` · 자기 반영

- `edit` 를 `RESERVED_TAGS` 에 더한다(`save.js:518`) — writer 는 `E_FORBIDDEN`. save 는 「`edit` 기록의 touches 가 모두 같은 save 의 sections 에 있다」 를 검사한다(`E_INPUT`). 등록부 밖 문서만 고친 기록은 좌표가 없으니 `touchesEmpty` 「등록부 밖 문서 <파일>」 이고, 그 save 에 통째 쓰기 · `edits` 가 있어야 한다. 대기열을 건너뛰는 데 쓰지 못하게 하는 자리다.
- `buildCuration` 은 `edit` 기록을 **state `reflected` · `self: true` · verdict `null` · into = touches** 로 계산한다. 이미 있는 「세울 때 함께 들인 기록」 의 `seeded`(`curation.js:26 · 217`)와 같은 모양이다. 저장한 상태가 아니다(I8). `/sources` 도 새 판정 값을 만들지 않고 `verdict: null, self: true` 로 낸다.
- **암묵 전환을 켜지 않는다.** 지금은 큐레이션 기록 · `_seed.json` 이 둘 다 없는 레포에서 큐레이터가 직접 편집(curates 없음)을 하면 암묵 전환이 켜진다(`curation.js:201`). 그러면 판정 없는 다른 대기 기록까지 「반영됨(암묵)」 으로 계산되어 대기열에서 사라진다(fixture 실측 — 대기 20 → 18 · `curation.js:243-251`). 새 개인 레포의 첫 고치기가 대기열을 지우는 일이다. `implicit` 판정이 `edit` 기록의 applied 를 보지 않게 한다.
- `applied` 는 고친 기록 id 가 된다(`save.js:790-793`). 지금 큐레이터의 직접 편집은 자기 기록이 대기 · 미반영으로 남아 둘째 save 로만 닫혔다(probe 2). 그 소음이 사라진다.
- **팀에도 같다**(같은 코드 · V14). 대신 팀이 볼 자리를 하나 둔다 — 큐레이션 › 이력에 「자기 반영」 거름 · 건수. `cdp-curate` 의 직접 편집도 `edit` 를 단다.
- 고칠 정본 문서 — 용어 §2 판정 표에 「자기 반영(`edit`) — 판정이 아니라 큐레이터가 같은 save 에서 쓴 기록의 계산 상태」 행 · 대기열 정의를 「판정도 자기 반영도 없는 작업 기록」 으로 · 시스템 설계서 §3.3 기록 종류 표 · §5.1 예약 태그.

### 8.4 섹션 내용 잠금 — `sections[].base`

| | 지금 | 바꾼다 |
|---|---|---|
| 잠금 | `applied` 주석만 견준다(`save.js:959-960` · current 는 `360-368`) | `sections[].base`(선택 · 읽은 `content` 의 sha)를 받는다. 지금 `content` 의 sha 와 다르면 `E_CONFLICT`. `base` 가 오면 applied 대조를 대신한다 |
| 계산 | — | 서버의 해시는 MCP `section` 이 내는 `content` 와 같은 함수로 — `splitBaseline(sliceSection(…).content).curated` |
| 덮이는 것 | 손 커밋 · 「origin 과 맞추기」 로 들어온 바깥 커밋 · applied 가 안 움직이는 save(옛 날짜 기록 reflect · `save.js:787-798`) 뒤에, 옛 읽기로 한 save 가 섹션을 **소리 없이** 덮는다(재현) | `E_CONFLICT` 로 멈춘다 |
| 싣는 자리 | — | v1.9.1 에 선택 입력과 MCP `section` 의 `base` 를 넣는다(`ctx-mcp.mjs:384-394` 의 sections 항목은 지금 모르는 키를 조용히 버린다 — `.strict()` 로 바꾼다). 단계 ② 부터 고치기 · 거두기 · 원본 맞추기 · 정본 맞추기 · `cdp-curate` 가 **늘** 싣는다 |

### 8.5 거두기 — 편집기로 고친 것

VS Code · Obsidian 으로 `D:\kmd\<레포>\docs\` 를 바로 고치는 사람의 길이다. **I2 의 예외가 아니다** — 커밋은 여전히 save 가 한다.

| 단계 | 하는 일 |
|---|---|
| 알아채기 | 개인 서버가 화면을 열 때 · 상태 줄을 볼 때 `git status` 를 본다. 첫 화면 「거둘 손 편집 n」 · 다른 save 가 `E_GIT dirty` 로 막히면 「먼저 거두기」 안내. 파일 감시 · 자동 거두기는 없다 — 사람이 누른다([거두기] · `ctx collect <레포>`) |
| 계획 | core 순수 함수 `collectPlan` — HEAD 와 작업 트리를 같은 쪼개기로 견준다. 줄 끝만 다른 것은 무시한다(CRLF · I13) |
| 등록부 밖 문서 | 통째 쓰기(`base` = HEAD 의 글 sha) — **거절이 없다**. 새 md 파일은 같은 입력의 새로 만들기로(§6.2) |
| 좌표 문서 | **헤딩 뼈대(`##` 줄 · 기준선 블록 자리)가 HEAD 와 같으면** 섹션 본문만 `sections[] + base` 로. 새 헤딩은 거절하지 않고 「항목 더하기 n」 으로 미리보기에 싣는다(사람 승인 · vocab add · I4). 헤딩 이름 바뀜은 어휘 rename 후보로 보인다 |
| 거절 | `work/` · `_vocab.md` · `_managed.md` 의 손 변경 · 기준선 블록 안 변경 · 헤딩을 옮긴 것 → 「그 파일만 되돌리기」 · 「정정 기록 쓰기」 · 「고치기에서 하기」 를 안내 |
| 적용 | 사본을 `<data>/collect/<시각>/` 에 → 트리를 HEAD 로 → save 한 번(고친 기록 · sections · edits · base) → **실패하면 사본을 그대로 돌려놓는다**(바이트 같음) |
| 손 커밋 | save 의 커밋은 작성자가 `<user>@cdp` 다(시스템 설계서 §5.6 · 메시지는 기록 제목 · `save.js:488` · 트레일러는 없다 — `git.js:338-350`). HEAD 까지 작성자가 `@cdp` 가 아닌 커밋이 `docs/` 를 바꿨으면 「밖에서 커밋됨」 으로 보이고 같은 거두기 길을 권한다. 막지는 않는다 — base 는 「읽은 뒤 바뀜」 만 막으므로, 막으려면 거두기 전 save 를 거절하는 자리를 따로 둬야 한다(Q8) |
| 되돌리기 | 개인 서버에서 「트리 되돌리기」(지금은 확인창 한 번 뒤 사본 없이 미추적 파일까지 지운다 · `git.js:312-324`)는 v1.9.1 에 사본(`<data>/discarded/<시각>/`)을 먼저 둔다. 개인 화면의 이름은 「편집 버리기」 |
| 부산물 | 빈 틀 `.gitignore`(`skeleton.js:86`)에 `.obsidian/` · `.vscode/` · `.DS_Store` · `*.swp` |

### 8.6 기록이 쌓이는 양

고치기 · 거두기 · 원본 맞추기 · 정본 맞추기가 save 마다 고친 기록 하나를 `work/` 에 남긴다. 노트를 하루 스무 번 고치면 하루 스무 개다(추정 — 한 개 1KB 안팎). 그래도 남긴다 — 보내기의 근거, 원본 맞추기의 S0 커밋을 찾는 열쇠, 「누가 왜 바꿨나」 의 유일한 자리다. 대신 셋을 한다. ① 거두기는 여러 파일을 save 한 번으로 묶는다 ② 기록 목록 · 「최근」 은 `edit` 를 기본으로 접는다 ③ 개인은 까닭이 선택이다(§8.2).

## 9. 프로젝트와 맞추기 — 보내기 · 받기 · 큐레이션

### 9.1 한 자리

개인 레포 하나는 프로젝트 레포 하나와 **짝**이 된다(0..1 · 개인 데이터 `personal.json` · 레포 밖 · I9). 여러 프로젝트면 개인 레포를 나눈다. 짝 프로젝트가 있는 레포에만 작업실 › **프로젝트와 맞추기** 가 보인다(§3.1 그림).

| 칸 | 무엇 | 단추 |
|---|---|---|
| 프로젝트만 바뀜 | 프로젝트 정본이 지난 맞춤 뒤 바뀌었고 내 판은 그대로 | [받기] — 정본 맞추기(§9.6) |
| 나만 바뀜 | 내 섹션 · 문서가 지난 맞춤(또는 지난 보냄) 뒤 바뀌었다 · 안 보낸 작업 기록 | [보내기 미리보기] → [보내기] (§9.2 ~ §9.5) |
| 둘 다 바뀜 | 둘 다 | 세 칸 비교 → 프로젝트 판 · 내 판 두기 · 고치기에서 합치기 |
| 보낸 것 | 보낸 묶음의 프로젝트 판정(대기 · 반영 · 기록으로 둠 + 사유) — 확인 시각과 함께 | — |

**사람이 누를 때만 나간다.** [보내기] · [받기] 는 개인 서버가 같은 core 함수로 프로젝트 서버를 부른다. 프로젝트 토큰은 같은 OS 사용자의 클라이언트 설정(`CDP_TOKEN`)에서 읽고, 개인 서버 데이터에 두지 않는다. 이것은 「개인 서버는 사람이 누른 행선으로만 나간다 — 미러 push(I12)와 같은 급」 이라는 해석이다(부록 A). 셸을 쓰는 사람은 `ctx send` · `ctx pull-docs` 로 같은 일을 한다.

### 9.2 작업 기록 보내기 — 들이기의 지식 레포 입력

새 장치를 짓지 않는다. **들이기(`ctx ingest`)에 지식 레포 입력을 더한다.** 오늘도 `ctx ingest <지식 레포>/work --repo <프로젝트>` 는 통과한다 — 지식 레포 거절 검사(`ctx-ingest.mjs:61-64 · 92-99`)가 입력 폴더 바로 아래의 `_vocab.md` + `_managed.md` 만 보기 때문이다(fixture 사본 실측 — 기록 38건 계획). 그 길이면 이미 되는 것이 많다 — run 접기 · 받은 날로 재는 대기 나이(`curation.js:65-71`) · blob 중복(다시 보내면 0) · `--status` · 새 id(같은 id 다른 내용 충돌이 생기지 않는다) · supersedes 는 들이기가 떨어뜨린다(`importdir.js:36` — broken-supersedes 가 안 난다).

| 칸 | 값 |
|---|---|
| 입력 | 레포 뿌리를 받는다. `recordKind` 로 거른다 — 큐레이션 · 기준선 · 스냅샷 · 시스템 기록과 태그 `private` 기록은 보내지 않는다 |
| 고친 기록(`edit`) | 정형 출처(`#blob`)가 있는 원문 · 업데이트 기록은 `edit` 를 떼고 보통 기록으로 보낸다. 출처 없는 고친 기록은 내용이 섹션에 있으니 보내지 않는다(섹션은 제안으로 — §9.3) |
| 원천 이름 | 레포 이름(폴더명 `work` 가 아니라) — 출처 `<레포>@<head>/work/<id>.md#blob:<sha>` |
| 머리줄 | 「> 내 kmd `<레포>` 에서 보냄 · 원 작성 `<이름>` · 원 날짜 `<date>`」 |
| author | 서버가 토큰 사용자(보낸 사람의 프로젝트 계정)로 채운다(`save.js:156-160`). 원 작성은 머리줄에만 |
| 좌표 | 들이기의 승인 길 그대로 — 프로젝트 어휘에 **있는** 좌표만 체크해 touches 로(review.md · 화면 승인 `POST /jobs/<id>/approve`). 나머지는 `touches/<좌표>` 태그. `--analyze` 없이도 원 touches 를 후보로 싣는다 |
| 어휘 | **보내기는 `vocab` 을 싣지 않는다**(코드 고정 · I4). 개인 이름이 프로젝트 어휘로 새지 않는다 |
| run · 대기열 | `ingest/<runId>` 그대로 — 대기열이 이미 run 으로 접는다(`Queue.jsx:162-194`). 라벨에 「받은 것 · <보낸 사람> · <레포>」 |

### 9.3 관리 문서 보내기 — 제안 기록 · 새 문서 제안

| | 섹션 제안 | 새 문서 제안 |
|---|---|---|
| 언제 | 내 섹션의 좌표가 프로젝트 어휘에 있다(`match` 대조 · alias 포함 · 라벨이 다르면 경고) | 짝 프로젝트에 대응하는 문서 · 좌표가 없다 — 등록부 밖 개인 노트는 대부분 이것이다 |
| 단위 | 섹션 하나 = 기록 하나 | 문서 하나 = 기록 하나 |
| 종류 | `kind work`(대기). **snapshot 을 쓰지 않는다** — 프로젝트에 섹션이 있으면 state `system` 이 되어 대기열에서 사라진다(`curation.js:203-213`) | 같다 |
| 제목 · 태그 | 「제안 — <문서> › <헤딩>」 · `proposal` | 「새 문서 제안 — <문서>」 · `proposal` · `new-doc` |
| 본문 | 섹션 `content` 전문(기준선 블록 뺌) · `## 왜`(입력) · `## 기준`(보낼 때 프로젝트 `section` 으로 읽은 applied — 정본 맞추기를 했으면 그날도) | 문서 전문 · `## 왜` |
| touches | 그 좌표 — 프로젝트 섹션을 읽는 모든 자리에 「미반영 1」 로 실린다(I7) | `touchesEmpty` 「새 문서 제안 — 좌표는 큐레이터가 정한다」 |
| 출처 | `<레포>@<head>/docs/<문서>.md#blob:<섹션 글의 blob>` — 섹션 글이 바뀌면 새 blob = 새 제안 + 「이전 판」 머리줄 | 문서 blob |
| 받는 쪽 | 큐레이터가 `cdp-curate` 세션이나 고치기 「반영하며 저장」 | 대기열의 「새 문서로 받기」 — 큐레이터가 등록부 밖 문서로 바로, 또는 서식에서 찍어 섹션으로(managed add · sections · vocab 을 한 save) |

diff 는 기록에 싣지 않는다. 큐레이터는 `section` 으로 지금 정본을 보고, 화면은 두 글을 나란히 보인다. 순서 있는 줄 diff 알고리즘을 새로 짓지 않는다(지금 core 의 `lineDiff` 는 집합 차이다 — `sourcerepo.js:165-171`).

### 9.4 정체성 · 두 번 · 고친 뒤 · 거절

| 경우 | 무엇이 지키나 | 결과 |
|---|---|---|
| 같은 것을 두 번 | 정형 출처 blob — 서버가 뮤텍스 안에서 건너뛴다 | 0건 · 「이미 보냄」. 개인 장부 없이 성립한다 |
| 보낸 뒤 고침 | 새 blob · 사슬 열쇠(보낸 사람 = author, 원천 이름, 경로) | 새 기록 + 「이전 판」 · 두 사람의 같은 이름 레포도 author 로 갈린다 |
| 도중에 끊김 | 묶음 하나는 전부 또는 전무 | 다시 누르면 이어 보낸다 · 중복 0 · 자동 재전송은 없다 |
| 거절 | 프로젝트 큐레이터의 「기록으로 둠」(사유 필수 · 있음) | 보낸 사람은 「보낸 것」 칸에서 사유를 본다 |
| 잘못 보냄 | 지울 수 없다(I3) | 보통 기록 「철회 요청 — <id>」 하나를 보내고 큐레이터가 둘 다 keep 한다. 민감 정보면 git 이력 삭제는 관리자의 사람 절차(설명서) |

### 9.5 미리보기 = 반출 검사

1. 계획 — 보낼 묶음을 짓고 반출 검사를 돈다. **거절**: 태그 `private` 기록 · 레포 설정 `noSend`(문서 glob 목록 · `personal.json`)에 걸린 문서. **경고**: 절대 경로(`C:\Users\` · `/home/`) · 토큰 · 키 모양 · 첨부 수와 크기 · 개인에만 있는 링크 수.
2. 프로젝트에 `dryRun` 을 보내 「새로 · 이미 있음 · 오류」 표를 보인다. 좌표는 「맞음 n · 태그로만 n」 을 같이 보인다.
3. 사람이 [보내기] (CLI 는 `y/N` · `--yes`). 미리보기와 보내기가 한 프로세스 · 한 화면이라 묶음 해시를 따로 두지 않는다.
4. 진행은 잡으로 개인 서버에 보고한다. 「보낸 것」 칸은 프로젝트 `GET /sources?run=` 의 판정을 확인 시각과 함께 옮겨 보일 뿐 저장하지 않는다(I8).

### 9.6 받기 — 정본 맞추기

| 단계 | 하는 일 |
|---|---|
| 받기 | 프로젝트 `GET /api/<p>/archive?layer=canon`(새 갈래 — `_vocab.md` · `_managed.md` · `docs/` 만 · 지금 내려받기 zip 의 거름)을 임시 폴더에 받고 같은 `core`(`loadRepo` · section `content`)로 읽는다(I1) |
| 견주기 | `syncSections` 하나(§7.2) — S0 = 지난 정본 맞추기 커밋에서의 내 섹션 글(그 고친 기록의 커밋 · `git show`) · S프로젝트 · S지식 |
| 덮는 조건 | **내 섹션 글의 sha = 지난 맞춤에서 쓴 글의 sha** 하나뿐이다. applied 가 아니라 내용으로 본다 — 손 커밋도 「나만 바뀜」 으로 잡힌다 |
| 적용 | 개인 서버에 큐레이터 save 한 번 — 고친 기록(태그 `edit` · `pull` · 「<p>@<커밋> 정본 맞추기」 · touches = 덮은 좌표) + sections(base 잠금) + vocab add(새 좌표 · 라벨 그대로) + managed(새 문서 행) |
| 둘 다 · 나만 | 덮지 않는다 — 둘 다는 세 칸 비교, 나만은 보내기 후보 |
| 없어짐 · 링크 | 표시만 · 본문 속 `../work/<프로젝트 기록>` 은 경고만(새 탭 링크로 바꾸는 일은 요구가 나오면) |
| 처음 | `--init` — 빈 개인 레포를 만들고(`newRepo`) 첫 받기 · 짝 프로젝트를 적는다. 「프로젝트 지식을 내 PC 에서 고쳐 보고 싶다」 의 출발점 |

정본 작성자는 그대로 하나다 — 개인 레포의 큐레이터(나)가 내 토큰으로 save 한다(I6). 기계는 합치지 않는다(I12).

## 10. 개인 git

**쓰임은 둘이다 — 백업, 그리고 다른 PC 로 옮기기.** 로컬 이력은 늘 있다(개인 레포도 git 이고 save 하나가 커밋 하나다). 옵션은 「원격에도 둘까」 다. 개인 git 은 공유 수단이 아니다. 프로젝트로 가는 길은 보내기 하나다.

| 자리 | 결정 | 근거 |
|---|---|---|
| 기본 | **꺼짐.** `ctx up` 의 자동 켜짐을 걷는다(v1.9.1). 지금 origin 이 있는 개인 레포로 쓰던 사람에게는 「origin 이 있는데 미러가 꺼져 있다 — 켜려면 …」 한 줄을 낸다 · CHANGELOG 에 동작 변화 | `ctx-up.mjs:242 · 253 · 262` — 재현: 프로젝트 레포 clone 을 개인으로 띄우고 save 한 번 → 프로젝트 origin main 에 개인 기록 커밋. 프로젝트 서버는 그것을 `behind` 로 보고 「origin 과 맞추기」 한 번에 ff 로 들인다(push 권한 · 보호 브랜치 아님 · origin 이 앞서지 않음일 때) |
| 켜기 | 서버(개인) › 레포 › 「개인 git 켜기」 또는 `ctx up --root <폴더> --git <레포>=<url>`. origin 연결(`reponew.js:189-217` · 강제 push 없음) 뒤 `personal.json` 의 `mirror[레포]=true` | |
| 재시작 | 서버의 `opt.mirror`(시작 플래그 하나)를 레포별 함수 `mirrorOf(name)` 로 바꾼다 — 바꿀 자리는 `ctx-mcp-serve.mjs:713 · 738 · 1570 · 1771 · 1931 · 1991 · 2019 · 2070`. 서비스 유닛에 박힌 `--mirror`(`ctx-up.mjs:253`)도 걷는다 | 지금 띄운 뒤 이으면 save 의 자동 push 가 없다(연결할 때 한 번 · 서버 › 지식 레포의 「다시 보내기」 는 민다). 서비스는 재시작해도 안 켜진다 |
| 확인 | 켤 때 「이 레포의 지식이 <원격> 으로 간다」 를 한 번. 허용 호스트 목록은 Q3 | |
| 프로젝트 clone 막기 | 켤 때 origin 주소가 짝 프로젝트 · `login.json` 서버의 레포 주소와 같으면 거절 — 「프로젝트로는 보내기만」. 개인 서버가 프로젝트를 부르지 않고 로컬 값만 견준다 | |
| 자격 | 그 사람의 git(GCM · ssh-agent — 개인 서버는 OS 사용자로 돈다). 서버 배포 키는 「레포별 키」 가 아니라 서버 데이터의 키 하나를 레포 로컬 `core.sshCommand` 로 거는 것이다(`gitauth.js:91-116`). **PAT 저장 안내는 개인 화면에서 감춘다** — PAT 저장은 CLI 만 하고 전역 `credential.helper` 를 바꾼다(`gitauth.js:262-268`). 막는 장치는 `--global` 만 읽어 system 에 GCM 이 있는 PC 에서는 걸리지 않는다(`:218-225`) | |
| 멈춤 막기 | 미러 push · fetch · `pullFfOnly` 에 `GIT_TERMINAL_PROMPT=0` · `GCM_INTERACTIVE=never`(v1.9.1). 지금은 env 를 넘기지 않는다(`git.js:29-46 · 225 · 260 · 272`). Windows 에서 timeout 은 실행기만 죽여 GCM 창이 남을 수 있다(추정) | |

### 10.1 PC 옮기기

「한 PC 가 쓴다」 를 그대로 둔다(`manual/관리자_설명서.md:267`). 자동 fetch · ff 는 두지 않는다 — v1.0 거부 설계 「지식 폴더 자동 최신화」 와 같은 일이고, 서버의 맞추기는 save 뮤텍스 안의 `mirror.syncWithOrigin`(`mirror.js:152-164`)이어야 한다.

1. 옛 PC 의 개인 kmd 를 멈춘다(또는 그 레포의 개인 git 을 끈다).
2. 새 PC 에서 `git clone <개인 origin> D:\kmd\<레포>` → `ctx up --root D:\kmd`(이름은 레포 save 커밋의 가장 많은 작성자를 제안).
3. 뒤처졌으면 이미 있는 단추 「origin 과 맞추기」(ff)를 사람이 누른다. 갈렸으면 미러가 멈추고 셸 안내가 나온다.

두 PC 가 모두 켜진 채로 번갈아 쓰기는 지원 밖이다(Q4).

## 11. 화면

### 11.1 원칙

- **같은 코드 · 같은 화면**(시스템 설계서 §7.7). 영역 셋(보기 · 작업실 · 서버 · L1) · 주소 체계(L2)는 그대로다.
- 개인 표식은 `/me.personal` · `/site/info.personal` 하나다. `viewer/src` 의 개인 갈래는 이 표식 · 머리 띠 · 착지 · [지금 실행] · 프로젝트와 맞추기로 제한한다 — 로컬 전용 코드가 불어나 V1 의 근거가 되살아나지 않게. 메뉴 표에 칸을 더하는 일(숨길 화면이 셋 이상 생길 때)은 그때 한다.
- 보기에는 쓰는 단추가 없다(G2). 개인 화면은 다른 서버의 API 를 부르지 않는다 — 나가는 일은 개인 서버가 한다(§9.1).

## 12. 단계

**단계 번호는 순서다. 판 번호(v1.10 …)는 사람이 태그 때 묶는다.** 판마다 끝에 전체 시험(`node --test test/*.test.mjs`) · 하네스 · CHANGELOG 「(다음 판)」 · 커밋까지 한다. 시험은 세 칸으로 적는다 — **core**(순수 함수 · `test/<새것>.test.mjs`) · **e2e**(시험 안에서 서버 하나 · 둘을 띄운다 — `test/ingest.test.mjs` 가 하네스를 대신한 선례) · **사람 실측**(판 완료 조건에서 뺀다 — 지식생성 TODO 「나온 것」 의 「진짜 claude」 줄처럼).

| F9 | ingest 의 이전 판 = 사슬 끝(계산) · 새 판 date = 그 판이 바뀐 날(§7.1) | P1 | 판 셋 연속 → 머리줄이 바로 앞 판 · date 순서 |

### 12.1 단계 ① 내 kmd 가 뜬다

**이 단계로 할 수 있게 되는 것** — 한 화면 · 한 로그인으로 내 레포 여럿을 보고, PC 를 켜면 개인 kmd 가 떠 있다. 프로젝트 서버와 한 PC 에 같이 산다.

| 범위 | 시험 |
|---|---|
| `ctx up --root`(훑기 · 데이터 자리 · 고정 포트 · 서버 묶음에서 세운 새 레포가 바로 보인다) · 옛 `ctx up <레포>` 와 함께 뜰 때 안내 · 개인 표식 · 착지 · 재인증 단추 · `--as` 이름 · 표시 이름 · 레포별 개인 git 켜기(`mirrorOf` · origin 주소 대조) · Windows 시작프로그램 · self-update 뒤 다시 띄우기 · 시작 안내 「나가는 길」 · 클라우드 폴더 경고 · `--to me` · `CDP_ME_TOKEN`(tokenstore 이름 인자) · 개인 큐레이터 폴더 `.mcp.json` | core: 레포 폴더 훑기 · 이름 고르기 · 클라우드 경로 판정. e2e: 개인(레포 둘) + 팀 서버를 한 시험에서 — 레포 둘이 한 `/me` 에 · Set-Cookie 이름 · 경로 단언 · `--to me` 와 `login.json` 이 각자 서버로 · 개인 git 꺼진 레포 save → push 0, 켜면 재시작 없이 push 1 · 프로젝트 origin 과 같은 주소면 켜기 거절. 사람 실측: Windows 로그오프 → 로그온 뒤 떠 있다 · 망 끊고 화면 · 찾기 |

### 12.2 단계 ② md 가 곧 지식

**할 수 있게 되는 것** — md 폴더를 화면 단추 하나로 그대로 내 지식으로 만들고, 화면 · 세션 · 편집기로 고친다. 좌표는 원하는 문서에만 단다.

| 범위 | 시험 |
|---|---|
| 등록부 밖 문서 통째 쓰기 save 입력(큐레이터 · `base` 잠금) · `ctx ingest --as docs`(MCP save · 파일마다) · 고친 기록 `edit`(예약 · touches 검사 · 자기 반영 계산 · 암묵 전환 안 켬 · `/sources self`) · `POST /api/<r>/edit` · 작업실 › 고치기(등록부 밖 통째 · 섹션 + base · 반영하며 저장 · 항목 더하기 · 좌표 달기) · 거두기(`collectPlan` · `ctx collect` · 사본 → save → 복원 · 손 커밋 표시) · 개인 [지금 실행] (들이기 `--no-llm` · 문서로 들이기 · 거두기) · `cdp-curate` 「직접 쓰기」 절 · 기록 목록에서 `edit` 접기 · 빈 틀 `.gitignore` · 이력 「자기 반영」 거름 | core: 문서로 들이기 계획 · 좌표 달기의 헤딩 변환(구두점 헤딩 「API (v2): 인증」 · ` - ` 든 헤딩) · `collectPlan`(CRLF 섞음 · 코드 블록 안 `##` · 헤딩 이동 거절) · 자기 반영 계산(새 레포 첫 고치기에 대기 수 불변). e2e: md 12개 폴더 → 문서 12 · 대기 0 · check error 0 · 다시 → 커밋 0 · writer 토큰으로 `--as docs` → `E_FORBIDDEN` · `/edit` 두 번 같은 base → 뒤엣것 `E_CONFLICT` · 손 편집 둘 + 새 md 하나 → 거두기 1회 → 커밋 1 · 트리 깨끗 · `work/` 손 편집 섞이면 전체 거절 · 가짜 `E_CHECK` 면 트리 바이트 복원. 사람 실측: 브라우저로 고치기 · Obsidian 보관함 폴더 |

### 12.4 단계 ④ 프로젝트와 맞추기

**할 수 있게 되는 것** — 고른 것을 프로젝트로 보내고, 프로젝트가 바뀌면 받는다. 프로젝트 큐레이터는 받은 것을 대기열에서 묶음으로 본다.
