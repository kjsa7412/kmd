## 0. 운영자의 말 · 결론

> 어찌되었든 개인지식이든 공유지식이든 깃으로 지식을 저장소에 올려두던 서버(개인pc)안에 두던 2가지다 운용할수 있게 해주고 깃은 백업장치 정도로 그리고 공유서버에 올라간 브라우저로 접속해도 내 개인지식을 경로로 하면 볼 수 있도록 하자. 개인 pc용 프로그램도 똑같은 기능을 지원하는걸로 서비스용 개인 pc용 둘다 saas냐 로컬 프로그램이냐의 차이지 기능을 동일하게 가능하다. 해당 내용 검토해봐라. — 운영자, 2026-10-22

**결론 — 받아들인다. 세 줄로 줄이면 이렇다.**
> 1. 지식은 **kmd 안에** 둔다. 팀 서버든 내 PC 든 같은 프로그램이다.
> 2. git 은 **저절로 하는 백업**이다. kmd 마다 백업 자리를 하나 두면 모든 지식이 백업된다. 백업이 멈추면 조용히 넘어가지 않는다.
> 3. 팀 화면에서도 **내 PC 프로그램의 지식이 열린다.** 내 PC 프로그램이 켜져 있으면 기능이 같다.

> **쉬운 말로 — 다섯 줄**
> 1. kmd 는 **두 자리에 같은 프로그램**이다. 팀 서버에 깔면 SaaS(늘 켜짐 · 여럿이 들어온다), 내 PC 에 깔면 로컬 프로그램(나 하나 · 망 없이도 된다). 보기 · 찾기 · 고치기 · 저장이 곧 반영 · 세션 저장 · 보내기가 같다.
> 2. 지식은 **어느 한 kmd 안에** 산다. 개인 지식이든 공유 지식이든 팀 서버에 둘 수도, 내 PC 에 둘 수도 있다. 남과 같이 쓰려면 늘 켜진 팀 서버에 둔다.
> 3. git 은 **저절로 하는 백업**이다. 설정에서 백업 자리(사내 GitLab · 다른 드라이브 · NAS 폴더)를 한 번 정하면 저장할 때마다 민다. 밀지 못하면 「백업이 n분째 멈췄다」 가 뜬다 — 조용히 넘어가지 않는다.
> 4. 팀 화면에서 **[잇기] 에 `D:\kmd\배포노트` 를 붙이면 내 PC 지식이 목록에 「내 PC」 로 섞여 나온다.** 경로를 여는 것은 내 PC 프로그램이고, 내용은 팀 서버로 가지 않는다. 처음 한 번 [허락] 만 누른다.
> 5. 한계 하나 — **브라우저 혼자서는 경로 글자로 폴더를 못 연다**(폴더 고르기 창만 되고, 그것도 https 주소에서만 된다 · 지금 팀 주소는 http). 그래서 내 PC 지식은 내 PC 프로그램이 켜진 PC 에서 열린다. 프로그램 없이 브라우저만으로 여는 길은 팀 화면이 https 가 된 뒤의 일로 남긴다(부록 A).

**운영자에게 묻는 것은 둘이다(§11)** — ① 한 지식은 kmd 하나에서만 쓰고 git 은 백업으로 둔다(v0.4 의 「어느 kmd 든 git 에 같이 쓴다」 를 걷는다) ② 백업의 기본 자리(팀은 사내 GitLab · PC 는 다른 드라이브나 NAS 폴더). 나머지는 권장안대로 정했다. **가장 먼저 낼 것은 L0 「백업이 조용히 멈추지 않는다」** 다(§10). 작고 값이 가장 크며, 실서버에 바로 올릴 수 있다.

| 원문의 말 | 지금 CDP 코드로 | v0.5 권장으로 |
|---|---|---|
| 깃으로 올려 두든 kmd 안에 두든 둘 다 | 반쯤 된다 — 지식 레포는 늘 kmd 안의 git 작업 사본이고, origin 은 선택이다(`core/reponew.js:44-45` · `viewer/bin/ctx-serve-doctor.mjs:212-218`) | 된다 — 둘의 차이는 「백업이 있느냐」 다. 공유 지식도 PC 에 둘 수 있지만, 남과 같이 쓰려면 그 PC 를 팀 서버로 열어야 한다(설치 선택 · 권하지 않음) |
| 깃은 백업장치 정도 | 반쯤 된다 — save 마다 미러가 민다(`core/save.js:454-473`). 그러나 재시도와 시작 시 push 가 없고, 실패해도 조용하며, 지워지거나 되감긴 백업을 ok 로 본다(실측 P1 · gone.mjs · 설명서 :219) | 된다 — 미러를 백업 장치로 고친다(KM50 · §4) |

## 2. 구조

```
 [백업 — git]  사내 GitLab 프로젝트(지식 하나 = 하나) · 또는 다른 디스크 · NAS 의 bare 폴더
   dpms_wiki.git   gdi.git                      kim-배포노트.git(D:\ 아닌 드라이브 · NAS)
        ▲ push — 팀 kmd 의 배포 키              ▲ push — PC kmd(켜 있을 때 · 시작 시 한 번)
        │  그 kmd 가 붙인 백업에만 · 원격 sha = 내가 민 sha 일 때만
 [팀 kmd = SaaS · 늘 켜짐]                      [김의 PC kmd = 로컬 프로그램 · 127.0.0.1:7400]
  dpms_wiki · gdi(공유)                           D:\kmd\배포노트 · 받은편지함(개인)
  이 · 박의 서버 안 내 지식(관리자가 본다)
        ▲ 브라우저 · /mcp(키 cdp)                  ▲ 브라우저 · /mcp(키 kmd · 사용자 범위)
  김의 브라우저 — 팀 화면  ── 1단계: 짝지은 토큰으로 PC kmd API 를 부른다(CORS) ──▶ 127.0.0.1:7400
                            ── 0단계: 「내 PC 지식 ↗」 링크로 PC kmd 화면을 연다 ──▶
```

하나인 것은 셋이다 — 지식마다 쓰는 kmd 하나 · 지식마다 백업 하나(0 또는 1) · kmd 마다 백업 자리 하나. 여럿이어도 되는 것은 kmd(팀 · PC)와 사람이 들르는 브라우저다. git 의 역할은 셋으로 갈라 부른다 — **원천**(세울 때 읽는 곳 · seed · 받아 온 곳) · **백업**(그 kmd 가 민다) · **작업 레포**(코드). 받아 온 곳(원천)은 백업이 아니다(§4.3).

## 3. 「기능 동일」 — 같은 여섯 칸과 허용된 차이(KM51)

A = 팀 kmd 안 · B = 내 PC kmd 안 · C = 팀 화면에서 연 내 PC 지식(B 에 붙는다 · §5).

| 기능 | A | B | C | 같은가 |
|---|---|---|---|---|
| 보기 · 찾기 · 그래프 · 검사 | ○ | ○ 같은 화면 | ○ = B | 같다 |
| 고치기(save · 커밋 · 되돌리기) | ○ | ○ + 편집기로 고친 것 거두기 | ○ = B(PC kmd 의 save) | 같다 |
| 저장이 곧 반영(기록 + 섹션 한 번) | ○ 내 지식. 공유는 대기열(설계대로) | ○ | ○ = B | 같다 |
| 세션 저장(MCP) | ○ 키 `cdp` | ○ 키 `kmd` | ○ = B | 같다 |
| 보내기 | ○ | ○ 팀 kmd 에 닿을 때 | ○ = B | 같다 |
| git 백업 · 이력 | ○ 늘 | ○ PC 가 켜 있을 때 · 시작 시 한 번 | ○ = B | 같다(때만 다르다) |

**허용된 차이 — 자리의 성질이라 프로그램을 고쳐도 같아지지 않는다(끝 시험이 이 목록을 들고 있다)**

| 차이 | A 팀 kmd | B 내 PC kmd |
|---|---|---|
| 들어가기 화면 · 명부 · 콘솔(토큰 발급) | 있다 | 없다 — 나 하나 · 루프백 자동 로그인 |
| 남과 같이 쓰기 | ○ | × — 같이 쓰려면 그 PC 를 팀 서버로 연다(설치 선택 `--bind` · 루프백 밖은 인증 없이는 거절 — `ctx-mcp-serve.mjs:544-547`) |
| 망 없이 | × | ○ 내 지식만 |
| 다른 기기에서 | ○ 어디서든 | × 그 PC 만(C 도 그 PC 의 브라우저에서만) |
| 관리자가 볼 수 있나 | **예** — 디스크 · 백업 · 서버 운영자(가림은 화면과 API 뿐) | 아니오 — **단, 백업을 GitLab 에 켜면 GitLab 관리자와 그 프로젝트 사람은 본다.** 나만 보려면 백업 자리를 내 디스크나 NAS 로 둔다 |

- 그래서 화면과 문서의 말은 **「같은 프로그램이다 — 팀 서버에 두면 같이 쓰고, 내 PC 에 두면 나만 쓴다」** 다(N14 · §8).
- KM54(초안)의 ⋯ 「팀으로 열기」 단추는 걷는다. PC 프로그램을 팀 서버로 세우는 일은 설치 명령의 선택(`--bind` · 팀 설치 마법사)으로만 둔다. 루프백 밖에서 인증을 강제하는 장치는 이미 있다(`:544-547` · 개인 모드는 127.0.0.1 고정 `:529`). 문서에는 「PC 프로그램도 팀 서버로 세울 수 있다 — 같은 프로그램이다」 한 줄만 쓴다.

### 4.2 미러를 백업 장치로 고친다

- **백업 자리 — kmd 마다 하나.** 팀은 설치 때 정하고, PC 는 설정 한 칸이다. 자리가 폴더면 지식마다 `<자리>/<지식>.git` bare 를 저절로 만들어 모든 지식이 저절로 백업된다. GitLab 이면 관리자가 지식마다 프로젝트 주소를 한 번 붙인다(지금의 콘솔 「origin 연결」 · `ctx-mcp-serve.mjs:1424-1440`). 끄기는 ⋯ 안에 둔다. 지식마다 붙던 [켜기] 단추는 없다.
- **레포마다 켠다** — 전역 `opt.mirror` 를 보는 여덟 곳(`ctx-mcp-serve.mjs:713` · `738` · `1570` · `1771` · `1931` · `1991` · `2019` · `2070`)을 「이 레포에 백업 상태 파일이 있나」 함수로 바꾼다.
- **판정 — 원격의 실제 sha.** 시작할 때 · 다시 보내기 틱마다 · 매일, `ls-remote origin refs/heads/<가지>` 를 HEAD 와 상태 파일의 `pushed`(마지막으로 민 sha)에 견준다.

| 원격 가지 | 상태 | 하는 일 |
|---|---|---|
| = HEAD | ok | — |
| = pushed 이고 HEAD 의 조상 | lag | 다시 보내기 — 1 · 5 · 15 · 60분, 그 뒤 시간마다. 사유가 auth 면 되풀이하지 않고 한 줄 |
| 없음 | gone | 바로 다시 밀고 bad 「백업이 지워졌다 — 다시 올렸다」 |
| pushed 의 조상이면서 pushed 와 다름 | rewound | 바로 다시 밀고 bad 「백업이 되감겼다 — 다시 올렸다」 |
| HEAD 의 자손(내가 모르는 커밋이 있다) | behind | 그 레포의 save 를 닫는다(`E_BEHIND`) · bad · admin [백업에서 받기] (§4.3) |
| 그 밖(남이 pushed 위에 밀었다 · 갈라졌다) | moved | push 를 멈추고 그 레포의 save 를 닫는다 · bad 「이 지식의 백업을 다른 kmd 가 이어 쓴다 — 여기서는 읽기만」 |

- **push 는 대상을 적는다** — `push origin HEAD:refs/heads/<가지>`. 가지는 읽어서 쓰고(실서버 dpms_wiki 는 master), 새로 세울 때만 `init -b main` 으로 한다. `ahead===0 → skipped`(`core/git.js:269`)는 걷는다.
- **경보는 안 보낸 커밋의 나이로** — HEAD 와 원격 sha 사이의 가장 오래된 커밋을 본다(추적 ref 를 보지 않는다). 6시간이면 warn, 24시간이면 bad 다. 경보가 뜨는 곳은 주인 화면 띠 · 콘솔 · healthz, 그리고 **MCP save 응답의 warnings · 세션 시작 brief** 다. PC 사람은 Claude Code 로만 쓰고 화면을 잘 열지 않기 때문이다. 백업이 설정돼 있는데 off 가 된 것도 경고한다(지금은 off 면 침묵 · `core/save.js:468`). 백업 자리가 없는 지식은 기록이 50건을 넘거나 7일이 지나면 warn 한 줄로 올린다(단추는 없다).
- 뒤에서 도는 git 에는 `GIT_TERMINAL_PROMPT=0` · `GCM_INTERACTIVE=never` 를 준다(F6 · 지금은 `reponew.js:137` · `gitauth.js` 에만 있다). `classifyPushError` 에 경로 대상의 실패 패턴을 더한다.
- **정직하게** — 이것은 정정 상자 ①②③ 이다. 백업 실패를 save 거절로 바꾸지는 않는다. 백업 때문에 일이 멈추면 안 되기 때문이다. 예외는 behind · moved 둘뿐이다. 바탕이 옛것이거나 다른 kmd 가 쓰는 지식이라서, 그대로 쌓으면 기계가 합칠 수 없게 된다.

### 4.3 한 지식은 kmd 하나 — 표지 없이 지킨다

- **규칙 한 줄 — kmd 는 자기가 붙였거나 만든 백업에만 민다.** 상태 파일 `<data>/backup/<레포>.json` 이 있는 원격이 그 kmd 의 백업이다. clone 으로 받아 온 원격은 「원천」 일 뿐 백업이 아니므로, 미러가 켜지지 않는다. F5(`ctx up` 이 origin 이 있으면 미러를 저절로 켠다 · `ctx-up.mjs:242` · `:262`)는 이 규칙으로 고친다. gdi 를 clone 해 둔 PC 가 운영 지식에 미는 일이 없어진다.
- **이어 쓰기** — 백업에서 받아 와 그 백업을 이 kmd 의 것으로 잇는 일이다(되살리기 · 옮기기). ⋯ [이 백업 이어 쓰기] 하나로 하고, 팀 kmd 에서는 admin 만 한다. 이을 때의 원격 sha 를 `pushed` 로 적는다.
- **두 kmd 가 같은 백업에 미는 사고**(옛 kmd 가 아직 살아 있다 · tar 를 다른 기계에 풀었다)는 기계가 막지는 못하지만 조용하지는 않다. 한쪽이 민 뒤에 다른 쪽은 「원격 ≠ 내가 민 sha」 → moved 로 save 를 닫고 bad 를 낸다. 어느 쪽이 맞는지는 사람이 정한다. 옛 kmd 의 백업 길이 auth 로 막혀 `ls-remote` 도 안 되면 moved 를 알 수 없다. 그래서 계획 옮기기는 옛 kmd 를 먼저 치운다(아래). 그사이에는 안 보낸 나이 경보가 bad 까지 올라간다.
- **옮기기 · 되살리기 — 관리자 설명서의 절차 둘.** 표지 save 같은 지식 쓰기는 하지 않는다.
  - **계획 옮기기**(옛 kmd 가 살아 있다 — 늘 이 길) — ① 옛 kmd 에서 그 지식의 백업이 ok(원격 = HEAD)인지 본다 ② 옛 kmd 에서 그 지식을 치운다(휴지통 · save 가 닫힌다) ③ 새 kmd 에서 [잇기] 에 백업 주소 → [이 백업 이어 쓰기]. v0.4 부록 A 의 옮기기 ①~④(v0.4 :449)를 표지 없이 같은 차례로 한다.
  - **인수**(옛 kmd 가 죽었다) — ③만 한다. 화면에 한 줄 「옛 kmd 에서 백업에 못 간 기록은 잃는다」.
- **서버가 옛 상태로 되살아났을 때**(VM 스냅샷 · 옛 tar 와 옛 repos) — 시작할 때 백업이 붙은 레포마다 fetch 를 한 번 한다. 원격이 HEAD 의 자손이면 behind 다 → 그 레포의 save 를 닫고(`E_BEHIND` 「서버가 옛 상태로 되살아났다 — 백업에 n건 더 있다」) bad 를 낸다. admin 이 [백업에서 받기] 를 누른다 — 지금의 syncWithOrigin(ff 만 · save 뮤텍스 안 · `core/mirror.js:152-164`)에, 받은 머리를 core check 하는 단계를 더한다. 받는 커밋이 `_members.md` 를 바꿨으면 diff 한 줄을 보이고, admin 이 확인하기 전까지는 앞 명단으로 읽는다. **자동 ff 는 하지 않는다.** 표지가 없어서 그 커밋이 내 것인지 기계는 알 수 없다. 그래서 :712 에도 예외가 생기지 않는다.
- **폴더 밖 이력의 되살리기** — bare clone · `remote.origin.fetch` · upstream 세우기를 한 함수로 묶는다(실측 P3 의 구멍).
- **실서버 upgrade 의 한 단계** — 지금 `--mirror` 로 미는 원격을 그 kmd 의 백업으로 적는다(`upgrade.sh` · admin). 원격이 HEAD 의 조상이거나 같을 때만 적고, 원격이 앞서 있으면 먼저 받으라고 멈춘다.

### 4.4 되살린 뒤의 권한 · 예약 파일

- git 으로 되살리면 등록표(주인 · 개인 여부 · 할당)는 돌아오지 않는다. 그런데 등록은 폴더를 두는 것이고(설계서 :504), `repos: ['*']` 인 사람은 모든 레포를 본다(`core/auth.js:67-80`). 그래서 **되살린 레포는 주인을 알기 전까지 admin 만 본다.** 주인과 개인 여부는 지식 안 `_members.md` 에서 읽어, 되살리자마자 가림을 다시 건다.
- **`_members.md` · `_format.json` 은 예약 파일이다.** edits · docdrop · 거두기가 모두 거절하고, 바꾸기는 주인 전용 연산(시스템 save) 하나로만 한다. 지금은 뿌리의 md 가 모두 edits 대상이라 아무 큐레이터나 명단을 고칠 수 있다(`core/docrefs.js:43-48` · `core/edits.js:31-35`).
- 사람 폴더의 `.kmd.json` 은 **백업에서 뺀다.** 주인 설치 id 는 `<data>` 쪽 표로 옮긴다. 보낼 곳과 비공개 목록만 `.kmd.json` 에 남는다(v0.4 :132 · v0.3 :67). 그러면 주인 판정이 한 곳으로 모인다. 되살린 뒤 보낼 곳은 「보낼 곳을 다시 이어 주세요」 한 줄로 안내한다. 화이트리스트에 더하는 것은 `_format.json` · `_seed.json` 과 첨부다.

## 5. 팀 화면에서 내 PC 지식(KM52)

### 5.1 먼저 정정

v0.3 :92 「화면의 판정 코드는 이미 브라우저에서 돈다」 는 **틀렸다.** 화면은 모든 계산을 서버 API 로 받는 얇은 클라이언트이고(`viewer/src/lib/api.js:186-243`), core 에서 가져오는 것은 `core/repopath.js` 하나다(`DocView.jsx:14`). I1 의 「화면 Store」 는 서버 쪽 `core/store.js` 다(설계서 :269). 같은 core 를 브라우저에 묶는 실측(14개 + js-yaml · node: 0 · gzip 31KB · 서버 Store 와 결과가 같음 — `browser-path\compare.mjs`)은 부록 A 「나중」 의 밑천으로 둔다.

### 5.2 길 — PC 프로그램에 붙는다

원문 「공유 서버에 브라우저로 들어와도 내 개인 지식을 경로로」 를 글자 그대로 하는 길은, **팀 화면이 내 PC 프로그램(127.0.0.1:7400 · `ctx-mcp-serve.mjs:529`)에 붙는 것**이다. 브라우저는 경로 글자로 폴더를 열 수 없지만 PC 프로그램은 열 수 있다. 이력 · 백업 · 세션 저장 · save 는 지금 코드 그대로다. 그래서 C = B 다.

- **0단계 — 새 장치 0.** 팀 화면의 사람 메뉴에 「내 PC 지식 ↗」 링크 하나를 둔다. `http://127.0.0.1:7400/r/` 를 새 탭으로 연다. PC 프로그램이 없거나 꺼져 있으면 탭이 열리지 않을 뿐이다. L0 와 같이 내도 된다.
- **1단계 — 팀 화면 안에서.** 팀 화면의 [잇기] 에 `D:\kmd\배포노트` 를 붙이면 PC 프로그램이 그 폴더를 잇는다(v0.4 §3.3 사람 폴더). 그 지식은 지식 목록에 「내 PC」 표시로 섞여 나온다. 두 프로그램이 같은 API 라서 `api.js` 는 지식마다 부를 주소만 바꾼다.
- **주소** — `<팀 주소>/r/#~배포노트/절차`. 해시 조각이라 팀 서버에도 Referer 에도 가지 않는다. `/me` 는 이미 화면 껍데기 API 라(`ctx-mcp-serve.mjs:1026` · `:1044` · 아는 접두 `:364`) 쓰지 않는다. PC 프로그램이 없는 곳에서 그 주소를 열면 「이 PC 에는 내 지식이 없다 — 내 PC 프로그램이 켜진 PC 에서 열린다」 한 줄이 뜬다.

| 실측 | 결과 | 근거 |
|---|---|---|
| http 사내 주소의 페이지 → `http://127.0.0.1` 로 OPTIONS + POST | 200 · 응답 본문을 읽었다 · isSecureContext false | Chrome 155 헤드리스 · `critic-loopback\run.mjs` · `out.json` |
| 왜 됐나 | 이 PC 에 회사 정책 `InsecurePrivateNetworkRequestsAllowed=1` 이 있다(HKLM\SOFTWARE\Policies\Google\Chrome · 편집 때 다시 확인) | `reg query` |
| 실제 창 · 다른 PC | 로컬 네트워크 접근 허락 창이 뜨는지, 다른 PC 에도 같은 정책이 있는지는 모른다(추정) | 사람 실측 S1 |
| 팀 화면이 https 가 된 뒤 | Chrome 은 루프백을 믿을 만한 출처로 보아 섞인 콘텐츠로 막지 않는다(추정) | 사람 실측 S1 |
| 견줄 것 — 브라우저가 폴더를 직접 읽는 길 | http 사내 주소에는 폴더 API · OPFS 가 모두 없다 | `browser-path\run.mjs` 'chrome lan-http' |

### 5.3 지을 것 · 지킬 것

① **Origin** — PC 프로그램의 Origin 검사(`ctx-mcp-serve.mjs:772-792` · 설계서 :497 — 지금은 남의 출처를 403 으로 거절한다)에, [잇기] 로 이은 팀 주소 하나를 저절로 더한다(정정 상자 ⑦).
② **CORS — 좁게.** 그 출처에만, 읽기 API 와 save(curate · 첨부)에만 준다. 콘솔 · 토큰 · 설정 · 삭제 · `/mcp` 에는 CORS 를 주지 않는다. `healthz` 만 누구에게나 준다(PC 프로그램이 있다는 사실과 판만 알린다).
③ **짝짓기** — 남의 사이트 요청에는 쿠키가 실리지 않으므로 토큰을 쓴다. 팀 화면이 PC 프로그램 창(`127.0.0.1:7400/pair`)을 한 번 열면, PC 프로그램이 「팀 화면 <주소> 에서 내 PC 지식을 연다 — [허락]」 을 띄우고 토큰을 postMessage(대상 출처 고정)로 넘긴다. 처음 한 번만 누르고, 그 뒤로는 저절로 된다. 토큰은 12시간짜리이고 탭 메모리(sessionStorage)에만 둔다. PC 쪽은 해시만 둔다(I13).
④ **팀 화면에 처음으로 페이지 CSP** — `default-src 'self'; connect-src 'self' http://127.0.0.1:7400; img-src 'self' data: blob:; frame-src 'self' blob:; object-src 'none'`. 지금 index.html 응답에는 CSP 가 없다(`ctx-mcp-serve.mjs:2804-2807`). index.html 의 인라인 스크립트 둘(서버 표지 `:2803` · 테마)에는 nonce 를 단다.
⑤ **fail-closed** — PC 지식의 요청은 팀 서버로 가지 않는다. `api.js` 의 `req()` 는 PC 지식인데 PC 주소가 아닌 곳으로 보내려 하면 throw 한다. 시험(Playwright) — 내비게이션 주소 · Referer · 본문 · 팀 서버 로그에 PC 지식 이름과 경로 조각이 0 이어야 한다.
⑥ PC 프로그램이 꺼져 있으면 한 줄 「내 PC 프로그램이 꺼져 있다」 를 띄우고, 목록의 「내 PC」 줄은 흐리게 둔다.

**솔직히** — 팀 화면에 XSS 가 하나 생기면, 짝지은 사람의 PC 지식을 읽고 save 할 수 있다(W36). 이를 막는 것은 ②의 좁은 범위 · 모든 쓰기가 save 검사를 타고 커밋으로 남아 되돌릴 수 있다는 점 · 백업 · ④의 CSP 다. 파일 지우기와 관리 길은 CORS 에 없다.

### 5.4 안 되는 것

- 다른 기기에서 · PC 프로그램이 꺼졌을 때 · 남에게 보여 주기(→ 보내기). 모두 자리의 성질이다(§3).
- 설치하지 않은 사람이 브라우저로 폴더를 직접 읽는 길(v0.3 §3.4 · 초안 KM55)은 **부록 A 「나중」** 으로 내린다. 조건은 https 뒤 · 읽기만 · 다른 출처다. v0.3 §3.5 의 file:// 정적 페이지 길(TODO V1 ③)은 걷는다. file:// 에서는 vite 모듈 묶음이 실리지 않는다(실측 `probe-file.html`).

초안(343줄)에 비평 둘(정합 · 안전 18건 · 단순함 13건)을 반영했다. high 는 모두 반영했다. 반영하지 않았거나 다르게 반영한 것만 한 줄씩 적는다.

- 정합 「집 표지에 kid · url 을 더하라」 — 표지 home 자체를 나중으로 내렸다(단순함 비평). 같은 위험(연습 clone · 다른 기계의 tar · 같은 설치의 두 사본)은 「붙인 백업에만 민다」 · moved 감지 · 같은 백업 거절 · 연습은 `<data>/drill/` · `instance.json` 새로 짓기로 막았다. kid 조건은 부록 A 에 남겼다.
- 정합 「옮기기는 v0.4 부록 A 차례로 · 옛 레포 표지는 `--claim-home`」 — 차례는 표지 없이 설명서 절차로 받았다. `--claim-home` 대신 upgrade 의 「지금 원격을 백업으로 적기」(원격이 HEAD 의 조상일 때만)로 바꿨다.
- 정합 「집이 백업보다 뒤면 자동 ff 해도 된다」 — 표지가 없어 백업의 커밋이 내 것인지 알 수 없으므로 자동 ff 는 하지 않는다. 관리자 [백업에서 받기] 로 두고, :712 예외도 만들지 않았다.
- 정합 「`/me` 경로가 보증을 깬다 · 다른 출처 · fail-closed」 — 브라우저 직접 길을 부록 A 로 내려 다른 출처는 그 조건으로 옮겼다. 해시 주소 · fail-closed · `/me` 쓰지 않기는 1단계(§5.3)에 반영했다.
- 정합 「브라우저 HTML 시각 자료 CSP · 바깥 그림」 — 페이지 CSP 는 반영했다(§5.3 ④). blob meta CSP · 바깥 그림은 브라우저 직접 길의 일이라 부록 A 로 옮겼다.
- 정합 「C 의 I2 모순 · 거두기 시점」 — C 가 PC kmd 의 save 를 타게 되어 모순이 없어졌다. 브라우저 직접 쓰기는 부록 A 에서 PC kmd 폴더는 읽기만으로 둔다.
- 정합 「save 스키마 strict · `Kmd-Schema`」 · 「토큰 이사 순서 · PC 토큰 만료」 — 대신 전하기를 걷어서 이번 판에는 해당하지 않는다. 조건은 부록 A 에 남겼다.
- 정합 「불변조건 여덟」 — 최종 설계에 맞춰 다시 셌다. 손대는 일곱(§1 정정 상자)과 손대지 않는 넷(I9 · I13 · :712 · :716)으로 적었다. 줄어든 것은 표지 · 대신 전하기 · 브라우저 쓰기를 나중으로 내렸기 때문이다.
- 정합 「관리자가 백업 주소를 바꾸면 주인의 「오늘 바뀐 것」 에도」 — 주인 확인 없이는 거절하므로 auth.log 한 줄만 남겼다. 주인 피드는 부록 A 로 옮겼다.
- 단순함 「주소는 `/r/<지식>/` 그대로 · 겹칠 때 `~`」 — 경로가 팀 서버 로그로 가므로(정합 비평) 해시 `#~<지식>/…` 로 합쳤다.
- 단순함 「KM 넷 안팎」 — 다섯(KM50~KM54)으로 묶었다. 첫 판 L0 를 따로 결정으로 남긴 까닭은 실서버에 바로 올릴 일이기 때문이다. 초안 §5.3 「셋째 길(PC 지식의 백업을 팀 kmd 에서 읽기만)」 은 git 주소 받아 오기가 팀에서 admin 전용이 되어 뺐다.
- 초안 W35(https P0) · W44(출처 바뀜) · Q41(https 시점) — 1차 길이 루프백이라 https 는 문턱이 아니게 되어 뺐다. https 는 S1 실측과 부록 A 의 조건으로만 남는다.
- 초안 「갈래 사이 닫음」 — 명단은 유지, 백업 층은 미러만 제품에 두고 나머지는 운영 절차, 오프라인 보내기는 단추 남김으로 닫았다(§11 「정해 둔 것」).
